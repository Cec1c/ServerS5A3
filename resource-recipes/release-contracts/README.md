# EXE 依赖服务切换与资源复用增量

这里公开三个经过筛选的实现增量及独立的资源缓存函数。补丁来自带有资源配对扩展的下游实现，**不能直接应用到缺少该扩展的公开游戏控制器**。公开游戏更新入口未因此新增资源发布、队列或审批能力。

1. 01-exe-only.patch：增加 kind=exe-only；要求 EXE 改变、PVF/频道保持原身份；不复制或重传 PVF，不重建 GM 索引。激活仍核验实际发布与受保护通道，相关回归随增量保留。
2. 02-profile-proof.patch：绑定发布 profile 的绝对路径、文件摘要和解析内容，只允许经过配对证明的 EXE/PVF 摘要变化；拒绝无来源证据和其他配置变化。
3. 03-shared-authority.patch：资源阶段复用 runtime/game-updates/.authority/master 专用权威检出，同时保持每次实际 pull 与来源证明，附对应路径断言。
4. resource_cache.py：从按 SHA256 命名的预取缓存读取 PVF，核对大小与摘要，复制到新的 stage 并再次验哈。缺失返回 miss；损坏保留证据并拒绝，不覆盖已有 Script.pvf。

补丁中的依赖路径用于说明原接口，包括独立客户端发布器和配对验证器；这些依赖的完整实现、生产配置和私有祖先不随补丁公开。集成方应实现相同契约并完成本地测试，不能以“补丁公开”视为该入口已经安装。

索引复用以 PVF、生成器逻辑、工具、配置/参数和格式全部匹配为前提；须重新读回六份产物的大小、摘要及兼容性，记录原生成提交、当前发布提交和 regenerated=false。源码或文档版本变化本身不要求重复全量索引；实际输入或证据变化时重新生成。该原则不替代正式服务端的当次主干构建。
