# 次元光辉地下城产出配方

次元光辉（10163136）的物品说明指向魔界地区，但配套归档没有引用该材料的掉落记录。本配方在 `etc/independent_drop.etc` 追加明确的副本材料规则，与同一 PR 的服务端读取逻辑配合使用。

| 副本 | 普通/精英怪 | BOSS | 每次命中 |
| --- | --- | --- | --- |
| 310–315：时间广场、兽人峡谷、恐怖的栖息地、疾风地带、红色魔女之森、血色防线 | 0 | 10% | 1 个 |
| 316：魔界裂缝 | 0 | 10% | 1 个 |
| 7539：时空裂缝 | 1% | 10% | 1 个 |

这些数值是可审查的运营配置，不是从原档恢复出的官方掉率。由当前怪物死亡流程确定接收者，采用个人掉落模式时每位队员独立抽取。概率不额外乘难度、队伍人数或成长契约；该材料不进入诞生之芽的共享权重池。规则覆盖同一副本编号下的迷宫和任务路线，其他编号的活动图、317 任务图不受影响。

## 配置契约

服务端扩展段 `[servers5a3 dungeon material drop]` 的每行六个整数为：

```text
副本ID 材料ID 普通怪概率 精英怪概率 超级精英怪概率 BOSS概率
```

概率分母为 1,000,000；0 关闭对应类型，1,000,000 表示必掉。每行独立判定，成功生成一个材料。示例：

```text
[servers5a3 dungeon material drop]
310 10163136 0 0 0 100000
7539 10163136 10000 10000 10000 100000
[/servers5a3 dungeon material drop]
```

这是 ServerS5A3 的显式扩展，不重新解释原生 `[independent drop]` 的类型字段。读取器拒绝重复副本/材料、未闭合段、非整数及越界概率；运行时解析真实物品，拒绝缺失或非材料的引用。没有扩展、没有本副本规则或概率为 0 时，不消耗额外随机数。

普通怪物沿用普通掉落入口；316 和 7539 终局 BOSS 会绕过该入口，因此专用裂缝奖励流程也读取此表。史诗之路同时执行普通与专用奖励，仅在普通入口读取，避免重复抽取。配置追加在原有物品抽取之后，保留原概率和数量规则；启用配置后房间随机流会增加抽取次数。

## 生成独立候选

安装 Python 3.10+ 和支持 schema 2 的 PVF-CLI，先确认自己的基线摘要，再执行：

```text
python resource-recipes/dimensional-radiance/build_candidate.py --base <baseline.pvf> --expected-sha256 <已审查的完整SHA256> --tool <pvf-cli> --output <新的输出目录>
```

生成器核对八张副本的列表路径与材料身份，拒绝已存在的扩展；保留原表所有 token 类型及 payload 位，只追加 50 个 token。输出 `plan.json`、独立 `Script.pvf`、完整 patch/verify 回执和 `result.json`。全档验证确保只改一条 ETC，其余条目保持；输出目录包含真实资产，放在 ignored 私有目录。

## 验证及接入

- 合成回归覆盖副本、四种怪物类型、五档难度、概率边界、错误引用、无配置随机流不变、裂缝专用奖励、队员独立物品、死亡重放及重复拾取。
- Linux 上设置 `DNF_RADIANCE_PVF_SMOKE=<候选PVF>`，运行 `go test -buildvcs=false -count=1 ./internal/services/dnfbridge -run '^TestRealPVFConfiguredRadianceDropAndPickup$' -v`，验证八图真实定义及两条掉落入口；时空裂缝额外覆盖真实普通怪物。
- 候选必须与读取扩展的服务端代码配套。单独更新 PVF 或只合并源码不会启用完整方案。发布者按常规资源流程统一玩家、游戏和 GM 的 PVF 摘要，并重建对应 GM 索引；外部频道表继续沿用已批准版本。
- 原生客户端拾取显示与实际刷图体验在配套部署后验收。
