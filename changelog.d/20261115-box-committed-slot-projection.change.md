# 开盒使用已提交的槽位变化，省去额外背包快照

## 变更

- 单开与连开在事务内记录实际扣除、合并及新建的槽位，仅在事务成功后返回完整变化集合；不再为了计算差分而在桥接层前后各读一次角色背包和账号仓库。
- 保留成功 ACK 之后按仓储权威数据刷新槽位的顺序、宠物延迟整容器刷新、公会勋章整容器刷新及显式整容器回退。
- 未声明完整变化能力的旧处理器继续使用原来的前后快照；事务失败不返回已提交投影。

## 验证

- 实际隔离 Linux 对照显示，单次开盒为计算变化而增加的仓储读取由 4 次降为 0 次，默认增量与整容器回退两种模式均保持逐字节相同的回包。旧处理器覆盖对照复现 4 次额外读取。
- 回归覆盖单开、连开、主背包以外的材料、溢出邮件、契约、失败回滚和容器例外；礼包、命令分发及关联仓储专项通过，真实一次性 MariaDB 十连结果与资产保持一致。
- 普通 Linux 服务端构建、适用 vet 和模块校验通过。这里消除的是额外快照读取，事务和发包所需读取仍保留；生产延迟收益及玩家画面须在部署后验收。
