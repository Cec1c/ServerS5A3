# 公会名单批量读取与在线状态刷新合并

## 变更

- 公会名单只批量读取角色姓名、等级、职业、转职和归属字段，按实际数据库路由每批最多256个角色；不读取整套属性、位置和装备，不将部分角色资料写回。转职取值保留主列权威和显式兼容开关的既有语义。
- 不含成员行的续页跳过成员资料读取；保留成员排序、职级、备注、在线频道与报文格式。读取失败、角色缺失或归属不符时保留公会登记资料，不自动删人或改库。
- 名单入口及在线文字投影的归属校验复用只读角色身份查询，保留查询前后的会话代次核对；事务及需要玩法字段的入口仍使用完整角色读取。
- 同一会话、角色代次与公会的可延后在线刷新最多保留一个排队事件；运行中又有变化只补一个后续事件，让普通操作继续执行。队列满采用有限重试，换角、取消、断线和退出频道清理旧任务。
- 增加固定维度的名单读取、构包、发送计时，以及实际摘要SQL、完整读取回退、合并和拒绝计数；慢日志关联连接、代次及触发来源，不增加玩家维度指标。

## 验证

- 红测复现无成员续页的额外完整读取和20次重复在线通知排入20个事件；修复后相关回归通过。
- 增加190成员、24会话、真实MariaDB窄读及ABBA持续负载测试，覆盖报文一致、错误归属、失败降级、运行中合并、代次隔离、有限重试、EXIT与实际死亡/经验幂等。真实数据库和持续负载需显式设置隔离环境，默认跳过不表示通过。
- 本次不改变客户端、PVF、资源索引、数据库结构或资产规则；源码验证、正式部署与游戏内延迟验收分别记录。
