# 公会支持 5000 人扩容分包与永久属性福利图标修复

## 变更

- 公会管理通知（NOTI 70）对永久公会属性福利（type=5）写入 `0x7fffffff` 永久哨兵值，修复客户端因收到 `0` 判定过期而不显示福利栏永久属性图标及“无期限”文案的问题。
- 公会扩容（type=6）与每日公会之契约（type=21）新增 `5000` 档位（前置 `1000`），并兼容已购 `1000` 档契约在扩容至 `5000` 后继续有效与无缝续期；配合 PVF `etc/(r)guild.etc` 新增对应商品条目生效。
- 成员列表（op 140/67 + op 141，每包 300 人）与阶级列表（op 1452 + op 1453，每包 500 人）按客户端原生协议分包流式下发，避免大公会单包过大；300/500 人以内保持单包原样。
- 公会红包贡献榜（op 1301）在成员超过 1000 时保留贡献前 1000 名并强制包含查询者本人，避免触发客户端固定 1000×40 字节栈缓冲区溢出并保持前 30 排行榜与个人贡献展示正常。
- 放宽 `LoadGuildCharacters` 单批成员上限至 5000（SQL 仍按 256 分批）、将只读快照缓存阈值从 4 MiB 提升至 32 MiB，并使成员变更/备注广播复用到各会话 coalesced 队列与共享只读缓存。

## 验证

- 已通过 `internal/modules/dnf/guild`、`internal/modules/dnf/repository/...` 及 `internal/services/dnfbridge` 全部公会专项与真实 PVF 单元测试、`go vet` 及 `GOOS=linux GOARCH=amd64 CGO_ENABLED=0` 服务端编译；尚未合并或部署至正式服，待 Linux CI 与维护窗口实机验收。
