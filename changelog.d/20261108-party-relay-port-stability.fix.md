# 组队中继的监听端口与角色绑定不再翻转

## 变更

- 建立中继腿时先按 (ownerID, peerID) 升序排序再分配端口，同一队伍重开一次不会再出现「角色与腿端口对调」。
- 原因：端口池是按顺序扫描分配的，原先直接遍历 map 建腿，而 Go 的 map 遍历顺序每次随机，导致同一两人队第二次进图时两条腿的端口互换。
- 客户端会缓存上一局学到的对端端点，端口翻转后它仍往旧端口发，单向不通即判定 P2P 失败，提示防火墙并退队回基地。
- 无新增配置，无行为开关；端口分配结果与建队先后、map 顺序无关。

## 验证

- 已做：`go build ./...`、`gofmt` 无差异；中继相关用例（含两人/三人腿、重试与队长掉线）通过。
- 待验收：游戏内同一队伍连续两次进入副本，确认两次的腿端口映射一致且不再提示防火墙。尚未部署。
