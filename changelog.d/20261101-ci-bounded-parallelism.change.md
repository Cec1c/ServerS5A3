# CI 核心验证并行与附件上传限流

## 变更

- 核心测试、频道检查和安全扫描不再等待六路构建附件上传；构建契约检查独立执行一次，全部构建仍依赖其成功。
- Go 运行与编译并行默认限制为 2；Runner 槽位与容器总限额由维护方按实测容量配置。
- 支持维护方将同一个锁文件挂载到各作业，并设置 `CI_ARTIFACT_LOCK_PATH`，仅附件步骤串行。等待超时或配置的锁缺失时失败，不跳过上传。
- 保留六份分组件产物、上传回执、现有测试和安全检查。锁为空时兼容其它 Runner。
- 支持四个调度槽位与单独的计算门禁：普通构建最多两个，核心测试/安全扫描独占计算门禁，轻量检查可继续。大包测试使用 3 GiB Go 软目标和包并行 1；Runner 容器总限额仍由维护方约束。
- 编译对象使用 Runner 本地 `/cache`，按项目和保护状态隔离；Go 自身按完整编译输入判定对象命中。所有验证命令与正式构建仍实际执行。

## 验证

- GitGud CI lint；上传器 Go 回归；构建组件契约；Linux 容器真实进程上传锁、双构建槽位、重任务互斥与失败释放验证。
- 完整流水线及 Runner 容量观察属于各环境的实际验收；不跳过内存不足或其他失败的作业。
