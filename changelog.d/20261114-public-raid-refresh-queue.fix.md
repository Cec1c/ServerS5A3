# 攻坚名单与进度按接收方合并刷新

## 变更

- 每个会话最多保留一个排队或正在执行的攻坚刷新，分别合并名单、进度和阶段结算目标；同一接收者的突发更新只保留较新版本，不再为每次广播新建 goroutine 或长期保存聚合快照。
- 真正发送前校验角色绑定与代际、攻坚实例、阶段和进度版本，并复核账号、频道和成员关系。会话关闭或角色换代时清除待发刷新，避免旧名单或旧进度写入新会话。
- 会话事件队列已满时只对有脏目标的接收者进行有界重试；后续更新合并在同一条目，队列不会随广播次数增长。真实 659 完成条件和奖励事务的幂等边界保持不变。

## 验证

- 本批加入回归覆盖：慢接收者不阻塞健康成员的名单广播，突发进度合并为单个队列事件，队列满时恢复最新名单或淘汰旧代际，席位过期时钟不等待 socket 写，以及一个慢接收者的奖励流程不阻塞其他成员。
- 上述适用回归已在隔离 Linux 执行通过；各包完整范围、跳过项和既有基线诊断见对应 PR 的验证记录。真实弱网、原生客户端名单与进度表现，以及真实 MySQL 奖励事务仍待验收。
