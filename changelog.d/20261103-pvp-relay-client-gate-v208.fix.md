# 擂台赛客户端放行骰子与申请状态报文（v2.0.8）

## 变更

- 服务端擂台修复上线后，v2.0.7 客户端仍看不到骰子：它的接收门把 class-0/112（骰子结果）和 class-0/113（申请状态）判为丢弃，报文到不了原生接收器。
- 新增 `scripts/client/patch_pvp_relay_gate_v208.py`：从 v2.0.7（`eca5ae90…`）生成 v2.0.8（`c6adcdff…`），在可执行的 `.bp0` 空余区写入一段 37 字节的辅助代码，只放行 class-0 的 112/113，其他报文一律交回原接收门。文件大小、入口和节布局不变，重算 PE 校验和。
- 新增 `scripts/client/verify_pvp_relay_gate_v208.py`，在两个版本上执行真实的接收门做比对。`Docs/PVP_RELAY_DICE_20261102.md` 补充了接收门地址、补丁内容、发布记录，以及换新版客户端时的迁移要求。
- EXE 本身不进仓库，以 Release 附件分发；没有服务端代码、PVF 或玩家数据变化。

## 验证

- 用仓库脚本从 v2.0.7 重新生成的结果，和已发布的 v2.0.8 逐字节一致；未声明的字节改动会被拒绝。
- 接收门比对覆盖类别 0～2 × 全部 65536 个编号，共 196608 种组合：没有执行错误，只有 (0,112)、(0,113) 从丢弃变为放行，控制组不变。
- 2026-11-03 14:40 已作为 v2.0.8 发布到 90CN 更新通道，当天经实机验证可用。
