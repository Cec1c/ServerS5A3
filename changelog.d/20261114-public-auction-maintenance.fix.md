# 拍卖维护、补发轮转与通知隔离

## 变更

- 拍卖恢复改为独立维护 worker：共享玩法计时器只唤醒 worker，不直接持有拍卖锁执行 SQL；重复请求不会替换已登记维护期限，普通请求也不会把维护无限后移。
- 维护轮次跳过尚未到期的在售挂单，按接收者持久待发项轮转，并从上一接收者之后继续，包含读取失败者；每轮最多处理八个接收者，坏邮箱不会长期挤占后续补发。
- 竞价退款金币、邮件提醒和拍卖通知提交到接收者会话事件队列，提交后重新读取权威金币并检查角色代际。慢连接或已满队列不会让已提交资产事务等待，旧角色或旧会话不会收到过期通知；持久邮件仍由维护恢复。
- 拍卖资产修改继续保留事务串行边界；本批缩小的是请求、维护和通知之间的等待范围。

## 验证

- 本批加入回归覆盖：计时器不后移且不阻塞共享队列，多轮维护越过失败接收者，通知在收件人事件循环中保持顺序，换代和会话重绑丢弃旧通知，队列已满时交易结果仍提交且不等待发送。
- 上述适用回归已在隔离 Linux 执行通过；各包完整范围、跳过项和既有基线诊断见对应 PR 的验证记录。真实 MySQL 的维护、补发与通知事务，以及真实慢连接和客户端到账展示仍待验收。
