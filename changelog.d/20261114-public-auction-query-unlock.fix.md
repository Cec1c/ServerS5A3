# 五类拍卖查询在锁外发送响应

## 变更

- 物品搜索、分类搜索、平均价格、我的上架和我的竞拍五类查询先在拍卖锁内完成必要维护、仓储读取和完整响应体构造；随后释放市场锁，再在该请求的原会话事件循环上编码并写入响应。
- 查询准备阶段原有的到期资产恢复和事务边界保持不变。响应体发送失败不会撤销已提交结果，重试查询也不会重复投递资产；已准备的列表不会被并发取消或其他交易改写。
- 慢请求者的 socket 写不再延长共享拍卖锁占用，其他查询、维护和交易可在该写完成前继续处理。

## 验证

- 本批加入回归覆盖：五类查询在准备阶段仍受市场锁保护，慢 socket 不持有市场锁，成功与失败响应字节保持原生格式，发送失败后到期恢复恰好一次，以及并发取消不改变已冻结的查询结果。
- 上述适用回归已在隔离 Linux 执行通过；各包完整范围、跳过项和既有基线诊断见对应 PR 的验证记录。真实 MySQL 查询耗时、真实网络慢写和其他市场事务的并发组合仍待验收。
