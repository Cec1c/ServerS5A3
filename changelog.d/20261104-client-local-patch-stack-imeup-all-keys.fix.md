# 客户端本地补丁栈，修 WASD/技能键卡住（v2.0.8.2）

## 变更

- 现象：用 WASD 走位或字母键放技能时，偶尔松手后角色仍一直走，或技能反复释放。根因：游戏在 WM_KEYDOWN 时把 messageCache[VK] 置 1、WM_KEYUP 时清 0，每帧对缓存非 0 的键强制补成按下。上游 `.imeup` 辅助代码会在补位前用 GetAsyncKeyState 复核，松开了就清掉，但它只检查方向键 0x25..0x28。其他键一旦漏收 KEYUP（输入法、焦点切换），就会一直被当成按下。
- 新增 `scripts/client/local-patches/`，统一收录我方独立于上游的 EXE 补丁：`stack.json` 记录补丁顺序和各版本的输入、输出摘要。`apply_stack.py --check` 用来判断上游新版能否自动叠加，`apply_stack.py --output` 用来生成新版本。每个补丁按字节特征定位，不认整个文件的 SHA；特征对不上时报 `incompatible`，要求人工移植。
- 擂台赛接收门补丁迁入补丁栈（`patches/pvp_relay_gate.py`、`verify/verify_pvp_relay_gate.py`），移除原 `scripts/client/patch_pvp_relay_gate_v208.py` 和 `verify_pvp_relay_gate_v208.py`。
- 新增补丁 `imeup-all-keys`：把辅助代码的范围判断改为 0x08..0xFE，共 4 字节，其余逻辑不变。没有采用“缓存为 0 时也用 GetAsyncKeyState 清 DirectInput 字节”的改法，因为数字锁定打开时小键盘的 GetAsyncKeyState 为 0，会让小键盘失灵。
- v2.0.8.2 = 上游 V208（`5ce2ce3f…`）+ 擂台接收门 + 全键松键复核，输出 `de0d10b4e05f7005994dfc31c8d40fedd30205d705ed7d00cc2891080f64b5f3`，112549888 字节。EXE 不进仓库。

## 验证

- 补丁移除后还原出的上游 V207、V208 与登记摘要一致。从这两个原版重新生成，与已发布的 v2.0.8、v2.0.8.1 逐字节一致。从 V208 原版一次打两个补丁，与在 v2.0.8.1 上只补新补丁，得到同一个文件。
- 松键复核模拟比对 v2.0.8.1 → v2.0.8.2：映射表中 138 个 VK、608 种组合没有执行错误，寄存器全部还原。只有“非方向键且已松开”的 286 种组合由补位改为清缓存、清槽位并跳过补位；方向键、按住的键和 VK < 8 不变。文件差异只有声明的 4 字节和 PE 校验和。
- 接收门模拟比对：V207 → v2.0.8、V208 → v2.0.8.1 只有 (0,112)、(0,113) 放行；v2.0.8.1 → v2.0.8.2 的 196608 种组合判定完全一致。
- 静态检查，未运行游戏；待实机验收：WASD、技能键、小键盘（数字锁定开、关）、连发插件、中文输入法下的按键。
