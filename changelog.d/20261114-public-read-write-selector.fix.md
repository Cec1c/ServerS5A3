# 拍卖读投影、增量保存与选角路径优化

## 变更

- 普通拍卖请求不再先扫描并结算全市场；到期与遗留邮件由拍卖维护负责，买卖请求仍在权威资产事务内校验挂单期限。拍卖搜索改用只读的挂单前缀投影，空搜索不会创建托管角色或读取完整背包。
- 邮件角标只读取未读计数所需表头，不打开、修复或写回邮件聚合；邮件及多 owner 角色资产事务启用脏槽增量写，未加载完整前像时保留全量写回退，每个 owner 使用独立前像并保持同事务回滚范围。
- 公会只读可重复读事务复用同一注册表版本摘要；缓存只存在于该事务，不跨事务、错误路径、普通仓储或默认隔离视图。
- 角色选择列表查询完成一次后，将同一批角色记录复用于连招预载，不再为同次 GET_USERINFO 重查账号角色；角色返回选择界面的队伍、副本和攻坚投影改为提交到各接收者有界队列，同时保留资产保存、事务、队伍和角色代际校验。返回选择成功包的处理阶段增加耗时记录，用于区分配置清理与 socket 发送成本。

## 验证

- 本批加入回归覆盖：拍卖搜索不创建托管或读取完整背包，邮件未读头投影与只读回退，多 owner 脏槽保存及回滚，公会事务内版本复用，角色列表与连招共用一次查询，返回选择的队伍和攻坚投影不等待慢接收者，以及换代后不发送旧视图。
- 上述适用回归已在隔离 Linux 执行通过；各包完整范围、跳过项和既有基线诊断见对应 PR 的验证记录。真实 MySQL 的锁等待与增量行写、真实慢客户端下的选择界面耗时，以及整服固定收益仍待验收。
