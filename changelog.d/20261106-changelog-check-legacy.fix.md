# 变更记录校验不再被历史格式片段卡死

## 变更

- `scripts/ci/changelog_fragments.py check` 原先会解析目录下全部片段，任意一个历史片段不合规就整体失败。由于已合并片段按规范不可就地修改，只要主干上存在一个缺 `## 变更`/`## 验证` 的片段，所有贡献者的校验都会永久失败，CI 在跑测试之前就红。当前主干已有 5 个这样的片段（20261105 三个、20261106 两个），且还在增加。
- 改为只对本次新增的片段强制格式校验；已存在于基线（或 HEAD 各父提交）的片段解析失败时降级为 stderr 提示，不再中断。不可修改校验仍按 blob 逐字节比较，未放宽。
- 无 `--base` 时按 `HEAD^@` 汇总所有父提交判断“已合并”，避免合并提交里只出现在第二父提交的片段被误判为本次新增。
- 片段计数口径不变（合规片段 + 降级提示片段），既有输出字段与文案保持兼容。

## 验证

- `python scripts/ci/changelog_fragments.py check --base HEAD` 在当前主干通过，五个历史不合规片段各输出一条 warning。
- 无 `--base` 的全量路径同样通过。
- `python -m unittest discover -s scripts/ci -p test_changelog_fragments.py` 18 项全部通过。
- 新增不合规片段时仍会失败（用临时文件验证后删除）；未放宽对贡献者自身提交的要求。未部署、未发布。
