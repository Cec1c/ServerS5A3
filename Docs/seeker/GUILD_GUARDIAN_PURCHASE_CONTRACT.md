## 显式运营策略

同时需要 `DNFBRIDGE_GUILD_ESSENCE_ENABLED=true` 和有效的 `DNFBRIDGE_GUILD_GUARDIAN_POLICY`。后者为完整 JSON 对象，字段如下：

Docker实例源配置分别使用布尔 `guild_essence_enabled` 和对象 `guild_guardian_policy`，生成器校验完整字段后映射至上述环境变量。省略策略时保留关闭状态，显式 `first_select=false` 原样保留。

| 字段 | 必填值与语义 |
| --- | --- |
| `first_purchase` | `free_once`：公会首次免费一只；`paid`：首次也按 PVF 收费 |
| `initial_level` | 1～50，作为每只新购守护神的初始等级 |
| `initial_skills` | 恰好五个0～5的技能等级，按原生星级规则解锁 |
| `first_select` | 显式 `true` 或 `false`，决定公会首次购入是否自动出战 |

以下是自动测试使用的策略示例，运营配置应填写已选定的值：

```json
{"first_purchase":"free_once","initial_level":1,"initial_skills":[1,1,1,1,1],"first_select":true}
```

未配置、字段缺失、非法范围、未知字段和多份 JSON 均拒绝。`false` 不等同于缺失。第二只按匹配 PVF 收费，当前两只均为 AP50000、GP1000，并保留当前出战选择。等级和技能不从截图、空 row 或经验表推定。

持久 `ever_acquired` 独立于 `active_id`。清空出战 ID 或未来移除拥有记录不能重获首次免费资格。不会根据客户端提交值决定金额；请求尾部两字段必须为0。

## 权限、场景与距离

本版同时要求 `MasterCharacterID` 与当前角色相同、持久成员 `Grade=1`。技能升级入口的 bit16 只证明升级权限，未用作首次购入权限；其他成员暂未开放购入/选择。

服务端检查当前账号、角色、规范会话及角色代，持久会籍和请求开始时冻结的公会 ID。角色资产预留持续到事务与响应结束，仓储锁序保持 registry→角色。会籍在事务获取锁之后再次核对，换会不会把旧请求应用到新公会。

交互范围限定为 town8、PVF 指定的守护神可见 area，并核对实际城镇表属于公会基地。持久角色的 town/area 必须与已就绪、具有正确 CharacterID 的位置快照一致，副本中拒绝。初次 NPC 从 `[first guardian]/[guardian npc]` 解析，并核对 `[attend guardian]` 参数；已有出战时从该守护神的 `[npc index]` 按星级取得实际管理 NPC，核对 `[agitwar guardian window]`。

V166 `03AA6DF4` 的 `[clickable distance add]` 读入配置 `+125C/+1260`，`029286F5` 复制到运行 NPC `+59C/+5A0`。`02879DCC..02879EA1` 对横纵坐标分别比较 `abs(delta) <= 40 + add`，边界包含等号。本版复用这一矩形范围：无出战时围绕请求 ID 的初次 NPC，有出战时围绕当前出战 NPC。管理窗口请求也要求在此交互范围内；跨地图或远距离管理不开放。

匹配资产的首次 NPC1/2 在 `(430,363)/(670,363)`，管理 NPC 在 `(556,348)`。具体位置和附加距离均在运行时读取 PVF，不将地图静态 NPC 列表缺少这两只动态 NPC 判成缺失。

## 原子性与回执

`guild.ApplyGuardian` 使用同一个 `GuildUnitOfWork` 保存公会精气、拥有列表、出战 ID 和 `guardian_receipts`。永久回执键为 `guardian:<connection identity>`；身份由现有连接 nonce 与扩展序号生成。相同身份换 action、ID、公会或账号拒绝。拥有结构与回执在保存、加载时验证。

- action8 新请求遇到已有 ID 明确失败，不切换、不二次扣费。
- 同一次成功请求重放返回永久回执。会籍、账号、权限、当前会话和基地场景仍重验；不再要求仍靠近已被首次购入替换掉的 NPC，不重新扣费或授予。
- action7 同 ID 重选不扣费。重放早先的 action7 回执不会撤销后来另一选择。
- 重连使用新连接 nonce。新 action8 请求遇到已有 ID 失败；重连1297投影当前持久状态。领域永久回执可在重建仓储后恢复。
- 并发相同 ID 只有一个新购成功；并发两个 ID 只有一个能取得首次免费，其余按 PVF 收费。
- 金额不足、会话失效、保存错误、提交失败均回滚，成功响应只在事务返回后发送。错误22表示不足，100表示未入会，其他已验证的无效操作返回3。

成功按1350 ACK→当前1297发送；同会成员沿现有事件队列刷新并重校身份和会籍。重复请求不恢复历史余额，读取的是当前状态。

登录精气属于可选支线。收入或其1297投影失败时记录日志，继续公会账号投影并完成场景就绪；失败收入保留当前角色/会话代的待重试标记。后续打开公会窗口的339请求在原事件队列和资产预留内幂等重试，成功后清标记；持续失败保留到后续刷新，换角/重连后的旧代标记丢弃。已提交但投影失败只修复当前快照，不再次增加收入。普通339也恢复当前1297，必要的NOTI70等写入错误仍上传。

## 验证与实测

自动测试覆盖两策略、两 ID、首次自动/不自动出战、缺配置、余额不足、已有/未拥有、序号重用、换会、换会话、账号、会长权限、场景、距离边界、保存失败与后段失效。一次性 MariaDB 验证真实 SQL 回滚、并发与重建仓储后的永久回执；Docker 保持运行。

生产 Go 请求经过1350路由和事务授予后导出1297。匹配 V166 的原接收器、row/getter、出战/星级 getter 对这些报文进行有限原生验证，不通过预置已有 row 替代购入。原生适配仍包括 CRT、guild lookup、UI/NPC副作用；完整游戏画面需实测。

1. 使用已发布兼容 EXE/PVF，在隔离环境配置选定策略并启用精气开关。会长进入守护神基地，靠近第一只 NPC 购入，核对费用、等级、五技能、星级解锁与首次出战。
2. 在管理 NPC 旁购入第二只，确认扣除 AP50000/GP1000、第一只仍出战；不足时余额和拥有均不变。若选择首次收费，两次均核对费用。
3. 在同一管理窗口选择另一只，确认不扣费、出战切换；重复点击、重复确认与重登保持状态，同会成员刷新一致。
4. 用普通成员、外会角色及远离 NPC 的会长尝试操作，确认无扣费、无授予；换角/换会后旧请求不得写入。
5. 配置 `first_select=false` 的隔离测试中，首次仅拥有，随后显式选择才出战。

GP收入、升级、战争准入/结算和赛季清理不在本事务单元中。付费用例在隔离数据库准备明确余额；本项不发放真实玩家精气。
