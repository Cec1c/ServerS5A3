# 成员任命接受权威区服 0

## 成因与目标

`guild.CharacterServerGroup` 已接受 0～249，成员列表也携带真实区服。`handleCurrentGuildMemberGrade` 仍在解析时拒绝 0，导致合法的零区服成员不能通过 126 任命。修改解析范围后继续由事务内角色记录和成员记录同时校验区服，不能把 0 当通配符。

V166 客户端发送器也将区服 0 拦在网络发送前。精确补丁将该边界从 1～249 改为 0～249，继续执行成员缓存和特殊状态检查；仅改变两字节指令及 PE checksum，不改接收门控或其他段。构建工具固定 V166 完整摘要，生成独立候选。

## 实现范围

- `go-server/internal/services/dnfbridge/guild_member_grade.go`
- `go-server/internal/services/dnfbridge/guild_member_grade_test.go`
- 可增加同目录 `guild_member_grade_zero_region_test.go`
- `scripts/client/patch_guild_grade_region.py` 及同名测试。

保留原有账号、角色、名字、会话代次、同会与权限检查，以及品级 2～4 的约束。成功 ACK 保持原生字段顺序与真实区服值。

## 测试与验收

先增加区服 0 的正向回归，证明原代码失败；覆盖 2／3／4 品级、重读持久状态、本人状态刷新和资产保持。继续覆盖 1／249 正常区服；请求 0 而权威角色或成员实际为其他区服时拒绝，250／255、跨会和撤权仍拒绝。已存在的 `region_zero` 夹具目标是区服 1，应保留作为错区服拒绝检查并清楚命名。

服务端成员任命专项和 V166 原生发送器对照已通过：旧版区服 0 无请求，候选区服 0/1/249 对品级 2/3/4 均发送正确 126；非法区服、缺缓存和特殊状态仍阻止发送。原生夹具替换缓存、网络和弹窗，执行完整发送器并检查栈与保留寄存器。

交付前执行仓库要求的服务端回归。依赖顺序为：上游 MR 合并 → 最终兼容客户端正式发行及镜像 → 玩家更新源实文件验哈 → 服务端累计部署。游戏内验收为会长任命零区服成员、双方立即刷新并重登保持。
