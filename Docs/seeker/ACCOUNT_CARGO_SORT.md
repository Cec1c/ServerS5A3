# 账号金库转移刷新与背包整理方式

分类：功能修复。

## 原因与修复

账号金库 op19 原来在每件转移后重新读取账号金库并发送完整 op13；发生堆叠、拆分或自动归并时还替换整张主背包。批量转移连续执行这条路径，金库数量已更新后，背包仍反复销毁、重建全部物品对象。

新实现保留每个原生转移请求及其账号／角色物品事务；仅在事务成功提交后，返回实际源、目标栏位的独立快照。服务端先发送 op19 ACK，再按容器发送 op14 变更行：源格清空使用 `item_id=0xffffffff`，拆分保留剩余数量，自动堆叠指向真实归并格。刷新不再重新读取仓储，也不重发钱包、共享晶体或无关物品。提交失败不产生快照或成功响应。客户端仍使用其原生逐件请求协议。

背包 op20 已解析 `condition`，但旧排序器未使用它，因此各选项都落到相同的“物品种类、模板 ID、原栏位”比较规则。现在按客户端页签选择算法：

| 页签 | 支持的排序方式 |
| --- | --- |
| 装备 | 0 栏位；1 品级；2 等级；3 部位 |
| 消耗品 | 0 栏位；3 类型；4 到期时间 |
| 材料／副职业材料 | 0 栏位；3 类型 |
| 装扮 | 默认品级；3 部位 |

按栏位沿用种类、模板 ID、原栏位的确定性顺序，压紧空格；按时间将最早到期的道具排前，永久道具排后。同一排序键使用默认顺序打破平局。类别、最低等级、稀有度和部位读取运行 PVF，临时键不写回物品。查询失败在改栏位前退出。锁定格、其他分页、快捷栏、共享晶体、物品数量及实例属性保持。

## 客户端依据

V210 DNF.exe SHA256：`24372bf2df57cdaecc696752299dbe8c61e222806a697e3d1c6f57fbcaffbdae`，ImageBase `0x400000`。

- RVA `0x2091f30` 标签函数确认 0/1/2/3/4 分别对应栏位、品级、等级、部位或类型、时间；文案 ID 22519–22524。
- op14 接收入口 RVA `0x1c25a90` 读取容器、行数及 119 字节行。RVA `0x2131a80` 将 list12 解析为账号金库容器；通用分支读取、更新、创建或清空对应栏位，并未排除账号金库。
- 已有同客户端 op14 刷新使用同一行构造器。本次不更改 EXE、包格式或个人金库流程。
- 已有匹配协议参考实现 `InventorySortService` 将 condition4 定义为 `ExpireTime`，采用最早到期优先；该结论区别于“获得时间”。

## 验证与验收

回归覆盖原版条件忽略、真实请求接线、运行 PVF 优先于旧元数据、重复排序、锁定格、实例属性、失败不写入，以及连续转移的 ACK／增量顺序、数量守恒、真实归并落点、账号隔离与装备品级。资源专项使用明确指定的真实 PVF；未提供资产时保留 skip。

实机重点：同种材料批量转入后，金库数量与背包消失及时一致；部分转入、取出和满仓仍正确；切换整理选项出现符合类型或到期时间的排列。自动化与静态证据不代替这一体验验收。
