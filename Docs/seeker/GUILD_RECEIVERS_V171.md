# V171 公会精气、守护神与排名接收恢复

## 成因与目标

已集成的公会服务端实现需要 class0/1284（精气收入提示）、class0/1297（完整公会战及守护神状态）、class1/1350（守护神操作应答）、class1/1503（个人公会排名模型）。V171 当前接收链仍止于已验证的传送门控，四项均返回拒收，导致服务端配置启用后客户端也无法呈现结果。

输入固定为 V171，SHA256 `c962e82d2258e15edb0ac372f1a4e3b58a1360ee53192201720f723302be5409`。其余 V171 累计修改全部保留。服务端仍需显式配置排名、精气开关及守护神初始策略；本项不修改运营配置或玩家数据。

## 方案与范围

`scripts/client/patch_guild_receivers_v171.py` 在已有 `.r195rx` 空闲范围增加四项精确匹配，未命中的分类与 opcode 委托原接收链。修改仅限 CALL、辅助代码、节虚拟长度和 PE checksum；保留原发送器、接收器、游戏逻辑及所有其他字节。

地址为固定输入 VA：CALL `02523A13`，原入口 `06EAD300`，新增入口 `06EAD400`。构建前核对完整摘要、节属性、旧 CALL 及空闲范围，输出到独立新文件。

## 测试与验收

- 修复前四项均拒收；修复后 class0/1 的全部65536 opcode仅上述四项变化，其他分类仍沿原链，栈和保留寄存器一致。
- 差异限定四个范围、输出确定、输入原件保持，错误输入和覆盖拒绝，Windows只读映像映射成功。
- 复核匹配版本既有2197字节守护神状态、1350操作应答、1284精气提示及108字节排名接收模型。
- 发行后先核对玩家通道实际EXE摘要，再启用服务端配置；会长首次购入/选择、同会刷新、重登和排名页总分/进度按实际状态实测。大厅排名板单独使用其真实榜单协议。

生成命令：`python scripts/client/patch_guild_receivers_v171.py --input <V171.exe> --output <new-candidate.exe>`。
验证设置 `DNF_GUILD_V171_CLIENT=<V171.exe>` 后运行 `python -m unittest discover -s scripts/client -p test_patch_guild_receivers_v171.py -v`。需要 Unicorn；未提供输入导致的跳过不计为验证通过。

## 本轮验证结果

3项回归全部通过、0跳过。class0/1完整域仅四项拒收变接收，class2/255完整域保持；Windows只读映像通过。最终独立候选 SHA256 `e1e78b6792e4d22ddae10e502d5b40555fb7a5f657f185578992eaefbe1348d4`，111915008字节。

既有正式1350购入/选择事务报文交本候选原生1297接收器及getter，360断言通过；正式1503 handler的108字节模型完整复制，名次及浮点点数getter通过。此验证保留CRT、UI副作用和对象查找的有限夹具；实际界面交互继续作为发行后的验收目标。
