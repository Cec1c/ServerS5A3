# 多次使用道具次数描述：MR209 后续

原 MR209 已完成疲劳药持久次数到 NOTI541 的投影。后续全类核查发现普通消耗品和礼盒没有相应的通用记账；单独发送疲劳药并带空周次数列表，还会清空客户端已收到的周次数。

本变更在已有使用事务中记录实际使用次数：普通消耗品的角色资产事务，以及随机／选择礼盒的账号角色资产事务。库存扣减、原有效果或奖励、角色计数共同成功或共同回滚。达到显式日／周上限时拒绝使用，失败不扣物、不发奖励、不递增次数。移动、购买、删除和奖励材料扣除均不当作一次使用。疲劳药继续使用原持久键、既有共享政策和专用恢复事务，避免重复记账。

日计数沿用服务端北京时间 06:00 服务日。周计数采用同一服务日及 PVF 的 `total weekly usable count reset day`（0～6，星期日至星期六）。`usable count group` 是使用计数组；`cooltime group` 不能替代它。新通用计数从上线后实际成功使用开始记录，不从剩余库存反推历史使用。

ACK 和源格刷新后发送日／周计数合并投影；选角重连和现有 06:00 定时刷新也使用这一投影。即使道具已用完、背包没有原物品，持久索引仍能重建次数。NOTI541 的非空列表覆盖对应条目，空列表清空整张表；超过 255 条分页时，较短的非空表重复末页，避免被后续空页清掉。

全量只读扫描依据 PVF SHA256 `94a2549598816198115340f84c0be2d31603ddeea58f70f27afe6f73b25e3df7`。56,703 个消耗品定义均可读取，其中 685 个带相关字段：

| 类别 | 定义数量 | 可由道具表引用 | 本次处理 |
|---|---:|---:|---|
| 疲劳药 | 324 | 318 | 保留原事务，扩展真实 PVF 与 1 点疲劳药回归 |
| 普通无 action 的消耗品 | 102 | 100 | 成功使用事务记账与次数投影 |
| 随机／选择礼盒 | 75 | 73 | 成功开盒事务记账，包含 3 个周限礼盒 |
| 特殊 action、任务或非直接使用类型 | 176 | 171 | 核对字段与投影能力，保持各自原有入口支持状态 |
| 活动弹窗 `usage limit count` | 2 | 2 | 不是此日／周通知的数据源；不伪造成功使用历史 |
| `using limit info` | 2 | 2 | 单独的使用条件，未改写成日限次数 |
| `use count limit all server item` | 4 | 4 | 字段值是关联道具 ID，不当作每角色使用次数 |

共有 677 个日／周限次定义，662 个已被道具表引用，另 15 个未引用。提交中的测试数据只保存这 662 项的 ID、路径和限制元数据。真实 PVF 测试逐项核对并验证历史投影、无原道具时的恢复和日／周刷新；这不代表所有特殊活动、塔层券或任务入口已经实现。没有为了显示次数放开原来拒绝的玩法。

客户端依据是已发行 v169，SHA256 `3e779126f50d02c689b27fbe3e1445ff19c8893a9c9bea9dcd8d4d5a6c432c15`。它已放行 class0/541。原生日／周 reader、setter 和剩余数减法可继续使用，本次不需要改 EXE。`verify_item_usage_projection.py` 消费 Go 测试导出的实际报文，执行该 EXE 的原生 reader/setter；物品工厂、报文 IO、映射容器和释放依赖是明确的离线夹具。三组各 665 条原生记录、共 9 包通过，不替代游戏内验收。

必要验证包括使用到上限、并发用物、失败回滚、随机及选择礼盒实际协议入口、重连恢复、跨日／周、日周分页混合、原疲劳药回归，以及隔离数据库事务。运行完整服务端回归、边界检查和独立构建后才进入更新；更新仍须当次实际 pull 并保留线上累计修复。

游戏验收需分别使用 1 点／50 点疲劳药、带日限的普通药水和带日周限的礼盒：每次成功后重新悬停显示实际剩余次数，用尽显示零，失败不递减；重登后保持同一计数。礼盒与疲劳药交替使用，周次数不能恢复成满额。部署与用户验收状态另行记录。
