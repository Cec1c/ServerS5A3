# V201 消息 28 缺失装备对象访问修复

分类：功能修复。状态：独立客户端候选，离线原生回归通过；正式发布及组队游戏验收待完成。

## 问题与依据

V201 的消息分派函数读取七字节包头，以 uint16 消息号查表。28 号分支读取两个 uint16 身份字段及一个 uint8 槽位，查找目标对象，再调用虚表 `+0xB54` 的装备槽位查询。外层对象有空值检查，返回的槽位对象没有；其后 `mov eax,[edi]` 可读取 NULL。

对应主查询 `0x02771FB0 → 0x0276EDB0` 对空槽、占位对象和无效槽位明确返回 NULL；代理查询也会因底层对象缺失返回 NULL。用原始机器码构造这些状态，可在 RVA `0x02EA5F58` 重现访问冲突。报告的现场栈落在同一地址，但没有故障指针或寄存器；是否属于本次玩家的 NULL 路径仍需新日志或组队复测核实。非零悬空指针不在此补丁覆盖范围。

## 精确基线与修改

- 输入：正式 V201，SHA256 `b965e2d1d04b4679eba1ba00de6bbceacdc1ccab8789ea22bef98a28f61283d5`，112123904 字节。
- 新节 `.p28null`：31 字节代码，磁盘占用 4096 字节。
- 修改 VA `0x032A5F56` 的 10 字节为跳转：保留 EDI 赋值；返回 NULL 时到原有共同清理路径；有效对象执行原指令后继续。getter 调用、调用返回地址、有效对象寄存器/标志/栈、身份检查及全部后续业务处理保持。
- 输出：SHA256 `b4608ecc165a7c32b11349ade0cc8ed6ab87da6e2f1d49b154f5fbc428998a5d`，112128000 字节。
- 工具仅接受完整输入摘要和长度，验证指令及分派表；拒绝未知版本、截断输入、重复修改及覆盖源文件。变动范围为该代码片段、新节及必要 PE 头字段；其余累计内容按字节保留。

## 工具与验收

相关文件：`scripts/client/patch_peer28_null_v201.py`、`scripts/client/test_peer28_null_v201.py`。补丁构造复用现有 PE 与 rel32 工具；回归需要 Unicorn 2.1.4。

```text
python scripts/client/patch_peer28_null_v201.py --input <V201.exe> --output <new-candidate.exe>
python scripts/client/test_peer28_null_v201.py --input <V201.exe> --candidate <new-candidate.exe> --report <private-report.json>
```

30 组 x86 原生回归覆盖：空槽、占位对象、边界/无效槽位、三种底层对象缺失的代理、本人/队友的有效槽位、通知条件和外层对象缺失。12 组修前都在同址 NULL 读取失败，修后都进入原清理出口；16 组有效对象逐项比较效果、寄存器、EFLAGS 和栈完全一致；2 组外层对象缺失行为保持。另验证 3 种错误输入均拒绝。

回归执行真实消息 switch、读取顺序、槽位判定、装备 getter、代理 getter 和消息 28 分支。场景查找、类型注册、读包器、装备值编码及最终 UI 为夹具适配；没有运行游戏、真实联网或模拟整个深渊。因此游戏验收需继续覆盖：组队连续刷图/深渊、本人及队友装备/换装和空槽、房间切换及成员离开、原先崩溃场景与日志。不能以本次通过推断所有组队闪退均已解决。
