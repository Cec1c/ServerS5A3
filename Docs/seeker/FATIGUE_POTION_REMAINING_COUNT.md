# 疲劳药每日剩余次数

目标：物品416连续使用后显示2/3、1/3、0/3，重登保留，06点重置；保留原扣药、疲劳恢复、冷却和每日限次事务。

## 原因与客户端约定

匹配V153客户端SHA256 `c7ba1bfe81d7283c97e33c6a3449f729b63e79a916357aa7ea69fb7754709bc8`。物品说明的每日上限来自PVF `[total usable count]`，剩余值是上限减去客户端每日已用次数表。现有服务端持久保存已用次数，却只发送515成功应答、14背包刷新和疲劳值。

客户端class0/541注册到RVA `0x01c2e240`。包体为：`daily_count:u8, daily_count * (item_id:u32, used:u8), weekly_count:u8, weekly_count * (item_id:u32, used:u8)`。计数非零逐项覆盖；计数为零清空对应表。每日setter RVA `0x021e4f20` 以物品或其 `[usable count group]` 为键；说明框RVA `0x02fd25d2` 调用剩余值getter `0x021dc680`。服务端已有冷却组和每日事务分组规则保持。

V153接收链过滤541。本修复需要独立的class0/541放行候选，其他类、操作号和已有补丁保持。发布依仓库EXE顺序执行，源码合并不代表玩家已更新。

## 实现范围

- 领域 `fatigue/potion.go` 在原成功事务内保存曾使用的物品ID索引，供共享冷却组、最后一瓶消耗后的重新选角投影；原计数键继续作为权威来源。兼容旧记录中的数字物品计数后缀，不将非数字分组伪装成物品ID。
- 新增 `fatigue_potion_usage.go`：从已用物品索引、旧数字计数键及必要的当前背包候选解析真实PVF疲劳药定义；按当前服务日、原分组计数生成确定顺序的每日used表。仅投影实际疲劳药及有效每日限制，记录缺失时为零。每包最多255项，超过时连续分包，used饱和至255。当前服务端未实现每周道具次数；本通知每周表为空。
- 成功使用后沿现有ACK、背包、疲劳顺序，追加次数通知；发送失败不撤销已提交的药品事务，重登恢复。
- 选角ACK后的快照和原06点刷新定时器接入次数刷新。没有疲劳药使用历史的角色可依已核对的客户端选角清表逻辑省略额外通知。
- 次数目录暂时不可读时记录延后投影，继续原选角流程；实际网络发送错误沿现有路径返回。
- 新增聚焦桥接测试，按需要更新已有疲劳药测试的额外包断言。客户端补丁和静态/有界原生验证由Seeker负责。
