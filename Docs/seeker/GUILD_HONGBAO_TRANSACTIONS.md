# 公会红包交易恢复

## 成因与目标

此前服务端只提供红包与贡献查询，缺购买限制、道具分份、领取、历史和到期结算。本单补齐 `guild.HongbaoOwner` 领域事务。匹配客户端的购买走商城 op64；发放1303携带道具ID和份数，领取1304与历史1302携带红包记录ID。红包交易同账号钱包、公会会籍、道具和持久回执一起提交。

## 规则

- 匹配表提供四档商品、金额和贡献参数：5000/10000/20000/50000点券，对应40/90/190/500贡献。贡献为实际已领取金额×表末列÷10000，向下取整，每角色业务日最多500；日界采用UTC+8 06:00。
- 至少30名公会成员可购买，每角色业务日购买总额最多50000；购买物品期限10天。领取者获得账号欢乐代币券，未领取金额退款为代币券。
- 一份道具发放5～30份红包，登记后24小时到期；每账号每日最多领5个，同账号不同角色共用额度，每红包每账号只能领取一次。
- 分额采用本服整数随机规则：每次在1至剩余额的两倍均值之间抽取，同时为剩余份额各保留至少1；最后一份取余。一次生成并持久化，重试不重新抽样。
- 领完或到期后按实际领取金额计算贡献，贡献币通过邮件发给发送者；到期剩余额用无期限代币券邮件退款。发送后退出公会，剩余额按原规则不退；会籍变更以入会时间识别，重入不恢复退款资格。
- 红包列表最多500行，已领完历史保留24小时；持久回执与未完成结算独立保留。

## 实现思路

领域代码负责规则、账户日限、分额和回执。复用 `GuildSettlementUnitOfWork`，在全局 `Registry.Hongbao` 保存红包及待结算状态，公会解散后账本仍存在；领取更新当前领取者的账号欢乐代币券。领完/到期通过发送者独立事务完成贡献、邮件和终结标记，失败保持待结算并可重试；查询保持只读。桥接后台调用 `Pending` / `Settle` 恢复离线和重启后的到期结算。

购买复用已有商城和账号钱包能力，在同一事务核对会籍、购买日限和物品投影。发放以连接nonce与已展开的原生请求序列标识一次操作，回执绑定正文和实际消费道具；相同正文的新序列允许连续使用第二份道具。跨连接重新确认是新操作，界面和背包从持久状态刷新。

### 领域与桥接契约

| 接口 | 权威变更与接线要求 |
| --- | --- |
| `Purchase` | 目录从 `etc/chn_hongbao/chn_hongbao.etc` 解析四档；只扣账号点券，核对会籍与日限后由 `GrantItem` 投影一件 stack1 物品。回调最后参数是 `expireAt`，须保留精确到期时间；不得修改其他库存槽。 |
| `Issue` | 从当前角色主背包选数值最小的合法槽，排除仓库、账号共享槽、锁定、过期、无期限或期限冲突实例。1303无槽号/实例号，直接使用现有库存；无需515准备请求。一次消费一件并保存全部份额，回包使用结果 `RecordID`。 |
| `Claim` | 核对当前公会、账号领取历史和业务日日限；金额来自已保存的下一份，和账号钱包、领取记录、请求回执一起提交。 |
| `Settle` | 使用保存的原发送者开事务。结果持久化 `Sender`、贡献点/币、退款额和邮件ID，重放返回同一身份与邮件；`DeliverMail` 最后参数为结算 `now`。后台据 `Sender` 刷新在线发送者邮件及贡献视图。 |
| `View` / `History` | 只返回当前公会可见记录的副本，不触发结算。可用份数取 `RemainingPortions`；业务状态和历史保留真实领取事实。 |

物品和邮件回调使用传入事务仓储，不打开嵌套事务或发送网络包。桥接提供真实物品投影、贡献币及代币券附件编码；领域验证新邮件确实存在、收件人正确、未领取且有附件。附件金额与编码由匹配PVF的投影验收覆盖。

购买、发放和领取分别保存正文指纹与操作结果，同ID异正文拒绝。重放先命中回执再检查新交易的目录、成本、额度和随机数；回包后应重读当前钱包/库存，旧回执里的钱包是交易当时快照。当前会话/角色代在事务内重复校验，失效则回滚。提交状态未知时复用原操作ID；发送者结算使用红包记录作为永久回执。

角色业务日购买额、红包贡献额与日常活动贡献分别计数；领取次数存在账号元数据中。会籍快照使用公会ID和 `JoinedAt`，退出/重入/换会后不退款、不向新会写贡献点，实际领取产生的贡献币仍寄给原发送者。结算按执行时的业务日计贡献上限；贡献已达上限时，仍按有效原会籍寄送应退余额。

可见历史在领完或到期后24小时结束。交易账本和操作回执持续保留，本单没有归档删除任务。发送者角色须仍有权威归属记录；物理删除或错属返回错误并保持待结算。只读视图是仓储读取结果，写后展示以重新读取的权威余额和库存为准。

客户端只补缺失的class1/1302与class1/1304接收门控，保留既有累计链。发布时重新核对最新正式EXE并生成匹配候选，正式发行、镜像和玩家通道先于依赖该门控的服务端启用。

## 验证与验收

领域测试覆盖四档购买和提取ETC核对，29/30成员、购买上限及06点日切；4/5/30/31份、道具过期、同品连续发放与重复请求；账号跨角色日限、并发抢最后一份、重启重放与金额守恒；领完/到期竞争、退会重入、生产解散路径、离线与贡献封顶退款；随机源失败、异常投影、晚存储失败回滚、提交状态未知后重试和损坏账本拒绝。内存仓储事务验证实际晚写入失败与邮件回滚，race覆盖并发领取和结算。

本单验收领域与内存仓储。桥接报文、真实附件投影、隔离SQL、客户端接收、最终整库检查和发布由集成单继续；领域测试中的退款附件是显式测试适配器。上线后检查购买、分份、领取动画和余额、历史、贡献邮件及退款。
