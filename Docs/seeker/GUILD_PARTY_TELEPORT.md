# 公会组队传送完整链路

当前购买入口拒绝真实目录的 type 7 次数，434/435 的组队确认和消费入口也未接入。修复将三档共享次数购买、原生确认窗口、全员目的地检查、一次扣次和实际位置提交连成完整链路。

原生请求 434 为 town:u8、area:u8、x:u16、y:u16、direction:u8、flag:u8；435 的同意为 1、拒绝/关闭为 0、超时为 3。通知 377 固定 30 字节，请求者字段是队伍槽位；phase0 询问、phase1 成功、phase2 取消、phase3 超时。失败 434 除失败码外还读取 u8/u32/u8。原生无已确认的 435 回调，响应通过 377 表达。

只消费发起者所在公会的共享次数；参与者为发起时绑定的同频道队伍，确认期间成员、队长、槽位或会话代次变化即取消。拒绝、超时或任一人不能到达时不扣次、不移动。购买的展示道具不发到背包。

提交使用最多四人的独立 GuildTravel 事务，保留普通 Guild UoW 的两人边界。事务内核对归属、出发位置、当前公会和剩余次数，原子保存所有实际位置、一次扣次与持久回执。全员提交后复用城镇场景通知；通知失败不回滚已经完成的多人事务，重登从已提交目的地恢复。

测试目标：三档购买和重放；两人/四人全同意、拒绝、超时、重复确认、离队、重连、换队长、缺次数、目的地等级/任务门槛、保存失败回滚。用匹配客户端有限执行验证发送器、377 窗口状态、434 失败消费及门控；确认普通城镇移动及单人传送不变。

验收目标：管理面板显示购买后的次数；组队发起后队员收到正确请求者和目的地，确认后全员抵达且只减一次；重登保持次数与位置；拒绝和超时保持原位置及次数。客户端候选正式发行并进入玩家通道后再部署依赖服务端。
