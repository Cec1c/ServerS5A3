# 公会专属地下城与守护神协议恢复方案

## 目标与基线

针对专属地下城全部锁定，续接登录快照、整队入场、通关净化与奖励事务。守护神/公会战保留后面的独立调查。普通地下城公会积分、守护珠与勋章合成保持现有行为。

## 本轮实施契约

源码基线更新至 `9218631a`；V166 SHA256 `0e16090f0e4e3ac830f70183c814f5b24724cec235935e6c1221bf2d865d4243` 的原十二个关键窗口与 V164 一致。

- 登录和重新打开选图发送持久状态的 NOTI741。未知头字段保持 0，不开放特殊商人；首图由真实目录无前置规则开放。无公会角色发送空快照清除上一角色缓存。登录投影不加载全档 PVF。
- 入场在任何成员提交前冻结公会、成员账号/角色/加入时间、周期、规则摘要和本次运行随机身份。全部成员必须同会并满足前置，沿现有 DGN 等级/难度/疲劳校验。每个成功结算成员贡献一个计数单位，组队 N 人全部成功则 N 单位；同一成员重放为零。
- 月度周期为显式服务策略：默认 UTC 每月 1 日 00:00 重置。公会 registry 的可选 `dungeon_policy` 提供 `reset_day`（1…28）、`utc_offset_minutes`（-720…840）、`clear_units_per_member`（1…4，默认1）；这是运营配置，不宣称来自客户端。变更策略形成新周期身份，拒绝旧入场写入。读旧周期展示空进度，首次有效新周期结算才持久替换。
- 基础奖励按真实目录的净化比例档（首个阈值≥当前比例）选择，物品和贡献度在既有 GuildSettlement UoW 内与净化、EXP/SP/TP、永久结算回执一起提交。重登读取相同进度，失败全部回滚。
- `[repeat clear bonus reward]` 的实际触发条件仍缺生产证据，本轮不自动发重复额外包；周奖励表只有 final dungeon 而无奖励条目，不创建周奖励。常规奖励表中的物品与 contribute 正常结算。未使用未知 NOTI742 字段替代净化。
- 验证覆盖六图、单人/同会组队、异会、重复/并发、满包与晚期失败、重登及跨周期；真实 Go 741 交匹配 V166 接收器消费。候选只提交本地，由审查者决定 MR 与发布。

初次研究基底为 `dae368b`，V164 SHA256 `2d56c7086c3fd9bc029d932571504b7f89147e47f1d563684f74b9e467f4f8a2`；本轮已按上面的 V166 摘要复核。PVF SHA256 `94a2549598816198115340f84c0be2d31603ddeea58f70f27afe6f73b25e3df7`。以下地址均为 VA，只用于已核对的完整客户端摘要。

## 取证与实施顺序

1. 读取 PVF 的公会地下城目录、入口、开放前置、净化与周期规则；查客户端选图锁定和剩余时间的生产状态来源。先确定首图开放条件，再实现真实状态投影。
2. 沿通用入图和结算链，明确公会成员、地图、难度、周期以及运行实例归属。净化只由已确认成功的通关提交，重复结算不能重复累计，重新登录读取同一持久进度。
3. 追守护神 NPC 的召唤菜单发送端、服务端入口和客户端应答消费，确定消耗、权限、幂等与重登契约；再划定公会战所需的独立状态。
4. 领域规则放入 `internal/modules/dnf/guild`，持久修改沿既有 `Guild` 事务；bridge 只承担请求校验、协议投影和场景接线。资源规则使用现有 PVF 读取设施，资产修改另行处理。

## 验证与交付

每个确定的实施单元先建立失败回归，再验证修复后的领域与报文行为。覆盖首图、后续门槛、跨公会隔离、重放、重登与周期边界；召唤另覆盖消耗不足、权限和重复请求。测试使用隔离公会与数据库。

允许失败。未闭合的协议需保留具体函数、输入、已尝试方法及缺失证据，不用固定开放位或虚构进度代替状态。冻结后记录专项结果与尚需执行的完整检查，经独立分支和中文上游 MR 交付；本研究不部署。

## 专属地下城：已闭合的契约

V164 在 VA `043EC4D0` 注册 **class 0 NOTI741 → `013A4990`**。它与 class 1 CMD741 的公会创建许可互不替代。接收器先加载目录 0，再读取快照。缺失快照时目录指针为空，`013A0610` 对六图全部返回关闭；目录加载后，无前置的 8500 在通关次数为零时开放。

741 body 的字节布局如下，长度为 `17 + 8 * N`：

| 偏移 | 类型 | 已证明的用途 |
| --- | --- | --- |
| 0 | u8 | 转 bool，存 manager+0x30；不是首图开放位 |
| 1 | u32 | 存 +0x34；与上一个 bool 一起参与特殊 NPC 可用性/菜单，完整语义未定 |
| 5 | u32 | 存 +0x38；绝对结束时间戳，UI 减当前 Unix 时间后显示剩余时间 |
| 9 | u32 | 存 +0x3c；完整业务含义未定 |
| 13 | u32 | N，后续记录数 |
| 17+8i | u32 | 地下城 ID |
| 21+8i | u32 | 通关计数单位，非原始净化 gauge |

接收器用新 map 替换旧进度。NOTI742 → `013A4C10` 另读一个 u32 到 +0x40，当前不把它映射为净化总值或周期字段。

匹配 `etc/guild/guilddungeon/0_2way6dungeon.etc`：

| 地下城 | 每计数单位净化量 | 自身征服门槛 | 前置征服 |
| --- | ---: | ---: | --- |
| 8500 伤城 | 150 | 50% | 无 |
| 8504 | 75 | 50% | 8500 |
| 8507 | 50 | 50% | 8500 |
| 8505 | 50 | 50% | 8504 |
| 8503 | 75 | 50% | 8507 |
| 8508 | 30 | 100% | 8503 和 8505 |

六图 gauge limit 都是 10000。`03C73EE0` 对 `count * gain` 做 float32 比例计算、截断并夹到 0…100；`013A0610` 检查每个前置的**自身**门槛。因此 8500 的 33/34 单位为 49%/51%；8508 开放需要 8503≥67、8505≥100 单位，不能要求这两个前置各自达到 100%。8508 自身达到 100% 要 334 单位。

`worldmap/guilddungeon.wdm` 的 worldmap 37 用 `dungeon is not open` 条件画锁盖。选图 `035D6319`、入图 `0371E2DF`、锁盖 `03733A1A` 都调用相同开放判定。入图失败路径使用文本 ID 60457。六图 DGN 另声明最低等级 50、指定难度 2、`[use fatigue only start dungeon] 8`。本候选沿既有等级/疲劳准入并补指定难度校验；疲劳扣除仍走现有逐房 FP1，未把这个区块扩成新的入口扣费规则。

## 已实现的接线与事务

- `guild/dungeon_unlock.go` 与 `dungeon_catalog.go` 解析前置及奖励；奖励目录的完整文本摘要进入入场身份。V166 `03C74270` 选第一个阈值不低于当前比例的奖励档。`03C74460` 解析 `[item]` 为 type0/id/count、`[contribute]` 为 type1/0/count；本服贡献域为既有 `Member.ContributionPoints`。
- `guild/dungeon_lifecycle.go` 定义月度周期、只读快照、整队准入和事务内净化。公会状态新增 `dungeon`，保存周期起止及每图 count；旧存档缺字段表示当前周期零进度。到100%后保留有限计数，后续合法通关仍可拿基础奖励。没有修改普通图 +10 公会积分。
- `dnfbridge/guild_dungeon_lifecycle.go` 接登录/成员变更、8号公会城镇选图、op16整队预检和已确认的最终房间结算。成员的账号、角色、加入时间、公会、周期、规则摘要在入场时冻结；不同公会、未入会、退出重入或策略变更均不能把旧运行转到新归属。
- `dungeon/guild_dungeon_rewards.go` 在现有 `GuildSettlementUnitOfWork` 内更新 registry、物品、贡献和永久回执；EXP/SP/TP沿同一结算事务。清算身份由周期、运行随机ID及成员组成；队伍每成员只提交一次。满包、物品解析失败或末尾SQL失败不会保留部分净化/奖励。
- 结算发送独立的背包槽刷新与741；同会在线成员通过各自事件循环接收新快照，队列满则由下一次登录/选图恢复。广播不等待对方锁，发送失败不重新发奖。重登与服务重新组装均读取持久状态。

普通奖励 `10154439` 对六图依次为 3/4/5/5/4/7 个，各加贡献20。`[repeat clear bonus reward]10156320×1`、`[level difference]10`、`[delete item]10154439` 的完整附加资格/清除时机还缺生产证据：本轮不发额外包、不按周期删除物品。周奖励块仅列最终图8508、无具体奖品。净化提示 `024F3C21` 能读出“旧count + 增量（可×2）”，但上游增量生产者未闭合；本候选采用明确的每成功成员1单位运营默认，未宣称恢复官方活动倍率。

`dungeon_policy` 属于持久 registry 的可选配置，缺省无需迁移。配置示例：

```json
{"reset_day":1,"utc_offset_minutes":0,"clear_units_per_member":1}
```

修改应经过持有 registry 锁的管理事务；本候选没有新增 GM 配置按钮。策略变更使旧入场身份失效；已有周期不能向更早的起点倒退。已提交回执跨周期可读回，但不能再累计或发奖。

## 守护神与公会战

匹配 NPC1500/1501 的 `[attend guardian]` 参数分别是 1/2。NPC 菜单 sender 分支 `0354D991` 从 role key 212 取参数，组装 CMD1350：

```text
u32 action=8, u32 guardianID, u32 0, u32 0
```

该分支到 `0354D853` 写最后字段并 flush；有限原生执行确认两个参数值的 16 字节请求。测试替换了 NPC role getter，没有运行完整 NPC 解析与菜单构建。字符串注册已找到 `[attend guardian]` 的 token 0x13d6，token 到 role key 212 的完整解析桥接仍待补证。

CMD1350 的 ACK 在 `010779C3` 注册到 `01067EF0`：成功分支直接返回，失败分支按错误码显示窗口。因此仅成功 ACK 不会持久化或显示已召唤的守护神。

公会战 NOTI1297 的 `01077450` 读取固定 2197 字节状态，比较守护神等级/技能并刷新公会对象和城镇 NPC；NOTI1337 的单 u32 进入 `010707C0`，所见路径是战斗结果/场景更新，不能把它当作召唤确认。完整状态布局、action8 的后续通知、重复召唤和重登契约未闭合。

`agitwar.etc` 两位守护神均列 AP=50000、GP=1000，但这些配置尚不能证明 action8 应立即扣哪种现有货币。先核清动作与消费字段，再新增扣费 owner；不能同时扣两项或拿普通贡献币代替。

V164 实际接收门控链的 34 个 class/opcode 观测表明：741/742 可接收；CMD1350 应答及所查公会战通知 777、778、779、784、1261、1280、1281、1283、1284、1293、1297、1337 均被拒绝。守护神闭环需要配套 EXE 精确门控变更及状态协议。先确认所需消息，再只放行这些消息并做全矩阵回归，按 EXE 发行→玩家通道→依赖服务端的顺序交付。

公会战后续还包含 8510…8520 地图、匹配/阵营/基地耐久/建设和胜负清算；真实 ETC 的 900 秒战斗时间、地下通路点数 300 和单人限额不能替代这一套状态 owner。本单没有启用公会战。

## 当前验证与完成边界

- 原失败回归：公会登录缺NOTI741，客户端目录未加载。修复后登录、通关、重登均发送真实状态；Go结算产生的33→34报文通过匹配V166原生接收与开放判定，重登同值、无公会清空旧count。
- 六图ETC奖励、前置、指定难度，以及同会/异会、并发重放、满包、成员/周期变更均有专项。隔离MariaDB普通/race执行真实事务末尾失败、同队两成员各自四次并发提交、重连、周期切换；奖励、贡献、EXP/SP和净化同进退。
- 原生验证替换PVF loader、STL/分配器/map替换及UI依赖；真实执行741读取、count getter、完整前置判定和商人可用性getter。Go测试的通关前33次状态与物品定义使用明确夹具，当前结算到34及报文由生产代码生成；未执行游戏进程或六图完整地图脚本。
- 全量检查与候选摘要随本地交付记录保存。此次不部署，不更改EXE/PVF；首图进入、六图实机通关与画面验收、前述额外奖励/清除/扣费语义、守护神/公会战仍分别验收。

## 实测步骤

1. 使用匹配客户端/PVF登录一个公会角色，进入公会城镇地下城选择页：零进度时只有8500开放；换无公会角色不能继承旧进度或入场。
2. 单人正常通关8500，检查净化增长、背包凭证+3、个人贡献+20；退出重登应保留。普通图的公会+10积分规则仍单独生效。
3. 同公会两人组队通关：每人一次基础奖励和贡献，共两单位净化。其他同会在线角色重开选择页应看到同一进度。异会成员不能被带入。
4. 在隔离测试公会累积到8500的34单位、8504/8503的67单位、8507/8505的100单位，逐条核对分支；末图必须同时满足8503和8505。不要修改真实公会进度来跳过验收。
5. 对照断线重连、结算重复回包和满包后重试，确认同次通关只发一次。周期切换在隔离环境推进时钟验证：旧运行不能写新周期，新周期首图重新起算。
