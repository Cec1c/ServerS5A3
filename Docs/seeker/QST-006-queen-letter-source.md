# QST-006 梅娅女王书信来源回归

## 目标与证据

玩家正常接取「梅娅女王」后，界面显示书信0/1、拜见女王0/1，仍不能交付。旧修复覆盖材料消费事务，本次追踪材料从何处获得。

任务3249的子任务为3609、3610；3610需要10164786书信1封。使用当前真实PVF及累计服务端，先核对3249、两个子任务和直接前置的接取物品、奖励、分支定义。

## 已确认成因

3226「前往阿法利亚营地」的完成奖励为书信10164786一封。正常完成3226，再交付3249及其子任务，真实PVF测试通过。

按等级无奖励完成3226时，任务变为completed，reward_state也被标为granted以关闭领奖入口，实际未发书信。随后3249仍可接取，3610因缺少书信失败。历史状态与隔离复现均出现该路径。旧材料消费修复覆盖正常持有书信的结算，本次修复来源被跳过后的衔接。

## 解决方案

在任务活动快照之前恢复这条已确认的剧情依赖，覆盖新接取和已有活动任务重登。领域事务重新读取角色、任务和库存：3226必须已按等级无奖励完成，3249及3610仍活动，真实定义仍规定3226奖励该信、3610提交该信。只补任务背包缺少的一封书信。

库存与3226上的一次性恢复回执同事务保存。已持有书信、正常完成来源、已交付后续任务和已有恢复回执均保持原状。桥接层以真实物品定义核对任务物品类别，复用现有分配器，提交后先发库存更新，再发活动任务快照。经验、金币及其他跳过奖励保持现有规则。

此次只启用3226→3249/3610这一组经过取证的关系，后续其他剧情依赖单独验证。

## 执行范围与测试目标

实现入口为quest领域的新恢复owner、bridge的新适配文件及`scene_active_quest_snapshot.go`。复用`seeker_qst006_real_pvf_test.go`及任务接取/结算测试入口。

- 从真实定义确定书信来源，并记录确切任务及字段。
- 正常流程生成书信后可交付3249，库存仅消费1封。
- 重复事件不重复发放或扣除；材料缺少与事务失败保持原状态。
- 无奖励完成3226→接取3249→刷新库存→正常交信，修复前失败、修复后通过；旧活动任务重登可恢复。
- 两种无奖励完成标记、重复快照、重登、并发恢复、背包满、库存或任务保存失败均有回归；失败可重试，成功仅一封。
- 普通来源、已有书信、后续已完成、定义不匹配均无额外发放；其他资产不变。
- 用户实测：不用任务券，正常推进前置、接取、对话、交信及重登，后续主线可接。

允许失败。返回已尝试步骤、失败证据、修改文件及下一步需要的信息。

## 修复验证

修复前，新接任务只发送 `1/31 → 0/574`，旧活动任务重登只发送 `0/574`，两路都缺少书信库存更新。修复后分别发送 `1/31 → 0/14 → 0/574` 与 `0/14 → 0/574`，书信进入任务背包；3610 正常交付只消费一封，重复快照保持结果。

两种无奖励完成标记、正常来源、已有书信、后续已完成、重复与并发、背包满、库存/任务保存失败回滚及重试均通过专项。正常3226来源、既有女王材料结算及危险研究四材料回归继续通过。

完整领域、bridge、control、Go list、vet 与 Windows/Linux 构建通过。旧PVF与恢复主线券的新PVF专项均通过；隔离数据库专项未配置。部署及实机结果按交付回执更新，用户实测目标为正常对话交信并继续后续主线。
