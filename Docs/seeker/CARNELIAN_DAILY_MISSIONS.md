# 红玉髓每日使命

## 原因和范围

现行任务表注册了 11 个 `[auto daily mission]` 地区击杀任务，覆盖 40–99 级，每次奖励红玉髓（10163959）15 个。原实现已正确读取奖励，但未将该 grade 纳入可接目录和每日刷新，且把 `-4, 地区, 最低难度, 怪物类别, 数量` 按普通击杀任务的四元组处理。

修复接入原有任务接取与完成事务，按 PVF 等级范围提供每日使命；普通使命奖励不变，不注册资源中的其他变种，不修改 EXE 或 PVF。击杀条件从服务端已确认死亡、实际地下城的世界地图归属和怪物类别取得，客户端触发不能代替战斗事实。保留初次进城门禁、重复死亡回执、完成发奖事务与北京时间 06:00 服务日刷新。

五元组第四字段的 `-1` 为普通怪物，`-3` 为领主，分开递减九位剩余计数。未注册的精英变种不扩展。世界地图选择页没有收录的副本（例如血色防线），仅在本条单地区每日任务的 `[dungeon info]` 明确列出时使用该归属；已知地区冲突不覆盖。当前 PVF 的四个此类副本均有回归。

共享击杀在队友自己的事件队列执行，复核角色代次、同一实例、同一房间和已提交战斗死亡；队友自行重报同一对象只读回原计数。领主后的剩余怪物强制清场没有战斗死亡凭据，不计入任务。奖励仍仅由原完成事务分配，击杀阶段不发物品。

## 验证目标

- 实际注册目录和奖励、等级边界及五元组初值。
- 正确地区的普通怪物及领主分别推进；错误地区、难度、类别、未确认和重复死亡不额外推进。
- 接取、权威击杀、完成入包的完整生命周期；当日重复确认不重复发奖，次日重新接取。
- 背包分配和持久化失败回滚、重建 owner 后回执仍有效，队友收到同一死亡的自身进度。
- 原四元组指定怪物任务保持原匹配规则。

上述专项、真实 PVF 入包、隔离 MySQL 及 race 验证均通过；完整领域、bridge、control、vet 和 Windows/Linux 构建通过。并发 SQL 竞争中被数据库中止的事务重试后读取既有回执，不重复发奖。

代码与自动验证已完成；源码合并由 MR 记录，部署及游戏界面、实际击杀与领取由后续维护窗口验收。离线请求夹具不代表客户端 GUI 已实测。
