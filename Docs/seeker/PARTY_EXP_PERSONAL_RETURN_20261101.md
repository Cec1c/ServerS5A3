# 同房经验与个人退队回城

当前客户端下，副本内退出队伍只让退出者回城；留图成员保留队伍、原副本实例及固定槽位，队长退出时由最低占用槽位接任。通关后普通返回城镇仍走原有保队流程，显式退出队伍另外摘除本人。

## 成因和实现

- 权威怪物死亡已共享给同实例队友，但击杀经验原先仅向死亡上报者提交。新增队友自己的会话事件，复查当前角色代际、中央队伍、实例、同房、存活与回城状态，再按该角色的等级和账号加成调用既有经验及技能点事务。只从首次接受的战斗死亡扇出；每个接收运行态记录房间和怪物键，事务成功后先记回执再发经验状态，避免写包失败后二次入账。未引入尚未核验的 PVF 组队倍率。
- 普通 op13 原先只摘队伍，未请求个人回城。现在使用原有 typed op24 回城流程，真实城镇确认后 ACK13、释放本人实例成员、摘除中央队伍并清理两种场景的名单。副本专用离队操作在同一管理器锁内核对队伍编号及角色代际，移交队长并保留队伍编号；剩一人继续发布非空名册和血条。
- 踢人已有 class0/op10 通知，但之后 kind3 名单销毁会额外触发“队伍已解散”。普通离队改发 kind2 的空成员名单；真正解散保留 kind3。被踢者在自己的会话队列执行个人回城，不替其他成员回城。
- 原生邀请依附发起者的当前场景角色；未接受时发起者切图会移除旧场景角色，邀请框随之关闭，需重新邀请。未把未接受的邀请当作队伍成员，也未强行维持跨场景弹窗。

## 协议取证版本

原静态取证匹配 EXE SHA256 `534b5ef166d0090d1ab88e01f5f443721abf97eabfacfb007e04e30fd9d51b24` 与 dstr SHA256 `8d6cb05216fdd65e498648864ae1e98c0adca5d3ebfd44055e8996743955aadb`。

- NOTI10 handler VA `0x200ABD0`，注册位置 `0x2031975`；读取 slot、mode 两字节，mode0 的本地踢出文案为 DSTR631。
- NOTI9 handler VA `0x2016350`：`0x2016705` 仅 kind0/1 读取角色身份头；`0x201697F` 允许 kind2 直接读取成员数；`0x201767F` 读取四字节尾。空 kind2 为十字节记录头、零成员数、四字节零控制尾，共十五字节。
- `0x2017C7D` 的 kind3 选择 DSTR627（队伍已解散），其它离队选择 DSTR628；`0x2018B7B` 的 kind3 分支还销毁整条记录。普通离队不能用整队解散帧代替。

## 验证范围

回归覆盖双方轮流击杀、双方重复上报、异房/已离队/死亡/待回城成员排除、经验写包失败后不重奖、队长和队员分别个人回城、固定槽位和原实例保留、多人离队帧顺序、网络写入失败和旧运行态回调。本公开候选的实际构建与回归结果见 MR；历史本地部署与本候选的公开验收分别记录。
