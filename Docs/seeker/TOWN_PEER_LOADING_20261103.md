# 普通城镇入场的配套显示初始化

原流程向同屏玩家发送 mode0 外观、完整 mode1 装备/技能、队伍状态和区域通知。非队友离区会删除角色，再次进入时完整 mode1 可能触发原生 LOADING 和主线程初始化。此修复让普通城镇路人的显示对象由原生显示创建器建立，完整队友仍走原有角色初始化。

## 服务端边界

`DNFBRIDGE_TOWN_DISPLAY_ONLY=on` 显式启用，默认关闭。只处理 `official-24.9` 的两个普通入区方向及 finish-loading 补发；双方必须在同频道、同共享区域，无私有或攻坚实例，且均为无队伍或仅含本人并由本人任队长的单人大厅。未知来源、其他 profile 和真实多成员队伍保持完整投影。

省略的仅是这些普通入场的 mode1；mode0、队伍身份和原生位置通知保留。完整包体仍先构造，因此不宣称消除了所有服务端构包成本。区域记录可以保留辅助连接，准入与组队补全均采用角色目录的当前绑定身份和完整频道，不让辅助连接夺取常驻连接。

收包会话记录收到轻量角色的精确代际。真正组队时先补齐仍在同区域的当前成员，再发 op153 血条和 op9 名单。单人 op9 不反向触发完整重建；通用名单刷新复用同一 before-frame 顺序。重复名单不重建，NOTI6、换场、换角色及关闭会话清理记录。保留主干现有的关闭流程、登录器上下文和战令任务清理。

## 客户端能力与独立交付

离线补丁只改同区域 NOTI23 的显示查询调用 `0x0203CBC4`，使用自有 RX 预留区。已有显示对象直接复用；已有完整对象、零角色键、没有本地场景和原生辅助命名空间均保持原行为。仅缺少普通显示对象时调用原生 `0x02965BD0(UserInfo, 0)`，随后继续原生场景加入和定位。离区分支、完整角色加载器、LOADING 绘制和既有保护保持，不增加 DLL。

补丁输入摘要是有界回归夹具身份：`f4c10881fb64446272c0beda95bf638c3a3eec6eeab1a705b8dab472aa26dd28`；输出为 `a5f1d5ef432064cccaeac6362d5f1405fceddd62739da85661154fc008d47f7d`。脚本拒绝其他输入，不自动迁移偏移或覆盖安装。它们不构成已公开客户端发行或玩家更新清单。启用前必须按目标客户端验证能力、独立完成客户端发布与实际更新源读回；本源码提交不发布 EXE、PVF、私有配置或维护材料。

## 专项验证与限制

`scripts/client/test_town_display_only.py --input <精确补丁输入> --output <新证据文件>` 覆盖48组原生同区域分支、getter、factory、writer、注册 guard、reset 和重复创建/释放。`test_town_singleton_binding.py --input <精确配套输出> --output <新证据文件>` 覆盖八槽及有/无完整角色的16组原生成员绑定。共享内存夹具独立位于 `town_display_native_memory.py`，不依赖此前客户端优化试验。

需安装 Unicorn 和 pefile。场景表查询、分配器、资源/外观构造、部分保护值及析构末端是明确适配器；单人绑定验证中的场景查询和本地对象查询也为适配器，本地查询返回零，未覆盖其本地角色修复分支。这些结果不是完整渲染、GPU、真实宠物/时装或整帧性能证据。

服务端回归覆盖实际建队、成员退队、队长退队、踢人、双方独立单人大厅、双向入场、辅助连接、真正入队前补齐、重复名单、加载完成补发、完整名单包体保持，以及离区、旧代际和频道准入。客户端实际验收仍需观察外观、移动、查看资料、组队血条、进本回城及相同角色下的停顿。普通本地试用和公开完整验收分别登记，未用旧成功覆盖新失败。
