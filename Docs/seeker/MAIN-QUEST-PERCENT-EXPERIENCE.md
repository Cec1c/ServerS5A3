# 普通主线按任务等级比例发放最终经验

## 策略

普通剧情主线的最终奖励设为任务最低接取等级升下一级所需经验的可配置百分比，首轮使用15%。设任务最低等级为L、累计门槛为T(L)，T(0)=0，奖励为`floor((T(L)-T(L-1))*percent/100)`。35级任务在35、60、89级角色正常交付时，15%奖励均为235974。

用户已确定15%是最终奖励：新模式不叠加契约、经验药、旧任务难度权重或现有主线倍率。旧倍率继续服务未纳入本策略的任务。满级及跨满级沿现有角色结算和挑战者经验规则，等级上限仍为90。

纳入具有显式有效等级的普通epic父任务或独立任务：`Grade=epic`、`MainQuestID<=0`、`JobChangeQuest=0`、`IgnoreQuestLevel4Exp=false`。转职、觉醒、六条忽略等级的决斗场任务、非主线及重复任务沿原规则。`NoExperience`任务和无奖励跳过仍为0，父子物品及金币结算保持。

新增`main_quest_exp_percent`配置，对应`DNFBRIDGE_MAIN_QUEST_EXP_PERCENT`，整数0..100；0或未配置沿旧策略，1..100启用上述最终比例，首轮候选15。比例可改为10、20等，无需修改公式。部署时核对配置源、容器和实际进程的同一数值。

## 实现思路

progression新增累计门槛差值百分比计算，使用uint64乘法并检查等级、非递增差值及输出范围。quest解析保存原始显式level存在性，在领域结算内分流：纳入且启用时使用该值作为BaseExperienceDelta与ExperienceDelta，ExperienceBonusDelta为0；其余走旧公式。缺失或异常等级返回明确错误，不改用角色等级。

沿既有CharacterSettlement提交、物品扣除和奖励回执。已提交回执重放原值，调整比例不重新计算历史奖励。bridge仅传可信服务端配置；客户端请求不能指定百分比。Docker实例生成器接入窄配置和类型校验。

## 验证目标

- 数值：等级1/3/15/35/65/88/89的15%分别150/192/14556/235974/2440828/32029581/42444667；先求相邻差再取整，覆盖边界和溢出。0关闭，10/20调整可验证。
- 囤任务：同一35级任务由35/60/89级角色交付结果一致，角色当前经验不影响基数。
- 叠加：同时配置旧倍率3、契约和药水，新模式仍仅15%，bonus为0；被排除任务完整保持旧行为。
- 父子与事务：NoExperience子任务为0，父奖励一次；正常物品和金币保持，重复领奖/更改比例后重放/失败回滚重试/无奖励跳过不多发。
- 90级边界：89跨90以及90级正常交付，普通与挑战者经验遵循现有实现，不突破上限。
- 桥接配置、严格Docker生成，默认关闭保持兼容；完整Go领域、bridge/control/list/vet、双平台构建及相关race。真实PVF由Seeker串行验证。

## 验收

部署候选后正常完成不同等级主线，核对实际经验增加、进度条与任务预览。服务端最终结算和客户端预览分别取证；预览若仍为客户端旧表计算，单列差异和配套方案。原始资源审计、逐职业可走链和测试回执在私人证据中维护。

## 当前实现

- `progression`已按累计门槛相邻差计算0..100的百分比，并检查等级、非递增门槛和输出范围。
- quest目录记录`[level]`是否显式存在；普通独立epic主线启用百分比时，缺失、空、非正或倒置等级返回结算错误，不再使用默认1级。
- 选中百分比任务后`BaseExperienceDelta=ExperienceDelta`、`ExperienceBonusDelta=0`，不调用旧主线倍率、契约或药水加成；其余任务保持旧分支。
- bridge启动配置、启动日志与Docker实例生成器已接入同一字段，客户端请求不能指定比例。
- 新测试覆盖15%关键数值、囤任务、NoExperience、职业/忽略等级/子任务排除、回执重放、父子材料与物品、失败回滚及89/90挑战者经验。

## 后段升级节奏

用正式`Catalog.PlanAccept`验证PVF前置与互斥关系，固定已完成88级前置及五种阵营选择之一，逐个完成可接节点。16个职业编号的结果一致：每条阵营路线含25个88级普通主线和55个89级普通主线，均可抵达终点4872。

| 任务等级 | 单角色路线任务数 | 单项15%最终经验 | 路线合计 |
| --- | ---: | ---: | ---: |
| 88 | 25 | 32029581 | 800739525 |
| 89 | 55 | 42444667 | 2334456685 |

仅按任务奖励，从刚升88级起算，第7个88级任务升89，第16个升90；从刚升89级起算，第7个89级任务升90。刷图经验会进一步提前升级。这是可走任务图的奖励估算，未模拟战斗耗时、完成券跳过或等级触发的无奖励跳过；满级之后继续正常交付按既有挑战者规则结算。

## 配置与上线验收

Docker实例配置示例：

```json
{
  "main_quest_exp_multiplier": 3,
  "main_quest_exp_percent": 15
}
```

其中旧倍率仅作用于保留旧策略的任务。百分比设为0恢复旧策略；后续改为10或20由配置发布生效。发布回执应同时记录两项配置，并核对源配置、容器环境和实际进程环境。

实现候选只涉及服务端与配置接线。完整领域、bridge/control、list/vet、相关race、Windows/Linux构建与Docker测试通过；真实PVF的639条范围审计和14组结算/路径验证通过。当前为本地验证候选，上游集成与部署回执分别记录。实机按正常领奖核对实际经验、挑战者进度和物品；任务预览数值单独记录，不能由服务端ACK通过推定预览已经同步。
