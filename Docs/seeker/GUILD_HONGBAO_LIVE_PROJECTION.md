# 公会红包请求与贡献榜等级修复

红包页签已开放。当前贡献榜使用入会时缓存的成员等级，角色升级后仍显示旧值；改为查询时从权威角色记录投影姓名和等级，校验账号归属，不保存或改写成员资料、贡献累计或资产。

修改范围：红包查询适配器及其回归测试。覆盖缓存旧等级/旧姓名、角色删除或归属改变、连续查询不写库，并保持贡献累计值与原生 40 字节行布局。累计获得的公会贡献点数与背包现存贡献币数量是两个数据，消费贡献币不倒扣累计值。

## 原生发包根因

V188 的发放、领取、历史查询分别在 `0x1091E57`、`0x11A61B3`、`0x11B3F17` 将结构起始地址和 18/17/17 字节长度传给原生 `0x374EEB0`。该函数把整个缓冲追加到已创建的包中，包含业务字段前 13 字节未初始化前缀。服务端需要的正文是 5/4/4 字节，因此拒绝该请求。

修复将上述三个调用点的地址向后移 13 字节、长度减少 13 字节，只修改六个指令字节和 PE checksum。不更改接收链、通知挂接、PVF、交易身份、份数限制或事务规则。发放仍由服务端在同一事务中消费真实库存并创建记录；领取仍校验账号和重复领取。

旧夹具在 `0x374EEB0` 适配器内先去掉 13 字节，漏掉了问题。新测试执行真实发送函数和真实 raw writer，只在下游字节接收端截获结果；毒化栈前缀证明旧版失败，四档红包、5/30 份边界、取消、领取及历史证明候选行为。原生导出正文再经真实服务端流解码、购买、发放、列表、领取、历史及重复领取测试，畸形旧请求不修改资产。

## 验证与交付

六项原生测试通过，包含真实 ACK 分类器和分派器的成功/失败字段消费、完整函数 ABI、精确字节边界与 Windows 只读映像映射。红包专项及真实 PVF 定义下的原生正文到服务端事务测试通过。完整 Go 回归及双平台构建结果随交付回执记录。

实际玩家更新并重启客户端后，使用背包红包，选择份数并确认，核对物品减少、可领取列表新增、领取到账、历史与重复领取；对照当前角色等级。代码验证、部署和玩家验收分别记录。
