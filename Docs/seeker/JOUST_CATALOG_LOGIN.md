# 马战目录不兼容时保持登录可用

## 问题与目标

马战属于可选活动。运行 PVF 的下注上限、材料和奖励属于另一活动期次时，`joust.LoadCatalog` 会拒绝该目录。登录初始化先发送活动目录和开场状态，再加载骑士目录；错误沿城镇初始化传回读循环，导致连接关闭。

本项让不兼容或缺失的马战资源退出活动初始化，正常城镇流程继续。有效目录的协议、下注和奖励规则保持原有行为。

调查基线：上游 `3b242e13ed16c5aa1871fbeed79f5b2d90c631f1`。交付基线：上游 `2303cdef5109fcb22cff6de10b16fbef5f154fbd`，保留已合并的租赁任务修复。

## 解决思路

- 在发布活动 2365、op1240 和骑士快照前确认目录可用，复用 `currentJoustCatalog` 的加载与缓存。资源失败记录具体原因，并省略该活动目录及推送。
- 登录、重新选角和阶段定时推送使用相同资源判据；定时器不能在稍后重新发送不兼容活动的状态。
- 活动总开关和目录选项仍表达配置意图，实际发布还需目录可用。保留现有严格期次、下注、物品和发奖校验。
- 网络写入错误继续返回给调用方。只在读取活动资源的边界处理不可用状态，不笼统忽略发送错误。

## 文件范围

`go-server/internal/services/dnfbridge/` 下的 `joust_catalog.go`、`online_event_spend_time.go`、`gameplay_module_joust.go`、`joust_scheduler.go`，以及必要的聚焦测试。公共记录更新本文和 `changlog.md`。

## 测试目标

1. 用真实目录加载器及另一活动期次字段复现原错误；修复前测试编译成功并因行为失败，修复后通过。
2. 开启活动且目录不兼容、文件缺失或格式损坏时，首次和再次城镇初始化成功；op108 不包含 2365，其余活动行和进度继续发送，op1240/1241/1242/1243 不发送。
3. 定时阶段推送也不发送不兼容活动；无新下注和资产写入。
4. 有效目录及关闭开关的既有回归通过；各阶段协议内容与发送顺序保持。
5. 有效目录下注入 op1240/1241 的网络写入失败，调用方仍能收到错误。
6. 按仓库入口完成领域、bridge、control、静态检查及双平台构建；真实 PVF 验证按串行窗口另行记录。

## 游戏内验收

使用发生错误的匹配客户端和 PVF，保持马战开关开启，首次进城、重新选角和切频道均应成功；不兼容马战窗口不自动打开，其他活动可用。原生验收结果单独记录。

## 执行交付

允许失败。返回尝试方法、失败证据、当前修改文件和需要确认的问题。日志留在私有目录，公开文档只保留技术结论。

## 实现与验证

实现将 `currentJoustCatalog` 的资源可用性检查前移至活动发布入口，直接调用开场状态、骑士快照及阶段推送也采用同一判据。无在线角色时定时回调维持原有快速返回。`catalog=on` 表示请求发布目录，实际发布仍需目录可用。

内存 PVF Source 经正式 `LoadCatalog` 重现另一期次 `max=1000`、材料与奖励 `49000918x` 的报错；缺失/损坏文件也在原代码上导致初始化失败。修复后的首次初始化、同进程不重发目录的选角、重新下发目录，以及五个阶段均通过。旧待结算记录、库存和邮箱保持；陈旧窗口提交下注仍返回拒绝。有效目录的 op1240/1241 写失败继续上抛。

已有马战和在线奖励回归、完整领域、桥接、控制器、指定静态检查、相关 race 及双平台构建通过。另以实际 PVF 只读加载，得到相同的期次字段不兼容错误，首次/再次目录、同进程选角及阶段推送专项通过；可用 `DNF_JOUST_INCOMPATIBLE_REAL_PVF` 指定实际归档重复此检查。

反馈中的特定客户端/PVF组合及游戏内登录、切频道为原生验收项。其他原因引起的客户端断开另行跟踪。
