# 公会退出、踢人和解散

目标：原生确认动作完成持久成员变更，并即时清理公会窗口、头衔、增益和大厅资格。

匹配客户端的退出与踢人均发送 class1/op153：区服字节及名称 DSTR；空名是本人。独立解散窗口发送空正文 op303。当前服务端没有两项路由；客户端已接收153和空正文NOTI151，303应只开放class1。原303失败回调只显示安全模式错误；为已证实的成员/权限错误复用原153错误提示，成功及其他错误仍走原303回调。

在既有Guild事务中重查角色账号、同会成员及权限。普通成员可退出；踢人要求权限位10和严格品级优先。会长只能在其他成员全部离开后解散。删除公会不重用ID，保留历史交易回执。主动退出按客户端普通服提示持久记录到下一次06:00的加入/创建限制；覆盖申请、直接加入、批准、邀请与两种创建路径。被踢不新增主动退出限制。

事务提交后发送原生ACK及NOTI151，撤销该连接的大厅presence，刷新账号公会列表、头衔和增益；其他成员刷新名单。大厅返回仍走原生op36及现有地图校验。通知前重查会话代次和最新成员关系，避免清除新加入的公会。重复失败请求不再变更成员或延长离会限制。

实现范围：guild领域成员生命周期与现有加入入口、bridge精确路由/身份/通知、客户端303接收门控及其测试。使用隔离公会验证，不操作玩家公会。

测试目标：原失败请求；零区服/本人空名/具名目标；权限与跨会；多人会长拒绝/唯一会长解散；06点前后及重登；保存失败回滚；退出/踢人并发；大厅原生返回和重复请求；客户端原生回调消费与完整门控差异。完整Go检查后提交。实机验收关注公会界面即时清空、返回原城及同会名单。

复杂失败可保留证据续接：写清已尝试方法、失败点和下一步，不把未接线单元记作完整修复。
