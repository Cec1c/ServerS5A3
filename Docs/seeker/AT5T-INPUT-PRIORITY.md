# AT-5T 上机输入与普通技能优先级

## 目标与证据

解决 AT-5T 已显示技能键提示、按键却释放普通技能的问题。现场 V141 采样中，上机 descriptor 已注册在输入缓存第 31 项；有两组新按下被采到，其中一组角色仍为空闲、descriptor 已启用，state 仍为 0，随后进入普通动作。

原生输入循环按缓存顺序评估规则。前置排他规则进入按下或持续状态后，会直接清零全部后续规则；后续规则不再接受本帧评估。用原生逻辑键规则构造同键竞争项后，物理 Z 可以稳定复现“普通规则为 1，上机规则为 0”；将上机规则先评估则可读到按下。现场采样没有保存前置技能规则内容，具体竞争技能身份尚未确定。

## 实现边界

客户端补丁固定正式 V147 输入 SHA256 `f17d9289658664f1a61069f322ace28608d24f93f1af30f81698d534ab4a8484`。V141 作为故障证据，V147 作为贡献基线；公开交付可复现补丁源码，不携带 EXE 或玩家日志。

在输入轮询入口加局部包装，以栈局部变量保存本次选中的缓存行及遍历阶段。原生硬件输入生成、begin 迭代器构造完成后，筛选当前本地角色的 input、已启用的上机规则、同场景且属于本人的 AT-5T、模式0/1、距离小于120及原生动作资格。符合时只调整本轮栈迭代器的当前位置：先评估上机，再从缓存起点继续，跳过已经评估的那一项。

其余规则保持相对顺序。缓存字节、行地址及 shared_ptr 引用始终不变，保留原生硬件历史中指向缓存行的引用。仅有新按下、且找到有效近距 AT 后才调用职业资格；按住、松开及受模态/回放管理的 input 保持原顺序。补丁不写按键结果，不改变设备绑定或原生按下/持续/松开状态机。

上机仍由原生载具处理器执行，保留占用、锁、状态、位置和资格检查。无载具、远离、其他角色/输入、忙碌、已骑乘等场景维持普通技能优先。改动仅限客户端补丁、相关回归与本说明。

## 测试与验收

- 原生同键前置规则：原件不能读到上机按下，补丁后可读到；按住不重复，松开后可再按。
- 无机甲、距离边界、错 owner、载具状态/占用/锁、角色动作/锁与其他 input：不改变普通规则结果。
- Z 改键、缓存首/中/末位置、不同规则键、普通技能相对顺序、缓存全程零写入及引用计数平衡。
- 精确输入哈希、指令指纹、唯一补丁范围、PE 校验和、重复应用拒绝；执行实际候选 helper 和原生输入评估窗口。
- 用户实测：目标任务内正常按一次技能键上机、驾驶/下机；离开交互范围后正常施放技能；记录客户端版本和结果。

## 自动验证与复跑

`scripts/client/verify_at5t_input_priority.py` 的45组回放通过，实际执行候选 helper、原生缓存遍历、descriptor 状态机、shared_ptr 处理及已注册键 reader。场景对象、职业资格返回、坐标返回与设备逻辑行是显式夹具；修复前/后同键排他结果为 RED/GREEN。另行20组原生硬件联测执行真实按键映射、输入行生成、保护动作字段、距离函数和载具处理器，覆盖 Z/X/F10 改键；正常用例到达上机副作用入口。Windows ImageHlp 独立校验和通过。

职业调查另有17组有限契约：已注册技能 descriptor state0 时，命令规则查询返回无命令；快捷槽和 pending selection 另有旁路。当前实际 `+E0C` 是空操作，尚未证实具体动作28来自哪一项职业回调。真人验收要同时确认普通动作没有抢先、角色确实上机。

```text
python scripts/client/patch_at5t_input_priority.py --input <official-v147.exe> --output <new-candidate.exe> --receipt <build.json>
python scripts/client/verify_at5t_input_priority.py --input <official-v147.exe> --candidate <new-candidate.exe> --receipt <verification.json>
```

补丁生成仅需 Python 标准库；原生回放另需 `unicorn`。输出为离线候选，不上传到 Release 或玩家更新源。
