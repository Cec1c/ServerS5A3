# QST-005：远程通话装置没有效果

## 结论与范围

“神秘的魔刹石”需要通过米娅的远程通信菜单打开梅尔文对话。匹配资产确认了两个独立缺口：服务端只有 COMMAND475 枚举，没有处理器；V124 虽有对应原生读写函数，接收过滤位图却拒绝475。补服务端回包仍会被该客户端过滤，单独开放客户端也没有扣费和应答来源。

服务端候选现已实现配置目录、收费owner、有限重放许可及legacy/upper桥接；真实PVF红例已转绿，并验证475→33→34任务链。源EXE与PVF保持；单字节客户端兼容候选已生成并通过原生离线验证，实际发布仍是服务端上线前的依赖。原反馈为未标记完成条目的前半段；同段后半的“危险的研究”不在本项范围。

## PVF与NPC选择

真实 `n_quest/quest.lst` 将3734映射到 `n_quest/quest_renewal/epic_quest/slough/slough_epic_13.qst`：名字“神秘的魔刹石”，等级82–99，前置3733，类型 `[meet npc]`，`[int data] 2000`，发起NPC78，完成NPC2000，任务指引为town14/area1/NPC78。

源场景从同一PVF的城镇区域、地图NPC（含地图导入）及NPC role解析。真实town14/area1为 `Town/Slough/Slough_up_street.map`，包含NPC78；区域还要求等级81和已完成3697。收费前同时校验服务端已就绪场景与持久位置。仅在别处持有3734不能使用通信。空请求没有点击坐标，当前契约只证明所在区域存在可见通信源NPC，不推定具体点击或交互距离。

V124筛选函数RVA `0x01ca3240` 遍历通信配置，对每个NPC的所有require quest调用 `0x01895180`；任一要求不满足就排除该NPC。成员查询查的是QuestManager的当前任务向量：NOTI574接收入口 `0x01c14370` 先通过 `0x018b51b0(0)` 清除该向量，再逐项调用 `0x018c46e0(...,0)` 装载；3734在历史已完成集合中不等于当前可通信。

选择函数RVA `0x01ff0890` 将UI选中行映射为合格NPC。目标在客户端本地选择，服务端请求中没有NPC字段。服务端能重新计算合格集合，不能从475获知其中具体选中了谁；完成任务也不能由475自动代办。

## 匹配V124的协议契约

| 方向 | class/opcode | body |
| --- | --- | --- |
| 请求 | COMMAND/class1/475 | 空体，无NPC、费用、金币或操作ID |
| 成功 | COMMAND/class1/475 | `u8 1 + u32 charge + u32 remaining_gold`，小端，共9字节 |
| 失败 | COMMAND/class1/475 | `u8 0 + u8 error`，共2字节 |

请求完整入口RVA `0x01ff0cd0` 先比较本地金币与配置费用，之后调用命令头构造器 `0x0334f280(475)` 和发送函数 `0x03350ac0`，中间没有追加body。金币不足走本地提示；服务端仍须重新检查余额。离线模拟还确认，本地选择函数返回-1时，某些路径仍会发送空体475，不能把客户端选择检查当成服务端权限保证。

COMMAND注册片段RVA `0x01be84f2` 将475绑定到 `0x01bbec30`。该接收器成功时读两个u32，第一项读后不用，第二项传入 `0x01ff0e70`：它调用角色钱包setter，然后重新执行本地NPC选择并打开对话。第二项是剩余金币，绝不是NPC2000；第一项按PVF费用及下述参考实现命名为charge，V124本身不使用它。

通用COMMAND分发片段RVA `0x02123cf6` 读取status；失败时 `0x004bab80(475)` 返回false，分发器再消费一个错误字节。475接收器遇失败直接返回，没有自己的错误提示或钱包更新，不能承诺失败码会显示对应中文提示。历史不足金币码为10，可作为实现候选，需保留失败路径及钱包重新同步测试。

NOTI/class0/475另行绑定RVA `0x01c06d90`，只读一个u32并处理另一类对象，和远程通信成功无关。不得使用class0回复通信。

历史只读参考 `df_game_r`，SHA256 `1a25bc91cc447081eadf2bdb70e5b27b6bef2f217788343a6d6b555b20eb2d77`，带符号 `Dispatcher_ImageCommunicationEquipmentUse` 的process从通信配置取费用，调用 `CInventory::use_money`，返回charge和 `getCurCharacMoney`。它支持上述字段语义，但历史编号是476，不能照搬到当前475。

## 客户端过滤是独立门槛

V124原生接收过滤函数RVA `0x06a83610` 根据opcode查询位图；475所在字节RVA `0x06a9233b` 为00，bit3未开。原生注册存在不代表能经过过滤。

离线验证只在模拟器内把该字节00改为08，比较全部65536个opcode，准入差异恰好为475。该门按opcode工作，不区分class，因此这一位也允许同号NOTI到达后续分发；服务端仍必须严格只产生class1通信应答。初次研究只在内存验证；后续已由固定输入生成独立候选，未覆盖原EXE。

任何依赖此能力的服务端上线必须遵守客户端发布顺序：先由相应维护者制作并验证最终客户端，完成双端Release、实际玩家通道、下载读回及完整摘要匹配，再部署依赖该能力的服务端。这里的内存反事实测试不构成客户端候选发布。

## 可执行实施单元

1. **通信配置与资格目录（已完成实现与专项验证）**：新增领域模块 `internal/modules/dnf/imagecommunication/`，从真实PVF解析费用、每个NPC及其require quest列表，保留嵌套边界并拒绝重复冲突、负费用和缺失NPC定义。资格由当前活动任务集合满足全部require quest决定。NPC源菜单角色与远程目标分开建模；从真实城镇地图/NPC角色核对源可用范围，本例指引town14/area1。不要硬编码“目标永远2000”，也不要仅凭历史完成标记开放。
2. **收费与重放owner**：复用 `repository.CharacterAssets` 事务，检查会话角色归属、当前城镇/无副本状态、配置来源、资格集合及实际金币；同一事务扣费并保存操作回执，发送失败保留可恢复结果。475没有操作ID，不能用空body或角色/任务ID永久去重。实现时引入有界的服务端通信许可：绑定会话/角色/场景代次、活动任务版本及资格集合摘要，在有效许可内重复请求回同一结果；换角、换图、资格变化和明确到期结束许可，新操作才可再次收费。有效期必须作为显式策略并用时钟测试，不能未经验证就把PVF的20000当成秒数。若要跨断线识别同一次点击，需要另行定义持久许可范围；现有线协议不能保证任意重连下的无限期exactly-once。
3. **桥接和wire**：新增 `dnfbridge/image_communication.go` 并接legacy与upper COMMAND475；仅允许匹配class和空body。成功严格写9字节，失败写2字节，不收客户端金币、NPC或费用。以提交后的钱包生成剩余金币。保留可识别的错误日志；需要重新同步钱包时使用既有协议。错误class/非空body、不可用资格、错误归属、错误场景和余额不足均不得扣费。
4. **客户端放行与联测**：以完整摘要绑定的窄候选恢复475，重复执行本报告的全opcode差分、原生读写离线回归，再按发布顺序交接。不得放开整个未知opcode范围；失败回包和同号NOTI仍做class独立验证。
5. **任务闭环**：475只收费并授权打开对话。后续NPC任务推进继续使用既有op33/34及活动任务快照，不在475中将3734改成completed。若需把远程NPC对话绑定到服务端许可，需在已有触发上下文中检查该NPC属于许可集合；本研究不宣称op33带有NPC身份。完成后再检查重复回调和重登状态，避免与其他任务条件修复混合。

单元1/2/3/5已形成候选；单元4由客户端维护者另行处理。客户端未完成发布门槛时保持功能不上线。没有玩家录包不阻止服务端自动测试。

### 收费候选的具体策略

- `imagecommunication.Use` 通过 `CharacterAssets` 的可选 `CharacterAssetQuestUnitOfWork` 扩展，在同一事务内读取当前任务和钱包。内存实现复用资产/结算共享锁；MySQL复用结算事务路由及 `FOR UPDATE`。不提供单独读取资格后扣费的降级路径。
- 角色Stats保留一个固定大小回执，随金币原子提交。许可摘要包含随机会话nonce、角色及代次、场景代次、当前活动状态/版本、合格目标及费用。没有客户端操作ID，也不永久以空体去重。
- `PermitLifetime=30*time.Second` 是明确的服务端策略，与PVF的20000无关。相同许可内重复点击、关闭后重开、发包失败重试均复用原回执；恰好到期可建立新许可并收费。事务回滚可重试；提交结果未知时读取持久回执恢复。
- 换场景（包括离开再返回）、入副本、换角、任务版本/资格变化使原许可失效。重连或进程重启产生新nonce，随后合法通信再次收费；此线协议不能辨认跨重连的同一次点击。发送失败后若连接已经关闭，不能承诺在新连接上恢复原许可。
- 重放成功回包保持原费用/余额；若期间钱包另有合法变动，随后用既有class0/op14投影当前余额。不足金币回class1/475的 `00 0a` 并同步实际钱包；其他拒绝为 `00 02`。这些错误码不保证原生UI有中文提示。
- bridge固定当前会话归属并锁定场景，拒绝错误class、非空body、未登录/无角色、旧会话、未就绪/错位场景、在副本、缺源NPC、无资格或余额不足。未新增op33的NPC字段、自动完成或发奖路径。
