# QST-001 父任务收尾时结算末子任务物品

## 目标与基线

完成父任务时，已达到零进度的末子任务应在同一事务内完成其物品扣除和奖励，重试只返回原结果。对应“返回赫顿玛尔”所需碎片不足的调查。

- 公共基线：`7972cce4071c1029c4bfbe42b3c2f9a067dc34b0`。
- 已核对 PVF SHA256：`fef4f46f6c3096d10cd88c84579dea8bd4fffa18e5a75b4684a2e920864f5525`。
- 状态：修复及自动验证通过，待合入累计版本部署及正常流程游戏内验收。

## 已确认成因

真实 PVF 的父任务 3458 包含 3472、3473。“阿尔伯特的请求”末子任务 3473 为 `[seeking]`，消耗物品 10164800 三个，奖励同一物品四个，净增一个。后续“返回赫顿玛尔”要求十个。

`go-server/internal/modules/dnf/quest/finish_owner.go` 的 `finishQuestClearTrigger` 接受同父任务、活动且进度为零的末子任务，然后直接标记 `completed` 与 `reward_state=granted`。它没有执行子任务的物品结算；后续 `ApplyFinishSettlement` 只计算父任务自己的奖励。

回归复现：库存四个碎片、3472 已完成、3473 活动且进度零，只完成父任务 3458，库存仍为四个，3473 却已标为已领奖。预期为 `4 - 3 + 4 = 5`。该缺失的净增一个与反馈吻合；真实玩家是否走过此路径需结合其持久状态确认。

## 解决思路

沿用当前父任务终止协议，先取得待收尾子任务，再在父任务已有的资产事务中应用子任务必要物品消耗和确定奖励。最后一起提交父子任务、库存和持久回执，回包投影应包含实际变化。

复用既有 PVF 奖励解析、物品分配和消耗逻辑；保留父子归属、活动状态、零进度及幂等校验。普通无奖励末子任务继续完成。奖励选择或职业变化等需要额外输入的类型按其真实规则处理，不能静默标为已领奖。

允许修改 `internal/modules/dnf/quest/finish_owner.go`、必要的同目录小辅助文件及对应测试。若结果结构或 bridge 刷新必须调整，先说明具体缺口，由 Seeker 扩展该单元。无需 PVF 或 EXE 变更。

## 测试目标

- 已有失败用例 `TestOwnerTerminalChildItemSettlementPreservesNetReward`：四个碎片完成父任务后为五个，重复父任务仍为五个。
- 真实 PVF：确认 3458/3472/3473 关系、三扣四奖及后续十个要求；以实际 Definition 驱动结算。
- 物品不足、分配失败或末期保存失败：父子状态、库存和回执均回滚。
- 已经独立结算的子任务不重复发奖；跨父、缺失、非零进度子任务仍拒绝。
- 无奖励末子任务、现有普通任务和选择奖励路径保持其原有行为；明确子任务奖励在返回结果和持久回执中的归属。
- 定点及完整 quest 包通过后，由 Seeker 按根 AGENTS 完成领域、bridge、control、list、vet 和构建验证。

## 验收目标

新流程从正常前置推进时不丢失 3473 的净增一个，重新登录仍一致，最终有十个碎片可提交“返回赫顿玛尔”。重复提交或断线重试不额外发奖。

使用任务完成券跳过卡点不构成本项验收。历史任务已完成也不能单独证明正常流程已恢复。

历史已被标为已领奖的角色单列处理：先核对已保存任务原因、回执和库存，给出幂等恢复方案及范围，再在所属事务边界执行。修复新流程不自动等于历史角色已恢复。

## 结果与依赖

DeepSeek 实现同事务子任务物品/金币结算与父回执归属；Seeker 复核补正父子同格奖励数量合并，并补充最后提交失败回滚、跨父拒绝、真实Definition驱动结算及ACK/库存刷新测试。

定点测试、完整领域/bridge/control、go list、go vet及Windows构建通过。数据库条件测试未配置独立库而跳过；本次新增事务回滚使用内存事务实现。无EXE/PVF变更依赖。随后由Syncer应用到实际累计源码并执行部署与运行读回；游戏内正常推进验收另列。
