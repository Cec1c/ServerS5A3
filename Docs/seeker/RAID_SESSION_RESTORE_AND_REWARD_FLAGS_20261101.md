# 攻坚队重连对象恢复与翻牌展示

## 重连后的队伍对象

服务端保留开战后的成员身份，而新客户端进程尚未创建自己的攻坚队对象。仅发591模式2更新已有对象，不能替代1359完整对象安装。后台584参与通知的可选播报尾段会读取该对象的路由字节，空对象可在 `0x01FF4CC7` 读取地址3。

新会话绑定前设置恢复门，阻止后台进度越过对象创建；完成场景加载或重新打开选择器时按752资料、ACK1359完整对象、591成员、591元数据、进度的顺序恢复。发送成功才释放门。校验当前会话、频道、冻结账号和团队可见性，不重新开战或重发加入通知。超时空沿其既有快照恢复链处理。

客户端工具 `scripts/client/patch_raid_participation_null.py` 针对匹配输入，在可选参与播报之前检查自己的团队对象。为空时跳过当前行的可选播报尾段，正常对象保留原处理，解析与参与记录的更新保持。没有修改公共解码或异常处理，也不启动游戏。

## 奖池标志和展示标志

PVF奖池选择的Flags参与选择与发奖指纹；NOTI600道具行最后一个字节由原生消费器写入描述符+0x41。该字节非零会让牌面过滤掉道具，并在没有可展示道具时进入奖励限制提示分支。两个字段不能直接互相复制。

实际已提交奖励的展示行固定不设置这个隐藏标志。保持原始奖池、概率、事务、幂等指纹与真实宿命数量；数量为零的宿命仍不显示，没有改成伪造奖励。商城券仍由既有账号钱包事务入账和刷新。
