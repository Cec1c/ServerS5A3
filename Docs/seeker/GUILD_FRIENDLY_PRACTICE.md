# 本会公会战练习运行链

## 问题与目标

匹配客户端把同时具有 `agit war dungeon` 和 `friendly agit dungeon` 标记的练习图作为专用入口，发送难度 3、state 1、token 65535。普通副本入口不接纳这一请求，点击练习没有后续。仅放开入口还会遇到本地生成防御怪物的身份不一致，以及普通副本奖励和返回流程不适用的问题。

本项接通本会练习的入场、建筑与守护神投影、战斗和回城。依赖公会建筑持久化与完整 191 快照；没有 PVF 写入。

## 运行规则

- 从匹配 PVF 读取练习目录，使用当前公会投影的扩张字节选择基地和围墙图；公会等级不替代扩张等级。
- 整队在同会、同频道、同地区且会话身份有效时入场，先完成全部成员预检，再安装本次运行数据。
- 固定本次入场的守护神和建筑表，191 在 op28/op29 前发送。练习期间的公会变更在回城后刷新，下次练习使用新快照。
- 布置怪物由客户端从建筑表本地创建。服务端维护对应战斗目标，不在 op29 再发送一遍；真实 key 0 限于该练习的已登记对象。
- 房间与已死亡对象由同一队伍共享，重访恢复已死亡本地对象；守护神替换沿用实际 PVF 和客户端星级规则。
- 练习不进入普通掉落、经验、翻牌、任务、公会贡献和奖励事务。完成后使用练习通知，再接用户选择回城的 op42；放弃使用原城镇返回流程。

## 验证与验收

客户端依据为正式 V177，SHA256 `027eca60196f8e22b7d05a9cad4ae37fe0098ab48e3048714b8ceb9270f5e752`。本次相关窗口与原 V176（`2a6cc14f3353e3d9d142b8580e432fe76ff3c1bbdc5be6818092347f9003bc74`）逐字节一致；地址为该模块 VA。

- 标签解析 `+C6C/+C6D`、资源复制 `+A42/+A43` 和 definition `+902/+903` 串到发送器 `03727F30` 的 state 1。
- `01076220 → 010690E0` 从实际出战守护神和等级计算星级；`01076530` 仅替换 type 3、dummy 9 的怪物编号，保留原始 op29 行让客户端执行替换。
- `01076B50` 按 MAP 区域扫描 64 槽并追加映射怪物。原生 key 经过对象注册、getter 和 `02758B39` 的 op39 写入保持一致，包括 key 0；NOTI38 可查找 key 0。
- 原生行 `+28` 经 `0263329D → 02823F50` 反向写入 actor `+5208`；`0251E3F0/0251E500` 的清场判定跳过该值为零的额外防御怪。静态目标仍参与清场。
- 额外守护神设施表在匹配 PVF 中只有三个地图条目，均无对象记录；原生零计数分支跳过追加。
- NOTI31 的 `01FEC7A0` 设置练习结果阶段；玩家选择回城后，`02262810 → 02261750 → 02262D10` 发出空体 op42。通知本身不自动选择回城。1337 的发送分支要求 dungeon ID 为 0，不用于替代这条练习返回链。

自动验证覆盖真实目录与地图、入场请求、跨会和旧会话拒绝、快照隔离、双方战斗通知、重复死亡、通关或放弃回城及奖励不变。客户端证据区分实际执行的协议、对象和返回片段与图形资源适配部分。

上线后实测本会基地和围墙入口，检查守护神和已放建筑、练习战斗、通关回城、途中放弃，以及组队双方回城。发布与实测状态记录在本地交接回执。
