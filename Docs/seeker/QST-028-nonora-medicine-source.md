# QST-028 诺诺拉任务的治疗剂来源

## 目标与成因

3347「把治疗剂交给诺诺拉」包含3425副本目标和3426交药步骤。治疗剂10164764由前置3346「惊讶的诺顿」消耗30个黑色小晶块、10个下级元素结晶后奖励1瓶；3426需要交付这瓶任务品。

匹配PVF的3091个任务中，该物品仅被3346奖励与3426材料条件引用。隔离测试使用原始任务、物品及经验表文本，执行正式接取、触发、领奖和交付入口：正常完成3346获得1瓶，3426扣药成功，3347可结算；无奖励完成3346后，3347仍可接取，完成副本目标后3426因缺药失败。此次复现将3425设为已完成，以单独确认交药阻断；其正常副本流程继续核对。

## 修复思路与范围

复用女王书信和小盒子的`storySourceRecovery`事务机制，新增明确关系3346 → 3347 / 3425、3426 → 10164764×1。采用独立一次性回执；新接取及旧活动任务重登时，来源为已确认的无奖励完成记录、后续仍活动且缺药，恢复1瓶。

在事务中重读任务与库存，核对来源奖励、父子关系、3425的`hunt enemy`类型、3426的`seeking`条件及物品类别。库存与回执共同提交，先发送库存op14，再发活动任务op574。正常领取过来源奖励、已有治疗剂、已交付或已有恢复回执时保持原状。

修改范围为新增治疗剂领域配置与入口、bridge接线及回归测试，复用既有共用实现。女王和小盒子的回执键、API及行为保持。文档与变更记录随本项更新。

## 测试目标

1. 正常3346消耗30/10材料、奖励1瓶；3426只扣1瓶，3347可结算。
2. 两种无奖励完成标记：新接取3347及已有活动任务重登各恢复1瓶；3426正常交药、父任务结算、重登保持。
3. 重复与并发只发一次；背包满、库存或回执保存失败回滚，重试可完成。
4. 已有物品、正常来源、来源未完成、已交付、已有回执、错误角色或定义不匹配保持原规则。女王与小盒子回归通过。
5. 原失败场景修复前失败、修复后通过；常规小夹具、完整领域/bridge/control/list/vet、Windows/Linux构建与相关race通过；匹配完整PVF专项按串行窗口执行。

## 验收目标
