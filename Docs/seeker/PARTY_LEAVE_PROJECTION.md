# 退队后清理角色的所有会话投影

已复现主连接正常退队、中央队伍成员删除后，同角色辅助连接仍返回旧队伍缓存。入场检查因而继续把已退队角色判为非队长。

修复目标：中央队伍状态与主/辅助会话一致。成员退出、队长退出、两人队解散、踢人均使离队者立即按单人查询；剩余成员保留当前队伍与队长。旧连接的清理不能覆盖角色重连或新组队后的状态。

主要入口为 `party_manager_runtime.go` 的 `clearRuntimePartyProjection` 和 `runtimePartyStateForSession`，结合会话注册、角色代际及当前中央队伍记录。复用既有锁顺序与权威队伍管理器，保留尚未迁入管理器的合法初始会话处理。

回归从真实退队分发器执行，断言中央记录、主连接、辅助连接及入场访问器，覆盖重连、重新组队和过期连接。对原复现做修复前失败、修复后通过，并执行既有退队与管理器测试及 race。

实现同时失效当前主连接及同角色活连接的缓存。目录代际、队伍快照和投影写入遵循既有锁序；重新组队后的新投影保持。一人大厅仍保留在中央管理器供再次邀请，角色端缓存按该次快照清空。辅助连接在中央查询未命中时跟随当前主连接投影，保留尚未迁入管理器的既有兼容路径。

原失败场景、队长离开、踢人、两人队解散、重新组队、旧连接及并发查询/失效通过定向与 race 验证。当前正式 V174 保留既有 kind3 退队记录上下文补丁；本次不增加客户端修改。客户端退队画面、原生入场提示和聊天分别验收；本项直接覆盖服务端已复现的缓存残留。
