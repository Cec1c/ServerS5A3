# 公会专属地下城入口疲劳

六张公会专属图 8500/8504/8507/8505/8503/8508 的 DGN 声明 `[use fatigue only start dungeon] 8`。旧解析将它当成无值标志，入场及换房仍每次扣 1；修正为读取整数，在入场时每人扣 8，同一场后续换房、重复首房和回执重放不增耗。

## 事务与接线

- 解析保留历史无值标志形式；六图必须有有效整数费用。普通图沿原逐房 1 点规则。
- bridge 从真实准备结果取得同场成员、绑定当前会话，并在权威队伍快照与成员地下城锁下调用公会领域。
- `CommitDungeonEntryFatigue` 在专属四人事务中重新验证会籍、加入时间、净化周期、目录摘要与解锁条件；从锁内角色记录刷新每日疲劳，保存所有人的余额及永久场次回执。
- 重放先验证回执，再读取已提交余额；首次恰好耗尽 8 点后，恢复运行时仍可重放。相同场次的费用、成员或定义不匹配会被拒绝。
- memory 与 MySQL 共用既有公会锁顺序，普通公会事务仍限制两名角色；专属设置访问只包含公会登记与本场回执。提交后标记所有准备运行时，避免逐房及每日次数路径重复扣除。

## 验证与验收

自动验证覆盖 1～4 人成功、零余额重复及并发重放、第二/第四名成员失败、回执失败、最后一次身份校验失败、会籍/周期/目录变更、余额锁内重读、06:00 刷新、会话替换、队伍退出/换队长以及普通图逐房行为。一次性 MySQL 库检查四人后段回滚、并发提交与重建连接重放；匹配 PVF 提取的六图检查实际费用声明。

游戏内验收：单人及同会四人进入任一专属图，完整通关每人总耗 8；换房和重复请求不再扣，重新进入新场再扣 8，余额与疲劳通知一致。测试及源码交付状态记录在对应 MR；上线后按此清单实测。
