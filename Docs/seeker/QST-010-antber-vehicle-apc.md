# QST-010：天界载具与剧情 APC

一条反馈包含南门乘车、根特防御 APC 出场后不能跨房、追击歼灭战尼贝尔出场后的白色对象。已验证下列相邻任务链的真实地图、死亡与清房；“南门乘车”尚未唯一对应到任务，白色对象的原生表现继续调查。

## 基线与定位

代码基线为 QST-007 `f9d35b1`，协议 `official-24.9`，真实 PVF SHA256 为 `fef4f46f6c3096d10cd88c84579dea8bd4fffa18e5a75b4684a2e920864f5525`。本项只增加回归与调查文档。

| 流程 | 任务和地图 | 真实对象及结果 |
| --- | --- | --- |
| 南门“奇怪的兵器” | 父3525、末子3560；副本82、迷宫2、地图92247 | 友军AIC10448与6只61801。清怪后可过门到92250，末子completed、父active/2 |
| 防御战巴比伦 | 任务3538；副本89、迷宫3，任务目标92342，剧情对象房92334 | 敌对10409及两名友军；复用007的真实ACT/CMT销毁与过门回归，友军保持 |
| 追击歼灭战大决战 | 任务3553；副本85、迷宫5、最终图92472 | 尼贝尔10449、Boss65502与dummy/boss63821；两个报告顺序均可清房；未覆盖全图条件和最终交付 |

南门各迷宫没有随机载具脚本，不能套用北门61235 AT-5T的成因。北门首次载具生成及入口由004处理；操作316报告仍缺服务端接线。原生state2发送后立即本地上车，不等待应答，不能仅凭缺少handler认定它是上车失败原因。

63821在真实PVF中为`[dummy] [boss]`，当前投影actor type为3。它确实存在于尼贝尔最终房，但这不证明它就是玩家所见白色对象。当前证据没有复现模型、染色或原生画面异常。

进一步读取原始内容：南门92247开场CMT2208仅包含表情、方向、对话及角色移动，没有骑乘指令。追击92472还包含泽丁27014；CMT2238为尼贝尔移动/台词、镜头及Boss对话，没有销毁行为。dummy63821位于`(1384,-351,0)`，其Stay/Last/Proc动画全部使用alpha0；原始资源意图为透明对象，不能据此删除该实例来修复“白怪”。

死亡剧情另有完整收尾：吉赛尔65502的MOB引用CMT2239；该剧情先销毁MONSTER index0（show1），让两名APC移动，最后销毁MONSTER index1（show0），分别对应吉赛尔与隐藏对象63821。隐藏对象四个AI均只return -1，销毁来自剧情而非自身攻击逻辑。

3553实际条件为`condition under clear / subtype11 / 85 -1 -1`，原文要求消灭所有房间敌人。仅以smoke路径到最终房清怪后仍active/1，不能据此认定任务进度故障。

## 验证和解决思路

新增`seeker_qst010_story_test.go`读取真实任务条件、迷宫、怪物与AIC定义，走正常任务接取和副本准备。中间房以既有smoke helper定位目标房；目标房使用真实对象键和生产死亡处理器。

南门和追击各覆盖三种报告：空贡献脚本报告、当前友军对象键、`ffff`加真实录包结构的友军贡献。dummy保持脚本报告语义。检查op38、权威死亡、清房、南门过门和任务状态。报告次序是受控测试次序，不推断客户端实际战斗顺序。防御战沿用007的单独真实剧情销毁回归。

后续方案：北门316/296契约与再生研究见[独立方案](QST-004-ridable-lifecycle.md)，当前证据不支持新增即时再生规则。QST-010继续围绕实际NPC/怪物的原生类型与资源定位，确认错误后修改投影或交PVF-Writer调整资产。

补充实际回包验证：在累计服务端上正常接取对应任务，提取地图92247、92334、92342、92472的真实op29响应；匹配V128客户端执行对象行读取循环及构造器普通字段赋值。四个包分别包含7、8、15、4行，共34行，均按每行21字节消费且与服务端字段一致；四个截断样本在严格读取桩中拒绝。

追击包中尼贝尔10449为index0/level70/type5，泽丁27014为index1/level70/type5；两个怪物65502和63821均level73/type3。没有出现APC读成普通怪物或相邻行错位。此验证替换了包基础拷贝、向量追加与加密整数存储，未执行APC实例化或绘制；它排除这四个包的行宽/字段错位假设，不构成白色对象已修复的结论。

按CMT内容顺序补测吉赛尔先、隐藏对象后，三种报告形状全部通过。吉赛尔死亡时，现有Boss清房逻辑已同时标记63821并发出两条op38；后来的63821报告只重放op38。当前服务端不会因这一顺序留下阻挡；原生剧情与自动清房的画面配合仍由游戏内实测核对。

## 测试与验收目标

- 自动验证：真实任务选图、对象阵营、三类死亡报告、op38、清房与任务状态保持；原生316研究给出准确字段及发送/消费条件。
- 正常游戏：不用完成券依次接取任务；南门观察机关师、战斗和过门，北门单列上车/攻击/下车/重进；防御战观察剧情目标离场和清怪后过门；追击清完所有房间，记录尼贝尔首次出现、白色对象、吉赛尔死亡剧情和最终交付。
- 失败记录：注明任务名、所在房间、单人或组队、当前客户端版本和现象。完成券绕过不计本项验收。
