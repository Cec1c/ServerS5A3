# 街头与公会擂台邀请边界

V179 成员菜单的街头挑战和公会擂台分别发送 op10 mode 4、13。现有通用 peer 处理器错误转发 NOTI7；接受后把双方加入普通副本队伍。当前修复在邀请阶段返回原生挑战失败，阻止这种错误状态变化。完整街头／公会擂台玩法仍待实现。

## 客户端证据

客户端 SHA256：`72254abd5214bc24f8bcb76a16184e07105dde33f4e762b4c71c2e264bc7789c`。

- 菜单 key 25、180 经 `036B8960` 选择 kind 0、1，确认后 `036B78E0` 发送 op10：`u16 target,u8 mode,u32 0,u32 0`。
- `023D2780` 接受发送 op11 value 1；`023D2820` 拒绝发送 value 0。`023D2980` 的取消与超时复用拒绝发送器，重复更新只发送一次。
- 正确邀请通知是 class 0 / 443 → `036B92C0`（目标弹窗 0x155）、444 → `036B91A0`（发起人等待弹窗 0x156），均读 `u16 peer,u8 mode`。原 NOTI7 → `02035F40` 打开通用 0x169 弹窗。
- ACK10 失败必须是 `0,error,mode,u32 value`，ACK11 失败必须是 `0,error,mode`。两字节通用失败会让客户端继续越界读取。错误 3 的 ACK10 显示“您挑战失败了”；错误 133 关闭两侧各自的挑战弹窗。

## 最小修复

仅 `official-24.9` 的 mode 4、13 在成功 ACK、邀请登记及通知之前被明确拒绝。已有 pending 请求按绑定角色和会话代次消费，接受、拒绝、取消、超时均终结为原生拒绝；重复或伪造应答不产生回包。普通副本队伍、交易模式与其他 profile 沿用各自处理路径。

现有 `currentPVPRoom` 是决斗频道的房间 owner；op44/45 开始以及死亡、结算均受决斗频道和房间条件约束。不能把街头挑战接到普通队伍或任意决斗房间后返回成功。完整实现需独立承担邀请过期和代次、参战队伍快照、街头场景与观察者、UDP 端点、开始/死亡/结算/回城，以及公会擂台资格和规则；这是跨领域状态机工作。
