# 完成副本回城的 op42 确认

完成副本使用完整城镇路由返回：动作表、城镇对象、带装备的角色绑定、任务快照及 typed op24。该路由成功后原先直接退休运行状态，遗漏玩家 op42 请求的成功确认，客户端物品使用等待标志可能继续保持。

目标是在已有路由成功边界补齐 class1 / command42 的单字节成功体 `01`。已保存的请求 ID 拥有确认；op72 返回和请求 ID 为 0 的队伍跟随路由不产生 op42。完成路由的退休、队伍处理及宠物时钟沿用原边界；活动副本放弃仍等客户端城镇证据，随后确认并放弃。没有新增客户端或 PVF 依赖。

## 当前客户端证据

批准模块 DNF.exe：111812608 字节，SHA256 `26abf551753c2745c2e5b349fb24336422a189187ff847c995e0df9a68871079`，x86，首选基址 `0x400000`。

| 位置 | 静态 VA | RVA | 已验证语义 |
| --- | --- | --- | --- |
| command42 注册块 | `0x1FAC9D4` | `0x1BAC9D4` | 命令表初始化注册回调 `0x1FA5400` |
| 回城发送片段 | `0x2285202` | `0x1E85202` | 写 command42，无额外正文，发送后经 setter 置等待标志 |
| command42 回调 | `0x1FA5400` | `0x1BA5400` | 获取当前角色，向 setter 传 0，无额外正文读取 |
| 等待标志 setter | `0x2961A90` | `0x2561A90` | 写 `actor+0x8EE` |
| 等待标志 getter | `0x2961AA0` | `0x2561AA0` | 读相同字段 |
| 通用物品使用判断片段 | `0x2600280` | `0x2200280` | 标志为 1 则提前退出；否则继续写 command44 |

当前命令表工厂 `0x2524210` 使用全局 `0x56A3064`，初始化链 `0x2523F80` → `0x1FAC980` 包含该注册块。另一上下文的 command42 回调不能代替此证据。旧服务端注释的 `actor+0x8BE` 和旧回调地址不匹配本模块，现已更正。

隔离片段回放使用实际 setter、getter 和回调；角色查找及包输出叶子为显式夹具。它证明请求置位、物品判断阻止、确认清零及随后允许 command44，也覆盖重复确认和无角色分支。该证据不覆盖完整场景、网络、药水冷却 UI 或玩家历史个案。

## 实现与失败重试

必要生产文件为 `dungeon_return_town.go` 和 `dungeon_runtime_state.go`。运行状态新增一次性确认标志，重置回城尝试时清除。所有城镇输出成功后设置原 `townReturnOp24Sent`，补确认成功才退休；确认失败保留运行状态和输出进度。下一次请求只补未完成确认，不重放对象、op24 或任务快照。活动放弃共用确认守卫，已成功确认后的内部失败不重复发送。

公开与累计必须验证：正式 op42 确认顺序及正文、完成 op72/跟随排除、输出失败和确认失败重试、保存的请求所有权、重复动作、活动放弃时机、原完成回城/队伍/宠物回归，以及真实普通卢克返回后的消耗品使用。源码检查、候选部署和玩家原生验收分别记录，隔离结算状态不能代替完整战斗验收。
