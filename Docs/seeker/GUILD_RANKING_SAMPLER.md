# 公会排名采样中的软删角色

## 成因与修复

账号角色列表仅返回未删除角色，公会会籍可能仍保留软删角色。原采样将名单与会籍数量不等统一视为角色缺失，导致一个软删成员阻断全服排名发布。

采样继续每账号读取一次活跃列表。对未在列表中的公会成员，按角色 ID 回读权威记录：只有记录存在、角色与账号归属均匹配且明确软删，才作为排除评分的事实保留。真正缺失、错属、活跃角色漏列和存储失败仍返回错误，保留原排名快照。

评分先验证身份，再排除软删成员的人数、周活跃、冒险团、决斗和团本分项及在线观察。公会会籍、角色数据、已有公会地下城和组队成绩保持；不生成上月历史。角色恢复后可在下一轮正常采样重新参与。

## 修改与验证范围

- `guild/ranking_sources.go`：补齐权威软删事实；不以列表缺席推断删除。
- `guild/ranking_members.go`、`guild/ranking_progress.go`：按有效角色计分与记录在线观察。
- 脱敏领域回归覆盖软删、缺失、错属、活跃漏列、读取失败、恢复及各分项。
- bridge 回归经过正式采样与发布事务，检查失败不覆盖旧榜、重试成功、会籍与角色不变。
- 外部提取表测试同时加载排名、六图目录与奖励表；私有快照回放使用同一生产入口。外部输入缺失明确跳过，不替代默认回归。

基线为大厅月榜候选 `a043d6de`。本项不改变客户端协议、PVF 或排名开关。自动化通过与部署、游戏内验收分别记录。

## 验证结果

旧代码在持久会籍包含软删角色时返回 `ErrCharacterNotFound`，完整提取表回放在成员采样阶段复现同一错误。修复后发布完整公会榜单，会籍与角色记录保持，人数及各成员分项与仅含活跃角色的独立参考结果一致。

默认回归覆盖成员、会长、全员软删，以及删除发生于列表读取期间、恢复、错误身份与存储失败。完整领域、bridge、control 测试、list、vet、专项 race 和 Windows/Linux 构建通过。提取表回放中的冒险团表使用既有测试夹具、在线状态置空，因此只验证该故障与发布契约，不作为运行环境的精确总分。

现有采样错误日志受 `packet_log` 控制。本项保持日志策略；关闭包日志时仍不能用缺少失败日志判断采样成功，应读回排名的 `sampled_at` 与行数。
