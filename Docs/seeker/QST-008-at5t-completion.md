# QST-008 AT-5T 上机与任务完成

## 目标与当前状态

正常接取3529「回收AT-5T步行者」，在北门任务迷宫靠近载具按Z上机，完成九房剧情后交付。

入口修复已上线。真实PVF的九房推进、终点报告、任务待领奖、结算与重复请求验证通过；用户反馈的按Z不上机仍在研究。场景遍历、载具更新、原生按键判定及本地角色独立input的生产链已有验证，当前调查动作设置、输入评估与载具读取的先后顺序。尚无新的生产修复候选。

最新复现表现为载具上方“技能(Z)”和蓝箭头可见，按Z会释放普通技能或做出动作，但不上机。原生提示绘制与输入判定分开：上机状态非零或交互锁开启时仍可显示提示。当前重点核对普通技能动作与载具上机资格判定的实际顺序。

原生验证复用了有限资源工厂、部分角色辅助方法与运行服务夹具。已闭合创建、登记、控制权及正常本地角色输入生产链；通用怪物更新、完整职业构造、硬件输入、顶层帧时序及实际驾驶属于后续范围。正常本地成员新绑定会创建独立input并注册角色描述符；角色字段为空时才回退全局input。优先角色指针仍指旧对象时，getter会继续返回旧对象，正常刷新后改指新actor；这是已验证反例，当前尚无现场值证明发生了该错配。

原始失败、替换点、完整摘要及脚本保存在私有调查记录。场景输入阶段42个代码/数据窗口、最终trace的7,061个地址及探索trace的12,445个地址处指令字节与V141一致；本地角色阶段另核对51窗口和13,295个记录地址，后者包含被替换函数的入口。V141在这两个阶段仅做静态比较。

交互状态补证在两个版本分别执行，所取代码/数据窗口一致。初始化片段用非零内存验证实际清零；提示检查止于坐标与渲染调用之前，保护动作解码值由夹具提供。`Common/Transports/zkey.ani`和`arrow.ani`属于独立引导动画，显示时没有检查距离或本地角色输入，不能据提示可见排除这些条件。

角色资格补证使用原生保护字段写入/解码及完整通用资格函数，应用上下文查询显式给值，止于上机副作用入口。其判定不会在动作恢复后留下永久锁。派生角色还可能检查扩展回调或职业状态；实际职业虚表及普通技能是否先改变动作继续核对。

本地输入驱动对象VirtualCharacter与实体角色分开。前者先处理joystick，再评估该角色input；后者更新时跳过本地input重评估，普通命令转入职业派生动作入口。动作设置尾段会关闭技能描述符使能，但已有state1仍可由载具连续读取；只关闭一次后的五帧按下/松开序列读值为0/0/1/0/1。设备采集和窗口间顺序由夹具提供，实际场景排列继续核对。

## 下一步方案

沿正常成员创建和载具登记，确定VirtualCharacter、实体角色、载具在场景数组中的插入与遍历顺序，并匹配实际职业的动作入口。若普通技能先改变动作再被载具拒绝，以同一帧回放验证最小交互入口调整；若载具在前，则查该角色的派生资格或具体输入条件。复用已验证的同一actor/input链，从首次不符处形成精确修复。

确认失败条件后做最小修复，并保留原失败与通过的对照。涉及PVF交PVF-Writer；涉及EXE先核对非fork上游最新Release及完整摘要，再由Syncer按Release/镜像、玩家实际更新源、依赖服务端的次序发布。服务端任务回归保留在`dnfbridge/seeker_northgate_real_pvf_test.go`及相关剧情测试。
