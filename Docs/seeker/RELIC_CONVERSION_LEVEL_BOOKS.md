# 魔法封印装备圣物转换书的等级系列

## 问题与成因

低等级使命任务发放的圣物转换书可以打开转换窗口，确认时被服务端拒绝。现有入口只接受转换类型17和20，分别覆盖Lv85、Lv90，遗漏同一规则的Lv15至Lv80转换书（类型8至16）。

真实资源中，Lv40～45转换书10149523为类型11，魔法封印链甲100080172的转换类型也为11，产物为100080461。配方消耗10149512碎片10、10099773稀有灵魂12、10100116高级灵魂24、10100115普通灵魂36。转换书上的`need material`用于生成书，不作为装备转换的额外材料。

## 修复思路

将同一魔法封印转换规则的类型8至17纳入现有事务，继续支持类型20。配方来自目标装备的完整`emancipate`块，转换书类型必须与其完全一致。输出绑定并清除强化、增幅、锻造和附魔，沿现有封印标志与271、14、14刷新顺序处理。

类型18传承转换、携带继承上限的书和装备等级成长属于独立规则，继续使用原拒绝行为。Lv85关于辅助装备、魔法石的排除保持。无需修改PVF或客户端。

允许修改：`equipment_emancipate.go`、对应普通/真实资源测试、本方案及`changlog.md`。允许执行失败；返回尝试方法、失败证据及所缺信息。

## 测试与验收

- 原代码对类型8至16的合法同类配方失败；修复后类型8至17及20均成功。
- 真实Lv40～45链甲使用正确材料转换，验证绑定、属性重置、消耗、回包和重复请求；Lv85、Lv90原案例继续通过。
- 不匹配类型、非法继承规则、材料不足、锁定与错误归属不改变角色和账号资产。保留原事务失败及发送失败回归。
- 完成仓库要求的领域、bridge、control、list、vet和构建验证。
- 游戏内使用Lv40～45书确认转换，检查材料与产物；重登后状态一致。自动测试和游戏内验收分别记录。

验证结果：原实现对类型8至16的合法配方全部拒绝，真实Lv40～45配方同样失败；修复后11种已支持类型、低等级拒绝边界、原事务回归及真实Lv40～45/Lv85/Lv90三组转换通过。领域、bridge、control、list、vet、转换竞态测试、Windows/Linux构建与仓库边界检查通过。未配置隔离数据库的条件测试按原规则跳过；本地部署预检缺少外部频道资产。游戏内转换与重登持久性待部署后验收。
