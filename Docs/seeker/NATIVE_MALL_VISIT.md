# 原生商城进入事件与战令计数

原生商城打开成功时原本没有发送服务端已识别的网页商城票据，因此每日进入商城任务没有计数。空 op63 也会在选角初始化、刷新余额及网页关闭时发送，不能用它代替进入商城事件。

本次在原生商城可见性检查通过、完成打开流程的状态转换调用处，发送 class 1 / op63 / 四字节 `MSV1`。共享状态设置函数保持，只有本挂接点且状态参数为 5 时追加通知。已经打开、打开条件不满足、其它状态及网络对象不可用时不发通知。普通空请求保留。

服务端仅对精确类别和完整标记调用既有账号绑定、事务及每日战令 kind 11 计数；所有请求保留原 Cera 查询应答。客户端不提供角色身份或计数量。

## 固定输入及构建

- 输入 SHA256：`30c936131e000bd7bc0940bfc1db1b902c84d92cd17ff1d8fbe28f62fbf91425`，112549888 字节，包含之前累计的团本及容器应答修复。
- 输出 SHA256：`f8d68484a8f4b7b25afa7692c6ba011aab67c6d1928952934057d570615ce646`，112549888 字节。
- 工具：`scripts/client/patch_native_mall_visit.py --input <累计输入> --output <独立候选>`。拒绝输入摘要不符、布局变化、占用的辅助空间或覆盖已有输出。
- 挂接 VA `0x197876e`，保留原目标 `0x243bd90`；辅助代码位于已有 `.bp0` 的空余区 `0x6f20500`。只改此调用、辅助代码、节有效长度及校验和；其它字节和来源通知保留。

## 验证范围

`scripts/client/verify_native_mall_visit.py --before <累计输入> --after <候选> --result <新回执>` 验证 8 组网络/状态组合、原版及候选的打开/已经打开/不可用 6 组路径、原选角与刷新发送仍为空、错误输入拒绝及 Windows 映像映射。实际执行原有接受条件、可见性赋值、辅助代码和共享状态设置；UI 构建/渲染、外部场景访问及网络写出是显式桩，未运行完整游戏。

服务端 `TestBattlePassNativeMallVisitSeparatesLoginQuery` 覆盖空请求、有效标记、错误类别、截断、未知版本、尾随字节与账号归属改变；验证计数及应答。正式发布保持最终客户端双端发行、玩家通道读回，再部署依赖服务端的顺序；离线通过不替代商城交互实机验收。
