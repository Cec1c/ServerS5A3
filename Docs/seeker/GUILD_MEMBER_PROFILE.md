# 公会成员资料与冒险团查询

## 目标与基线

在当前累计客户端上，公会在线成员跨场景、跨频道时可查看角色资料和冒险团。保留普通场景、队伍和攻坚队既有查询权限；离线、跨公会及已失效的成员身份不能借此读取资料。

源码基线为 `c8a529ba3b78d05aa3575e77553067822e11bf90`。本项已实现并通过专项验证，尚未发布或实机验收。

## 已确认的契约与缺口

- 角色菜单跨上下文发送 C2S819：`channel:u8, uid:u16, kind:u8, directory:u8`，kind 0 为角色资料，kind 4 为冒险团；服务端缺少此入口。
- actor UID 位于 +0x20；辅助角色的频道、目录分别位于 +0x604、+0x605。辅助缓存键同时包含三项，不能只按 UID 查找。
- 公会名单只按区服和名字查已有角色。没有可用对象时走名字菜单，缺少资料入口；必须同时验证名单到菜单的完整路径。
- 同号 class0/819 是名单通知，不是查询应答。回复应沿已核对的角色资料与冒险团原生接收路径，不能根据请求号编造布局。

## 实现范围

新增独立公会资料授权入口：严格校验请求长度、种类、频道与目录，绑定双方当前 canonical session、账号归属及当前公会成员关系；仓储读取完成后重新校验身份。保持原队伍/攻坚队授权函数不变，网络发送期间不持全局锁或执行仓储查询。

复用现有资料构建器、辅助角色缓存和冒险团投影。客户端如需调整，仅修复公会名单对象与菜单身份衔接；以最新累计成品精确移植，保留来源通知及此前售货机修复。

实现使用公会行的真实 UID、在线频道和运行目录建立 category-4 辅助对象，沿原菜单构造与请求分流；已存在的角色对象保持。查询回复为 mode8 缓存刷新及显式 mode3 资料、或 class1/1401 冒险团。冒险团使用已记录的登录天数与账号状态，不触发新的每日登录写入。

允许范围：独立公会资料 handler、授权与测试，命令分派中新增入口，必要的公会名单适配及原生验证脚本；复用资料/冒险团构建与发送工具时只作必要提取。

## 验证

1. 用匹配成品执行名单、菜单、实际发送和回复消费，保存旧版失败与候选通过的对照；确认 UID、频道和目录没有串位。
2. 覆盖跨频道及同频道跨场景、角色资料和冒险团、离线、跨公会、错误路由、过期名单、换角色/重连、成员退出及慢连接。
3. 运行领域和 bridge 完整回归、静态检查、双平台构建；数据库与游戏界面验收另记实际证据。
4. 独立提交并经上游 MR 集成；客户端发行和实际玩家通道先行，Syncer 串行部署依赖服务端，最后进行双玩家交互验收。

## 客户端工具与已验证范围

`scripts/client/patch_guild_member_profile.py` 只接受 SHA256 `5465ab19a41e51b2fd51d10be47a47bae6309d394321a1c298dc76bd61f3f478`，生成独立输出 `01b313275faf7b598211f4d8adb932e1b31ce4347827583a2df3cfa4d350e94c`，长度 111988736。该输入已累计售货机错误消费修复。工具只变更公会行入口、声明的 PE 字段及新增 `.gprof` 节；其它字节逐段核对保持。

```text
python scripts/client/patch_guild_member_profile.py --input <approved-input.exe> --output <new-candidate.exe>
```

原生验证使用 `DNF_GUILD_PROFILE_INPUT` 指向固定输入；Go 专项测试可通过 `DNF_GUILD_PROFILE_PACKETS` 导出真实名单、mode8、mode3 和冒险团回包，再运行 `test_guild_member_profile.py`。七项验证包括名单解析到菜单、旧版缺对象失败/候选通过、两类请求序列化、目标命名空间选择、冒险团完整报文消费和他人资料分支，以及离线/无效身份/分配失败/原对象保留/范围外字节。

对象分配、字符串和容器、保护序列化、资源与 UI 构造仍有显式适配器。资料选中正确辅助对象与冒险团进入他人窗口分支已验证；这些结果不代替实际 DirectX 画面、装备详情与双玩家点击验收。
