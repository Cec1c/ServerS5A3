# 裂缝领主奖励与组队过图一致性修复

## 目标与依据

时空裂缝终局领主先死亡、其他敌对对象尚存时，旧专属奖励分支依赖 cleared，而权威强制清房在该分支之后执行，导致保底碎片与成品抽取都被跳过。只修正当前客户端、指定裂缝副本、终局领主的奖励条件，保留物品池/概率、个人归属与死亡回执。

另一条组队过图故障会在队长提交目标房间后，发现队员没有提交同一目标/种子而把错误传到连接主循环。已用真实处理器复现队员请求夹在队长预检查与内部跟随之间：两次独立选种子使同一目标不一致，重复请求被本地拒绝后升级为连接错误。修复将目标种子在共享实例中固定；只有完全相同的实例、房间对象、访问缓存、成员和种子才视为已跟随成功。队员先到时队长可接续该已验证目标，未清房/错实例继续拒绝。

## 文件与验收

- 奖励：dungeon_combat_runtime.go 及裂缝死亡、归属、重复请求回归。
- 过图：dungeon_navigation_runtime.go、dungeon_party_move_preflight.go、dungeon_party_move_seed.go、共享房间状态与相关回归。
- 使用当前匹配 PVF 运行领主先/后死亡、队长/队员报告、死亡重放、双方真实回包及普通副本边界。
- 过图必须覆盖先到队员、交错请求、重复跟随、相同坐标但错误实例/种子、未清房与实际发送失败；同一目标使用同一权威房间和种子，不重复扣疲劳。
- 运行 Linux 专项、受影响服务验证与构建。源码验证、合并、部署和玩家验收分别记录。

## 已覆盖的场景

真实 PVF 专项覆盖普通领主房 80303/80304 与特殊领主房 80290/80296。含小怪的房间分别验证领主先死、队友先上报，以及双方重复报告后的个人奖励和回包；单领主房作为对照。合成回归无需外部 PVF，固定保底数量并校验重放不增加奖励。概率与碎片数量仍使用原配置。

过图回归覆盖队员请求在队长预检查之前、之后到达；校验只发送一次开始房间通知，拒绝错实例、房间、种子、成员或访问缓存，并验证往返旧房间保留种子与死亡状态。保留已合入的队友房间同步代次更新。
