## 成因与对象身份

`worldmap.FreezeRandomizedObjects` 只接受 `[regenerate] 0`。北门普通迷宫声明 `[select] 1`、`[regenerate] 99`，对象61235、neutral阵营、房间(3,1)、坐标(216,240)。因此进入普通迷宫时在随机对象预检被拒绝，主线券只是使角色离开无此对象的剧情迷宫。

Helper 已使用同一真实 PVF 补充取证：`monster/monster.lst` 的61235指向 `monster/NewMonsters/Riding/at_5t/at_5t.mob`，名称 **AT-5T 步行者**，显式类型 `[monster object type] [ridable object]`。同号 `passiveobject.lst` 指向 `ActionObject/Monster/Anton_Quest/Phase3/Meltadoroc/move/move.obj`，名称“移动诱导物品”。两个命名空间不能互换。

当前 bridge 已有“同号 MOB 明确为 ridable 时优先 MOB”的分类逻辑；真正提前挡住本例的是领域的 `Regenerate.Value != 0`。因此不是缺少模板，也不是主线券漏写任务。

## regenerate 语义的证据强度

当前 Go parser 保留原整数，没有把99解释成计时或次数。为核对历史字段含义，另对一个带符号的历史 `df_game_r` 做了只读、从完整函数入口开始的有限静态分析，摘要为 `1a25bc91cc447081eadf2bdb70e5b27b6bef2f217788343a6d6b555b20eb2d77`：

- `ImportDungeonScript` 的 `[regenerate]` 分支读整数后执行 `test / setne`，保存布尔值；该参考实现中的99等价于true，不是99秒或99次。
- `CRidable::SetRidableObject` 冻结选择，将该布尔值存到run owner，并令初始对象状态为4。
- `CRidable::CheckAppearRidableObject` 仅在匹配房间且“状态4，或状态3且允许再生”时产生对象，把状态改为1；它没有每次重新随机选择，也没有99次循环。
- `CRidable::SetRidableObjectState` 仅接受已有可转移对象的状态变更。历史操作dispatcher有读取状态与对象ID的路径，说明再生依赖对象生命周期，并非每次入房都无条件生成。

以上证明的是**该历史实现的非零再生开关**，不能直接作为V124当前协议契约。历史dispatcher应答编号317，而当前源码枚举为316；历史生成函数写四个整数，当前START_MAP行写五个整数，禁止直接搬用旧包布局或编号。

本次V124 SHA256为 `eaa2485609fa9cc2c9ca99fadd743b5206a37b5517dd07d195eb35b3c0a29d50`。有限静态字符串定位未找到这些原始标签；没有运行客户端、重做大型REA全量导入，或取得该客户端的载具状态写包函数。当前版本中状态3的准确业务名称、状态回报编号/布局及重访消费路径仍待证明。

## 生命周期边界

基线的 `worldmap.RandomizedObjectPlan` 保存不可变选择与来源摘要，bridge补充模板namespace和faction；候选新增 `SelectedRandomizedObject.Regenerate` 保留真实再生字段。run owner尚无对象存活/占用/销毁状态。当前仓库检索到 `CmdPacketOperateRidableObject=316` 枚举，但没有对应专用处理器。

首次房间完整START_MAP通过 `roomGroups()` 下发五整数：`x,y,ObjectCode,Faction,SpawnMode`。现有分类对本例产生 `61235 / faction0 / spawnMode0`，这些是当前Go构造结果，尚未做V124载具画面验收；不能把99填入第五字段。

`buildCurrentDungeonMoveStartMapBody` 的缓存重访分支只写16字节mode0包，未设置 `RidableGroupCount`，因此是0；完整build/refresh分支则重新取不可变 `roomGroups()`。单独删除regenerate门禁既没有对象状态转换，也没有已销毁对象再生判据，不能据此报告完整载具支持。

为隔离下游分类，本次只在测试内深拷贝解析后的Dungeon，把副本88各99组临时改为0：现有owner能按正确房间生成61235的上述字段，并且该owner被实际99来源的签名校验拒绝。这是**反事实诊断对照**；没有修改PVF或生产代码，不能当作“99已支持”的验证。

## 给用户的实测步骤

由Seeker/Syncer确认候选上线后执行，使用配套V124/fef4。已有角色通过任务券绕过只说明任务状态，不算本项实测通过。

1. 使用已完成北门主线的角色，或67级使用主线完成券后的角色，进入根特北门普通难度；确认进入实际地图。再测可选择的其余三档难度。
2. 在普通迷宫走到小地图(3,1)的AT-5T房间。确认只出现一台步行者、位置正常、不会被同号“移动诱导物品”替代；尝试上车、攻击和下车，分别记录结果。
3. 不销毁载具，离开该房再返回；检查载具是否仍在、是否重复、能否继续操作。随后销毁载具再往返一次，单独记录能否再生；再生尚未实现为服务端权威状态机，该项失败归后续单元，不和入口通过混记。
4. 有活动北门剧情的角色按任务正常进入：3528应走无载具maze1；3529、3530、3533分别检查(0,0)、(0,1)、(0,1)载具房和剧情推进。任务2957可用时比较低于难度2与难度2/3的迷宫选择。
5. 有两人时补测队长/队员看见同一台车、分别尝试操作、离房重访；没有两人则记录组队未测。
6. 每项反馈角色名、服务器时区时间、难度、当前任务、卡住的步骤和截图即可；由维护者按时间关联入口/换房日志，不要求玩家自行抓包。
