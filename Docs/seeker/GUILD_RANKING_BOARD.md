# 公会月榜与大厅排名板

大厅排名板和公会面板使用两条协议。CMD1503返回本公会108字节评分模型；CMD1504返回月度公会列表，大厅前三名也消费后者。只有1503可用时，NPC排名板仍缺少数据。

匹配V171摘要 `c962e82d2258e15edb0ac372f1a4e3b58a1360ee53192201720f723302be5409`。原生1504发送器为 `029836C0`，大厅初始化发送器为 `02983710`（正文 `01 00 01 00`）；回调 `01FB5A70`读取列表后调用 `02986EB0` 更新前三名，NPC绘制入口 `02987680`读取对应缓存。列表行固定72字节，公会ID、名次与float32点数独立。接收门控由累计客户端适配单元统一处理。

实施目标：复用真实持久月度快照和既有排名采样，在同一会话身份校验下接通月榜查询与前三名响应；按原生字段、分类与分页编码。仅选取实际存在的已结算月份，不以本期预计分数补造上月成绩。无历史、空榜及公会已经解散的情况须有明确边界。

涉及领域 `guild/ranking`、bridge公会路由及排名报文，另补匹配客户端的有限原生消费验证。先证明请求和原缺口，再对新增handler覆盖排序并列、空榜、缺月、月界、会籍与会话，使用正式handler报文驱动原生模型。排名页单独验证108字节的各项getter和进度计算，确认门控恢复后是否还需要独立改动。

## 实现范围

- `MonthlyRankingBoard`读取紧邻上月实际快照，按原名次、公会ID稳定排序；删除已解散公会但不重排名次。完整月榜保留所有并列项；大厅每个名次只容纳一个公会，因此同名次选择最小仍存在的公会ID。例如1/1/3在大厅占第1、3槽，第2槽为空。
- 默认列表 `00 00 page:u16` 每页5条；大厅 `01 00 01 00` 最多3条。角色必须属于当前账号和当前会话代；未入会角色也能查看公开榜单。查询不采样、不改变积分、玩家资产或持久快照。
- 成绩来自上月，公会名、会长、徽章和人数来自当前公会目录；旧快照不含历史名称。字符串以客户端编码按字符边界截断，固定字段保留NUL。
- 分类filter1..8尚未建立各分类分数/名次的服务端契约，本候选返回失败。72字节row中的12/13与70/71保留原生零初始化，未将未确认字段映射成加入权限。申请/跨区分类行为不属于本次显示验收。

| row偏移 | 字段 |
| --- | --- |
| 0 / 4 / 8 | u32公会ID / u32名次 / float32点数 |
| 14 | 徽章byte |
| 15 / 38 | 公会名char[23] / 会长名char[30]，含NUL |
| 68 | u16当前人数 |

响应success后为kind:u8、未使用头字段:u16（0）、count:u16与72字节行。原生先读出该头字段，后续不消费，不能用它声称已实现总页数。

## 空榜与排名页

缺上月、上月零分或公会已解散时，不制造历史成绩。**成功空榜在V171大厅仍显示“正在统计……”**：原生回调清空三个ID，绘制分支选择DSTR100002202。该文字不能区分未加载与已加载空榜。新服当月没有上月快照时，这就是原生预期；本单保留文案，不改PVF。角色页上月名次/分数仍为0，原生按未排名处理。已有真实上月成绩后显示对应公会及分数。

排名页108字节布局无需更改。匹配报文经完整`01FC0E70`写入模型后：`02983420/02983460`分别读取各月名次和点数，`011A931D`读取当期总分；`011A7D60`的9个分类从对应float字段截断整数，7个有上限的类别把当期整数与上限送入进度控件。上月分数仅影响历史标记。实际采样的2成员得分0.2经原生显示为0，不能由空条直接推断未收到数据。

## 客户端依赖与验证

`patch_guild_board_v171.py`仅接受四项公会接收补丁的累计输入SHA `e1e78b6792e4d22ddae10e502d5b40555fb7a5f657f185578992eaefbe1348d4`。在已有接收段新增38字节定点助手，只增加class1/1504，其余回落既有D400→D300链；保留原生发送器、回调、显示代码和所有其他段。输出SHA `9886866b28aef3ab6f97789fca9ba09b359b499735e7a80b3ca0ac6d08041060`。它是独立后续候选，不能替换为原V171再叠加而漏掉四项累计补丁。

Go测试覆盖真实路由、月份边界、并列/分页/缺月/解散、无会籍和错误身份、非法请求、只读性及多字节终止。修复前原生初始化请求在真实guild dispatcher返回handled=false；修复后得到成功空榜。

原生测试用Go处理器导出的报文执行完整1504发送器/接收器、前三缓存setter及1503模型复制和getter；分类运行到实际进度控件调用，空榜执行真实绘制选文案片段。替换边界是socket读源、STL分配/迭代器/字符串辅助与UI资源；未启动图形客户端。门控完整类别/操作码矩阵只改变class1/1504，ABI、精确字节差异、checksum、只读Windows映像映射另验。

复现方式：运行Go `TestGuildRankingBoardSettledPacketsReadOnlyAndExport`，以`GUILD_BOARD_WIRE_OUTPUT`指定JSON输出；设置`DNF_GUILD_BOARD_CLIENT`为上述累计输入，安装Unicorn后运行`test_guild_ranking_board_native.py`和`test_patch_guild_board_v171.py`。最终游戏画面与实际点击留给后续实测，服务端部署须先满足对应客户端发布顺序。
