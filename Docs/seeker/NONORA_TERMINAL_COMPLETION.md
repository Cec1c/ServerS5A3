# 诺诺拉末子任务交付进度

## 成因与目标

3347 的剧情子任务 3425 已完成，末子任务 3426 持有治疗剂并处于 active/0 时，父任务仍按未归档子任务数量保存为 active/1。旧来源修复解决缺药；旧结算测试直接调用父 op34，能扣药领奖，但没有验证按钮能否发出该请求。

匹配 V164/V166 客户端的完成入口 `0x01CAAF40` 先调用 `0x01C98510` 读取活动任务进度，非零直接返回。末子任务会转向父任务，再经过同一检查；parent=1 因而阻断此入口的请求。活动快照 op574 原样恢复这个数值。有限原生执行覆盖完成入口、转向与 sender，进度 getter、目录查询及网络出口使用显式夹具；原始反编译和现场快照留私有证据。

补充实测：普通重登未恢复，完全退出客户端后成功交付，后续主线也已完成；成功回执确认治疗剂只扣1瓶。本轮投影候选尚未发布。完整重启与同会话的刷新差异仍待核对，验收重点是同一运行内无需大退完成交付。

本轮静态输入 SHA256：V164 `2d56c7086c3fd9bc029d932571504b7f89147e47f1d563684f74b9e467f4f8a2`；V166 `0e16090f0e4e3ac830f70183c814f5b24724cec235935e6c1221bf2d865d4243`。以上地址是这两个输入的 VA。

目标：正常剧情结束后立即发送父任务可交付进度；重登读取同一持久状态时保持相同投影。点击完成通过现有父任务结算消费一瓶治疗剂并关闭父子任务。

## 最小方案

以现有任务目录和已提交任务记录生成活动任务协议投影：父任务为 quest clear；前面的必需子任务均已完成；最后一个子任务属于该父任务、为无独立奖励的材料子任务且 active/0。此时仅在发送投影中把父进度置0。原持久记录和子任务状态保持，材料消耗、奖励与完成回执继续由现有 ApplyFinishSettlement 原子提交。

两种活动快照入口均接入：已提交记录直接发送、重登或主动刷新从仓储读取。目录不可用沿原投影；先用持久任务类型检查活动 quest-clear 父任务，再加载目录。缺少类型的旧记录保持原投影。使用真实目录确认父子关系和材料要求，不按单个任务ID放行。

## 测试与验收

1. 正常领药、接父任务、材料子先置0、剧情子type16并op34结束：收到父0/材料子0；不额外伪造父op33即可发出父op34，药品仅扣1，父子结算完成。
2. 同一持久卡点新会话刷新也发父0，投影不写数据库、不提前扣物品或发经验；重放保持现有幂等性。
3. 前置子任务未完成、末子进度非零、错父关系、非材料/有独立奖励子任务、普通任务、缺目录及缺状态均保持原投影。States与Progress按既有主记录优先级处理。
4. 实际缺药时正式父结算仍失败且资产不变；原缺药恢复和材料子任务结算回归通过。
5. 原生有限执行以服务端下发的两组父子进度复现旧版未发请求、修正投影后发出父op34。最终结合匹配PVF只读定义核对，不以完成券验证。

游戏内验收：正常来源角色从剧情入口一路完成，全程不退出客户端；治疗剂减少1、父子任务关闭、后续主线出现。另测旧卡点重登后的交付。源码、部署和实机分别留档。
