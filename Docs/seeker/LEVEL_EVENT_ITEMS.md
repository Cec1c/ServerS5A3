# 升级活动赠品使用修复

分类：功能修复。公开基线：`65a72c14d9007251af95549a0d640a94fb4d972b`。

## 已确认缺口

- 圣物防具盒的 26 字节五件套请求仅允许一个旧活动物品编号；同结构的新活动盒被拒绝。
- 银质金库工具的 PVF booster 奖励 110 是容量效果，不能当作普通物品生成。
- 物品栏扩展券发送 op430、u16 源槽，目前没有处理器。
- 灵跃永久兑换券发送 op515/action88，尾部为 u32 目标容器及 u32 目标槽，目前未实现。

当前客户端与资源摘要分别为 `534b5ef166d0090d1ab88e01f5f443721abf97eabfacfb007e04e30fd9d51b24`、`95147859374186dbeb99f998829a1c642f949e56942ac98be8b5af4492aefe1c`。原始日志与汇编只留本机私有证据。

已核对的客户端位置使用该模块的 RVA：`0x020A5DF0` 写 op430 与 u16 源槽；`0x01D29BF0` 附近写 op515/action88 的目标容器与槽；`0x020F3580` 为 action ACK 读取器，88 没有额外成功字段，消费分支返回真。op430 未登记专有 ACK 读取器，容量与道具状态使用已验证的 class0/op13；金库使用 class0/op66 子类型 1 的容量通知。

## 实现范围

1. 紧凑礼盒按实际 PVF 的完整五件防具类别验证，保留选项、材料、到期及库存事务检查。
2. 容器工具使用既有账号/角色/背包/settings 事务，原子扣券并更新容量；已有更大金库不能降级，背包不能超过客户端合法扩展量。
3. action88 校验真实源券、背包目标及 PVF 配对映射，在事务内更换装备模板、清除到期时间并扣券。保留强化、锻造、品质与绑定状态；限时武器说明明确要求转永久时删除附魔，沿用该规则。使用原生 ACK 及槽刷新，替换模板时先清除旧客户端对象。
4. 协议适配放 bridge，资金和物品规则放 inventory 领域；不修改玩家资产、PVF 或 EXE。

## 验证与验收

覆盖真实赠品、错误物品/类别/目标、过期与锁定、容量上限、重放、事务回滚和客户端回包。使用实际 PVF 的可选集成测试，完成仓库要求的 Go 验证和构建。

专项已验证两期活动背包券 `490008261/490009309`、金库工具 `490008262/490009310`、圣物盒 `490008265/490009313`，以及永久券 `490009319` 的全部 37 组映射。没有改动资源；所有新效果使用既有资产事务。

代码验证、公开合并、群服累计、部署和游戏实测分别留档。部署准备完成后由 Syncer 接续；正式服切换需要本次维护确认。游戏验收检查开盒五件、容量立即更新及重登保持、永久武器强化与锻造保留且按说明移除附魔。
