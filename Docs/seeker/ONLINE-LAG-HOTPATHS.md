# 多会话卡顿中的静态配置重复解析与属性写放大

分类：功能修复。基线：公开 master `d8fa0b99`。


补充日志同时出现选角、副本与周期签到慢处理。短窗只读指标显示大量短查询和属性写入、连接池等待及 CPU 压力；未发现能解释全部长延迟的单条 SQL 或持续行锁等待。

两个可独立验证的开销另行修复：

- 资产事务遗漏已有的角色属性差量保存。复用同事务完整加锁快照，只写变化属性，保留无快照、历史影子属性及二次保存回退，以及永久事件回执。
- 普通签到的启用检查、结算及定时器重设反复加载同一 PVF 配置，包括完整 stackable 列表解析。按 Service 生命周期缓存成功验证的目录，与周签到现有方式一致；角色资格、签到日期和领奖仍每次走事务。失败/取消不缓存，初始化并发串行化。

允许修改上述资产事务入口、普通签到目录缓存字段与加载方法及对应测试。通过真实 PVF 比较热调用分配量和并发复用，通过独立 MariaDB 核对差量与全量最终行及回滚。上述候选分别提交，性能改善范围以专项测量为准。


## 测量与限制

- 真实 PVF 基线：重复加载普通签到目录约 450210 次分配/调用，四次热调用约 358 ms。缓存候选热调用为零分配，四次约 0.43 ms。该数值是独立 Linux 容器的配置读取专项，不是整服请求延迟。
- 真实隔离 MariaDB：80 个无关属性下，单计数 INSERT/DELETE 从 84 次降到 2 次；删除属性 83→3，永久回执 84→3。持久化角色记录等价；晚期失败完整回滚；二次保存保留原回退。
- 普通签到每轮刷新中的启用检查、结算和定时器重设都会查询目录。复用的是同一进程的静态 PVF 结果，登录账号、角色状态、日期、等级资格、领奖回执和邮件事务均继续实时处理。
- 现场存在多系统慢处理和大量短 SQL；本次修复两处已复现开销。完整上线效果需要在相近在线负载下复查请求延迟、SQL量、连接池等待与分配速率。
