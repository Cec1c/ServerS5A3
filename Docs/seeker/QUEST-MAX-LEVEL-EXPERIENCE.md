# 满级任务领奖的等级上限与挑战者经验

## 目标与成因

DNF90 角色上限为 90 级。90 级角色领取任务奖励后应保持等级与 SP/TP，满级后获得的经验按既有 HonorExpert 规则进入挑战者进度。

任务领域的 `planFinishProgression` 使用无上限循环，只检查经验阈值与下一等级的 SP 表行。真实 PVF 包含 91 级阈值与 SP/TP 数据，因此足够高的累计经验会让任务结算写入 91 级。副本结算已经显式限制到 90 级。任务结算同时缺少 HonorExpert 推进。

真实 PVF 的任务 2941「向着传说出发」是支线见面任务，基础经验 829,380，成长契约加成 165,876。90→91 阈值为 1,961,802,808。阈值附近领取奖励可复现越级并多发 270 SP、1 TP。原累计源码与新版累计源码、新旧 PVF 均已复现。

## 解决思路

1. 给任务结算传入可信角色等级上限，默认沿用本项目 90 级；bridge 显式传入兼容 profile 已使用的上限。升级循环到上限即停止，原经验奖励计算与 uint32 溢出检查保持。
2. 在原任务结算事务内计算满级后经验：使用 `honor.CalculateHonorExperienceGain` 的阈值分割和 `Tables.AdvanceExpert`，与角色、技能、物品和任务完成回执一起提交。89→90 只计越过满级入口的部分；90 级领奖全部进入挑战者。零经验任务保持原状态。
3. 持久回执记录本次 HonorExpert 增量及结算后状态。重复提交返回原回执，旧回执按原内容重放，不补发历史经验。
4. bridge 按需要装载 Honor 表，在挑战者状态变化时发送既有权威状态刷新。保留任务 ACK 的顺序和同会话重复抑制，避免额外经验奖励。

关键入口：

- `go-server/internal/modules/dnf/quest/finish_owner.go`
- `go-server/internal/modules/dnf/progression/experience.go`
- `go-server/internal/modules/dnf/honor/honor.go`
- `go-server/internal/services/dnfbridge/quest_finish.go`
- `go-server/internal/services/dnfbridge/current_honor_expert.go`

## 测试与验收

- 90 级累计经验接近或已超过 91 级阈值，领取 2941 后仍为 90 级，SP/TP 与同步等级保持；挑战者经验准确增加一次。
- 89→90、一次奖励跨多个等级并触及上限、主线倍率 1/3、成长契约及经验药组合，验证奖励与满级经验分割。
- NoExperience、零增量、挑战者最终等级、非法已有 91 级状态和缺少必要表分别覆盖。
- 重复领取、换倍率后重放、旧回执、后置物品失败和存储失败，验证幂等及完整回滚。
- bridge 覆盖领奖 ACK 与权威等级/挑战者状态刷新；完成三倍经验原回归与新旧真实 PVF 回归。
- 实机：90 级角色领取有经验任务，观察等级保持、挑战者进度增加，重登一致；89 级角色正常升到 90。

已经越级的历史角色按单独的数据修复方案处理：核对原回执、当前技能消费与挑战者状态，再通过有事务和审计的修复入口调整。功能补丁不在登录时静默回写历史角色。
