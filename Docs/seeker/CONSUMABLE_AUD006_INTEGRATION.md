# 消耗品审计成果的累计集成

分类：功能修复。

本批接收既有消耗品审计成果，覆盖金库与背包扩容券、容器奖励语法、水晶之光城镇效果、固定疲劳药来源校验，以及装备礼盒的固定强化、锻造和随机强化概率。只接收精确功能差异，保留现有升级活动赠品、永久武器转换和任务销毁通关修复。

## 实现与边界

- 扩容复用账号、角色、背包与容量事务，按 PVF 及库存授权；扣券与容量保存原子完成。
- 容器奖励沿用既有开盒事务；奖励语法、选择元数据与装备实例投影一同核验。
- 城镇药剂与疲劳药校验来源期限、锁、会话和使用条件，失败回滚。
- 随机强化读取运行 PVF 对应类别的概率表，255 仅作随机标记。
- 积分卡、塔推荐书、随机疲劳及尚未证明语义的礼盒保留显式待处理状态，不将保护性拒绝统一改为放行。

修改集中在 `internal/modules/dnf/{cargo,inventory,fatigue,alignedcmd}` 与 `internal/services/dnfbridge`。不改运行资源或配置。

## 验证与验收

对新累计源码重新运行逐 ID 真实 PVF 回归，覆盖成功、重放、期限、锁、会话、回滚、装备119字节字段保留和随机权重边界；同时回归已有活动赠品和任务销毁通关。执行领域、桥接、控制器、vet、构建及仓库边界检查。保留原包与新输入各自摘要，不把旧源码的测试结论当作新累计验证。

扩容券 op408/op430 的原生 ACK 依赖客户端 class1 接收许可；集成时必须核对最新累计客户端，并在依赖服务端上线前完成兼容客户端发布与玩家通道读回。源码合并、资源发布、服务部署和玩家实测分别记录。
