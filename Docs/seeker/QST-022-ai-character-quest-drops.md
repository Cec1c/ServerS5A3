# QST-022 山之泪：APC任务物品掉落

## 目标与成因

任务2949要求在利库天井取得物品10164883。真实任务定义指定敌人类别2、APC323、副本42、难度1或2，每次一件、100%概率、持有上限1。

当前任务掉落器只处理普通怪物与类别1的`enemy reward item`。已接收的APC死亡未进入类别2掉落分支，因此该任务物品没有发放入口。普通怪物等级/首领标记与任务敌人类别属于不同字段，沿用现有怪物类别1。

## 研究与解决方向

先用现有内存仓储、真实定义的最小文本和房间APC注册建立失败回归，走正式死亡处理入口。确认APC323被接受死亡后库存仍缺少任务物品，再从权威APC记录取得类别和代码接通掉落。物品发放复用既有库存事务、任务槽位和库存增量更新。

新增路径需要按房间对象与角色去重；数据库失败可重试，重放不多发。普通怪物掉落保持原行为。任务提示刷新复用既有物品条件同步。

## 文件与测试目标

入口为`dnfbridge/dungeon_combat_runtime.go`、`dungeon_monster_runtime.go`、`dungeon_quest_drop.go`及相关测试。正式死亡入口已复现，接入以`HostileReference.Kind=ai_character`和权威`AICharacter.Code`作为身份依据。

- 合法APC323死亡应发一件10164883；使用当前代码记录实际缺件的失败断言。
- 普通怪物同码、未知对象、错误副本或难度、未接任务、已持有物品均不新增。
- 后续实现验证重复死亡、跨房重放、保存失败和重试，最终正常交付只扣一件。
- 本项针对物品来源；反馈中的再次挑战副本跳转另查实际选图链。

允许失败。返回已尝试方法、失败证据、修改文件及需要确认的问题。

## 正式入口回归

当前代码成功提交敌对APC323死亡并发送死亡确认，普通同码怪物仍在场，任务物品数量仍为0。六组对照通过：普通怪同码、未知对象、错误副本、错误难度、未接任务、已经持有物品。

实现时把任务物品事务放在死亡确认之前；已死亡重试路径继续处理尚未成功的掉落，事务成功后记录本次角色/副本/房间/对象的回执。重复请求仅刷新确认，不重新投骰或发物品。使用权威对象记录解析APC，普通怪物路径保持类别1。

状态：类别2掉落候选已通过正式入口专项及当前真实PVF的两种难度正常链。测试从完成前置2948开始，正常接取2949、按真实迷宫7移动到APC323房间，由正式死亡处理器发物品；再模拟客户端条件回调，正常交付扣1件并领奖4件10149512，重复死亡与领奖均不增加数量。路途清房由既有烟测辅助函数输入，未预写目标任务的待领奖状态。
