# 租赁武器引导任务推进

## 问题与依据

任务 8581「尝试租赁幸运星武器」要求确认租赁职业武器。当前定义路径为 `n_quest/common/chn_system_10_starpoint_guide.qst`，类型 `[custom quest]`、`[int data] 1 0 1`，接取后的剩余计数为 1。玩家反馈租赁装备已入包，任务仍未完成。

基线 `3b242e13ed16c5aa1871fbeed79f5b2d90c631f1` 的租赁成功路径只提交幸运星和装备，随后发送租赁回包、余额、背包；没有推进任务。原租赁事务不含任务仓储。现有 `CharacterSettlement` 在同一事务中提供账号、角色、任务、背包和装备，内存与 MySQL 均已实现。

只解释这条已核对定义的租赁目标；`custom quest` 其他数据组合的含义留给对应功能调查。

## 方案

1. 用真实定义建立接取→租赁成功→任务可交付的失败回归。
2. 在任务领域识别该路径、类型及数据组合。有效租赁提交时，将已接取任务的剩余计数从 1 改为 0；保持 active，奖励继续走原交付流程。支持已有 States/Progress 投影，保留其他任务和元数据。
3. 租赁领域复用 `CharacterSettlement`，把扣点、装备新增/续租和任务推进放进同一提交。普通购买幸运星、过期清理沿原规则。未接取/已完成/已达标任务不产生任务变化。
4. 桥接层传入当前任务定义，在事务成功后重置本任务的客户端触发重放缓存并发送现有任务快照；保留租赁回包、余额、背包原顺序。发送失败可通过重选角色恢复已提交状态。
5. 对这条已由服务端租赁确认的任务，客户端 trigger 仅回显已提交计数，不能代替租赁或将其重新递增。

## 修改范围

- `go-server/internal/modules/dnf/quest/rental_guide.go` 及专项测试；`quest/owner.go` 的该任务 trigger 分支。
- `go-server/internal/modules/dnf/rental/owner.go` 及专项测试。
- `go-server/internal/services/dnfbridge/gameplay_module_rental.go`、`rental_asset_projection.go`、`quest_trigger.go`、现有租赁测试和新增租赁引导专项（含隔离 MySQL、真实 PVF）。
- 本方案及 `changlog.md`。

优先复用现有事务，不新增表、不改 PVF、EXE 或部署配置。需要扩展文件范围时先将依据写入结果。

## 测试与验收

- 接取真实结构的 8581，成功租赁后点数扣除、武器入包、计数归零；可通过既有交付领取一次奖励。
- 未接任务、已完成、计数已零、其他 custom quest 保持各自状态；重复成功续租只执行原租赁扣点/续期语义，不重复发奖。
- 点数不足、满包、归属不符及事务后段失败：点数、装备和任务共同保持原值。
- 客户端伪造或重放 trigger 不代替租赁；提交后快照计数为零，发送失败不回滚已提交资产，重读能恢复。
- 完成仓库要求的领域、bridge、control、list、vet 与构建；真实数据库测试使用隔离库并单列结果。
- 游戏内：接取任务、选择职业武器并确认租赁，任务即时变为可交付；交付后重登，装备、余额和完成状态一致。

执行者允许失败：返回尝试方法、失败证据、当前修改和下一步所需信息。
