# QST-026：问答任务答案与后续分支

## 目标与成因

普通 NPC 问答应保存玩家选择，正常完成任务，并开放与答案匹配的后续任务。当前任务触发解码把答案字节转成 `IsIncrement bool`：答案 1、2 均变成 true，并按普通触发增加剩余进度。答案前置条件 `PreRequiredAnswers` 目前一律返回不满足，完成问答也无法进入后续分支。

匹配客户端的普通问答回调发送：

```text
op33: u16 33 | u16 questID | u8 0 | u8 answerID
op34: u16 34 | u16 questID | u16 FFFF | u16 1 | u16 FFFF
```

答案位于 op33，op34 的奖励选择仍为 FFFF。`[question info]` 的前两段是问句，后续文本依次是选项；普通 NPC 对话为它们分配 0 起的编号。

| 问答任务 | 选项 | 已核对的分支条件 |
| --- | --- | --- |
| 3868 | 0 联合调查团；1 冒险家联盟；2 暴戾搜捕团 | 3870 / 3871 / 3873 分别要求答案 0 / 1 / 2 |
| 3869 | 0 冒险家联盟；1 暴戾搜捕团 | 3872 / 3874 分别要求答案 0 / 1 |

两条问答互斥，3868/3869 各自以 3867 为前置。后续分支仍须通过等级、职业、碰撞任务等既有资格判断。

## 协议与定义证据

客户端 SHA256：`8de790c1974fe74d3b74ec6095b7281ea337759a4adcdfebdd874bf67a94126f`。以下为 preferred VA，复用时先匹配完整摘要。

- `039FE1E8..039FE2DF`：`[question info]` 两段问句与后续选项的解析分流；选项进入任务字段 `+6E4`。
- `01CBC0F0`：普通 NPC 问答构建，核对类型及 NPC，选项编号从 0 递增；`01CBC39E` 调用 setter 将任务 ID 写入对话框 `+794`。
- `034A5910`：读取选中行的 ID。`01CC23A0` 回调在普通模式下通过 `01CC262D` 写 op33，再调用 `01F006B0` 写 op34。
- `01CC0CE0` 和 `01CBC430` 属于批量问答路径，单独使用模式字段和批量命令；本项覆盖正常 NPC 问答。

4 项答案报文测试及 3 项解析/UI 构建有限原生测试通过。执行了选项编号、容器插入、选择 getter、回调和 writer；文本解码、UI 资源分配、迭代器及普通模式初值由夹具提供。完整 UI 生命周期与批量问答尚未验证。

## 解决思路

1. 保留 op33 原始值及是否存在该值；普通任务继续使用既有增减语义，问答由任务定义分流。重放键保留原始答案，使 1、2 可区分。
2. 从 `[question info]` 解析有效选项数。领域 Owner 校验任务活动状态、触发通道与答案范围，在既有事务边界保存明确的答案元数据并将剩余进度置 0。答案 0 必须与“没有答案”区分。
3. 同一活动任务首次有效答案持久化后保持；相同答案重试幂等，修改答案不覆盖已确认选择。放弃后重接使用新任务状态。保存失败可重试，发送失败不重复修改状态或发奖。
4. op34 沿用正常奖励事务，保留答案元数据。问答完成资格要求有效答案，完成券或旧完成记录中没有答案时不推测选项。
5. 单对 `[questionID, answerID]` 前置依据已完成任务及持久答案判断。可接列表、直接接取和关联任务选择使用一致条件；未确认的复杂格式保持不开放。

主要入口为 `quest/request.go`、`command.go`、`catalog.go`、领域问答 Owner、`finish_owner.go` 及 `dnfbridge/quest_trigger.go`。公开基线包含现有任务领奖与书信修复，独立工作树实现。

## 测试与验收

- 正式 op33→op34 入口分别选择 3868 的 0/1/2，以及 3869 的 0/1；答案持久化、进度归零、奖励只结算一次。
- 重建 Owner/会话后答案保持；3868 的 0/1/2 分别只开放 3870/3871/3873；3869 的 0/1 分别只开放 3872/3874。答案未提交、缺失、越界、错误通道与碰撞任务不满足资格。
- 普通非问答任务保持原增减进度。重复报文、存储失败回滚、发送失败重试与完成回执覆盖原事务行为。
- 匹配 PVF 核对任务定义、选项数与后续资格，并执行仓库要求的领域/bridge/control、list/vet 与双平台构建。
- 实测：正常接任务、对话选择阵营、提交并重登，检查只出现对应分支，再正常接取后续。

执行者允许失败，返回尝试、失败证据、当前修改和需要确认的问题。

## 实现与验证结果

原始答案已接入领域Owner，以角色结算事务保存首次选择；op34保留答案并正常领奖，后续任务使用同一份持久答案判断资格。普通任务继续沿用原增减规则。

三答案原失败回归已转为通过。复核另发现并修正缺答案短请求的越界及并发选择覆盖：两个不同答案同时提交时仅一个成功，另一个返回冲突。事务内保存失败回滚、同答案重试、放弃重接和发送失败重试均通过。

完整领域、bridge、control、list、vet、race及Windows/Linux构建通过。匹配PVF的五组正式接取→选择→完成→后继接取通过：普通职业三选分别进入3870/3871/3873，女鬼剑两选分别进入3872/3874。该回归使用真实等级、职业过滤及碰撞定义；3867完成记录为隔离前置。部署与正常客户端对话按交付记录继续验收。
