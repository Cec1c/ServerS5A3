# QST-NNN：问题标题

## 目标与基线

- 目标：一个可观察的结果。
- 基线：源码 commit / tree，所需 EXE / PVF 完整摘要或公共版本索引。
- 状态：调查中 / 可执行 / 执行中 / 待复核 / 自动验证通过 / 待实机验收 / 已验收。

## 现象与成因

用简短段落写触发步骤、预期/实际行为、已确认成因及关键代码位置。有未确认前提时写清验证它的方法。

## 解决思路

给出主要改动方向和必要的数据/事务/协议约束，让执行者选择实现细节。列出允许修改的文件或模块；环境、工作树和原始证据通过私有派工单提供。

## 测试目标

- 原失败场景：输入、预期结果，适用时证明修复前失败、修复后通过。
- 相邻行为：与本次问题相关的正常路径及一个关键边界。
- 命令：实际目录、定点测试；交付前按仓库 AGENTS 完成所需检查。

## 验收目标

明确用户在任务接受、推进、完成、重登后能观察到的结果，以及事务/重复请求等本项必要条件。列明自动化覆盖和仍需游戏内观察的部分。

## 执行交接

允许失败。返回完成/部分完成/失败、修改文件、验证命令与结果；失败时附关键证据、已尝试方法和需要 Seeker 确认的问题。完整日志放指定证据路径。

## 结果与依赖

记录实际实现与验证；需要 PVF-Writer / Helper / Syncer 时给出具体输入和期望交付。公开提交、同步、部署和原生验收分别记录。
