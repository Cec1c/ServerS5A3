# 公会展示读路径隔离与贡献汇总

分类：功能修复。基线为公开 master `3fdee192`。

公会名册逐人加载完整角色，贡献展示又在公会写事务内遍历全部历史结算回执。前者占用角色事件队列，后者持有全局注册表和角色锁，可将一次展示请求的等待传播到其他结算与资产操作。

修复采用只读一致性快照，统一读取会籍、请求人身份、成员轻量资料与贡献投影；MySQL 使用主库的 repeatable-read 只读事务，不执行锁行插入或 FOR UPDATE。角色资料按分片批量查询，只读取名称、等级、职业、成长及删除状态，保留权威列与历史兼容开关。

成员保存本次会籍的公会副本贡献汇总，结算在原事务内同时更新，红包榜直接减去该汇总，不改变旧贡献总分及其他消费者。新会籍从零开始。历史成员启动时在只读快照内补算，释放快照后以原注册表值比较更新；发生并发修改重新取快照，不能覆盖结算或离会操作。正常列表不进行历史扫描或保存。

验证覆盖旧失败路径、191/1000人成员批量查询次数、写事务与只读快照并发、离会再入及重复结算、历史汇总幂等与竞争、跨分片一致性、删除和账号归属、原生回包和完整 Go 验证。上线另记录首次补算、实际运行摘要、查询时延和锁等待；未捕获的其他卡顿来源不归入本修复验收范围。

数据兼容：新字段 `dungeon_contribution_points` 属于成员会籍；缺失表示需要补算，显式零表示新会籍。副本跨月重置不清空该累计值。原有 `contribution_points`、货币、物品和历史回执均保留，不新增数据库表或索引。回退旧程序后若旧程序重写注册表并丢弃此字段，再次升级会重新补算。

启动补算只对缺字段的公会执行历史读取，读阶段没有写锁；完成后用注册表原值和更新时间比较更新，最多三轮。非法历史数据或持续并发冲突会让启动失败，沿用部署健康检查与二进制回退，不能删除回执或覆盖玩家进度来放行。首次启动耗时应在实际发布回执中单列。

本地定向验证已证明：双分片的191人与1000人投影均为两条角色SELECT；同一测试恢复旧处理函数后，六个展示入口失败，候选全部通过。隔离MariaDB中，展示快照保持打开时公会写入和并发副本结算均能提交，快照内资料不变，下一快照读取新值。真实数据库专项通过 `DNFBRIDGE_PLAYER_TEST_DSN` 指向一次性测试库运行，未配置的环境明确跳过。
