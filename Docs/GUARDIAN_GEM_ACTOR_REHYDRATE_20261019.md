# 守护珠在完整角色重建后恢复

## 行为

勋章的四个守护珠字保存在穿戴装备的 0x77 原始行中，位置为 +101、+103、+105、+107。完整 mode1 装备创建行不携带这些字。初始登录已有补发，但场景提交后的登录重建、入图后的完整装备重建、城镇返回等独立完整重建路径没有再次补发，因而新对象缺少持久守护珠数据。

在这三条完整 mode1 之后，只对穿戴槽 32 且至少一个非零镶嵌字的勋章，发送一条 class0/op14、list3 的权威原始行。mode1 创建时从已有装备读取中保存这一行的值副本，随后一次补发，不重复读取装备或容器。新投影先清理旧候选，其他角色的投影不覆盖本地候选，换角不发送旧行，发送失败保留同一行供重试，成功后消费。宠物、称号与 Buff 换装已有顺序保留，错误按既有调用链返回。城镇返回通过通用完整 mode1 helper 覆盖；没有新增持久存储、客户端补丁或属性求和规则。

## 选图边界

主动打开选图页及默认的被动队员选图保留城镇 actor；默认队员接收 op15、op36、op27。兼容队员转换路径的 mode1 仅绑定角色，装备 create/update 均为零。因此本修复没有在 op27 之前增加勋章更新，也没有为了守护珠额外创建角色。

回归从登录重建继续走实际主动选图，并覆盖默认被动选图、兼容被动选图及正式组队入图。正式入图要求 op27 → op28 → op29 → 完整 mode1 → 槽 32 op14，且只出现一条对应的守护珠更新。主动/默认被动选图维持现有 actor 与仓储装备。这些协议测试证明补发边界；报告中的原生 UI 显示及属性数值仍须分别验收。

## 原生指令证据

匹配当前客户端 SHA256 `26abf551753c2745c2e5b349fb24336422a189187ff847c995e0df9a68871079`，静态地址为 VA，映像基址为 0x400000：

- VA 0x2596510：仅在装备描述槽为 32 时清理列表，逐个解析四个 u16；零保留为空，非零按有符号 16 位值加 89999 转为物品编号，再写入列表、缓存及原始字存储。
- VA 0x255ee40：返回上述编号列表。VA 0x2563420、0x2563500 遍历非零编号，查询物品、解析效果资源，并进入两个效果应用虚调用。
- 635 次 setter 指令回放覆盖活动 PVF 的 52 种守护珠、四个孔、重复应用、清空、存储聚合形状及非勋章槽。434 次 consumer 指令回放验证编号依序进入物品/效果解析及应用调用，空孔、场景门禁和缺资源不调用效果。

回放隔离了容器内存分配/插入、资源查询、效果应用叶函数及场景门禁，验证这些边界的参数及调用次数。未执行完整网络分发、渲染或最终属性数值计算，不能据此宣称游戏验收。服务端 userinfo 基础属性块不额外叠加守护珠，避免与客户端效果重复计算。

## 测试和限制

真实资源固定为 PVF SHA256 `a56cacf96087ba34ca5299e04ab65f8268f694b214b97dec9879fdebf46f5290`。测试勋章 100380058、宠物 400990167，以及四种不同属性的二级守护珠 90002/90012/90022/90032 均由该档解析；字值为 3/13/23/33。角色账号归属、宠物实例序号及存储键保持一致，控制测试确认夹具能通过现有生产投影。

禁用三处补发调用的基线验证三条完整重建缺行、登录重建后实际选图缺行、正式组队入图缺行；夹具投影/归属/真实资源和两种无完整装备重建的选图控制通过。另测同一快照值副本、失败重试、其他角色投影、换角、重复消费和新投影清理。完整回归保留原外观刷新读取次数限制；首次按仓储重读的候选超限，最终使用创建时快照解决，没有放宽测试阈值。候选需通过全部专项、完整领域/bridge/control、vet、构建、BAT 无数据库预检和边界检查后，才能作为验收候选。

本项不清理历史重复镶嵌、不改守护珠唯一性事务、不手工更改玩家资产。源码验证、累计部署和玩家原生验收分别记录，未验收前不关闭原问题。
