# 可选地图完整定义缓存

本提交依赖基础内存优化提交中的紧凑地图Token与PVF缓存释放API，应先合入基础提交，再合入本提交。它只改变完整地图定义的保留策略，不修改PVF或地图/奖励规则。低内存流式预载属于第三个独立提交。

## 启动参数与默认行为

默认不开启，保持全量地图预载和完整定义常驻。通过官方控制器/BAT启动时显式设置`DNF90_MAP_CACHE=on`；直接启动游戏程序时设置`DNFBRIDGE_MAP_CACHE=on`。控制器不透传任意继承的`DNFBRIDGE_*`，所以两种启动方式的变量名不同。用`off`关闭；切换需重启服务。本提交不在运行中热切换已发布的地图目录。

```bat
set "DNF90_MAP_CACHE=on"
call deploy\windows\control.bat start
```

启用后仍在启动时解析校验全部地图、建立相同路由及教学索引，然后只保留普通地图路由元数据；完整定义按当前PVF读取、解析和克隆。普通LRU受128张及估算16MiB双重限制，复杂地图按脚本复杂度/大小评分保留，估算总预算64MiB。阈值和预算由`DefaultMapCacheOptions`声明，当前不是额外的环境变量。这些预算是定义缓存的估计量，不是进程或整机上限。

## 读取失败与入场资产

Resolver、普通和深渊读取链传播真实缓存读取错误，避免将损坏/缺失资源误当成不存在而换用其它地图。完整地图及本次运行时准备成功后才调用既有PVF票据消费器；读取失败不提前扣票，不建立可玩的半成品运行时。材料、数量、事务及奖励保持原实现。关闭策略时保持原票据消费位置。

## 成本与适用范围

多人分散刷图时，不同队伍的活跃地图可能超过预算，淘汰后需要重新解析；不能假设所有人集中刷同一张图。PVF归档字节已在内存，下层命中文本/解压缓存时可复用，但完整MAP解析、临时分配和GC仍有成本；它是内存与CPU/冷读延迟之间的取舍，不保证所有负载更快。

本策略只在全量预载之后释放定义，因此不解决全量预载期间已经出现的启动峰值。2GB专项的流式预载及PVF有界缓存另行贡献；`GOMEMLIMIT`仅为Go软预算，不能代替该实现。需要按真实资源和分散进图负载观察命中、淘汰、读取错误及进图P95/P99，不能把单人实验写成多人容量保证。

## 验证

单元测试覆盖预算/淘汰、import、返回值隔离、复杂地图保留、并发读取、显式开关及读取错误。真实PVF专项逐张比较公开地图字段、路由候选和顺序；完整服务依赖回放比较首次、命中及淘汰后进图、加载完成、过门、回城重进和疲劳拒绝，并保留读取失败不扣资产/成功仅扣一次的断言。
