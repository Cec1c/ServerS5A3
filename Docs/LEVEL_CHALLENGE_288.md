# 国服升级大挑战 288

旧活动 222 调用历史韩文预约窗口。该实现增加独立活动 288，使用现有 PVF 中文创建选择页和升级大挑战面板；活动 288 与旧 222、116 互斥，默认关闭。

- `event/createeventcharacter.evt` 控制创建名额和职业。配置兼容手动选择和名额规则；当累计PVF开启自动参加标记时，活动生效后新建的普通角色自动登记，不受旧账号一次名额限制。旧角色不补资格，决斗专用角色不参加；未启用自动参加配置时保留原手动模式及名额规则。
- `event/eventgift.evt` 的 `[level up reward]` 需明确指向活动 288。主奖励 10 档、额外礼包 21 档、邮件标题正文均从 PVF 读取。现用主奖励累计 300，按达成等级自动发送邮件。
- 可调整上述档位的物品、数量和递增等级；当前原生界面固定 10 个阶段、21 个礼包，服务端会拒绝不匹配的行数及累计数量溢出。
- 登记加入既有角色创建事务，名额、角色及初始资产共同提交；发奖邮件与账号持久回执共同提交。重复选角、升级同步及并发重试不重复发奖，换角后失效会话拒绝结算。
- 活动时间沿用移植活动策略中的 `LevelAiming` 窗口，默认长期开放。资源中的历史日期或宣传图仍属 PVF/UI 文本，不随服务端时间设置自动变更。

当前客户端契约：op5 创建名字之后第 8 个选项字节为 288 参与标记；class0/815 同步已创建数和活动角色的零基显示序号（是显示序号，不是角色 ID，也不是 SQL 槽位）；class0/816 同步参与标记和满级主奖励数量。原生 0x36C45C6 把当前显示序号传给 0xEA1E40 匹配名单。816 第二字段用于 `max_level_reward_count`，不是角色 ID。没有复用旧 689 目标领取协议。

op5 普通创建的第 7 个选项字节为 0xFF（旧明文请求兼容 0）；它不表示决斗创建。第 9 字节由 0x36C3650 重复读取客户端选中值，未启用决斗时也可能保留非零值。普通模式忽略这个值，不据此改变转职或等级；其余冲突模式仍拒绝。

首次选角及创建、删除后的角色表刷新，都在角色表之前下发 815，使客户端绘制角色标记时已有最新名单，名额变化无需重新登录。实际登录/返回选角使用 `GET_USERINFO` 入口；普通及固定 15/16 封包均在角色表之前同步目录和 815 名单。独立角色表发送器不能代替该入口的验证。普通旧角色的 816 参与标记为 0，原生城镇活动图标按此标记隐藏；在新建时通过当前自动或手动规则登记后显示本角色活动。

选角确认后、进入首场景前另外发送只读 816 状态，覆盖新手地下城先行、尚未初始化城镇在线时钟的路径。此时不结算邮件；升级发奖保持原事务入口。调序及删除后 815 显示序号随新的角色表重算，账号报名记录仍按角色 ID 持久保存。

源侧历史验收针对创建资格、事务回滚、邮件幂等、状态字节及现用 PVF；原生窗口、创建入口、达级邮件和重登需另行实测。288 客户端接收许可与游戏 EXE 补丁不在服务端文档范围内。
