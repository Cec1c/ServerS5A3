# 选角初始化的读取期限

选角入口使用已有的 `currentRepositorySnapshotTimeout`（15 秒）完成角色解析、绑定后的权威记录复核和初始化读取。`createWriteTimeout`（3 秒）继续用于独立写入事务。

此前两个选角入口共用 3 秒写入期限。`bindGameSessionCharacter` 会同步持久化公会在线观察并刷新在线成员；其中一次独立的 3 秒处理就可能耗尽外层选角期限。后续改名保护重新读取角色时收到 `context.DeadlineExceeded`，于是清理刚建立的绑定并发出 op7，客户端再次请求选角名单。退回时的公会观察又可能等待 3 秒，形成约 6 秒后返回选角的表现。

修复保留绑定后重新读取角色的顺序，以及账号、槽位、名字和待改名状态检查。读取失败仍拒绝进入，并用固定原因码记录超时、取消或仓储故障；日志不保存角色名字或原始报文。

回归使用同一选角入口、会响应取消的角色仓储和独立公会期限：原实现约 6 秒后发出 op7，修复后在公会处理结束后发出正常选角响应。另覆盖 legacy 入口，以及账号、槽位、名字、待改名、记录缺失和读取失败的拒绝边界。

公会成员刷新仍同步执行。这次调整解决选角与短写入期限共用的问题；成员刷新成本需要单独测量和优化。客户端按钮在失败后是否恢复、实际进城及新建角色页面须在发布后用原受影响会话复测。
