# 守护珠属性唯一性

同一勋章的不同孔位此前可装入同一守护珠，也可装入同属性的不同品级守护珠。op829提交层虽然解析了被选守护珠，却丢弃属性族；raw socket写入前没有检查另外三个孔。现在按真实PVF的enchant属性族检查非目标孔，重复属性拒绝，来源数量和勋章保持不变。

## 规则与边界

固定a56 PVF SHA256为 a56cacf96087ba34ca5299e04ab65f8268f694b214b97dec9879fdebf46f5290。52个flag gem分为13个属性族，每族4个品级；所有文档均明确相同属性无法重复装备。唯一性比较使用PVF解析的属性族，不按名称、ID区间或品级猜测。

正式class1/op829入口要求来源位于list38守护珠页，目标为实际穿戴勋章。原有角色物品事务内先校验其它孔的属性，再写raw和扣减来源；领域Owner保留原来的背包/装备原子保存。目标孔不参与重复检查，保留既有占用孔替换和只消耗新珠的行为。

当前编码沿用既有119字节物品行、offset101的四个u16和ID基数89999。其它孔空值0跳过，非空值还原ID后由同一PVF catalog解析；无法解析的旧值拒绝，不猜测其属性，不自动删除或替换历史资产。此检查阻止新增重复，不清理已存在的重复。

成功回包、失败日志、目标装备行和list38刷新保持现有流程；不新增op829 ACK，不改变客户端、PVF或物品布局。本变更只处理重复装备，选图后显示或属性丢失另行跟进。

## 验证

同一组正式提交/handler回归对照基线与修复，基线允许同ID及同属性不同品级的重复，修复后拒绝且来源与目标raw不变。真实a56矩阵覆盖52个守护珠及全部4个目标孔：208次跨孔同属性拒绝、208次目标孔替换、208次不同属性成功，共624次隔离资产事务。合法事务只改变目标socket字节并消耗一颗来源，额外覆盖无法解析的旧孔拒绝。真实目录及list38路由、原有穿戴/替换/来源定位回归一起运行。

发布前要求完整领域、bridge、control、规定vet、Windows构建、BAT无数据库预检和服务边界通过，真实PVF专项不得把资源跳过计为通过。源码、部署与玩家实机验收分别记录；隔离内存仓储回归不代表原生UI验收。候选保持Draft，验收环境与回滚回执另行保存。
