# 2017劳动节随机称号附魔

问题收集2第116段反馈礼包宝珠不能用于礼包称号。当前PVF的14颗拨云见日宝珠（490700960、490700964..490700976）为 `[auto enchant]`，通过 `[random title enchant]` 指向配置10001..10014；不是带怪物卡片ID的普通宝珠。目标白名单恰为街道迷影400330094、塔楼迷踪400330096、宅邸迷云400330101。旧解析要求 `[monster card id]` 或 `[enchant index]`，返回零卡片后直接拒绝。

新分支读取当前归档 `etc/randomtitleenchant.etc`，按正权重选一条真实结果，禁用行不参加抽取；缺配置、全零权重、溢出或损坏行均拒绝。随机规则与怪物卡片混合、非auto-enchant、无明确称号部位或白名单的模板也拒绝。背包内称号的附魔与扣一颗宝珠使用现有背包事务，锁定、过期、数量异常不修改资产。仅支持脱下的背包称号，当前分支不开放穿戴目标。

结果用两个u16保存：配置号和行号。当前v115 `op14`在0x2025B74读119字节行并交给0x2436FE0；0x2437CA1把raw+0x61的四字节复制到内部记录+0xAB，0x27E12F4/0x27E130A分别读取两个u16并传入0x3DB0620。故使用raw+0x61/+0x63及对应Extra双键，不将随机结果伪装为怪物卡片。普通与随机附魔互斥，额外维护raw_entry_hex缓存；从Extra合成的行与原始行使用同一投影。

mode1创建不携带raw+0x61..0x65。在登录、角色重建、装备变更、入图及完整容器恢复后，仅对已有随机附魔的穿戴称号补发当前list3/op14完整行。重放复用mode1创建时已读取并映射的同一条装备快照，限定当前角色、成功发送后消费一次，不再读数据库，也避免按actor槽再次查找旧数据库槽号。无附魔称号及其它装备不补发此包。

协议和数据依据为当前PVF SHA256 ad7d05c70421278f7385729bcba3e81e37d99d0f3df85a87a9f0dc19c92504cb、preview v115 EXE SHA256 72a18ad4a109778135a80281760ba8e8c367a1b25fa099f6591a0601e4181f01。工作区参考源码提供已有随机附魔结构，移植时按当前源码边界与上述原生指令独立核对，未替换EXE/PVF、未改历史玩家资产或GM系统。

验证回执另存本轮工作目录。原生指令夹具只执行字段复制及调用方传参，虚函数取记录被stub，未执行GUI、表查询或实际游戏。内存端到端及数据库失败注入也不代替用户实机验收。验收可先脱下三种称号之一，使用对应宝珠，确认只扣一颗；重新穿戴、进出图、小退重登后核对随机技能及等级仍显示，普通附魔覆盖时旧随机效果应被替换。
