# v141 异次元入场计数通知与离线接收候选

匹配已发布 v141 完整模块 SHA256 `26abf551753c2745c2e5b349fb24336422a189187ff847c995e0df9a68871079`，111812608 字节。本文更正旧说明中“812 不是次数”的结论：该通知确实写入异次元计数管理器。服务端发送和客户端发布尚未实施，MR 保持 Draft。

## 原生契约

方向为 S2C、class0/812。注册 RVA `0xC4C7CB` 绑定回调 RVA `0xC49E00`。回调依次调用真实 u32、u32、u8 读包函数，消费 9 字节，写入同一管理器的 `+0x18`、`+0x1C`、`+0x20`。第二字段同时通过真实 setter 写入存在的本地角色 `+0x548`，然后产生事件 `0x98` 和刷新调用。角色不存在时仍更新管理器。

| 偏移 | 类型 | 消费者证明的含义 |
| --- | --- | --- |
| 0 | LE u32 | 基础次数已用数。普通模式 UI 以 `base - value` 显示剩余次数，分母为 base。 |
| 4 | LE u32 | 可用额外次数。UI 直接显示此数，另列每天最多可追加次数。不是服务端“当日累计已发放”的同义字段。 |
| 8 | u8 | 每周隐藏领主出现/最高奖励计数。UI 以此数与每周上限比较，并将显示值钳制到上限。 |

管理器构造函数 RVA `0xC4C680` 加载 `Etc/DimensionGate.etc`、`Etc/DimensionGateDropList.etc` 和 `Etc/DungeonEtc/DimensionDungeonInfo.etc`。最后一份配置对象挂在管理器 `+0x28`。真实配置解析器 RVA `0x3779150` 的 tag 分支将 `[max extra enter count]` 写入配置 `+0`、`[max daily enter count]` 写入 `+4`、`[hidden boss appear count on week]` 写入 `+8`。当前 a56 PVF 分别为 5、10、2，所以 base = 10 - 5 = 5。

普通模式 UI 的算术片段从 RVA `0xCF619C`、`0xCF62A2`、`0xCF636B` 执行，分别在 DSTR 查找边界留下以下参数：

| DSTR | 模板 | 原生参数 |
| --- | --- | --- |
| 48010 | 进入次数 : %d/%d | base - 基础已用、base |
| 46854 | 额外入场次数 : %d | 额外可用 |
| 67064 | 可追加入场次数(每天最多%d次) : %d | max extra、额外可用 |
| 67057 | 隐藏领主最高奖励可领次数 %d/%d；隐藏领主出现时计数，每周重置1次 | min(每周计数, weekly cap)、weekly cap |
| 67063 | 追加入场次数每天不能超过%d次。 | max extra，动作 ACK 错误文案路径 |

模板来自匹配客户端资源的 DSTR；67057 表中分号后的说明是对原文字面 `\\n(...)` 的排版展开。文案和 UI 不证明每周重置的具体星期、账号/角色归属或组队分配。

## 离线候选

`deploy/client/dimension_count_gate.py` 固定输入完整摘要及原生门控指纹，只把共享接收位图的 opcode812 从关闭改为开启（同一字节 `02 -> 12`），重算 PE checksum，拒绝覆盖输入和已有输出。门控为各 packet class 共用；证明的是操作号的放行，通知注册本身仍属于 class0。806 仍关闭，829/830 保持原样。

生成候选 SHA256 `94eac2e557662cb0206efc36c834fe6580a805272d3037a3e0e15a400e328c22`，111812608 字节。这是未发布的独立离线候选，没有叠加另一个 296 接收候选。

```text
python deploy/client/dimension_count_gate.py <published-v141.exe> <new-candidate.exe> --receipt <new-patch.json>
python scripts/verify_client_dimension_count_812.py --exe <published-v141.exe> --candidate <new-candidate.exe> --receipt <new-native.json>
```

验证器需要 pefile 与 Unicorn 2.x。全部 65536 个 u16 操作号执行真实门控，对比只新增 812；四组字段 `(0,0,0)`、`(1,1,1)`、`(5,5,2)`、`(5,0,255)` 分别覆盖本地角色存在/不存在，共八组真实回调、读包、字段赋值、角色 setter、UI 减法和每周钳制。后一个 255 只证明显示钳制与字节零扩展，不是合法服务器状态样例。

单例查找、本地角色查找、事件总线、刷新末端、普通模式判断及已加载配置标量为明确夹具；UI 执行停在 DSTR 查找参数处。完整网络 dispatcher、场景和绘制没有执行，不能称为玩家画面验收。

## 服务端仍缺的内容

当前 official-24.9 成功用券发动作 ACK 与背包 op14，入场只提交共享额度；登录、选图、日切没有异次元计数投影。现有领域统计中的 used 是共享池累计使用，extra_granted 是当日累计发放。接入前必须分别建立基础已用和额外可用的投影，并保持“用掉额度不重新开放当天发券上限”的规则。

真实 a56 新族 7165–7179 有第二个 `[hidden boss maze]`，每周上限 2、按入场数的出现表、专用 11 项奖励表。现行代码没有 typed hidden maze 门禁、每周状态或专用奖励表发放；不得发送伪造的每周 0 来掩盖这些缺口。原生 UI 只证明第三字段的消费意义，不证明完整隐藏领主业务。

旧 7100、7165–7179 新族、316 魔界裂缝需分别保持实际配置边界。START_MAP 的 20 字节 extra entry 行是被动对象掉落数据，继续按其独立契约处理。

下一步先确定每周归属、重置边界、出现与组队记账及奖励列语义，再实现事务和一次性投影、真实 PVF 回归。依赖服务器上线前，按 `Docs/CLIENT_RELEASE_SYNC.md` 发布最终 EXE、同步镜像、核对玩家实际通道签名及配套资源摘要。当前没有 Release、通道更新、服务器部署或实机验收。
