# 退图后仅剩一名成员的客户端记录退役

两人副本中一人退出后，服务器需要保留留图者的活动实例和固定槽，客户端则需要移除旧组队栏及退出者连接。继续发送单人kind0名单会保留旧组队显示；直接删除本人旧记录又会触发现有客户端模型销毁。

本次仅在最后一名留图者路径先清退出者记录、最后清本人记录，随后删除退出者actor并发空153；发送失败不继续删除actor。三人以上继续沿已有名单差异路径。服务端不清留图者实例、不重新编号固定槽、不重建角色。

配套`scripts/client/dungeon-peer-retire/repair_published.py`在kind3旧键等于目标键且实际角色确为本地角色时，只清旧记录/反向引用，保留本地模型。其他成员及其他上下文保持已有销毁逻辑。必须先发布并验证配套客户端，再启用依赖服务端。

原生`verify_survivor.py`覆盖初始记录绑定两种方向、本人槽0/1及命名空间，旧/新共16项；执行真实kind3调用、清槽、本地队伍getter及网络重置分支判定。角色查找和析构为夹具，未运行完整UI/UDP。Go回归覆盖队长/队员退出、包顺序、重复请求、实例及槽保持，共24项通过。

验收：两人进图，一人回城，留图者左上旧组队UI消失且无退出者超时，本人模型/攻击/通关正常。互换队长和退出者，再测三人退一人、连续退队、重新组队进图。原MR范围完整保留，用户验收前不合并。
