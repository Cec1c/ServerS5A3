# 拍卖结果通知的魔法封印属性尾部

购买、撤单和流拍返还先通过拍卖事务生成邮件，再向在线角色发送 class 0 / op169 提示。旧通知只有 8 字节，而匹配客户端固定读取第 9 字节的属性数量。魔法封印装备的通知随后会构建临时物品并应用刚读取的属性；缺失字段使客户端读取包外数据。

## 协议依据

匹配客户端 SHA256：`686eaa069ba3cc374520d249628efc9de89bf0892ad45ad1e4bd2d2206b08dc5`，映像基址 `0x00400000`。

- 通知入口 RVA `0x01C33270` 在读取 route、kind、物品 ID 和 u16 后，无条件调用属性读取器 RVA `0x01B0EEC0`。
- 属性读取器先读 u8 数量，再清理上一条通知的属性缓存。数量为零时直接进入空摘要路径；非零时还需属性记录和后续元数据，不能只补若干属性 ID。
- 普通拍卖提示 RVA `0x02F02140` 对装备调用属性应用器 RVA `0x01B0F300`。空缓存跳过重建与清理装备属性的分支。
- 有限原生测试执行真实包读取器与属性应用分支；UI、物品工厂和部分所有权操作使用适配器。完整游戏收信显示仍需实机验收。

当前服务端发送以下空摘要格式，整数采用小端序：

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u8 | 路线：普通拍卖 0、金币寄售 1 |
| 1 | u8 | 结果类型 |
| 2 | u32 | 物品 ID |
| 6 | u16 | 原有 UI 刷新字段，保持 0 |
| 8 | u8 | 临时通知物品的属性数量，0 |

通知以物品 ID 展示结果，空摘要适用于这一提示。邮件附件继续从服务端托管的物品实例复制 `RawEntry`、`Extra`、绑定与到期信息；空摘要不写回库存或邮件。无需更新 EXE、PVF、数据库或配置。

## 回归与验收

自动化回归覆盖两条路线的所有现有通知类型，并从正式上架、购买、取消、到期处理入口检查在线通知、邮件附件属性、押金、完成后重试不重复发信。旧包在原生读取器 offset 8 越界；补零后准确消费 9 字节并清空缓存。

部署窗口后分别用未解除及已解除魔法封印装备验证：买家在线购买、卖家在线撤单、在线流拍返还。每次检查通知出现时连接稳定、邮件可打开且可领取、领取后装备属性与上架前相同；卖家成交款和普通物品、金币寄售作对照。源码验证与游戏验收分别记录。
