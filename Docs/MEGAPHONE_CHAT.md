# 服务器喇叭与频道喇叭

当前客户端把普通服务器喇叭（物品 36）和频道喇叭（物品 37）作为 CMD17 的聊天类型 11、13 发送。此前服务端把无目标的请求交给只接受类型 3 的普通聊天处理器，两种喇叭因此被拒绝。

## 协议依据

本次离线验证客户端 SHA256 为 `478611607f7b6567fcaff7af1ca53c4700eec93b9285ac75d47bd5465d535586`。原生主聊天发送器 `0x2A02AF0` 的正文分支写入：`type:u8, target:u16=0, sourceSlot:u32, message:DSTR`。类型 11 查找物品 36，类型 13 查找物品 37；第三字段是准确的背包槽号，不是保留零，也没有另一条使用道具命令。

NOTI118 接收器 `0x200C9A0` 消费 `type:u8, serverGroup:u8, decoration:u8, ownerChannel:u8, sender:u16, name:DSTR, message:DSTR, groupName:DSTR`。它以姓名显示发送者，不要求同屏角色对象。同频道与其他频道分别进入对应聊天显示路径。发送者收到自己的通知时，客户端会预测扣除一个喇叭；服务端必须在该通知之后发送权威库存行，避免重复扣数的显示。

## 处理规则

- 仅当前协议的两种普通喇叭文本请求进入付费处理。物品链接 CMD424 与其他喇叭变种沿用各自现有处理，不使用未经验证的布局替代。
- 源角色须是当前绑定身份、已进入城镇且不在地下城。根据运行 PVF 核对物品路径、类型、等级、位置和期限；账号须有 Lv86 角色。角色的现有禁言期限、源格开放容量和物品锁定也参与校验。
- 角色资产事务重新核对账号归属和准确源格，只消费所选类型对应的物品。库存与连接序号的持久记录一起提交；失败一起回滚，同一请求不重复扣除或广播。新的请求允许重复发送相同文字。
- 服务器喇叭投递给本服务所承载、同服务器组的在线角色；频道喇叭再限制为当前连接频道，均不限制地图。每个目标通过有界事件队列投递，并在执行时复核角色代次、账号、服务器组和频道。
- 成功后发送 ACK、本人 NOTI118、库存 NOTI14，再向其他角色投递。接收端离线、队列满或写入失败不取消已提交使用，也不阻止健康接收者；提交后不自动重试广播。

## 验证与部署

回归覆盖两类范围、准确扣除、重复/旧序号、错槽/错道具、过期/锁定/等级/禁言、事务保存与提交失败、并发和角色换绑。真实 PVF 只读验证两种物品；原生脚本执行实际发送分支，服务端消费其输出，再由原生接收器消费 Go 构造的通知。隔离 MySQL 验证回滚、并发与重开仓库后的持久记录。

无需修改 EXE 或 PVF。代码验证、仓库合并、正式部署与游戏内验收分别记录；上线后需用两个账号验证跨地图同频道接收、服务器跨频道接收、频道范围及背包数量。
