# 公会图标与装饰保存阶段

公会图标请求 787 和装饰请求 832 原来没有处理路由。现在通过公会事务保存；图标费用取自实际 PVF 的 `[guild mark]`，只扣公会积分，重复保存相同图标不再收费。角色金币、成员贡献、仓库和其他公会保持。

图标列表由 `ui/guild/guildmark_cn.xui` 的连续编号确定，当前匹配资源为 15 个零基编号，前 5 个免费，其余每次变更扣 2000 积分。装饰和印章列表各有 25 项；请求先发印章、再发装饰。有效组合和两个 `UINT32_MAX` 的清除请求均可保存，半组清除、越界、无权和旧账号归属拒绝。当前阶段沿用会长编辑规则并同时校验会长 ID 和成员 grade；其他职务的客户端入口权限仍待核实。

保存后重新加载公会状态并向同会有效会话发送 NOTI70，缓存读取和重开路径已静态核对。787 使用原生成功／失败回调，832 的提示由客户端在发送前显示；本阶段不发送其他业务的 class0/832，也不打开未经验证的 class1/832 接收位。832 失败目前记入服务端日志；准确失败提示和角色场景外观投影仍待完成，因此这份交付不代表全部外观功能已经修复或通过原生验收。

事务中重验角色所属账号、会员和会长身份；保存后、提交前再次检查会话，失败回滚积分和外观。测试覆盖原路由缺失、免费／付费、余额不足、同值并发、错误编号、清除、权限、真实 SQL 失败及保存后会话失效；真实 PVF 校验与一次性 MariaDB 读回通过。全量结果记录于私有回执，环境跳过不计为真实验证。

`scripts/client/patch_guild_appearance_v110.py` 仅接受完整 SHA256 为 `2deb9a1a02451c2b7d1c68e52a61aa3e13723a227f04c589806fa7f6245a7b6e` 的 V110 成员菜单／公告／仓库组合文件，只新增 787 接收位并重算 PE checksum。输出 SHA256 为 `2fad11bb052d46695fb849475ac9e2eccb42d807477fe28d2116a1c51f287b49`。输入文件保持，拒绝覆盖和未知版本。

原生依据：完整 V110 SHA256 `fc4fa42ce9fd47307992fb6808840e68f84d89285570c383a100918aa641c3de`；787 发送器 VA `0x159ad50`／`0x159c230`、回调 `0x1fbf9a0`；832 保存 `0x11ba5b0`、清除 `0x11bb720`、重开 `0x11bb9a0`、NOTI70 缓存 `0x203e980`。复用的 184 个 IDA 代码范围与该模块逐段匹配；原始伪代码留在忽略目录。旧版本场景光环地址不适用于此版本。
