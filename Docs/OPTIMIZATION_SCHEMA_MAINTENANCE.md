# 公会指纹与升级奖励索引的显式维护入口

公会持久指纹避免每次读取大段公会原文后再计算摘要；升级奖励恢复索引为待处理奖励的前缀查询提供索引路径。这两项已有运行时实现，本入口补齐既有数据库的显式安装与实际状态检查。源码合入不等于已安装或已部署。

普通游戏启动不调用这项维护入口。公会指纹仍由原有启动资格检查决定是否使用，缺失或未就绪时回到权威来源；奖励恢复、持久回执与原子资产写入保持。普通 schema 初始化原有的恢复索引 SQL 仅提取为共用函数，语句内容不变。

## 有界请求与运行范围

普通 Linux 服务端程序以唯一参数 `--optimization-schema-v1` 接收标准输入中的单个 JSON 对象，在应用装配和监听前返回。输入上限 64 KiB，未知字段、多余 JSON、未知模式或不匹配的规格摘要均拒绝。连接凭据只从标准输入读取，计划导出不能附带连接或批准字段。

三个模式为 `plan`、`inspect` 和 `apply`。共同字段为 `tablePrefix`、`readDatabases`、`writeDatabases`。规格包含规范化且有序的分片、固定格式 `guild-fingerprint-level-recovery-v1`、写分片的新增表/触发器/索引语句和 SHA256。读副本只参与就绪检查，不会自动成为写目标。

`inspect` 和 `apply` 还需要 `dsn` 与匹配的 `planSha256`。连接限于数值回环 TCP 或规范绝对路径的本机 Unix socket，禁止 multi-statements。连接的默认库若非空必须属于规格。连接池上限为 1；只读检查总时限 20 秒，安装总时限 2 分钟。维护进程不启动游戏、发奖或迁移业务历史。

`apply` 还必须提供刚检查得到的完整 `expectedBefore`。执行前重读并比较所有分片状态；安装库接口还要求显式 `AutoCreate`。这些约束是维护 API 的输入合同，不能替代调用方对主机、实际数据库身份、源码/程序、备份、维护窗口及授权的核验。

## 实际对象核验与安装

先检查全部分片，再进入第一个写分片。源 settings、setting_values 和 character_stats 必须存在且为 InnoDB。公会表和三个触发器复用原安装器的定义核验和锁定回填；原 JSON、updated_at、奖励统计及回执不改动。

恢复索引必须是 `idx_stats_pending_level (stat_key,stat_value,character_id)`，非唯一、完整列、BTREE、升序。仅同名但列顺序、前缀、唯一性或可见性不符会拒绝，不删除后重建未知对象。MariaDB ignored / MySQL invisible 标记按实际 information_schema 能力检查。

已完整就绪时只读返回。部分指纹表/触发器只有在定义已知且来源完整时才允许新的显式维护任务补齐。安装索引使用专用连接和命名锁，元数据锁等待限制为 5 秒；离开时恢复会话变量和释放命名锁，无法清理的连接从池中丢弃。

## 失败与回退

DDL 不是整个安装过程的原子事务，失败可能留下已验证定义的部分新增对象。调用方应在提交前持久记录本批意图。超时或回执丢失后先只读 `inspect`；旧请求不得当作新授权反复提交。未就绪或状态不明需要检查实际对象，再建立新的明确修复任务。

这些对象是增量结构：旧版来源写入仍由触发器更新指纹，旧版读者可忽略指纹表和新增索引。游戏回退可以保留已验证兼容的完整或部分新增对象，不需要恢复旧业务数据。若触发器存在而目标表缺失、定义陌生或实际检查失败，不能据此宣称旧版写入安全。

## 已执行验证与限制

实际隔离 Linux/MariaDB 11.8.9 验证包含读副本不写、全分片写前检查、已知部分安装、错误列顺序/唯一/前缀/ignored 索引、陌生触发器和错误指纹表拒绝，原来源与时间戳、奖励统计保持，旧写者更新，以及就绪重入和丢失回执后的只读检查。原公会安装与 25 万统计行的奖励索引/EXPLAIN 验证也已执行。

正式 Linux 程序分别通过回环 TCP 与 Unix socket 执行安装和复核，没有启动应用监听；两侧原值保持。8 个不同主测试、32 个不同通过节点，无适用失败或跳过；相关 vet/list/mod 与普通 Linux 构建完成。不是 MySQL 各版本、全游戏、正式发布器或玩家 GUI 验收，尚未在生产安装。隔离 Linux 成功与宿主 QEMU exit 1 原因未知分别记录。
