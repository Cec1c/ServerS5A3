# 首次账号补档原子创建

同账号首次初始化的多条连接可能同时读到账号不存在。旧逻辑随后对初始快照完整保存，慢连接可能覆盖另一连接已经保存的新手周期、领取位、余额或冒险团。修复将补档改为独立的 `CreateIfAbsent` 能力：账号行和初始元数据一次提交，主键已存在时不更新旧行或元数据。

MySQL 使用普通 `INSERT` 和原事务；主键竞争后从写库核对账号确实存在，其他 SQL 错误保留，元数据失败一起回滚。不使用 upsert、`INSERT IGNORE` 或先查后写的退化方案。内存实现与账号保存共用互斥锁，只允许一个创建者。不支持该能力的仓储明确报错，补档入口沿用原来的失败告警和不阻断登录口径。

已有账号仍走一次读取后直接返回。补档前检查失效登录；竞争失败的连接不会重发新手标记。资格规则、任务、签到、发奖事务及普通账号保存语义保持。

共享容器不再额外补写空壳，沿用正常建号时缺失按空读取、首次真实写入时创建的原路径，避免空容器覆盖竞态；已有共享物品保持。

源侧历史测试覆盖并发首次创建、旧记录保留、取消及唯一名称冲突、MySQL 事务和失败回滚、旧补档交错覆盖、失效会话及共享物品保留。这些记录不代表本轮重新验证或多账号实机验收。
