# 同账号新登录接管旧连接

公网账号 API 启用登录令牌时，同一账号通过密码验证的新登录会关闭旧启动实例的全部认证游戏连接。客户端闪退后可以重新登录；同一次启动使用同一令牌的辅助连接和正常换线继续有效。

严格登录模式同样执行接管。每台设备同时只允许一个账号，同账号重新登录替换自己的名额；切换到已有其他账号的设备时拒绝本次登录，保留旧连接。服务器人数上限按其他账号占用检查，同账号重登不重复占用名额。注册 IP 的注册数量限制独立于同时在线限制。

## 接管顺序

1. `/api/account/login` 保留请求、频率和密码检查，在事务内再次核对当前密码哈希。
2. 登录审计、新令牌写入、该账号旧令牌撤销在同一数据库事务提交。错误密码或事务回滚保留旧会话。
3. 提交成功后撤销该账号旧令牌缓存，标记全部旧认证连接并关闭 socket；严格模式中已通过设备准入、尚未绑定角色的旧连接一并关闭。旧会话排队中的请求和定时事件停止执行。
4. 新游戏连接从 SQL 验证令牌，等待旧连接正在执行的操作和退出清理完成，再接入角色流程。等待期间释放登录互斥锁，其他账号照常登录。
5. 旧连接超过原有退出等待时间时，后台继续等待事件循环实际结束并完成退出清理；完成后释放新登录。新连接的验证受自身上下文和 10 秒超时约束，超时可以重试当前有效令牌。

同时登录只保留最后成功提交的令牌。等待清理期间再次登录也会撤销前一个新令牌，旧连接迟到的清理不能删除新连接。公网令牌模式中的无效或缺失令牌会终止该登录连接，不能回退到共享账号。

本地 loopback 密码登录令牌继续使用原有内存生命周期。显式关闭 `DNFBRIDGE_ACCOUNT_API_LOGIN_TOKEN` 的模式保持原行为。本实现管理同一服务进程内的连接；多个独立进程共享账号表时，跨进程踢线需要独立的协调机制。

没有新增客户端报文或 EXE/PVF 依赖。旧客户端通过连接关闭退出，界面提示沿用客户端现有表现。

## 自动验证

普通测试覆盖多连接退出门槛、重复接管、旧连接迟到清理、排队事件拒绝和慢操作结束后的清理。设置指向一次性测试库的 `DNFBRIDGE_PLAYER_TEST_DSN` 后，`TestAccountLoginReplacementMySQL*` 覆盖真实事务、两阶段故障回滚、六路并发、旧缓存、正式上层登录包、辅助连接、本地登录及令牌关闭模式。数据库测试会创建并删除自己的测试表。

`TestStrictTakeover*` 额外覆盖严格模式的完整账号登录入口、主/辅助/尚未绑定的连接撤销、逐个退出清理、密码错误/禁用/绑定要求/设备上限/事务回滚保留旧端、并发登录只保留最后凭证和等待中再次顶号。`TestPlayerAdmission*` 覆盖每设备单账号以及设备与服务器名额计算。

```text
go test -buildvcs=false -count=1 ./internal/services/dnfbridge -run TestAccountLoginReplacement
go test -race -buildvcs=false -count=1 ./internal/services/dnfbridge -run TestAccountLoginReplacement
```

## 游戏内验收

1. 旧客户端进入城镇，记录背包、金币和任务状态；新客户端用同一账号正确密码登录。
2. 确认旧端断线、新端可以选角进城，旧端无法继续提交动作。
3. 主动结束客户端进程后立即重登，确认可以恢复账号和角色。
4. 旧端在线时输入错误密码，确认旧端继续正常游戏。
5. 新端完成换线、换角色、进出副本，核对背包、金币和任务状态一致。

源码测试与游戏内验收分别记录；合入源码后由部署方安排更新及上述实测。
