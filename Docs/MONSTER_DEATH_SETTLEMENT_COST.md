# 怪物死亡结算的数据库开销

## 问题与改动

怪物死亡在回复 op38 前提交经验，回复后继续处理击杀任务。同一会话按顺序处理消息；逐只击杀重复加载完整角色/技能、重写整份角色属性，会同时推迟当前死亡通知与后续消息。

实现减少数据库工作量，保持死亡、掉落、经验及任务的业务规则和发包顺序：

- 成长事务只读取角色基础/属性和当前 SP/TP 账本，省去选角装备摘要、位置、技能等级、布局、另一页加点及冷却数据的重复加载。事务外构建角色状态所需的完整角色读取继续保留。
- 成长提交仅更新等级、经验、时间及实际改变的属性；升级属性、满级名誉经验、升级事实标记仍随技能点在同一事务提交。普通经验变化不再删除、逐条重插所有额外属性。
- `[hunt enemy]`、`[hunt monster]` 路径中只判断角色存在的读取，使用主键存在性查询。任务的实际加载、规划、保存及回读验证保持。

优化使用可选仓储能力。现有完整读写、内存仓储及不提供该能力的包装器保留原路径；历史属性影子优先模式继续使用原属性保存逻辑。没有新增启用配置或数据库迁移。

## 一致性边界

事务内继续校验账号归属、等级/经验/SP/TP 版本及名誉经验的前置值，读取保留原 `FOR UPDATE` 路由。完全相同的提交幂等返回，过时版本拒绝；技能写入失败时，先前角色属性和升级标记一起回滚。

局部角色读取只用于成长提交，不得作为完整角色记录保存。技能点读取只用于账本消费/局部账本保存；选角表现、技能加点、两页布局、冷却及其他资产仍由各自完整入口管理。永久升级事件和领取记录继续沿用既有合并规则。死亡确认没有提前到持久化成功之前，也没有改为无界异步结算。

## 击杀任务读取视图

单个击杀的 `[hunt enemy]`、任务物品掉落和 `[hunt monster]` 检查显式共用一个临时任务仓储视图；其他仓储、事务工厂和调用顺序保持。视图只在该处理函数栈内存在，不放入服务、session 或 runtime，不跨击杀/角色共享。

任何完整或字段写入，包括失败写入，均先作废视图。后续校验从真实仓储重载，不能以待保存的计划当作已落库事实；读取错误不缓存，返回记录独立拷贝，跨角色读取不复用选中角色快照。后继任务自动激活、父子任务同步仍由原规划器及保存/回读入口执行。任务掉落先匹配实际候选，有候选后才读取账号的任务助手/成长契约资格。

## 宠物成长局部保存

清房路径中的宠物饱食度和成长事务原先均通过 `PetFieldEntries` 重写所有宠物、额外字段、饰品和所有宠物的历史清房令牌；单宠物令牌最多 128 条，逐条重插使同步处理尾段随历史积累增加。

`PetGrowthWriter` 在原 `CharacterPets` 事务中只更新当前宠物的饱食度、分数饱食度、等级、经验及记录时间。饱食度结算不重写防重复令牌；清房时仅替换当前宠物的令牌并用一条批量 `INSERT` 保存有序历史。其他宠物、名字/原始字节、扩展字段、饰品、装备和显示设置不重写。启用进化的路径仍使用完整宠物与装备原子保存；不提供新能力的仓储继续走原字段保存。

原有锁定读取、宠物与装备身份校验、跨角色事务限制、饥饿/满级规则、分数计时、清房令牌裁剪及重复奖励保护保持。没有合并两笔事务、推迟持久化、提前确认、改用后台写入或新增配置；通知仍在成功提交后按原路径重新读取。

## 验证边界

历史实现曾用隔离数据库比较旧完整能力与新路径的落库结果，覆盖升级属性、名誉经验、升级事实、金币、职业、位置、选角摘要、技能等级、两页加点、布局、冷却、重复/过时/并发提交及技能写入故障回滚。这些测量依赖数据库、硬件、任务和宠物历史规模，不能换算成游戏总延迟或服务上限承诺。本次只提取设计语义，没有重跑测试、采样、构建、部署或实机测试。
