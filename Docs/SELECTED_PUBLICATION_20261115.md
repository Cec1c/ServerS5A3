## 部署与资源要求

- 黑钻礼包 490709931 打开获得 490709930，二者可以交易/拍卖；原生 518 用券激活账号权限，44 兼容，续期从有效期末再加 30 天。资源中的 490709932 为内部结算权限，不另行出售。
- 疲劳上限 188、通关经验加成 5%、额外翻牌与黑钻售货机按有效账号权限生效。每角色每天 06:00 起累计消耗 150 疲劳获得一枚黑钻硬币邮件；满邮箱延后，事务回执去重。重复用券不会重置已消耗疲劳。
- 加百利按真实 secretshop 七列数据冻结遭遇、个人报价、库存及幂等购买；普通 2 行、黑钻 4 行及加倍库存。客户端需要本批 EXE 的 279/280/296 消息门与 NPC 货架拷贝修正。用券权益显示使用原生黑钻通知 56，存储类型仍为 17。
- NPC 赠礼只接 class 1/type 812；普通角色恢复好感快照，空快照也发送清空。商店上下文修复仅在权威场景及货架证明成立时进行，出售要求正价格，拒绝原因及日志有界。
- 组队分解机 8–11 级的无色奖励在逐件舍入后加 5/10/15/20%；原有有效暴击机会在非勇士地下城增加 1–4 个百分点并封顶，其他产物保持原规则。
- 锻造道具 490008445 的绝对期限为 2028-12-31 23:59:59，取消相对 7 天期限。既有实例仅在匹配该资源定义时更新，显式 GM 期限优先；卢瑟道具已公开期限继续保留。
- 攻坚奖励资格使用入场组别冻结，合法离队换组仍保留权益；原生个人牌位按真实普通队伍冻结，四人各自单走均为个人第一张，真实小队牌位互斥。安徒恩 585 只发送接收连接所需地图增量，避免同状态重复播报。
- 卢克二阶段的 10%/4000、超时空最终阶段的 10%/5000 欢乐代币券分支，同时取得一份原生奖励；两个奖励池、钱包/背包/周次数及事务回执沿原有原子提交和重连幂等处理。所需 token 容器和团本权重已在指定输入 PVF 内，新增计划不重写它们；实际 PVF 回归会检查每个原生分支和权重。
- M01–M03 在普通 Linux 服务端以 `DNFBRIDGE_EXPERIMENTAL_PEAK=on` 显式启用：拍卖写事务完成后释放市场锁再回包；事务内至多 8 owner 的角色缓存遇任意 SQL 写失效并深拷贝返回；升级属性批量写入。默认关闭，无新增迁表步骤；合成测试和 SQL 行数变化不代表整服固定收益。

资源重建参见 `resource-recipes/selected-gameplay-20261115/README.md`。V214 的 `64028352…` EXE 为正式增量输入，输出固定为 `28e04d1d…`。继续保留已有配套客户端依赖、两 DLL 和界面 NPK，Buff 双组仍按 `Docs/BUFF_GROUP_DEPLOYMENT.md` 配置。

## 精确配对准入 E12

`deploy/remote/client_pairing.py` 提供可复用的 `checked_client_files(pair)`：新旧两个正式 EXE 各绑定精确长度和摘要的两 DLL、NPK；拒绝缺失整个依赖对象、漏文件、测试插件、额外 DLL、路径别名和 EXE-only 绕过。部署系统在读取配对 profile 后、写入资源前调用该函数；它不会执行部署。`scripts/ci/sync_client_releases.py` 已接入新正式 EXE 的同一完整组件规则，发布同步不能接受只带正式 EXE 的残缺包。私有固定发布机、账号、队列策略和服务器配置不随本批源码提供。
