# 宠物时钟的副本边界

登录建立宠物城镇恢复时钟后，普通commitDungeonRuntime没有切换为副本消耗；正常副本内仍可能一直按城镇模式结算。只在成功入场后补一次模式切换还不完整：组队队员运行时先于队长安装，后续入场回滚可能留下副本模式；旧切换方法在仓储失败时也没有保留原始边界。

## 运行时与时钟所有权

- 普通和付费特殊副本成功提交后记录副本时钟边界，入场拒绝和重复commit不记录边界。
- 组队预安装队员运行时先保留城镇计时，整组成功后才激活副本模式。预安装标记也约束op105状态投影，避免它提前启动队员时钟。回滚只处理仍匹配该次准备运行时的会话，不覆盖后来安装的运行时。
- 确认返回城镇和通关回城在真正退役当前运行时时记录城镇边界，保留原场景确认门禁。未确认回城继续按副本计时。
- 在dungeon.mu内只记录时间边界；仓储结算与共享队列调度在解锁后执行。计时回调不反向取得dungeon.mu。

## 失败重试

会话保存尚未完成的有序模式边界。每次先结算边界之前的旧模式区间，再移动模式/起点；失败时保留该边界。连续城镇→副本→城镇不能用最后一次切换覆盖中间副本区间。相同目标模式的重试保留第一次请求的时间，已完成区间不重复结算。

待处理边界复用现有共享宠物计时器的60秒档重试，没有新增独立定时线程。调度失败保留已提交模式和起点，后续同模式调用可以重新调度。旧代数回调、倒退时间和角色失配均拒绝。结算仍由既有宠物领域Owner通过角色宠物资产事务保存。

停止/换角沿用既有最终结算和停止机制；本变更不增加跨进程的持久计时流水。隔离回归证明的是事务中止后同一活动会话的区间重试，没有模拟SQL未知提交或进程崩溃恢复。

## 数值、资源与验证

既有60秒副本消耗、360秒城镇恢复、神器修正及饱食度公式保持原值。本次没有独立重新确认原生周期，固定a56的饲料、神器字段不能代替周期证明；喂食入口及自动喂食另行处理。

正式边界回归覆盖入场失败/成功/重复、确认回城、组队回滚、组队准备与激活、旧运行时回调；6063付费入场检查票据和运行时仍按原规则提交，并探测宠物仓储调用发生时dungeon.mu已释放。故障注入保留城镇360秒、副本120秒、城镇360秒三个区间，持久值依次91→89→90；队列失败重试不移动起点，旧代数和角色失配不改资产。既有房间成长、死亡重放和共享计时队列回归保留。

固定a56 SHA256为a56cacf96087ba34ca5299e04ab65f8268f694b214b97dec9879fdebf46f5290。实际宠物目录由equipment.lst解析，选择可由宠物领域catalog确认的creature，检查既有模式切换后的副本消耗写入仓储，并通过新的仓储服务读取，区别于时钟内字段或客户端乐观显示。
