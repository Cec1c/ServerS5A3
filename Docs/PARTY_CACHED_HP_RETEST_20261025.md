# 城镇队伍缓存角色的实时HP更新

当前队伍栏可以通过已发布的身份校验查找辅助缓存角色，但153接收函数只查活动角色。角色重建或不在当前场景时，队伍栏可能继续读取缓存对象而漏掉最新HP通知。

`scripts/client/ordinary-party-hud/build_hp_realtime.py`严格绑定v173摘要；原活动查找优先，仅在普通城镇、当前本地队伍包含目标且目标不是本人时，复用现有HUD查找辅助缓存。继续校验目标UID、上下文和模型。副本、竞技场、离队及跨身份不扩大范围；原接收器按报文原值写入HP，包括真实零值。

`verify_hp_realtime.py`执行153接收及读包、原生辅助哈希查找、HP描述符写入和HUD百分比读取，15种边界×三种HP×新旧两路共90项通过。活动角色查找、命名空间解码和场景单例使用夹具，不能替代游戏渲染验收。`--candidate`可核对最终组合产物中的实际补丁字节。

只修改153查找CALL、保留区内辅助函数及PE校验和。原MR的服务端角色初始化、常驻连接解析及HP投影继续保留，不引入新的战斗HP来源或硬编码满血。

验收：两端分别切城镇、进出场景、重建角色及重新组队，左上血条持续对应已有报文；副本受伤/死亡零血正常，离队后不显示旧队友。最终实机验收由用户完成。

## V176 后的闪烁续修

跨场景自动资料刷新和主动查看资料发送的 mode8 内含 mode0。原路径在普通城镇 mode0/op153 已发送 HP 后，仍可能用零值覆盖该描述字段。两条真实发送入口的负向回归均复现此覆盖。

发送 mode8 前，按接收者与角色当前中央队伍关系，从原有 op153 显示正文投影 HP。只修改每次发送的副本，批次共享的资料模板保持原值，避免普通队伍显示值泄漏给已退队或其他关系的接收者。原身份、频道、外观修订和发送前校验保持，副本与超时空不扩展范围。

定向检查 64 项通过、0 失败、0 跳过，涵盖批次两名接收者、主动查看资料、共享模板隔离以及原跨场景刷新和身份边界。旧行为两项预期失败；该结果只确认数据链修复，组合构建、部署和游戏内血条连续显示须分别记录。
