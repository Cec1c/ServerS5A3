# 公会普通成员品级：op126

普通成员升降级请求此前未注册处理器。本单元接入 class1/op126，按职位权限位 11 校验操作者，在同一 Guild UoW 中修改目标的普通品级 2～4，再返回原生 ACK 并刷新同会管理状态和已请求的成员列表。会长转让与司令官职位使用其他动作，本单元不处理。

## 匹配客户端

本记录对应作者 v105 preview，EXE SHA256 `6fd3183de3cff52fa2feb5a5327ca43855cabbc6b0b63d920a87ab8ddf316da5`，ImageBase `0x400000`。地址均为该版本 RVA；换版本必须重新核对。

| 路径 | RVA | 已核对行为 |
| --- | --- | --- |
| 发送器 | `0x25794f0` | 区服 1～249；`u8 region + DSTR targetName + u8 grade` |
| class1 回调 | `0x1bd3510` | 成功读取额外标记字节、区服、DSTR 名称、品级；更新成员缓存和打开的窗口 |
| class0 同号回调 | `0x1c38410` | 另一种通知，不是品级 ACK |
| 成员菜单 | `0x3143bf0`、`0x31445a0` | 普通职位动作检查权限位 11 |
| 权限辅助函数 | `0x2578b20` | 位 11 直接读取当前职位掩码；并非硬编码仅会长可操作 |

成功包体为 `01 00 region DSTR grade`：`01` 为成功状态，第二字节由回调读取但未用于后续判断。直接回显请求会缺少一个字节。拒绝码使用回调可识别的 3（目标/身份/保存失败）、83（无权限）、85（本人）、87（会长）、88（非法普通品级）。原生错误文本还包含副会长名额、经验和司令官条件，出现文本不能证明其现行服务端规则。

## 事务和刷新

- 从当前角色仓储按名字定位目标，在事务锁定双方账号/角色后重新核对目标的名字、账号、社交区服和同会成员记录。旧账号、旧名、区服不符、跨会和不存在的目标均拒绝。
- 权限每次从事务内职位掩码读取。748 授予位 11 后生效，撤权后下一次操作拒绝；默认副会长掩码没有该位。
- 不允许修改本人、会长 ID 或 grade1 的成员；不允许把普通成员改为 0、1、5 等其他品级。相同品级重复请求不改变成员和公会时间戳。
- 仅修改成员品级和实际变化时的公会更新时间；保留金币、经验、贡献、角色资料、会长身份及权限定义。保存失败回滚。
- 发送 ACK 前重新预约当前会话代次。随后释放发送者，再逐个预约并重读同会成员，发送 NOTI70/127 等管理状态及已订阅名单，避免旧会话收到 ACK 或跨会刷新。成员离线仍可持久保存，下次上线从仓储加载。

## 验证与限制

修复前回归确认 op126 `handled=false`。回归覆盖 2/3/4 品级、额外 ACK 字节、本人职务通知、授权/撤权、离线目标、相同请求、保存失败、class0 拒绝、旧成员身份，以及事务期间目标改名/区服/账号变化和会话代次变化。领域测试覆盖权限撤销与改职务并发，内存 UoW 验证原子性。

EXE-GUILD-011 只在 010 上补 126 接收位，输出 SHA256 `be54f7a587b93849f266b0854cabf26d1f2eca87ee6e3134d2cad66cdebe36fd`。相对作者版累计 32 位、13 字节，保留 65 和接收上限 1474；125/155/351/746/811 仍未开启。完整文件精确重建、原有 IDA 函数范围一致性和隔离签名更新验证分别留有回执。

副会长名额及经验要求尚无准确服务端源码证据，本离线候选未实现这些限制，不能据此认定原服策略等价。成员特殊状态、会长转让、司令官、退出/踢人和场景退出仍需后续核对。真实数据库与原生客户端交互尚未验收。

依赖服务端上线前，须取得准确累计源码并完成集成，再发布最终派生 EXE 至作者 GitGud/本方 GitHub Release，更新玩家实际通道并读回验签与下载，确认 EXE/PVF/dstr/NPK 与批准 profile 一致且复查不重复下载，最后部署依赖服务端。原版 preview 镜像和离线签名夹具不代表玩家 stable 已更新。
