# 原生批量分解与副职业提取

## 问题与处理

配套客户端在一次多选确认后，会连续发送多个原生26、235或416请求。逐件提交及逐件写连接会使结果窗口反复显示当前一件；整容器刷新、普通经验重发完整副职业资料，以及活动状态穿插也可能重建或拆开显示。请求仍需逐件校验，不能靠虚构客户端选中总数或改写奖励数量解决。

连接层使用有界预读队列，只集中处理已经到达、入口一致的连续请求。每个原生应答及其中的本次获得数量保持，按原顺序集中写连接；不增加等待定时。不同入口、其它业务、队列排空、127件或256KiB上限及时释放。按最近进展保护单件停滞，不按整批总耗时强制拆分；固定格式签到1386与在线状态561可以按序随本批写回，其计时和奖励逻辑保持。

分解师个人机及三类提取成功后仅刷新来源和产物槽，保留原生结果窗口引用的道具对象。提取普通经验使用角色进度通知，实际升级时才重发完整205资料；零经验和失败不发布新增经验。

## 事务与性能

- 已到达的免费NPC连续26请求可在原账号角色资产事务内结算一次。三类连续416提取复用原CharacterSettlement事务，经验按成功件递进，后续装备仍按新的经验/等级计算。
- 每件先在独立工作副本试算，失败丢弃该件改动并继续后续请求；最终保存或提交失败整组回滚，全部返回失败。原有紧凑批量请求的原子规则保持。
- 提取在本次事件内保存各步局部槽及必要经验快照，整组提交后才发送。每次来源、材料堆叠量和经验对应那一件之后的状态，不把最终状态冒充中间通知，不跨事件缓存玩家资产。
- SQL事务复用已加载快照，背包和共享仓库按真实变化保存；提取经验优先保存权威经验字段及时间，保留其它角色属性，未提供窄保存接口的仓储仍有原兼容路径。
- 同一PVF目录复用静态分解规则，随机产物仍逐件计算；失败读取可重试，新目录不复用旧规则。

只在配套official-24.9、有效绑定的城镇会话及原生投递开启时启用连续合批。单件、其它客户端、显式legacy经验档、换线/登录重建、副本及比赛等入口保留原路径。上游德利拉准入、扣费、金币投影和提交后发送失败保护保留；收费或不准入入口不会提前结算资产。

## 验证与使用边界

普通回归检查连续请求、输入碎片/EOF/坏帧、上限与停滞、入口切换、会话归属、失败隔离、保存回滚、短写和原有单件路径。真实PVF检查四类副职业产物、来源与共享仓库、24/127件三类提取、普通/跨级/零经验、每件局部槽与经验顺序、最终资产总量及正式输入循环。SQL用例检查差量和经验局部保存，不用测试事务调用数代替真实数据库或游戏耗时。

真实资源中的经验端点固定、保存失败及缺失产物注入仅用于覆盖确定边界，不修改资源文件或生产随机规则。需要在匹配客户端分别确认NPC和副职业入口的结果汇总、普通与跨级经验、单件操作及其它业务穿插；源码验证与游戏实测范围分别记录。

本修复使用现有原生协议和服务端实现，不依赖客户端EXE改写或新增DLL。客户端原有结果窗口关闭定时保持。`DNFBRIDGE_NATIVE_RESULT_DELIVERY=off`可回退传输集中投递，原生资产校验与事务规则继续生效。
