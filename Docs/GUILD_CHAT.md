# 公会聊天协议与验证范围

当前实现接入 op17 的类型 6 公会聊天。服务端以绑定会话、角色账号归属和当前公会成员表确定发送者与接收者；同进程中的同会在线成员可以跨场景、跨频道收取消息。不同公会、已移除成员及不匹配的账号不接收。暂不跨独立游戏服务进程转发。

成员表在每条消息发送前重新加载。在线参与者按角色编号统一预约，避免两个发送者互相等待，并阻止投递期间重连或换角更改接收者。成员移除影响后续消息；本实现不承诺对其他进程正在提交的成员变更提供分布式线性化。聊天不会修改积分、经验、贡献或出勤记录。

## 匹配客户端协议

本次取证 EXE SHA256 为 `e3fe061fd6918c11f2ddca7359498bcd7baf964c66600b2526fcec6323a24329`，PVF 为 `b86dd8fa5bcde40a445d9e494a9e1a89d0fc15ddd15d61041e4b97f78973d00f`。以下地址均为 RVA，其他模块版本需重新核验。

| 位置 | 已核实行为 |
| --- | --- |
| `0x0260c114`、`0x02602af0` | 选择聊天类型 6，发送 op17；正文为类型 u8、客户端提示 u16、零 u32、消息 DSTR，无目标名称尾部 |
| `0x01c31b3a` | 将 NOTI65 注册到读取入口 `0x01c1b510` |
| `0x01c1b510` | 类型 u8、结果 u8；类型 6 额外读取装饰 u8 和 ChildrenMark 标志 u8；随后发送者 DSTR、频道 u8、消息 DSTR、辅助 DSTR |
| `0x02123c96` | 接收资格位图检查在 class 分流之前，class0 通知也会被过滤 |

公会消息使用 NOTI65 的具名显示路径，不依赖接收者场景内存在发送者。消息最多 255 字节，发送者名称最多 30 字节，文本采用客户端多字节编码；不允许内嵌 NUL。两个装饰字节置零，未将会员职务伪装为奖励装饰。客户端请求中的 u16 不参与身份或收件人授权，其具体全局对象语义仍待进一步确认。

服务端保留既有 op17 成功/失败 ACK 形状。当前客户端位图过滤 17，因此不能依靠该 ACK 提供可见拒绝提示；成功消息由 NOTI65 显示。未凭推测扩大 17 的接收资格。

## 配套客户端依赖

当前 E3FE 版会过滤 NOTI65。配套候选继承已核验的 op515 与 op747 修订，仅比上一候选 `74d776fe5b5106efaee27d4ca1ffa45c228ca91054355d857f33a86d9418416f` 多开启 65 位：RVA `0x06a83560`，字节 `FD → FF`。

新候选完整摘要为 `c68d5641512df036129187ae34ad09db0eaf17ec688bb79a72309e590c0bd5fc`。兼容准备仍要求精确原版/已知衍生版及 PVF 摘要、游戏退出、原子替换和前版备份。65 与私聊共用，现有私聊通知同步限制为 255 字节并拒绝 NUL。服务器源码不携带客户端二进制。

## 验证与待验收

自动化覆盖同会跨场景/频道、异会隔离、移除后下一条消息、账号与角色归属、旧会话、畸形请求、原生长度边界、并发发送和投递期间换号保护。客户端真实临时副本覆盖四种前版升级、完整摘要、全命令位图决策、游戏运行拒绝及备份/回退；只修改临时测试副本。

此实现与配套候选均为本地验证状态。部署与多人原生聊天显示尚待验收；聊天贡献计分属于后续独立结算单元。
