# 冒险团内容熟练度累计

冒险团基本信息右侧的七项内容熟练度从已提交的游戏记录生成。原生统计是七个独立的 `u32`，不再借用角色收藏的二十组 `u16` 字段。账号投影相加时在 `4294967295` 饱和，查看页面不修改玩家存档。

## 来源和提交入口

| 界面项目 | 持久来源 | 累计规则 |
| --- | --- | --- |
| 推荐地下城通关 | 角色 `adventure_recommended_dungeon_clears` | `dungeon.Owner.CommitSettlement` 中通过推荐通关判断的新结算加一；上限由 `65535` 提升为 `u32` |
| 无双决斗场获胜 | 正式决斗的角色 `pvp_wins`，以及三角色总力战的账号战绩 | 复用正式胜场；总力战不重复增加三个角色的个人胜场；练习、自建房和未判胜结算不计入 |
| 绝望之塔100层 | 角色 `adventure_despair_100_clears` | `CommitSettlement` 新提交的第100层结算加一 |
| 悲叹之塔100层 | 角色 `adventure_grief_100_clears` | `CommitSettlement` 新提交的第100层结算加一 |
| 安徒恩攻坚 | 模式1的永久逐实例终局回执 | 通过现有终局结算资格检查并成功提交 `raid.CommitWeeklyClear` 后计入 |
| 卢克攻坚 | 模式2的永久逐实例终局回执 | 同上 |
| 超时空之战 | 模式3的永久逐实例终局回执 | 同上 |

副本及两塔使用同一个副本结算事务；团本和决斗各自沿用其正式结算入口。全部来源统一汇总到冒险团状态并编码发包，没有新增平行通关入口。

两塔累计放在既有结算回执重放检查之后，与经验、物品和楼层进度同事务提交。重复结算不加，后段提交失败不保存计数。第99层不加，第100层新的独立结算继续累计。

团本只统计值为正、实例ID严格为16字节十六进制的 `raid_clear_v1_<mode>_<instance>` 回执。每周用量、翻牌回执、阶段副本、失败和返票不计入；周重置保留永久回执，不改变历史次数。

安徒恩、卢克的单人和团队成功终局都使用同一模式的永久回执，因此两种都会累计到对应项目。单人必须完成整套单人序列；团队必须最终攻坚成功，角色达到最终阶段的最低参与通关要求才有回执。每个独立成功终局对符合资格的角色计一次，不按小图数量或翻牌次数累加。

公开主干当前的终局调用器只接入模式1和2。超时空新通关生成模式3回执依赖[超时空终局接入 MR !158](https://gitgud.io/16ww/servers5a3/-/merge_requests/158)；本次只加入模式3已有回执的读取及发包，不携带该贡献的团本引擎。模式3读取回归通过不能代替超时空终局接入或游戏验收。

## 发包契约

当前原生冒险团信息的 raw 区长 `7424` 字节。七项按小端 `u32` 写入以下 raw 偏移；角色收藏仍独立使用偏移 `7348` 起的二十组条目。

目标客户端须支持当前 `class0/1339` 冒险团信息和上述原生布局。本次只修改服务端发包与持久来源投影。

| 项目 | raw偏移 |
| --- | ---: |
| 推荐通关 | 16 |
| 决斗胜场 | 32 |
| 绝望100层 | 24 |
| 悲叹100层 | 28 |
| 安徒恩 | 36 |
| 卢克 | 40 |
| 超时空 | 7420 |

原生复制和七处显示取值指令的隔离回放能读取 `70001..70007`，覆盖大于 `u16` 的计数；这是字段读取证据，验收范围不含完整客户端解析和界面交互。

## 兼容和验收边界

角色来源汇总当前账号的有效角色，排除已删除角色；总力战保留既有账号战绩。本次未新增跨角色删除后永久保存的账号终身流水。推荐通关、正式决斗和团本可以读取既有有效记录；历史两塔完成圈数没有可靠存档，不按最高层或每日剩余次数推算补发，旧推荐计数已被上限截断的部分也不回填。

新增回归覆盖七项偏移与收藏互不覆盖、跨服务实例重建读取、角色/账号决斗来源、团本周重置和非法回执、两塔99/100层、重复与失败回滚，以及推荐计数超过65535。完整领域、桥接、控制/诊断、静态检查、纯服务端边界和隔离BAT配套检查的本轮结果随合并请求记录。

累计部署的操作者已确认通关后计数增加；其它六项及重新登录后的保持尚未逐项实机确认。当前公开上游组合未另行部署，自动回归和原生字段回放不扩大为七项游戏验收。
