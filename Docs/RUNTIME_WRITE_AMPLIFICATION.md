# 高频成长、任务与资产路径的读写缩减

普通经验、任务触发、宠物饱食度和账号活动状态只改变少量字段。旧路径仍可能读取展示数据、全部历史任务及附加记录，再删除并重建整组记录。本改动缩小这些请求的读取和写入范围，并保留事务、权属、重放与失败回滚约束。

## 行为与边界

| 路径 | 本次变化 | 保留的正确性边界 |
| --- | --- | --- |
| 角色成长 | 成长专用读取、扩展属性差量写、事务返回完整属性；普通经验外层不再读展示集合，实际升级再读职业及完整角色 | 角色和账号归属、等级/经验/SPTP版本、永久升级审计、完整事务提交后回包 |
| 击杀任务 | 活跃ID及必要父任务依赖读取、单次请求复用、按改变ID/Extra键提交、受影响记录读回 | States对同ID Progress的遮蔽、旧状态别名、奖励和完成回执、写入前乐观校验；写入或失败即使请求快照失效 |
| 宠物成长 | 当前宠物成长字段及有界去重窗口增量写 | 原事务内读取和锁、跨宠物去重、128条窗口、旧序号迁移、失败整体回滚 |
| 账号活动 | 事务包装转发单键metadata能力，在线状态只写改变的键 | 原账号/角色权属和邮箱同事务；在线时长持久化仍为30秒 |
| 主背包 | 金币槽/契约预检请求内复用；到期事务提交成功后复用其角色、背包和共享容器快照构包 | 不跨请求缓存；每次仍核对到期和契约；失败不暴露未提交快照；权威空背包不复活旧导入物品 |
| SQL | 有上限的固定形状预处理复用，默认64、0关闭、最大1024 | 事务使用当前连接，事务新语句不再向连接池申请额外连接；保留驱动编码；大动态批次不占缓存 |

活跃任务SQL使用现有角色/状态组索引筛选候选，然后用既有Go状态规范再次验证。历史完成任务不再全部传到Go或复制其Extra，但数据库仍需检查该角色的状态行；本改动没有创建新的状态索引，不能宣称数据库扫描量已经与历史数完全无关。

请求快照属于单一串行操作，不可跨会话、并发goroutine或下一次请求复用。未接入可选窄读/差量写能力的存储实现继续走完整兼容路径。清图和子任务激活中需要全历史状态头的路径保留原语义。

## 可观测性

桥接耗时使用17个固定类别，包括队列等待、事件执行、wire锁和实际写出、op39、成长/主死亡通知/任务/清房，以及入队至主死亡写出、公会排行和红包轮询。没有玩家、SQL正文或任意opcode标签。300ms以上的慢样本每类最多10秒一条，使用单调时间限频。

SQL记录池/事务两个固定路径和六种操作，查询耗时覆盖消费结果集；另记事务从成功Begin到首个Commit/Rollback结束的寿命。池等待、读取行数、累计分配字节/对象、GC暂停和GC CPU占比帮助区分等待、数据量及分配成本。事务错误指标表示SQL结束操作的错误，成功Rollback不等于业务请求成功。

四类签到补偿定时器按账号分散在30秒内的不同相位。领取即时校验和原在线时长持久化周期不变。没有用跨请求缓存跳过可能受GM、邮件或其他角色影响的状态。

公会排行、红包轮询批量、网络发送顺序和连接处理保持现有规则。上线后按固定指标观察再决定批量读取、退避或慢连接隔离；不预先关闭功能、调整GC/持久化、扩大连接池或丢弃战斗消息。

## 验证与解释

领域和桥接测试覆盖版本冲突、存储故障回滚、权属、历史保留、响应金币、提交快照隔离、空背包/旧导入边界、签到相位和慢样本并发预算。

`mysql_integration`下的真实MariaDB测试须使用显式开启的loopback隔离库，不得指向玩家数据库：

- `TestRuntimeDeltasDisposableMySQL`：成长/升级/重放/回滚、账号与邮箱同事务、活跃任务依赖与历史保留、宠物窗口和旧序号。
- `TestPreparedSQLDisposableMySQL`：预处理与驱动插值对照，覆盖中文、转义、NULL、时间、二进制、大整数、重连和回滚。
- `TestRuntimeMixedDisposableMySQL`：六个独立角色并发执行任务与成长、宠物饱食度、合成背包扣发事务。固定数据量、操作数和计划间隔，校验最终状态并记录SQL字节/次数、操作耗时及分配。

混合测试没有运行完整游戏会话、组队协议、开盒随机奖励或客户端。它不能证明公网延迟、op39→op38目标和组队画面已验收。比较时必须同时记录实际完成吞吐；旧版本落后于计划间隔时不能称为双方实际吞吐相同。CPU采样和分配profile可能包含初始化，计数窗口及其限制须与结果一同保存。

### 本地真实数据库对照

2026-10-31在隔离MariaDB 11.4.13、8连接池、六个工作协程上完成两轮交错对照，两边均为GOMAXPROCS=2、GOGC=30、GOMEMLIMIT=1536MiB。基线为公开提交`a59d3d41`，两边使用同一合成夹具和正常优化编译；每个角色有674条任务、约4000条Extra、70条无关角色属性和128条宠物去重记录。两次候选和两次基线均完成240个操作并通过最终状态检查。

| 同量操作的测量 | 基线两轮 | 候选两轮 |
| --- | --- | --- |
| SQL Questions增量 | 414,241 | 19,705 |
| PREPARE / EXECUTE增量 | 413,600 / 413,600 | 2,032 / 19,064 |
| 数据库返回字节 | 约115.36 MB | 约4.09 MB |
| Go累计分配字节 | 约846.84–846.96 MB | 约53.29 MB |
| Go与数据库累计CPU时间合计 | 114.05–116.28核秒 | 2.66–3.23核秒 |
| 完成240操作的墙钟时间 | 44.73–49.12秒 | 1.97秒 |

计划间隔为每个协程50ms；基线未能跟上，因此这是相同输入和操作数的容量/成本对照，不能描述为双方维持了相同实际吞吐。这里的毫秒与CPU结果限于本地Windows、loopback、合成数据及领域事务。真实服务队列、组队消息及客户端还需部署后的指标与实机回执。该结果支持先合入读写缩减，不构成调整生产GC、网络布局、排行或红包行为的依据。

另以只替换测试夹具的Go overlay补做固定速率对照：同样六个工作协程，每个协程每3秒执行一次、共20次，前后各120个操作，均在60秒计数窗口内完成并通过最终状态核对。生产源码保持不变，使用上述相同数据库、数据规模及运行参数，按基线→候选运行一轮。

| 相同60秒、120操作的测量 | 基线 | 候选 |
| --- | --- | --- |
| SQL Questions增量 | 207,121 | 9,865 |
| PREPARE / EXECUTE增量 | 206,800 / 206,800 | 1,032 / 9,544 |
| 数据库返回字节 | 57.68 MB | 2.05 MB |
| Go累计分配字节 | 423.42 MB | 26.71 MB |
| Go与数据库累计CPU时间合计 | 64.47核秒 | 1.45核秒 |

固定速率补测仍是合成领域事务，不是完整组队或客户端负载；不能将单轮CPU比例作为正式服收益承诺。候选任务与成长组合操作P95约40ms，基线约2002ms，这也不是op39到op38的时延。隔离库在检查完成后关闭，未使用玩家库。

公开MR合并及群服CI同步均不等于部署。最终发行仍需最新权威主干的干净检出、实际成功pull、必要测试和固定提交构建，再按目标环境要求切换及读回。
