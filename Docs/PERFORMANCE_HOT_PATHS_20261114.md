# 游戏热点查询与分配优化

本批从公开主干 `44e34822b5c57fe528a6a53c0dc26bc51de17d3e` 实施。目标是减少普通操作附带的数据库工作、重复聚合和对象分配，并在短时拥塞时保留健康连接。生产收益需切换后在相近在线人数、活动和采样时长下复测；以下数字来自 Docker 内隔离夹具。

## 本批改动

| 路径 | 原行为 | 当前行为与约束 |
| --- | --- | --- |
| 收包与升级奖励 | 每个包结束后探测自己及队友，满级幸运状态还会等待资产锁 | 普通包不再触发奖励查询；提交成功后将角色 ID 放入有界队列，合并处理；保留启动和 30 秒持久补偿。非幸运状态在获取资产锁前返回 |
| 奖励属性前缀 | 对 `stat_key` 调用 `LEFT` | 使用转义后的 `LIKE 'level=_up=_event=_%' ESCAPE '='`，下划线保持字面含义；具体执行计划仍取决于索引及数据分布 |
| 地图读取 | 战斗、移动的局部读取复制原始地图语法树 | `RuntimeScene` 只复制玩法字段和动态对象，移动诊断使用标量位置；需要原始语法的调用继续用 `Scene` |
| MySQL 参数 | 显式预编译缓存和驱动临时 PREPARE/CLOSE | 默认驱动参数插值，跳过额外 prepared wrapper；显式 false 可回退。危险多字节字符集不自动插值；保留驱动编码校验 |
| 数据库池与批量 | 未配置的 idle 与 open 不一致，默认单行插入 | idle 默认跟随 open；默认每批 200 行，仍受语句尺寸上限约束；不扩大 open 默认值 |
| 背包和穿戴 | 部分事务没启用背包增量，装备 SaveFields 重写整个集合 | CharacterAssets、Rental 启用增量；装备比较同事务完整前像，只重写改变的条目；缺前像回退完整写入。CeraShop 原已有背包增量 |
| Buff 快照 | 只读事务内含 `FOR UPDATE` | 同一个 Repeatable Read 只读快照，读取当前写库；inventory、pet、legacy 底层读锁一并去掉；资产变更事务仍持锁 |
| 城镇坐标 | 收件人队列满会断开 TCP | op22 合并同 actor/双方 presence 代际的最新坐标，队列满可丢弃；场景进入/离开仍有序，真实 socket 写失败仍关闭损坏流 |
| 日志和定时器 | 关闭包日志仍构造字段并争锁；无争用路径也创建 timer | 关闭日志快速返回并保留应用诊断；wire TryLock 快速路径、复用嵌套预算，eventloop 仅在队列满后创建重试 timer；取消和写超时保留 |
| 冒险团 | 摘要读取全部角色聚合 | 只读等级与荣誉经验；一次投影内复用，完整列表接口保持 |
| 好友过门 | 在线归属未变仍广播、重读自己好友列表 | 按账号/角色/代际/频道/在线归属短路；自己的列表 30 秒内复用。邀请包仍发送，成功关系变更即时刷新，失败不建立成功缓存 |
| 公会广播 | 每个收件人分别读取管理和名册，全员摘要重复加载 | 一轮广播共享不可变成员展示，合并管理/名册读取；各收件人仍在自己的 RR 事务内核验 registry 版本与身份，版本改变即重建 |
| 公会婚礼 | 为婚礼检查读取完整角色 | 单独读取身份和完整 `wedding_v1_` 属性命名空间，保持婚礼判断所需数据 |

明确设置 `performance_profile: "shared-4c-16g"` 才采用游戏容器 10g、GOMEMLIMIT 8GiB、数据库容器 3g、buffer pool 1g。原小机器默认值不变；显式配置覆盖模板。buffer pool 必须留出数据库进程内存余量，不能把 1GiB buffer pool 放进 1GiB 容器。模板改变不代表已更改某台机器。

## 隔离验证与测量

- Docker Linux：领域全量、bridge 全量、控制入口、logic/dnf、vet；实际 MariaDB 11.8 夹具验证回滚、提交通知、前缀、参数转义及 Buff 并发快照。
- 4 角色冒险团等级读取：完整角色路径 **17 条 SQL / 817 行**，窄投影 **1 条 SQL / 4 行**；荣誉经验另走窄读。
- 200 次参数操作：普通 database/sql 路径 **200 次 PREPARE**，prepared wrapper **2 次**，插值 **0 次**；`NO_BACKSLASH_ESCAPES` 同样通过，包含中文、引号、NUL、二进制及 uint64。
- 合成地图：`Scene` **7541 ns/op、22608 B/op、11 allocs/op**；`RuntimeScene` **1117 ns/op、752 B/op、8 allocs/op**。
- 关闭包日志：旧路径 **282.4 ns/op、200 B/op、2 allocs/op**；新快速路径 **14.17 ns/op、0 B/op、0 allocs/op**。无争用 wire lock **10.05 ns/op、0 allocs/op**。
- 190 人公会，两位收件人：全员摘要 **190 + 1 行**，第二位只校验自己；移除成员后拒绝使用旧快照。各收件人的版本查询仍存在。

这些是特定路径的结果，不能相加成为整服 CPU 降幅，也不是百人游戏验收。

## 与交叉报告及 A21 对账

最新主干的拍卖搜索已有 listing 前缀只读投影、空查询不建 escrow、五类查询在市场锁外发送响应，以及独立维护任务。这些属于已有实现；历史行情读取和独立订单表仍需继续优化。

当前 SQL 观测器已采用原子累加，不能把通用 metrics API 的排序与锁开销直接算成每条 SQL 的实际成本。本批保留现有计数，便于上线后比较。

`activity_events` 的唯一事件键参与防重；插入事件与更新计数属于同一事务，重复请求还要比较原事件内容。把它直接改成异步日志或按日期删除会破坏防重及奖励一致性。本批不执行这种转换。

A21 参考提交 `1870c85860375f7232a022b6b1b98e78cf840e4f` 的 `Game/Progression/CharacterProgressService.cs` 中，`PersistLevelAndExp` 仍执行 SQLite 查询及事务更新；`OnlineInventoryMutationCommitCoordinator.cs` 也保留 dirty 保存、提交与回滚协调。可借鉴的是脏状态、租约及恢复协议，不能概括成所有杀怪与经验更新都为零 SQL。参考仓库：[ServerS4A21](https://gitgud.io/rewio/ServerS4A21)。

## 后续架构及实施验收

下面四项尚未实现，不包含在本批热路径修复中。

1. **跨请求外观快照**：新增不可变 wire/projection DTO，键包含角色及绑定代际、频道 owner、资源版本、装备/时装/技能/Buff/婚礼/冒险团版本。数据库事务同时更新 durable revision；游戏、GM、离线工具使用同一写协议，旧写入口纳入审计。只有版本一致才复用城镇三轮和副本六轮重发；身份/房间/队伍/原生回执仍在发送前校验。现有 `repositoryMemo` 返回可变聚合且只有单次调用生命周期，不可直接挂到 session。验收要求并发换装、同秒多次写入、换号重连、跨频道、GM 改名、进出房 ABA 时不发送旧快照；稳定输入才达到一份构造、多收件人复用。
2. **公会关系表**：分出 guild、member、entitlement 与事务版本；先回填及双读比对，再改读路径，最后迁移写入口。旧 JSON 保留用于回退直到双读验收；踢人/解散/权限变更必须与版本提交原子一致。验收是在成员变更与广播并发时不越权，并消除逐收件人的大 JSON SHA2 探测。
3. **拍卖与历史归档**：订单、物品托管、领取回执、行情历史分别建索引；使用操作意图、资产凭据、最终状态和恢复扫描，迁移期间避免双花。活动流水先分出永久去重事实与可归档载荷，保留原语义要求的重放比对信息；归档须证明老事件重放不会再次奖励或更新计数。没有这项证明不启用删除任务。
4. **房间进度租约**：角色/房间持单写者 token，累积经验、普通任务计数、耐久和宠物变化；以确定性事件 ID 记录恢复日志，按房间边界原子应用并更新 applied cursor。掉落资格、升级奖励、任务完成、跨玩家资产和换号退出均要规定刷盘顺序。当前已有最多 32 怪的 death burst 合并，可先测其覆盖率。验收包含提交前后崩溃、超时未知提交、租约失效和重复结算；不能只延后 Save，否则会出现物品已到账、资格或消耗回退。

独立 GM 的自动福利与统计扫描应在其私有仓库单独核验：已有有界扫描不等于查询足够窄，禁用无活动扫描、按活动水位重扫及窄角色枚举是后续落点；私有实现不随公共修复回流。

## 切换与验收

先完成公开贡献、私有累计、最新权威拉取、正式 Linux 新构建、预传、备份和冻结。用户触发切换后，核对实际版本及健康，再比较相同窗口的 CPU、分配速率、SQL 按类行数、PREPARE/CLOSE、连接等待与游戏排队分位数。覆盖四人进图/过门/换装、好友上下线、公会变更、升级邮件、背包修理和 Buff；编译成功不代替游戏验收。

程序回退恢复旧程序与配置，保留玩家当前数据库。本批没有数据库结构迁移。
