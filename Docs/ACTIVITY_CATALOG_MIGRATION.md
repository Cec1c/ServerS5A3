# 活动配置更新与进图失败处理

活动规则来自 PVF 的 `etc/chn_actionpointsystem.etc` 中 `private activity tasks` 和 `private activity rewards` 两节。指纹只覆盖解析后的任务、奖励；它不是整个 PVF 的文件摘要。

## 同一服务日更新或回滚

服务日按 UTC+8 每天 06:00 切换。角色当天第一次使用新规则时，在原有角色/活动事务中迁移，无需全服 SQL 批量改指纹。

- 8 个任务 ID 对应既有固定玩法事件。保存每项原始计数、完成标记、已获得积分和 3 档奖励领取位。
- 已完成任务保持完成，配置提高目标或修改积分不会取消完成、扣回积分或再次计分。
- 未完成任务保留计数；降低目标后，已满足新目标的任务按新规则完成并计分一次。
- 配置来回切换不截断计数，不重复计分。客户端显示已完成任务为当前目标值，数据库保留原始计数。
- 已领取的同日同档奖励保持已领取，不补差、不重复发邮件或代币；未领取奖励使用当前配置。
- 保留的积分使用整数账本存储；客户端 16 位积分字段最高显示 65535，领取资格按完整存储值判断。
- 次日按原规则清零当天进度、领取位和迁移账本；钱包及已经发出的邮件不撤销。

已知历史配置可校验原规则下的状态；缺少历史规则快照的旧指纹保留已有持久化事实并校验数值/标记范围。损坏的状态仍报错，不使用清零或强改指纹掩盖。历史 017→011 规则变更也保留已经取得的积分，不再按新权重扣减。

迁移账本使用原 `dnf_character_stats` 的 `private_activity_v1_carry_*` 键，无新增 SQL 表。事务失败时迁移与奖励、疲劳写入一起回滚；旧界面的领取请求仍按服务日与指纹拒绝，刷新后再领取。

## 升级与回退约束

先更新到支持此迁移的服务端，再切换活动配置。同日回滚 PVF 时继续使用支持迁移的服务端；旧可执行文件不了解迁移账本，不能保证读取迁移后的当天状态。原始规则文件与数据库备份仍用于核对，不直接覆盖玩家后来取得的进度。

不要全量改指纹，也不要只删指纹键：这些操作不能迁移积分、完成与领取语义。此前手工改过指纹且没有原始状态备份的记录，无法由新代码推断其历史规则。

## 进图失败

普通选图请求在副本运行时提交失败后，通过已有原生 op16 拒绝协议结束客户端等待，并显示失败信息。已经有活动副本的重复选图及明确保留的旧兼容模式继续遵循原有静默规则，避免破坏已进入的副本。

设计取舍：仅替换指纹无法表达旧积分与新权重的差异；清零会损失玩家进度。因此使用按稳定任务 ID 的一次性计分账本，保留既有事实，并继续在原事务内提交。

回归覆盖配置升级、回滚、目标升降、积分与领取保留、并发领取、事务失败回滚、06:00 换日、原始进图提交失败和修复后重试。没有以清理角色数据作为恢复步骤。

## 既有组队结算限制

普通组队入场沿用队员先提交、队长后提交的既有顺序。这里的队员回滚只清理内存运行时；如果队员已完成持久化结算、随后队长提交失败，已提交的队员扣费和活动记账不会被整队撤销。本次补齐拒绝响应不提供跨成员原子结算或自动退款保证。故障重试前需核对实际结算记录，不能用恢复旧角色快照覆盖玩家新进度。
