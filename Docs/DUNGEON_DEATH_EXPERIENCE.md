# 连续击杀、经验结算与累计保护

连续普通怪死亡请求在同一连接串行处理。即使单只怪已先收到死亡通知，逐只读取任务、提交经验及清房仍可能推迟后续死亡请求；首次通用掉落池整表加载会进一步放大等待。

## 处理边界

- 仅收集已经到达的连续原生39，最多32条，不增加静默定时等待。NPC分解与副职业提取保持优先匹配、各自事务和实际消费数量；半帧、坏帧、EOF及其他协议保持原顺序。替换登录逐条复核。
- 普通怪仍逐只校验死亡、掉落、任务与加成。每只奖励按原公式及取整规划，在同一会话事件内集中提交；升级门槛、清房、领主、故事推进和错误出口排空队列。团本、锦标赛和公会练习场继续各自生命周期。
- 死亡通知可以先发出，经验状态只在成功提交后发送。连接写失败仍结算此前已接受的击杀；失败事务不发布预测经验。组队通知、故事强制清房、重复死亡及退出边界保持。
- 未满级升级使用已经提交的真实等级计算后续掉落、经验及SP/TP。满级普通EXP保持原值，溢出继续进入熟练度及冒险团胶囊，角色与账号增量在同一事务内提交。饱和EXP仍以受保护统计版本防止漏记或重放。

## 累计和持久化

| 范围 | 保存规则 | 保留的校验 |
| --- | --- | --- |
| 账号元数据、角色额外属性 | 同一结算事务完整锁读后比较前后值；仅保存变化键 | 账号归属、角色主行锁、原子提交、永久升级及领奖事实 |
| 技能点 | 独立技能点投影，经成对窄读写保存；未变化点数不重写 | 技能页头、归属、页码、SP/TP及版本；不覆盖技能、双技能页或布局 |
| 任务物品 | 原物品事务完整读取后推导真实变化槽 | 原概率、难度、上限、堆叠、容量和提交后刷新；失败完整回滚 |
| 宠物成长与饱食度 | 保留两个原事务，只保存成长字段和有界清房回执 | 进化、增删实例和神器变化回退完整保存；通知使用成功提交的独立快照 |

快照不跨事务保存。不完整读取、失败读取、历史影子属性、不支持的能力或后续保存保持原完整路径。所有主表镜像、额外属性、槽位RawEntry及Extra仍以原权威规则保存；不修改数据库结构、连接参数或持久化可靠性。

任务判断逐只窄读实时编号和状态，分别按原PVF目标筛选消费者。主任务可能激活子任务、同步父进度，定义缺失、查询失败或仓储无窄读能力时保留完整流程。普通掉落、称号触发和其他统计消费者继续原命令边界。

通用掉落池及四类静态表提前装入实际怪物目录缓存，不消费随机数；保留缺表降级、启动取消及后续抽取结果。

## 冒险团页面

骁勇结晶条目分别发送结晶数量和经验余数。成长胶囊容量按PVF单个容量乘累计数量计算，领取预告发送下一次领取实际发放的经验点数；不补造历史经验。连续获得、达到容量、领取、持久化重载和领取后继续击杀使用同一账号权威状态。其他玩家资料查看继续复用上游只读投影。

## 诊断与验证

慢请求分别记录读块消费等待、同批完整帧等待、死亡处理、经验与宠物及任务入包事务耗时。计时不保存SQL、参数或原始协议数据；不同起点的最大值不能相加解释为某只怪的客户端白光时长。提交计时包括数据库往返及调度，不能单独称作磁盘刷盘时间。

回归覆盖未满级、跨满级、熟练度与胶囊、账号并发累计、版本和重放保护、SQL完整关系行等价、逐步写失败回滚、任务目标和物品上限、技能页数据、宠物回执窗口、通知失败、输入分片及其他协议穿插。真实PVF专项覆盖经验、冒险团、任务物品、普通掉落、预载随机流、宠物、升级和共用锦标赛入口。

源码回归、资源验证、实际部署和游戏体验分别记录；测试通过不等于全部职业、任务或客户端视觉场景均已实机验收。
