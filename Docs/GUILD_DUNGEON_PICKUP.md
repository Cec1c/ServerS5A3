# 公会勋章地面拾取

公会勋章使用 list38 的 0..48 格，守护珠使用同一容器的 49..97 格。地面掉落的 scene slot 必须非零，但库存槽可以为零，不能共用前者的校验。

此前第一枚勋章被分配到 38:0 后，库存行构造仍调用拒绝零 scene slot 的函数，事务回滚且没有拾取成功回包，原生客户端的单次拾取等待没有清除。即使已有勋章、分配到正数槽位，随后的物品更新也误写为 list0；通关收据同样只搜索主背包。

修复保留地面 scene slot 非零约束，为已支持的专用容器构造实际库存行、允许勋章第0格的拾取回包，并按 list38 刷新。重复请求只重放原通知，不重复发奖。通关时对照冻结的拾取回包和完整实例行校验专用容器，不将其混进主背包奖励行；缺失行、错误容器和仅模板相同但实例行不同的其它勋章不能代替收据。

回归覆盖首枚、同模板第二枚、守护珠、后续普通物品、重复请求和结算。`DNF_WORLDMAP_REAL_PVF_SMOKE` 指定真实归档时检查耀眼勋章；现用资源为物品100380023。客户端原生回包处理接受第0格，本修复只修改服务端，无需改EXE/PVF或数据库结构。候选完成回归不等于已经部署或完成游戏验收。
