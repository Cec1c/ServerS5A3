# 决斗系统阶段记录与续修入口

本阶段整理普通决斗、无双决斗、每日任务、风铃训练和独立技能页。房间、对战与任务规则属于 `internal/modules/dnf/pvp`；报文、会话和当前客户端适配属于 `internal/services/dnfbridge`。公开分支基于权威上游提取业务增量，保留上游公会、拍卖和任务的新逻辑。

运行环境的客户端、资源、配置及原始玩家报文不随源码提交。本记录提供可公开的行为说明、协议关系和排查入口。

上述修复没有通过直接修改玩家任务、技能或装备存档来制造完成状态。

## 协议与数据约定

- 入口按频道目录的 `pvp` 分组判定。现有无双类型判定仍用于相应玩法；它不能代替整个 PK 频道的技能和装备入口判定。
- 部署目录必须实际包含相应频道和有效等级窗口。本分支不发布本机频道配置，不用虚构目录行让入口显示。
- 普通入口的 class0/800 是既有角色场景快照；三角色阵容使用同号的另一种载荷。不要在这两个发送入口之间互换包体。
- class1/195 用于入口可用性；class0/323、578 为每日完整及增量任务；class0/504、505、506 为匹配资料、配对及状态通知；class1/520、521 为排队和取消应答。
- class0/1229 为训练选择状态，1230 为两页备份；19 为技能窗口刷新。客户端上行 1266 表示复制选择，1267 为秘籍领取，377 为姿态上报；不要把客户端上行编号当作同号下行开放要求。
- 28、29、491、260 在 PK 频道使用独立技能仓储。当前请求仓储视图在角色归属校验之后建立；不能将其写回全局普通仓储。
- 独立技能继续使用 `character:<id>:pvp_dojo_skills_v1`，保留历史存档。更改域名需要显式迁移，不能在进频道时重新复制普通页覆盖旧 PK 页。
- 1266 的确认复制与选择标记在同一事务提交；复制 PK 当前页到普通当前页，另一页保留。模式 2 只保存关闭选择，不能把整个频道切回普通技能。
- PK 切页只改变独立页索引，不改变普通 `skill_tree_index`。自身和对手资料、19、37 及角色活动页元数据使用同一个频道口径。
- 返城原位标记为 `pvp_return_origin_v1`，坐标字段前缀 `pvp_return_`；仅保存角色本人已提交、经 PVF 地图和坐标校验的普通位置。历史记录缺少原位时沿用已有房间回落，不能补造旧坐标。

接收开关属于客户端配套条件。本次源码贡献不发布或修改 EXE，也不新增网络端口；接收许可存在不代表包体、业务和多人流程已全部通过。

## 每日任务与奖励的明确口径

- 服务日边界为北京时间 06:00；角色、日期及 PVF 权重决定分配，同日稳定，跨日允许再次抽到相同任务。
- 当前资源前三池分别有 3、11、3 项，第四池只有 134。界面第四格显示卡片不等于斗兽场进度已接通。
- 131 按数值解释为两组、每组三连胜；132 为三组、每组一胜。失败和平局清理未完成组的连胜，已完成组保留。部分资源文字与数值冲突，资源文字未在本次修改。
- 133 采用资源数值的一轮、三种不同姿态，完成后一次发 100 印章；不采用冲突文案中的两轮。只信任服务端已提交的排位胜者和最近结果，拒绝场外、失败方及重复姿态包推进。
- 134 的定义是斗兽场胜利目标及物品奖励；普通排位、练习和风铃训练不冒充斗兽场胜利。其物品入库事务可独立验证，玩法入口未接通前不能宣称可正常实战完成。
- 秘籍 10158452 与 2674 的 2 TP 是现用资源和客户端显示已核对的特例。其它空 `[tp]` 数量不能猜测沿用 2。
