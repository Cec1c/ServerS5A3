# 魔法封印装备的拍卖上架请求

魔法封印装备可以只填写一口价上架。原上架解析器将 op183 最后 9 字节当作全零保留字段，导致客户端发送魔法封印属性时在解析阶段失败，显示“最低竞拍价或一口价中输入了错误数值”（错误码 152）。

## 当前客户端契约

本次核对的 x86 EXE SHA256：`5ce2ce3f01dacd05a6ce542d088911cc4fceb0f44ffa85dfa3a0886339e7cb5c`，首选基址 `0x00400000`。

| 入口 | RVA | 依据 |
| --- | --- | --- |
| 上架 sender | `0x02eea7a0` | VA `0x032ea7a0`；写入 op183 与固定字段，再调用属性尾部编码器 |
| 价格校验 | `0x02eea540` | 允许竞拍价或一口价单独填写；不允许两者皆空、负价、竞拍价高于一口价 |
| 属性尾部编码器 | `0x02ef7c10` | VA `0x032f7c10`；op183 固定写三组 `u16 option + u8 value` |

请求 body 长度仍为 37 字节：

```text
u8 pay, u8 container, u16 slot, u32 item_id, i32 count,
i32 start_price, i32 instant_price, i32 unit_price, u32 hours,
3 * {u16 option, u8 value}
```

未解除魔法封印时，尾部编码分支 `0x032f7c99` 写出三次 `{30000, 0}`，即 `307500307500307500`。已生成属性时按三组写入，缺组补零；普通物品的尾部为零。它们都是同一长度的合法请求。

真实 PVF 中的 `100170220`（密制花岗岩条纹肩铠）具有 `[attach type] [free]`、`[random option] 1`、`[price] 60900`，交易资格无需修改。PVF SHA256：`4bd851752f2d02c229d89f4959571e2d1d9ac41bdd7bdf876f38c36dc22526f5`。

## 修复边界

解析器保留固定长度、价格、数量、时长和容器约束，移除属性尾部必须全零的假设。尾部只是客户端提供的属性摘要；托管、展示和返还继续使用库存中原有的 `ItemStack`、`RawEntry` 与 `Extra`。客户端填入的属性不参与物品生成或更新。

锁定、过期、不可交易、库存物品身份与数量检查，以及押金和托管事务沿用原逻辑。无需修改 PVF、客户端或存量装备。

## 验证与验收

- 有限原生执行覆盖未解除魔法封印、普通装备、只填竞拍价、同时填写两种价格及已生成属性的尾部编码。UI、RTTI 和传输使用适配器；已生成属性用例替换了属性收集向量，未执行完整客户端界面。
- 回归将原生生成的上架请求交给正式 handler，检查托管、一次押金、重复请求、取消退信与装备元数据保留；异常长度和原有价格/容器约束继续拒绝。
- 部署后的实机验收：分别上架未解除和已解除魔法封印的可交易装备，只填写一口价；确认搜索/本人列表，再取消并领取退信，核对属性。普通材料和锁定装备作为对照。

本项为服务端修复，发布与实机验收另行记录。
