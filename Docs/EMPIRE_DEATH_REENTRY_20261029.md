# 帝国竞技场死亡接替与休息室重入

单个队员死亡后，旧桥接层保留死亡角色为当前出战者，要求普通切人请求才能继续。当前 V195 的键盘输入在角色 HP 为零时已提前退出，因此不会发出这个请求。另一方面，休息室保存成功的应答清空客户端战斗身份缓存，旧入场创建没有重新安装该缓存，导致回城后合法同区队伍被识别成无效区服。

修复有三部分：

- 领域层只在战斗中、当前队员已确认死亡且另一人存活时接替；死亡接替不受生前手动切人冷却阻塞。保持死者 HP/MP、回合和奖励不变，普通手动切人的冷却继续生效。
- 桥接层记录专用死亡事件后，单人死亡只投影存活队员，全灭才发送失败倒计时应答。重复死亡不再次交接或启动倒计时，写失败沿用原补发机制；全灭不补发旧切人，成功离场后退休未完成的战斗切人状态。
- 入场预检冻结本体在前、备用在后的四字节名单，并在创建战斗角色前发送该名单。数据库的用户设队顺序不变；免费重入也安装完整身份，不能依赖上一次打开设置窗口留下的缓存。回城仍等待实际城镇请求，不能紧跟回城包发送会销毁旧战斗角色的名单。

匹配客户端为 V195，SHA256 `ab82e1d747c3018f97fac7c3f2c0f2f787f70a10db8a2be7904bf63199ac09ff`，没有修改 EXE。

后续实机反馈确认自动接替已生效，但旧死亡成功应答仍启动约10秒倒计时并强制回城。精确 V195 的 `1466` 成功接收器 `1456140` 调用 `2262810(2)` 设置失败状态，再由 `2261750` 置自动退出标志；`2262F33` 到期后实际构造并发送 `42`。它不是普通的“死亡已收到”应答，也不是换人等待标志。修复为仅在领域状态 `Defeated`（两人全灭）发送该成功应答；单人死亡只通过 `1402` 接替，重复事件仅补未完成的换人投影。手动放弃和全灭回城仍使用原流程。

补充验证执行完整死亡成功接收器、失败状态和计时器初始化，以及实际到期分支和42序列化；时钟输入、对话框装饰构造、角色/场景查找使用适配。旧“死亡应答+换人”在10秒后发42，单独换人两方向推进至60秒无退出；全灭与重复应答保留原倒计时且不延长或重复退出。服务端新增两种设队顺序、先死本体/备用与重复包的真实回包导出，供该原生链回放。最终GUI和实际操作验收仍单独记录。
