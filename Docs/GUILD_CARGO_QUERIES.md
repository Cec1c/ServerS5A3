# 公会仓库查询与 8 格初始化

本阶段接通 261 仓库快照和 262 历史查询。新公会或尚无仓库记录的历史公会，在首次合法打开时初始化为 8 格；上限从当前 PVF 读取，配套版本为 56 格。已有容量、物品和历史记录保留，重复打开不保存或重置。后续容量通过购买功能扩容，购买事务尚未接线。

访问要求绑定的账号/角色及会话代次有效、角色已进入实际公会大厅且不在副本、地图含正确的仓库 NPC，以及当前成员具备 bit15 仓库权限。检查场景和 PVF 后才进入 Guild 事务；事务内再次核对角色归属、成员和权限，保存前后复核会话。初始化失败或保存后的会话失效均回滚。

261 成功体在状态字节后为 `u32 capacity + u16 count + 119-byte item rows`；262 为 `u32 count + 57-byte history rows`。仓库实例保留数量、品质和扩展字段，拒绝超过原生数组边界的数据。历史只展示真实记录，最近 50 条，不生成示例物品或操作记录。读回不泄露其他公会数据。

`ReadCargo` 仍为只读接口；初始化必须显式调用 `OpenCargo` 并提供策略。持久化新增字段可缺省，旧记录按原结构读取。导入的存入、取出和交换事务原语保留；247/248/249 尚无生产路由，物品完整准入和网络重试防重尚待完成，不能据此宣称仓库存取已可用。

## 客户端依赖

V110 仍屏蔽 261/262 回调。生成器只开启这两个接收位并重算 PE checksum，其余字节不变；保留成员菜单和公告候选，以及既有 65、1474 接收支持。没有开启购买或物品转移回调。

```text
python scripts/client/patch_guild_cargo_queries_v110.py <成员菜单及公告组合候选> <新候选>
```

输入 SHA256：`d9533c44bf4147e9621ac47c45233b2985a95d3d4e808195a23a3e5e37755e52`。
输出 SHA256：`2deb9a1a02451c2b7d1c68e52a61aa3e13723a227f04c589806fa7f6245a7b6e`。

已保存的 375 个 IDA 代码范围与完整验哈 V110 相同，包含请求发送、权限、字段和回调；这是静态协议依据，不等于游戏窗口验收。三项真实文件测试核对唯一两位变化、checksum、拒绝未知输入/重复应用和写后摘要。

## 验证和发布

初始化回归在旧查询实现上失败，新实现通过。内存事务覆盖首次/重复打开、已扩容库存保留、跨公会隔离、权限和场景拒绝、保存/提交/会话失效回滚与并发。一次性 MariaDB 使用真实 SQL 失败触发器、独立仓储并发与重连读回验证初始化；真实 PVF 验证大厅 NPC 和容量上限。

规定领域、bridge、control 共 5622 项顶层测试通过，701 项条件跳过；list、vet、Windows 构建通过。仓库相关 race 91 项通过、9 项条件跳过；真实 PVF 两项及一次性 MariaDB 专项另计通过。跳过的真实环境用例不计入验收。
