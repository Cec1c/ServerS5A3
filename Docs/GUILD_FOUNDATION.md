# 公会基础链路

本实现覆盖创建认证、原子扣费、成员加入／申请审批、搜索与列表以及重登持久化。创建需要另一名在线且尚未加入公会的角色认可，并从创建者扣除 300000 金币。公会金库、战斗、退会及管理扩展尚未接入；不能把原客户端可见按钮视为后端已实现。

可显式开启单人创建：Docker 实例源配置设置 `"guild_solo_create": true`，对应环境变量 `DNFBRIDGE_GUILD_SOLO_CREATE=true`。默认仍为双人认证。单人模式名称检查成功后由服务端允许创建，玩家直接点击创建；不需要填写邀请对象，也不会生成虚构的第二成员。依旧原子扣除 300000 金币，名称、归属、已有公会、余额、取消和会话世代检查不省略；持久回执区分两种模式，重试不重复扣费。单人模式无需认证介绍，该字段可以为空。

### 匹配客户端的接收白名单

下述匹配 EXE 的接收资格入口 RVA `0x0336e6c0` 跳转到 `0x06a83610`，后者通过 RVA `0x06a83558` 的位图过滤回包。原版未允许名称检查 156、创建 68、认证状态 686 及多项成员列表；即便服务器返回成功且 TCP 正常，原生回调也不会执行。连续点击产生的两秒提示只是本地 UI 节流。

客户端兼容修订须先核对完整 SHA256，再仅补充已核对接收回调的公会位图和必要的操作码上限。原版 `2af985b6…` 的已验证白名单衍生版完整 SHA256 为 `e3fe061fd6918c11f2ddca7359498bcd7baf964c66600b2526fcec6323a24329`，共改动 12 个字节。保留既有允许项，其余操作码仍拒绝；不对未知 EXE 套用地址、不关闭全局检查。配套入口应校验原版／衍生版与 PVF，并在游戏退出后原子替换和保留原版备份。服务端上线本身不能替代这一客户端兼容步骤。

## 区服与登录入口

匹配客户端的创建认证下拉框枚举公告区服 1～249，公告为 0 时不会显示。Docker 实例源配置可增加：

```json
{ "channel_advertise_server": 1 }
```

由 `deploy/docker/manage.py` 生成 `DNFBRIDGE_CHANNEL_ADVERTISE_SERVER_INDEX`，不要手改生成的 env。省略该项仍为 0，避免未经协调地改变既有登录行为。源频道资源编号和角色存档 `server_group_id` 不随此项迁移。

**变更公告前，先使登录器支持对应目录编号和本机频道历史。** 有的入口固定检查目录编号 0，并在每次启动时恢复 0 号频道历史；仅改服务端可能阻止这些入口登录。测试应覆盖已有配置、新配置、原生配置校验、目标频道及回退，不能用 TCP 探针通过替代游戏内验证。

## 协议依据

静态依据为 x86 EXE SHA256 `2af985b6e344e5fdbb78f6598d40924f152af924a156f5d45b671bed350a9675`，ImageBase `0x00400000`。以下为 RVA；其他客户端版本须重新核对。

| 入口 | RVA | 本次确认 |
| --- | --- | --- |
| 创建认证区服枚举 | `0x03037b60` | 循环从 1 到 249，0 不进入候选 |
| 公会搜索发送片段 | `0x00dcdf14` | 操作码 1450 |
| 账号公会索引发送片段 | `0x00dd609c` | 操作码 1451 |
| 公会等级列表读取 | `0x01bd67c0` | 1452／1453 为首批／后续等级列表 |
| 成员列表读取 | `0x01bd2d10` | 成员行尾额外读取两个可选账号分组字节 |
| 审批加入回调 | `0x01bddae0` | 失败分支也读取角色标识和区服字节 |
| 公会身份通知读取 | `0x01c3fc50` | class 0／308，与命令 365 含义不同 |

保留当前客户端场景对象尾部的 `u16`；不能直接套用另一版旧源码的结构。可选账号分组当前使用客户端默认空值，没有实现账号分组管理。成员在线状态来自当前会话，不伪造在线成员。

## 存储与事务

公会聚合保存于既有 Settings 仓储的 `global:guild_registry:v1`。专用 `GuildUnitOfWork` 只允许访问该聚合和至多两名已核对账号归属的角色，不开放无关钱包或任意设置。MySQL 在首次创建时也锁定实际聚合行，随后按稳定顺序锁定参与角色；扣费、成员关系和创建回执同一事务提交。

连接世代与既有角色资产预约共同保护双方认证到提交的边界。提交成功但回包失败可重试，失败事务不留下扣费或半成品公会。内存仓储回归与一次性 MariaDB 真实事务回归分别验证，环境跳过不算数据库验证通过。

## 验证与实机待验收

自动化入口：`internal/modules/dnf/guild`、桥接层 `TestGuild*`、`deploy/docker/test_manage.py`。数据库测试仅使用隔离一次性库，遵循仓库的 `DNFBRIDGE_PLAYER_TEST_DSN` 约束。

实机至少需要两名在线未入会角色：名称检查 → 选择区服 → 邀请／接受 → 创建 → 核对只扣一次金币 → 另一角色加入 → 查看成员列表 → 退出并重新登录。还需检查拒绝／取消、断线重邀及既有频道登录。完成这些之前应保留“待原生验收”状态。

单人模式另测：一名未入会角色名称检查 → 直接创建 → 仅扣一次 300000 金币且成员仅一人 → 重登恢复。自动化已覆盖并发、重复请求、取消、身份／余额／重名拒绝和隔离 MySQL 的提交后重读及 SQL 失败回滚；实际按钮与画面仍需原生客户端验收。
