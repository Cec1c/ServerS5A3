# 剧情 APC 的被动对象脚本死亡兼容候选

用户问题：寻找阿甘左任务使用香料后无法完成并卡住。本文记录可复现的服务端兼容缺口；尚无原账号/原时间的这次任务死亡包，资源回放不代替原生验收。

## 实际资源

固定资源 SHA256 `ad7d05c70421278f7385729bcba3e81e37d99d0f3df85a87a9f0dc19c92504cb`。任务3213“寻找阿甘左”属于 clear map，目标53529、副本26，实际选择maze2。该map的AI行 `2004 810 264 0 [monster] [boss] 0 0` 表示角色目录索引2004、坐标810/264；不是第二个编号810264的boss。房间没有普通怪物，只有一个敌对阿甘左APC。APC不计普通阻挡列表，场景Cleared可先为true，但其权威死亡尚未提交。

AICharacter.lst的2004指向Cataclysm/Behemoth/Aganzo/Aganzo.aic；proc action为action/proc.act。实际触发2检测400范围内被动对象76328，执行ME行为2的SET HP 0。此前由HP<=50/monster team开启该触发；脚本另有香料提示。76328在passiveobject.lst中指向ActionObject/throwitem/perfume_powder.obj，名为“艾丽丝的香料”。目录编号与文件名是不同概念，不能以没有名为AI2004的文件推翻目录注册。

## 改动

仅official-24.9的严格variable/count0/owner=ffff形状可进入新判据。复用现有74字节基础解码（31字节前缀、39字节运行块及4字节原生完整性尾）；不修改解码器，也不把旧66字节夹具套入此档。

必须是当前会话角色拥有的run、对应地下城和maze、当前房间坐标/地图、已宣告敌对AICharacter及同一HostileReference，scene与map的AI行、元数据ID和START_MAP code都一致。教程命名空间保持排除。maze必须连接一条活动clear-map任务，任务目标正是当前map；任务仓储读取失败不接受新死亡。

从该APC真实目录定义读取proc action，只识别明确的WHICH PASSIVE / IS INDEX / 正半径 / CHECKED NO>=1 / DO PROC BEHAVIOR ME N，且行为N仅为SET HP 0。按顶层trigger/behavior切块，行为中的TRIGGER开关命令不另算块。不根据中文名或具体任务/地图/APC/物品ID放行，也不从HP比较、文本0、其它对象行为或缺失/非零/不完整脚本推导死亡。此判据证明脚本允许自置零，不声称服务端观测到了客户端触发实际执行。

接受后仍调用既有CommitActorDeathReport、op38和普通最终房间结算链，任务Phase A与通知沿原路径处理；不增加APC掉落，不人工完成任务，不发放奖励或物品，不生成香料。记录任务、动作路径、APC、被动对象和行为下标用于下一次现场定位。

权威死亡提交成功后冻结本run内的证明，绑定角色run/地图/坐标/reference/object key。重复或op38/后续写包失败只修复原死亡通知和未完成的既有结算阶段，不再次提交死亡或奖励。没有原证明的已死APC不进入新重放路径。运行期证明不写玩家表，不跨run/房间使用。

真实PVF重建任务3213的选图与跨房，定位map53529实际APC2004，输入一份通过现有official-24.9解码器的74字节兼容回放请求。旧处理器拒绝，新处理器提交唯一APC死亡、op38、既有结算入口，活动任务trigger持久为0。该输入是协议回放夹具，不是从原现场抓取；尚待用户游戏内使用香料复测原症状。

普通自动化覆盖严格角色/房间/ref/元数据/任务/脚本/请求形状反例、明确自置零解析与其它对象/非零/文字/不完整反例、op38与后续写包失败续发及重复不改角色资产。旧处理器红、新版绿和完整检查回执在外部round16目录。起初夹具误把坐标拼作第二个boss、又误用旧66字节形状，已修正测试并保留失败日志；那些失败不算旧版缺陷证明，以old-native-red及最终回执为准。
