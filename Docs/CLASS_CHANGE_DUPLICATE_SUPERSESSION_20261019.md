# 转职任务重复：已完成后继应隐藏较早分支

## 现场与真实资源

本轮以真实 `Script.pvf` 为准。资源 SHA256 为 `a56cacf96087ba34ca5299e04ab65f8268f694b214b97dec9879fdebf46f5290`。

现场报告同一角色同时可接「转职 - 精灵骑士」和「守护森林的战斗」，其它多个角色的初始转职也有同类现象。a56 中对应任务为：

| 任务 | ID | 前置 | 转职字段 | 奖励 |
| --- | ---: | --- | --- | --- |
| 转职 - 精灵骑士 | 12757 | 3155 | `[job change quest] 1` | `[grow type] 1` |
| 守护森林的战斗（骑士通用/精灵骑士分支） | 6986 / 6987 | 3153 | `[job change quest] 1` | `[item]` / `[grow type] 1` |
| 赛丽亚的决心 | 3155 | 3154 或 6930..7002 中任一森林分支 | 普通后续任务 | 无职业变化 |

`3155` 将每个职业的各个「守护森林的战斗」分支分别列为互斥的前置选项；完成 `3155` 意味着该分支已经被消费。旧 NPC 转职任务 12757 又以前置固定的 `3155` 作为入口。

## 根因

任务列表和接取预检仅按 `[collision quest]` 的已完成记录过滤。12757 的碰撞表没有点名 6986/6987，森林分支的碰撞表也没有点名旧转职任务，因此 `3153` 与 `3155` 都已完成时，两代入口会同时进入 op21。

活动中的互斥也只覆盖 `[reward type] grow type`。6986 是同样带 `[job change quest] 1` 的 `[item]` 占位分支，旧逻辑不会把它与同职业的另一个初始转职任务视为同一家族，因而还能先后接取两条。

## 修复

- 对 `[job change quest] 1` 任务检查已完成后继：若某个已完成任务的 `[pre required quest]` 直接点名该任务，则不再把该任务放入 `QuestList`/`Acceptable`，并拒绝新的接取。
- 该规则只隐藏尚未活动的较早分支；已经 active 的记录仍保留在列表中，可正常完成或放弃。
- 活动冲突按角色职业把同职业的 `[job change quest] 1` 视为一个初始转职家族，同时覆盖旧 NPC 链和森林 `[item]`/`grow type` 分支。该判据也经 `QuestList` 的接取预检生效，不只拦截最终 op31；普通任务和其它职业的记录不受影响。
- 列表、`Acceptable`、`DecideAccept` 和连接子任务预检继续共用 `definitionAcceptable`，避免“列表能看、点击接取被拒”的分叉。
