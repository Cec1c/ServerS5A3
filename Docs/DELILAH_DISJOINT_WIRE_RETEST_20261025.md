# 德利拉分解九字节正文保留 NPC 编号

当前 v173 模块 SHA256 为 `9886866b28aef3ab6f97789fca9ba09b359b499735e7a80b3ca0ac6d08041060`。

单件分解发送路径 VA `025F5B66–025F5C17` 写出 op26，以及 u16槽位、u8容器、i16工具槽、u32 NPC编号，共九字节。公共发送前处理 `0231EA90` 调用 `008C5CA0` 判断指令是否追加四字节校验；op26走零返回，不追加。原生片段及完整校验尾选择函数使用固定模块离线验证，op28作为会追加的正对照。验证边界为序列化与尾部选择，不覆盖物品校验、网络传输或玩家实机。

旧服务端 legacy normalizer 同时把九字节和十三字节请求剥去末尾四字节。实际九字节请求的 NPC1000 被删去，解析后 Context 为0，绕过德利拉500金币收费及通关资格检查。此前只有九字节正文加人工四字节尾的回归，不能证明当前线路正确。

修复保留完整九字节正文，只对历史十三字节兼容形状去掉额外尾部。五字节旧无NPC形状、批量槽位形状、upper入口、普通NPC317和个人分解机保持各自契约。费用继续由现有同一资产事务按每件500扣除，余额不足拒绝整笔，提交后仅刷新一次最终金币。

新增完整legacy请求回归与既有handler、upper及带尾兼容入口并列，覆盖单件、批量、恰好余额、不足余额、未通关、普通来源及重复请求。使用现用真实PVF；记录测试结果和游戏验收分别处理。原 MR 完整范围保留，不创建拆分 MR。
