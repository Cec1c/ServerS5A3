# v137 装备超链接请求 ACK 接收准入候选

## 缺口与改动

v136 的收包片段对 class1/424（装备超链接请求 ACK）返回 0：424 不在显式 class1 列表，共享 bitmap 对应位也为 0，因此该 ACK 在进入原生 consumer 前被丢弃。class0/370 已由共享 bitmap 原生放行，class0/371 维持拒收；本轮都不改。class0/1239 继续由 v136 的显式 class0 列表放行，class1/1288 继续由共享 bitmap 放行。

v137 只把 424 追加到现有 `.clsgate` 的 class1 显式列表。class0 列表、class0 1483–1491、class1 51/658/668/820/868/889、370/371 的原生判定、570/377/1266 的排除规则以及未命中尾跳 `0x376e6c0` 的原生 consumer 全部保持不变。没有修改共享 bitmap、类别切换逻辑或其它类别，也没有新增节或改变文件大小。

文件差异仅限：PE checksum 4 字节、`.clsgate` 节 VirtualSize 4 字节（217→228）、适配器正文 228 字节（旧 217 字节正文与新正文重叠部分被替换，随后 11 字节由零变为新增比较与跳转）。其余输入字节逐字节保持一致，因此既有交易、物品栏、穿戴、公会、字体列表等修复代码与数据均保持原字节。

## 验证

`test_patch_item_link_gate_v137.py` 对精确输入和输出镜像执行实际收包 call 片段，穷举 class 0/1/2/255 的全部 u16 编号，共 **524288** 次（65536 × 4 × 2）。结果：

- 唯一变化为 class1/424，`0→1`。
- class0/370 保持 `1→1`（原生 bitmap 放行），class0/371 保持 `0→0`（拒收）。
- class0/1239 保持 `1→1`，class1/1288 保持 `1→1`。
- class2 与 class255 的所有判定不变。
- class0 47/323/504/505/578/1229/1230、class1 51、class0 1483–1491、class1 658/668/820/868/889 保持放行。
- 每次执行均校验返回点为 `0x2523a18`、栈和 EBX/EBP/ESI/EDI 保留。

范围专项核对 RX 属性、节表、SizeOfImage、call 五字节、共享 bitmap、共享 gate 和精确文件差异范围；独立 PE 校验和与 Windows ImageHlp 校验均通过。负输入（错误 SHA/长度）、同路径覆盖和已有输出覆盖均被拒绝，已有输出保持原字节。

## 边界

本候选不包含真实游戏启动、发布、部署、玩家通道或玩家数据操作，不访问进程、服务器或数据库。原生 read/consumer 的正文布局及游戏内超链接显示由父线在最终预览中验收；用户验收后才进入正式发布。
