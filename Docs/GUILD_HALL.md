# 公会大厅准入与场景隔离

大厅使用运行时 PVF 的 `town/GuildAgit.twn` 和其 `Guildagit/*.map` 区域。大厅场景按城镇、区域、频道和公会 ID 分组：同公会同频道同区域可以相互看到；其他公会、其他频道及没有有效会员身份的角色不能进入该场景名册。赛丽亚房间继续使用角色 ID 隔离。

## 已实现的服务端边界

- 普通过图先核对当前连接、角色账号与公会会员归属，再落库和发送场景包；拒绝不改变持久位置。命令 36 的失败体保留客户端读取的目标 town/area 字段。
- 登录、频道重连和副本返回使用同一公会实例规则。读取会员身份失败时，不发布共享大厅名册，并撤销该连接残留的大厅存在。
- 组队的跨区域角色补发不能把另一公会的大厅角色重新放入本地场景；普通区域聊天沿用同一场景分组。
- 失去会员身份后，持久大厅位置在登录时回落到 PVF 中的赛丽亚房间，并清除失效的大厅返回目标。赛丽亚出门时再次校验会员身份，必要时使用该房间真实外门，避免旧会话快照绕过准入。
- 保留既有等级、任务、跨城请求形状与团队副本校验，不新增传送标记或硬编码落点。

## 验证范围

`TestGuildHall*` 覆盖同会/异会/不同频道、非会员、账号错配、会话替换、仓储读取失败、发送失败回滚、重登及赛丽亚返回、普通聊天和组队补发。`TestRealPVFGuildHallOwnershipAndCatalog` 使用配套真实 PVF，验证全部 13 个区域及既有 op36 形状的进入、内部移动和离开。

`TestGuildHallMySQLLoginMembershipAndRollback` 仅在显式配置一次性测试库时运行，验证新仓储实例读取会员关系、重登位置持久化及注入 SQL 失败后的完整回滚。原有单人/双人创建事务回归保留。

这些检查证明服务端处理与持久化边界。客户端实际大厅入口是否发出该 op36 形状、入口前置提示、画面及双玩家交互仍需原生验收。大厅 NPC、仓库、积分、基地等级和公会地下城结算属于后续独立功能，不因本次隔离修复而宣称可用。
