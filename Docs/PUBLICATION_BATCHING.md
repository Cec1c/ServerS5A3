可信开发者的本地通过声明与常规GitHub CI是两条合入路径，见[quick规范](TRUSTED_QUICK_MERGE.md)。下文ready CI规则适用于普通PR；quick不再等待或重跑云端验证。

# 小修复合批与发布阶段分离

多个已完成、可兼容的小修复优先保留各自提交，合入一个累计分支和 PR。先完成范围审查与必要专项，再将累计 PR 标为 ready，完整 CI 覆盖最终合并组合一次。未完成或依赖未满足的工作留在 Draft，不混入批次。

## CI

- Draft PR 仅运行范围和变更记录检查，不启动完整测试、构建，不产生完整验收绿灯。
- `ready_for_review` 触发累计组合 CI；ready 状态下新增源码会取消过时验证并验证新组合。
- 开发阶段可随时手动 `workflow_dispatch` 验证指定分支。普通 branch push、合并后的 master push 不重复全套。
- 同批子分支不再分别转 ready 触发重复完整 CI；累计 PR 列出子提交、修复、依赖和已有专项结果。每项 changelog 保留。
- 最终组合改变时，已有子分支绿灯不能替代新组合验证。合并后部署消费固定提交，不在部署端重复完整测试。

## 准备与切换

prepare 完成最新累计源码固定、正式 Linux 程序构建、目标端资源预放置、配置生成和回退准备。资源按 SHA256 寻址，相同内容直接复用。发送端记录长度与 SHA256；接收端计算摘要并返回小型 JSON 回执，禁止为算 SHA 再把整包搬回开发机。

解压、索引生成等变换在执行主机记录输出摘要。第三方存储未提供 SHA256 时如实区分上传协议摘要与自有存储 SHA256；不能标记为已执行全量下载。

切换仅消费冻结清单、接收回执和本次授权，在唯一执行者持有的窗口内变更运行指针。大文件传输、完整 CI、历史目录清理和普通数据库全量备份在切换前完成；运行程序与健康状态读回一次，由各参与者共享。未知任务查原现场，不另建任务重放。

准备好后等待用户已约定的切换通知，是执行时机开关。同一范围已获授权不增加重复申请；各部署环境沿用自身现有授权和唯一执行者协议。
