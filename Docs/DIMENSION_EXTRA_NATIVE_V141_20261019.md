# 异次元裂缝追加券原生入口

当前客户端将PVF动作`[add dimension dungeon enter count]`映射为156。道具使用先打开确认框，确认回调调用通用道具动作发送函数，形成op515的19字节请求。追加券没有`[use action packet]`段，不代表它没有原生发送路径。

本轮对完整SHA256为`26abf551753c2745c2e5b349fb24336422a189187ff847c995e0df9a68871079`的v141镜像只读核对并执行隔离原生回放。图像基址为`0x00400000`，以下明确列出VA，不能将它直接当RVA或套到其它客户端。

| 路径 | VA | 已证机制 |
| --- | --- | --- |
| 动作映射器 | `0x03ad7540` | 解码描述符`0x04d92290`对应动作文本，初始化映射的token为`0x2d8d`；真实运行分派表返回156。初始化的延迟映射模式使返回分支位于描述符前，不能仅按相邻字符串顺序推断。 |
| 使用回调注册 | `0x024f7320` | 原生注册表为156选择`0x024f5bf0`，后置回调为0。 |
| 道具初始化 | `0x024f8550` | 元数据`+0x444`的动作值写入实例`+0x550`，作为当前使用和回包动作。 |
| 确认框及回调 | `0x024f5bf0`、`0x024f8870` | 使用回调创建确认框，保存当前道具引用；确认结果0且引用验证成功才调用通用发送函数。取消、缺失或失效引用不发送。 |
| 通用发送 | `0x024edc40` | 检查当前道具、库存对象和槽位，再写入op515与19字节业务体。 |

19字节body依次是`slot:u16, list:u8, reserved0:u32, action:u32, reserved1:u32, reserved2:u32`。本路径三个保留值均为0，action为156。原生写入器分别消费u16、u8、u32；剩余数量、追加次数、等级、期限、冷却和材料费不来自请求。

隔离回放覆盖真实token分派、165项回调表初始化、实例动作选择，以及13组发送/确认边界：槽位和列表原始宽度、取消、缺失道具、身份验证失败、缺失库存对象和无槽位。发送函数的被调用者保存寄存器和栈保持。UI/world身份查找、虚拟库存/元数据查询、受保护物品编号读取、槽位/列表查询以及包上下文/叶子写入器使用夹具；没有启动游戏、模拟完整UI或把夹具称作玩家原始报文。

服务端仅在当前official-24.9路径接入action156，严格校验19字节、主背包、非负槽位和零保留字段。从该槽位实际道具的PVF读取追加量、最低等级、期限、冷却、允许场景及材料费；当前真实1次、5次券及材料券均走同一入口。事务内重新校验账号、等级、城镇位置、期限、冷却和精确道具，原子扣一张券及可选材料，并增加该服务日累计额度。失败不扣资产，冷却重放拒绝；已消费额度不会重新开放当天追加上限。

成功先发送8字节动作ACK，再从仓库读取并发送op14，包含券槽位和所有被扣材料槽位，避免材料在客户端残留。失败沿用现有动作失败体，回显槽位、列表及动作低字节。入场计数与门票、入场房间疲劳继续使用同一个角色资产事务。

原生计数UI、隐藏BOSS/碎片掉落和完整游戏内使用仍需独立验证。后续匹配v141的原生回调、配置和UI消费者已确认812为次数通知，详[计数契约与离线候选](DIMENSION_COUNT_NATIVE_V141_20261019.md)。接收门仍关闭、服务端每周状态尚未实现，本修复继续不发送次数包；这份源候选不表示这些后续目标已经完成，也不表示已发布新客户端或部署服务端。
