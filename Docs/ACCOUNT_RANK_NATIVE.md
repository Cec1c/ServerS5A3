# 账号排行榜原生预览

该实现增加真实冒险团名、无色/金币两类及 `RKQ2`/`RKA2`；旧 `RKQ1`/`RKA1` 保持兼容。扩展口径及容量见[消费榜说明](ACCOUNT_RANK_CONSUMPTION.md)。

入口为小悦 → 账号统计 → 排行榜。账号合并疲劳、史诗拾取及适级通关，今日、本周、累计独立切换；每页五行，自身名次固定显示，“我的贡献”仅展开当前账号的角色。适级累计直接复用冒险团，日周从接入后统计，详见[账号适级通关榜](ACCOUNT_RANK_RECOMMENDED.md)。榜单使用该账号贡献最大的角色名，原始登录账号不传到客户端。同分并列名次；全部数值保持 64 位整数。

游戏请求 class1/0x7f02，固定 20 字节：`RKQ1`、request(u32)、epoch(u32)、metric(u8，0 疲劳/1 史诗/2 适级通关)、period(u8，0 今日/1 本周/2 累计)、mode(u8，0 榜单/1 本人贡献)、保留 0、offset(u32，5 的倍数，上限 100000)。身份仅来自服务端认证会话。失败不携带数据；请求不包含账号、奖励或资产字段。

应答沿用固定 16 字节游戏传输头，独立 `RKR1` 包体：请求号、epoch、status(u16)、保留 0(u16)、payload 长度(u32)。status=0 成功、2 忙、4 查询失败、5 容量超限。载荷 `RKA1` 固定 64 字节头及至多五条 80 字节行，总游戏报文至多 500 字节。头包括选择、行数、总量、分页位置、本人名次/64 位分数、生成时间、服务日期和贡献角色数。行包括名次、角色数、64 位分数及 32 个 UTF-16 单元的原生显示名称。无登录账号、角色数据库 ID、管理凭据或可执行内容。

查询在后台执行，与个人统计共用四个工作名额，每会话至多一笔；每秒限流、三秒数据库截止、非阻塞回传至会话事件循环。回复前再次核对账号、角色代次和最新请求号。领域排行榜 15 秒缓存按服务日/周分键；06 点换日，周一 06 点换周。客户端额外校验 epoch、窗口代次、请求号、容量、完整 UTF-16 和选择条件，关闭/换角废弃结果，六秒超时可刷新。

客户端以当前统计和战令源码为基础；原生公会月榜边框和五行背景复用，独立布局与空闲窗口槽。不调用原公会 181 窗口，不拦截 1503/1504 响应。既有战令资源及 PVF 保持。周榜快照和外观待发资格沿用前轮领域逻辑；具体外观、自动周结与发奖尚未开放。
