# 金币分类与账号排行榜逻辑

金币榜复用养成费用分类，排除 NPC 买卖、转账和手续费；无色实际扣量及冒险团名见[无色与金币榜说明](ACCOUNT_RANK_CONSUMPTION.md)。本节记录服务端逻辑、协议与存储边界。

## 金币口径

| 分类 | 记录内容 |
| --- | --- |
| 强化、增幅 | 原资产事务实际扣除的金币；操作失败但已消耗仍计入，材料兑换、免费道具与拒绝操作不虚增 |
| 修理 | 背包、身上装备、修理全部的实际费用；免费契约与零费用不增加 |
| NPC 购买 | 商店事务提交时的钱包实际减少；出售收入不计 |
| 锻造、附魔 | 保留独立分类；已核对锻造只扣材料、宝珠附魔路径无金币扣款时保持零 |
| 玩家交易 | 转出总额、扣手续费后的到账金额、手续费分别记录，普通交易及账号晶体混合交易均接入 |
| 玩家邮寄 | 附带金币转出与邮费分别记录；本期不统计收件到账 |

`goldSummary.spent` 只合计不包含 NPC 购买、交易和邮寄的养成费用；明细沿用活动事件表，账号与角色合计沿用计数表；内部查询增加 `goldSummary` 和 `characterGold`。消费记录与资产使用同一事务，后续保存失败一起回滚。未归属账号的旧独立角色不归到公共账号，正常账号角色必须记账成功才能提交。

历史金币无法从当前余额倒推，从安装生效后采集。拍卖、仓库转移和其他尚未接入的经济路径不归入上述合计，也不宣称覆盖全服金币流向。购买后卖回的退款未做净额抵扣。

## 排名与周期

- `fatigue_spent` 和 `epic_pickup` 可排名，复用原成功消费、地下城新产出史诗入包统计。交易、管理端生成、奖励领取不会因为本次改动变成史诗产出。
- 按账号合计，保留每个角色 ID 及贡献；删除角色不抹除已提交历史。尚无统计的账号不上榜。
- 日榜按北京时间 06:00 换日，仅展示。周榜为周一 06:00 至下周一 06:00，06:05 后允许结算，预留五分钟提交缓冲。累计榜从已有采集起点累计，只展示荣誉。
- 同分并列，名次如 1、1、3；账号 ID 仅用于稳定排列，同名次使用相同外观档位。公开展示层后续使用冒险团称呼，不直接展示登录账号 ID。
- 每页默认 50、最多 100，支持单独返回本人排名及角色贡献。重建只读取持久汇总，15 秒缓存，跨日、跨周使用新缓存键，结算会使对应周缓存失效。每份榜最多 10 万条角色贡献，超限报错，不悄悄截断成错误排名。

## 周结算与奖励边界

内存和 MySQL 均支持同周同指标幂等结算；快照及待发奖励记录在同一事务提交。重复请求返回原结果，不生成第二份资格。结算后晚到事件不改写原名单，规则版本或外观档位变化不能覆盖旧结算。`SettleDue` 供后续调度器按明确启用周补结，每批最多八周；本期未启动定时器，不自动给历史周发奖。

奖励配置仅接受 `appearance:` 开头的外观逻辑编号，不能直接填金币、材料或装备。它是待配套外观白名单验证的符号，不证明已有同名客户端素材。当前默认无奖励档位。`pending` 记录表示待发资格，不表示已提供领取、邮件发放或已发标记操作。

运营策略可排除测试/管理账号。领域服务的实时排除名单来自构造策略，当前桥接默认空名单；管理结算允许保存当周最终排除名单。后续接运营配置时，应统一实时策略与结算策略，避免玩家看到两套口径。

## 管理联调契约

管理请求复用既有内部版本和鉴权，不新增公共监听，也不接受玩家自行指定其他账号。查询支持 `day`、`week`、`all`，历史周另传周一日期；日榜、累计榜不能走周结算。服务端决定当前时间并返回待发资格。

MySQL 新增 `activity_rank_weeks` 和 `activity_rank_rewards` 两表，以及汇总表排名索引；使用原表前缀和写库路由。旧库由现有显式开启的建表迁移流程添加，不改写存量统计。跨分库榜单用同一连接的一条聚合查询；周榜在可重复读事务内生成，避免读从库延迟。新增索引首次创建耗时及实服负载需在安装前按数据量评估。
