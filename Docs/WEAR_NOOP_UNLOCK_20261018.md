# v133 零移动穿戴应答收尾

基线为正式 v132，SHA256 `153903d7e76c9e2feed6fd19c053742365f04484d6dadcf24b78d5b58daf0391`，111812608 字节。输出同大小，SHA256 `29a3f7f141841483f492e63834aac6c3f0eeb50baf373c0100ba6a3e33ec32b8`。

登录时权威穿戴重申可能返回成功 MOVE_ITEMSPACE/19、返回移动值为0。旧 `.wearnop` 分支避开重复穿戴，但也跳过了源容器动作状态清理。动作向量非空时，原生使用消耗品和背包移动入口均提前退出，所以角色可以走动而两类物品操作同时失效。

## 当前映像证据

以下地址均为基线映像首选 VA（基址00400000），不是任意版本通用地址。原始报文及实机身份不公开。

- 穿戴发送函数025f9a70在025fa661构造19、025fa9a9发送后，于025fa9b8/025fa9bf向容器动作向量追加7。
- 使用入口02603890与拖动入口02600d67/02600d75检查容器+6c/+70；非空直接阻挡操作。
- 正常穿戴成功 helper 025f0e80跳到受保护代码068bb3d6。离线执行实际指令到069663d7，先将源容器+70减4，再到后续actor调用029610e0；清理前没有被替换的外部叶调用。
- 旧 guard 06e9d000直接跳01fdfca8，绕过上述清理。868消费者仅清两个移动等待表的key19，不清动作向量。
- guard命中时还跳过了01fded9e的`add esp,1c`。共同尾部在恢复ESP之前先弹EDI/ESI/EBX，因而旧分支会用残留parser参数错误恢复寄存器。

## 修改

仅修改现有 `.wearnop` 内93字节、该节VirtualSize和PE checksum；不增加节、不修改其他原生代码、接收门、位图或868恢复。

仍仅在成功应答已解析、返回移动值0、src0/1且dest3时命中。按ACK源列表调用原生02531a80取得容器，只有非空且顶部为7时调用原生025f0290弹一次；空向量和其他顶部状态保持。保留全部寄存器/EFLAGS，用`lea esp,[esp+1c]`回收七个parser参数槽，再进入既有UI尾部。其他计数和端点恢复原指令及原分支。
