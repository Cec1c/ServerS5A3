# BUFF登记实例与穿戴坐标

当前1426的list3/index是原生actor穿戴槽。仓储中仍可能保留旧PVF槽键，例如15投影成actor16。旧登记把原生index直接作为仓储键：可能找不到合法装备，或取到另一个投影槽的实例。旧1368使用仓储index，登录BUFF块则因仓储index与物品投影index不同而省略该实例。这些行为不能靠停止重发或清空登记修复。

1426登记在现有BUFF事务内，用与物品/actor投影相同的规则把原生槽解析回唯一仓储装备，再执行已有实例身份分配与登记；多个源映射同一原生槽、键/记录冲突仍拒绝。持久登记保存物理实例和仓储位置。1368及登录BUFF物品块仅把已解析的同一实例转换为原生坐标，不重写持久登记、不迁移装备，不按当前身上同名物替换登记。

原生v150 `00998890→009985F0`先重置管理器，再按list/index取物品；list3走本地actor的`vtable+0xB54(index)`。合法对象还需通过装备类型检查，随后`009983F0`保存登记记录及对象指针。新回归实际1426登记→op19同名实例交换→卸另一实例→重穿登记实例→冷会话，验证同一身份及正确输出；保存失败、最终事务失败、歧义源与旧身份登录控制保持。

原生回放执行真实读包/分支/记录复制，容器、RTTI、对象vtable和UI/map叶子是受控fixture，未执行实际对象工厂或GUI。真实PVF验证装备类型，旧槽来源是受控历史记录形状，不代表已读取用户角色的线上旧记录。当前直接槽完整路径在基底已绿；本修复关闭已证的坐标域缺口，不宣称涵盖D20全部实机反馈。原“独立于身上穿脱”的验收要求仍须在用户原角色核对。
