# 可选低内存流式预载模式（2GB专项）

本提交依赖基础内存优化及地图按需缓存两项提交，应按顺序合入。它来自独立低内存专项，当前普通模式默认关闭；不是在所有机器上强制设置GC，也不是给整机设置2GB硬上限。

## 这层代码解决什么

普通地图按需缓存先全量载入再释放，因此仍会出现启动峰值。本模式逐张读取、解析和校验全部地图，立即保存相同路由和教学动作投影，完整定义交给同一PVF按需缓存；复杂地图仍按原评分及预算选择后读回保留。缺失/错误地图仍在启动时报错，不把预检推迟到玩家入场，也不改变候选顺序和地图内容。

共享PVF归档的可重建脚本文本与解压块分别使用8MiB的LRU预算；超过单项预算的内容可以正常返回，但不留在缓存。每项记账包含载荷及固定开销，单次解压、调用方已持有对象、归档/目录和其它业务堆不受该预算限制。小预算会增加淘汰和重读/重解码成本。

低内存档每个成功预载阶段结束后清理可重建读取缓存，最终仍只在启动结束执行一次系统内存归还；玩家操作路径不强制GC。框架传入的相同PVF归档与按路径打开的归档使用同一预算入口，不因本模式另开第二份归档。教学索引使用等价的必要字段投影，避免为了索引再次克隆整份地图表。

## 启用与关闭

控制器/BAT：`DNF90_LOW_MEMORY=on`。直接启动游戏程序：`DNFBRIDGE_LOW_MEMORY=on`。两种方式的变量名不可混用，控制器继续清理未经校验的`DNFBRIDGE_*`继承值。低内存模式会自动包含地图缓存，优先于单独的地图缓存关闭选项；不需要同时开启两个变量。

```bat
set "DNF90_LOW_MEMORY=on"
set "GOGC=25"
set "GOMEMLIMIT=1152MiB"
set "GOMAXPROCS=1"
call deploy\windows\control.bat start
```

这是历史单人低内存实验的示例参数，不是本程序写死的默认值或所有服务器的推荐值。Linux直接启动时使用`export DNFBRIDGE_LOW_MEMORY=on`，其它三个Go变量同名；systemd使用服务的`Environment=`。`GOMAXPROCS=1`会限制Go同时执行的CPU数，多人和高吞吐不应未经测量直接套用。`GOGC=25`回收更频繁，若软预算过低可能增加CPU/延迟；需要根据当前存活堆和系统余量调整。

关闭低内存模式用对应变量`off`后重启；如果还保留`MAP_CACHE=on`则回到第二项的普通地图缓存策略，否则回到基础全量预载。运行期不支持热切换归档缓存预算。代码不修改Go运行时默认值，不升级数据库或改表，不随提交上传本机运行配置。

## “低于2GB”的准确含义

历史专项在固定资源的Windows隔离整端测试中，带嵌入GM的游戏进程工作集采样峰值约1333.6MiB；它不含云服系统、安全代理及所有数据库常驻开销，也不是本次新上游组合的Linux实测结果。原生客户端、多人和长期压力需要另测，不能把旧数字写成当前承诺。

`GOMEMLIMIT=1152MiB`是Go运行时软预算，不是进程RSS、启动峰值或整机硬限制。本模式通过改变预载数据保留方式降低峰值，不能仅把`GOMEMLIMIT`调低来代替代码实现。服务端、独立GM/网关、MySQL和系统需要分别计入整机容量；缓存预算不能限制其余业务目录。

## 验证范围

单元测试覆盖流式与普通模式的重复ID/路径、import、公开字段和教学投影、复杂地图保留、启动取消/缺图拒绝；PVF缓存覆盖LRU、超预算条目、并发读取与清理及快照。真实PVF专项按整档比较字段、路由候选及顺序、教学动作投影和复杂地图保留，检查共享归档预算。完整公开回归、构建和部署预检证据另随MR说明提供。
