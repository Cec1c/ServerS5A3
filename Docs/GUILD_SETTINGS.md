# 公会组合设置（op740）

匹配v105客户端一次发送 `u32 changeMask + promotion DSTR + u8 webPromotion + u32 tagMask + u8 joinMode`。所有字段始终存在，掩码只指定本次要修改的部分。服务端现在逐项检查权限，全部通过后在公会事务中一次提交；不使用表单中的未选字段覆盖较新的持久值。

| 掩码 | 修改字段 | 权限 |
| --- | --- | --- |
| `0x2` | 入会方式 | bit1 |
| `0x20` | 介绍及“添加到宣传栏”开关 | bit5 |
| `0x20000` | 公会倾向标签 | bit17；会长有原生默认回退 |

入会方式0是“接受后加入”，1是“立即加入”。PVF只有这两个实际选项；原生选择器对缺失控件或无效选项返回2，不能据此增加第三种入会政策。选择修改入会方式时仅接受0/1，未选择时忽略该字段，包括回退值2。

标签只接受七个位，最多选择三个；可清空。介绍保留空格与换行，上限80个UTF-16代码单元且GB18030编码不超过255字节；拒绝非法编码、NUL和非换行控制字符。原生发送器拒绝将已有介绍清空或改为全空白；初始空介绍可以保留并仅调整宣传栏开关。成功回包是class1的单字节`01`，随后向同会在线成员发送现有管理状态投影；账号、角色、会话代次与成员归属在事务及投递前重新核对。

保存失败不写入部分字段，相同值保持公会更新时间；不改变资产、积分、经验或贡献。介绍与其他公会编辑并发时复用同一UoW锁，刷新复用逐个会话预约，避免互锁。

## 字段语义更正

旧代码把宣传栏开关命名为`AllianceRecruitment`。匹配PVF `ui/guild2017/guildsetting2017.xui` 的对应控件实际是 `cb_set_web_promotion` / “添加到宣传栏”，旧版UI也标为“网页宣传申请”。现改名为`WebPromotion`，保留原JSON键`alliance_recruitment`，已有持久记录可原样读取；这不是联盟招募状态。

本单元实现该开关的持久状态与管理界面投影，没有接入历史外部宣传网页，也不据保存成功声称外部刊登服务可用。宣传栏消费路径仍需独立核对。
