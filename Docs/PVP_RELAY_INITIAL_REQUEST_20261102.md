# 擂台初始出战请求补充

## 原因与修正

前次修复仅在所有参战者发送 C2S298 后启动骰子，并把初始选人阶段的 C2S112 当作无效替补请求。当前客户端实际在 op45 开始通知后发送空体 C2S112，没有发送 C2S298/299，因而初始选人一直停住。

本次接纳初始选人阶段的空体 C2S112：第一个有效参战者请求启动五秒选人窗口，后续请求不重置计时器，class-0/113 广播申请状态。初次骰子仍包含双方全部存活候选者，不要求所有队友点击。使用该原生请求路径的房间向所有成员广播 class-0/112，并允许未发送 298 的替补继续申请出战。已有 298 加载路径及退出、结算的计时器清理保留。
