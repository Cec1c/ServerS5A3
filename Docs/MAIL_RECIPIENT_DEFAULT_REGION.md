# 邮件收件人默认当前大区

玩家输入收件人并点击确认时，客户端原分支把收件人大区0当成“尚未选择”，在发送op324查询前弹出“请选择接收人的大区”。当前角色的大区编号也允许为0，因此单大区部署同样可能被拦截。累计V197还未放行class1/op324，单改前置提示会使查询应答无法到达原生消费者。

## 修复行为

- 未手动选择大区时，从当前角色读取真实大区编号，接受原社交范围0～249，调用既有收件人查询生产者。保留0，不替换成目录编号或伪造1。
- 已有非零手动选择时继续原路径。当前角色或管理对象不存在、大区越界时保留原提示；不任意选择其它大区。
- 在原累计接收链之后，补充class1/op324和账号内角色列表class0/op718。所有报文先执行原接收链，原权限、来源通知、其它类别和编号保持。
- 服务端按既有op324查询真实角色，既有op789按当前已认证账号查询其他角色并以class0/op718回复；本次不新增跨实例寻人能力，不改查找、发信、附件或金币事务。

## 构建

工具为 `scripts/client/patch_mail_recipient_default_region.py`，只生成独立候选。默认只读计划绑定已发布V197的完整SHA256及长度；其它累计输入由本地精确profile提供，仍必须通过本版本原生指纹、PE布局、校验和和差异窗口检查。不得将旧地址直接用于其它版本。

```text
python scripts/client/patch_mail_recipient_default_region.py --input <V197-DNF.exe>
python scripts/client/patch_mail_recipient_default_region.py --input <匹配输入> --profile <本地profile.json> --output <新候选DNF.exe>
```

profile字段为 `inputSha256`、`inputSize`，写入另需 `outputSha256`、`outputSize` 固定计划输出。写入拒绝原地覆盖、已存在的输出和任何不匹配输入/输出。新增一个RX节，保留全部原节和通知挂接，原文件范围内只改两个挂接点及必要PE元数据。不分发私有profile、EXE、PVF或运行配置。
