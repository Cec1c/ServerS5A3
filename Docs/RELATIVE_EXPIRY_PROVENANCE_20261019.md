# 相对期限来源与邮件原始到期日

相对 `[usable period]` 在发放时按确定的发放时钟转换为实例到期日。这个日期即使后来已过去，也不是 PVF 原文声明的退役绝对日期，不应再被统一续期策略改成 2028 年。

此前两种来源共用 `ExpirationDate` 字段。发放入口按注入时钟解析出相对期限，后续通用堆栈构造用当前墙上时钟投影，可能把已解析的相对期限当成退役 PVF 日期。固定历史时钟的正式冒险团购买可复现：发放日为 2026-10-03、相对 7 天，本应到期于 10-10，实际被改成 2028-01-01。

新增仅存在于目录定义值副本中的来源标记，由相对期限解析器设置。后续到期投影对这种已解析的实例日期保留原值；只有 PVF 声明的绝对日期继续使用原退役日期策略。没有改变相对期限起算时刻、时长、GM 覆盖、每日删除规则或客户端协议，也没有增加数据库字段。

回归包括堆叠物/装备的过期后投影及重复投影、同一个日期作为 PVF 绝对声明的对照、正式冒险团历史时钟购买及重登，以及活动 PVF 10304122 的七天定义。相同测试在旧代码上失败，在候选上通过。真实资源摘要为 `a56cacf96087ba34ca5299e04ab65f8268f694b214b97dec9879fdebf46f5290`。

邮件领取存在另一条续期路径：一封创建于八天前、存续十五天的邮件，附件为真实 PVF 的七天远古精灵改良秘药，领取时原实现会补成当前时刻再加七天。正式 op95 领取、背包持久化及 op14 list0 道具行均能复现错误日期；已经过期的原实例被投影成可用。

领取事务现在先读取附件原实例到期证据，沿用现有读取器的 Extra `expire_time` / `expire_unix` 优先、ExpireAt 回退规则。没有实例日期的系统发奖附件使用邮件 CreatedAt 加相对天数。玩家邮寄（包括旧 op315 来源）和拍卖成交、返还、到期退信属于既有道具的转移，邮件创建时间不能证明道具获得时间；缺实例日期时领取失败，保留邮件和资产。缺创建时间或计算超出道具时间字段范围也在资产事务内失败，不改用当前时刻。

领取前的邮件兼容修复采用同样的转移来源边界，并保留已有相对实例到期日。模板同时声明相对期限和活动绝对日期时，与统一发放解析保持一致，相对期限优先。领取落地同时统一 ExpireAt 与两个 Extra 日期字段，避免持久化日期正确而客户端行仍沿用新发奖默认日期。原本已经过期的明确实例仍按既有策略领取为过期道具，不续期。

领域回归覆盖原期限、缺锚点、溢出、事务失败回滚及并发重复领取；真实 a56 资源矩阵走正式 op95 和 op14，检查持久化日期、119 字节线上的道具行 +0x38 日期和 +0x0B 可用标记、重领不重复入账。矩阵包括默认、无效配置回退及 legacy 三种领取修复模式，GM 覆盖开关开关两档的已有实例元数据，以及玩家/拍卖转移。GM 覆盖、每日删除、绝对日期及相对日期来源回归单独验证，不增加数据库字段或客户端协议。

没有原始发放时间的存量零期限背包行不能据此恢复，未以首次登录或容器更新时间重算七天。此修复覆盖日期来源混用和邮件领取续期；玩家原生界面、原始存量报告及整个到期系统的验收分别记录。
