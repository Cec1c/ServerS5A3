# R134 勋章强化与相对期限库存清理候选

当前修复针对已确认的两个服务端缺口，仍需原生客户端验收。

## 勋章专用强化

当前客户端专用请求把 mode 和 list38 分别写成一个字节。普通强化解码曾把它们组合为不支持的模式值，导致请求被拒绝。专用处理器按真实 flag 表读取概率、材料和稀有度费用，持久修改同一个 list38 实例；材料扣除与等级保存共用事务。正常响应补齐原生必读的槽号与数量公共尾部，总长度25字节，再通知材料与勋章最终状态。

当前资源允许旧等级0..9尝试升至+1..+10。+9尝试的资源结果为成功+10或失败降至+6，不保证成功。旧等级10及以上所需的碎毁返还尚未核实，因此整次拒绝，不掷点、不扣费。此候选没有宣称完成全部强化等级。

专用入口不使用主动保护券或便携强化器。被动强化成功率效果适用范围尚未确认，当前实现只使用flag基础概率；没有有效buff的回归不能证明有buff场景正确。当前NPC和客户端专用UI均走材料费用，不额外扣金币。材料费用按float32稀有度权重计算后截断，保留现有零耐久和所有非等级属性。

验证包括真实PVF策略与完整请求处理、合成确定性成功/不变/降级、身份/期限/锁定/材料校验、事务失败回滚及25字节响应。原生局部指令重放只验证读取边界，不代表整场游戏已验收。

## 相对期限库存清理

两天体验指环的实例已带完整发放期限，但旧清理只删除每日到期物品，普通相对期限实例会继续留在库存。现在使用既有资产事务清除期限已到且来源完整的相对期限实例。必须同时满足当前资源的usable period、发放来源标记、记录天数和两份Unix期限与ExpireAt一致，才会删除。

未到期物品、永久物品、过往绝对活动期限续期规则、GM期限覆盖、租赁和来源缺失或冲突实例均保留原处理。处理覆盖现有背包、仓库和账号仓库清理遍历；测试中把同一体验物品放进三个存储容器仅验证事务，不意味着该物品允许仓库存放。

当前调用时机沿用登录/物品列表协调和每日清理。已穿戴装备删除、在线到达精确期限的即时清理仍未补齐，因此问题保留部分修复状态。清理失败时所有资产回滚，不发送清空通知；重复协调不重复删除。

## 待实机验收

- 公会NPC对未强化勋章执行一次强化：材料、等级、动画、分页与重登结果一致，金币不额外扣除。
- 缺材料、锁定目标、旧+10请求拒绝后，物品与材料不变。
- 到期的两天体验指环放在背包中，重新登录或触发既有清理后消失；同角色未到期及永久指环仍在，重登一致。
- 已穿戴与在线即时到期单独保留开放，不能据库存测试关闭整项问题。
