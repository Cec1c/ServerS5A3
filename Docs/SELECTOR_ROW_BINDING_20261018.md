# 修正删角后选角名单行绑定

删除后客户端将角色卡片向前压缩，数据库仍保留存活角色原槽位。当前两字节选角请求按客户端行号寻址，旧逻辑按SQL槽位优先查找，导致空槽失败或后排误选；重新登录后仍发送紧凑名单，故不能消除问题。

仅当前official-24.9名单成功发送后记录行→角色ID/账号/SQL槽位绑定。删除同步压缩绑定，改名保留原有旧名快照以支持幂等重放；后续选角按绑定与权威名单交叉验证，越界、身份或槽位漂移不退回其它身份。创建仍使用原空SQL槽，发送新名单后重建绑定。显式角色ID和保护/明文SQL槽请求保持独立，旧profile保持原行为。

回归覆盖中间删角后所有后排行、重登、创建复用空槽、改名、连续删除，以及越界、跨账号和槽位漂移。角色ID、存活角色数据库槽位及资产均不迁移；源码测试不代替实机验收。

既有角色选项受控夹具此前把角色ID写进两字节字段，现按目标在已发送名单中的行号构造请求；原有选角、角色选项和键位结果断言保持。
