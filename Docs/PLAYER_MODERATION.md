# 通关记录与玩家封禁

游戏端在角色结算事务中保存 `clear_history`，以角色 ID 与完成键 SHA256 去重。采集时间、地图与难度来自游戏运行状态，不接收网页或玩家提交的统计事件。查询跨角色写入分片聚合，按次数排序，支持最多 31 天的时间范围及耗时、小时频率筛选。

私有 `/api/game/admin` 新增四个动作：`clear_stats`、`moderation_accounts`、`bans`、`change_ban`。数据结构见 `internal/modules/dnf/moderation`。管理页面与登录会话属于独立 GM 项目。

注册库新增账号/IP封禁与永久操作回执表，原因、到期时间、状态及版本持久保存。封禁操作与登录准入使用同一策略锁，再持登录会话锁；事务成功后撤销凭证、关闭匹配连接。登录器账号登录、注册与原生远端凭证绑定均检查封禁。IP 使用受信代理来源或实际游戏连接地址，支持 IPv4/IPv6 规范化，按单地址匹配。

重复请求读取原回执；相同请求编号改变内容或旧配置版本会拒绝。到期通过准入时间判断自动失效，解封后旧请求不会重新启用封禁。兼容读取已有 `player_accounts.disabled` 管理状态；本次不增加设置该状态的公开接口。

新表由既有增量 schema 初始化流程创建，关闭 `auto_create_schema` 的环境须先创建通关表。不会清理玩家数据或已有回执。采集从启用后开始，既往无完整记录的通关不推算。


## 排序与疲劳消耗

统计及封禁查询支持 `sortBy` / `sortOrder`（asc、desc），按资源字段白名单校验。SQL 聚合并排序后分页，相同值按身份固定排序，未知值始终末尾。

每个成功结算记录新增可空 `fatigue_spent`。普通房间与每日副本在 Refresh 后测量本次扣除，事务成功后累加到副本运行态；史诗入场记录权威结果，公会入场按已提交的成员扣费计数并防重复。成功结算把该值写入同一事务。药剂补充和每日恢复不改变已消耗值，退出和失败局不进入成功统计。

启动增量迁移对各分片增加列，保留旧记录 NULL。输出 `fatigueSpent` 为已采集局次总和，`averageFatigue` 为其平均，`fatigueSamples` 为采集局数；没有已采集局次时前两者为 null，免疲劳的局次为 0。
