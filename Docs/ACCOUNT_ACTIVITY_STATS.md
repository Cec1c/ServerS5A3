# 账号活动统计一期

本模块为账号每日/每周任务、排行榜和战令提供统一数据。采集业务行为并提供账号与角色查询；金币分类及账号榜逻辑见[账号排行榜](ACCOUNT_GOLD_RANK.md)。客户端展示与实机验收不属于本模块。

| 指标 | 口径 |
| --- | --- |
| `fatigue_spent` | 角色实际减少的疲劳；零余额、药水恢复、每日补充和重复房间不增加。普通房间、每日次数入场、史诗之路入场及街机实际付费路径均接入。 |
| `abyss_completed` | 常规深渊最后一波在册怪全部击败即完成，之后直接回城保留；未完成退出不计。裂缝及史诗之路按已有专用运行标记和权威终局计入。 |
| `epic_pickup` | 地下城新产出史诗装备成功入包，PVF 品质 4。 |
| `unique_pickup` | 地下城新产出粉装成功入包，PVF 品质 3。 |
| `legendary_pickup` | 地下城新产出传说装备成功入包，PVF 品质 5。 |

普通深渊完成不改变原地下城 Boss 结算。共享实例中完成时处于同房间的有效成员分别贡献角色记录；账号汇总为角色贡献合计。退出成员不补计，死亡仍在场的成员保留参与身份。领取类来源、制作、管理端发放、弃置恢复和史诗碎片不混入副本装备拾取。

疲劳来源分别为 `dungeon_room`、`cycle_entry`、`epic_entry`、`arcade`；街机没有地下城编号，明细中的 `dungeon_id` 为 0，扣除量读取现有 PVF 规则，零消耗不记账。深渊来源为 `hell_party`、`rift`、`epic_road`，后续任务可筛选适用来源。史诗之路和街机保留原资产事务与原有保护，不新增第二套付费流程。

冒险团现有登录、推荐地下城、团本和 PVP 继续沿用原业务；本模块不生成第二套对应累计值。后续任务如需这些事件，应在原成功节点复用。

## 持久化与成本

新增 `dnf_activity_events` 与 `dnf_activity_counters`，使用现有表名前缀和区服数据库计划。统计按账号键路由，角色所有权按角色键核对，资产与事件处于同一物理事务。仅新增表，不修改存量玩家数据。

每个有效事件写一条明细，并通过一次多行 upsert 更新角色累计与当日汇总。账号汇总查询这些持久行，删除角色不会删除历史贡献。没有文本日志扫描、定时全服清零或每帧查询。明细量随有效行为增长，当前不自动清除。

时间按 UTC 保存，服务日为北京时间 06:00 至次日 06:00。查询包含首尾服务日，周/赛季可以按日期范围读取；本期不写死战令周界或赛季政策。历史仅从本功能安装生效后累计，不用当前疲劳余额或库存倒推过去。

事件使用每轮随机 nonce、角色及行为对象标识去重；队伍共用实例 nonce。相同编号不同业务内容拒绝。同一事件重复请求不增加统计；疲劳/拾取失败时账本和资产一起回滚。深渊完成时间与在场成员冻结，数据库失败可由死亡重放、后续完成检查或回城入口重试，成功后跳过重复写入。进程异常退出前未能落库的纯战斗内存状态仍受现有副本运行恢复边界限制。

## 内部只读查询

查询复用既有内部管理请求版本和鉴权，不提供公共玩家查询或新的认证方式。接口支持按账号、角色和服务日读取累计及明细分页；空结果只代表指定统计范围无记录，不证明历史曾被采集。

## 历史验证边界

源侧记录覆盖内存事务、SQL 事务驱动、实际桥接死亡/疲劳入口、满包和实例投影失败、同账号并发、重复/冲突/所有者隔离、06 点边界、角色删除、分页及真实 PVF 装备品质。构建成功、提交、安装和游戏实测在原始记录中分别登记；本次提取未重新执行。

常规深渊完成依据为真实深渊房间及在册波次全部击败，不要求可选的 op235 开始通知。未击败的波次仍在册，因此未开打或末波未打完不计入。修复不根据拾取史诗或回城动作推测深渊完成，也不自动回填既有漏记记录。

## 史诗拾取来源分项

个人统计的今日、本周、累计及各角色行增加 `epic_sources`，四项之和等于原 `epic_pickup`。史诗总数保持一次成功拾取计一次，按账本已有副本编号分类，不追加采集或重复累加：

| 字段 | 展示 | 当前资源副本编号 |
| --- | --- | --- |
| `epic_road` | 史诗之路 | 6062、6063、6064、6065（含引导图） |
| `demon_rift` | 魔界裂缝 | 316 |
| `time_rift` | 时空裂缝 | 7539 |
| `other_dungeons` | 其他地下城 | 其余编号；包含仅凭副本编号不能与普通刷图进一步区分的常规深渊 |

仓储 `ActivityQuery.include_epic_sources` 默认为 false，普通汇总仍使用原计数表查询。显式启用时按账号、角色及服务日聚合已提交的史诗拾取事件，不受事件分页 200 条上限影响。MySQL 以一条 `UNION ALL` 查询返回计数和来源，保证同一查询读视图；仅打开或刷新个人页时读取，不增加每次拾取的写入，不改变表结构。累计查询成本随该账号事件量增长，可按实际数据量评估专用汇总索引或计数。

本机原生统计适配在账号及角色的原五项 int64 之后增加四项 int64，顺序与上表一致，编码前校验非负、溢出及合计。原 `native-v1` 字节格式保留。账号仍由现有游戏进程身份识别，读取结束重查身份；不接收任意账号查询参数，也不向客户端分发管理凭据。

删除角色的真实贡献保留，空角色显示零；服务日与周界沿用北京时间每日 06 点、周一 06 点。历史分项来自已有事件，不根据当前装备或库存补造。
