# 可信开发者 quick 合入

已获仓库负责人批准：`Cec1c`（170788854）和 `16www`（45917572）具有目标仓库写权限时，可以用本地已完成验证的文字声明，合入精确提交并跳过远端 CI 等待。普通外部 PR 继续使用 CI。

```bat
SOURCE_MERGE.bat --quick --repo Cec1c/ServerS5A3 --pr 123 --head <完整40位SHA> --local-ci <READY.md> --output <本地回执.json>
```

没有PR时省略 `--pr`，可用 `--branch <已推送分支>`；省略分支时从目标仓库已有提交建立 `quick/<SHA前缀>` 分支及PR。完整SHA是实际绑定对象，分支名不能替代摘要。目标主干支持 `--base master` 或 `main`。

声明直接使用已有READY/交接文本，写清精确提交、本地实际通过的命令或检查范围、时间、负责人和依赖。原文保存在本地回执；公开PR仅记录调用身份、提交和声明摘要，不上传私人日志。多个完成的小修复优先合批验证最终组合一次。

## 两条合入路径

主干要求独立的 `merge-ready` 提交状态：

- `github-ci`：正常 Verify 的所有已选择检查成功后，默认主干上的 Merge admission 工作流发布状态。支持外部fork，特权工作流不执行候选源码、不消费候选附件。
- `local-attested`：quick 核调用者身份和当前写权限，记录声明后发布状态，立即请求精确SHA合并；不把原始CI job改成成功，不等待runner、不临时改保护规则。

GitHub的提交状态写权限来自仓库写权限。目前公开仓库仅上述两位有写权限；授权名单还由入口固定检查。新增仓库写权限人员时须同时审查合入资格策略，不能把可写者视作一般外部PR者。

quick标签抑制该PR转ready时重复跑完整CI；没有新SHA的合入资格仍不能合并。正常验证工作流与手动验证保留。CI结果和本地声明在回执中分别记账。

## 基线和恢复

候选须已经包含当前目标主干。主干前进或代码冲突时，先累计并补受影响检查；不自动重跑全量CI。合并请求绑定完整head；异常结果记录原PR和回执，先读回，不反复提交。已成功的同一输入再次调用只读回原合并结果。

公开与私有历史边界保持。源码合并后按本服统一准备入口累计、构建、上传与备份；切换仍等待约定扳机。文件目标端算SHA，小回执返回；开发机不为验哈回传大包。

## 全程计时

已本地验证完成的普通纯服务端批次，目标从决定quick到备份完成、扳机就绪为10～15分钟。记录合并、私有累计、准备、失败与排队；不能仅展示最后成功prepare。用户触发后下一条命令就是activate，健康恢复立即告知；文档归档和缓存清理移出用户等待链。
