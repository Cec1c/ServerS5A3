# op29 额外掉落行补回末尾标志

START_MAP 的每条额外掉落记录漏发末尾 u8，导致下一条开始发生累计错位。恢复 `ExtendedFlag`，每行总长为 21 字节。物品计划、每件数量、PVF 权重和资产事务保持原规则；不通过增加数量补偿协议错误。

这纠正了 [2026-10-19 的行宽记录](START_MAP_EXTRA_ROW_WIDTH_20261019.md) 和 MR139。历史 `changlog.md` 与既有合并片段保持原样，本次用新的变更记录说明原因。

在完整 SHA256 为 `534b5ef166d0090d1ab88e01f5f443721abf97eabfacfb007e04e30fd9d51b24` 的累计模块中，地下城场景注册表在 VA `0x2001f81` 将 op29 绑定到 `0x1ff8d80`，在 `0x20025ae` 将 op387 绑定到 `0x1ffbbd0`。原文引用的 `0x1ffbe93..0x1ffbf8c` 属于后者。相同编号在其它场景也有注册，不能仅找到某个相邻读取循环就认定它属于 START_MAP。

op29 的实际 extra 区间为 `0x1ff96be..0x1ff9830`，循环逐行读取：

| 字段 | 字节 |
| --- | ---: |
| 物体下标 | 1 |

| 物品模板 | 4 |
| 数量 | 4 |

| 增幅类型 | 1 |

最后一字节的读取调用点是 `0x1ff9798`，在行循环内部；雾效另在循环结束后的 `0x1ff9828` 读取。该 370 字节区间 SHA256 为 `a9f407b14d0cbb3a85457d55225d764e0951b8934ebb4cc384b0ee9ae0663092`。累计 V206（`f8d68484a8f4b7b25afa7692c6ba011aab67c6d1928952934057d570615ce646`）也纳入精确输入验证。

独立原生脚本 [test_start_map_extra_tail.py](../scripts/client/test_start_map_extra_tail.py) 在 Unicorn 中执行实际循环、原包读取叶子及复制指令，记录构造参数、游标、剩余长度、雾效和栈平衡。构造器、容器及析构用明确替身；不运行游戏或修改 EXE。合成对照包含 0/1/4/6 行、零及非零行标志、四种包对齐、20/21 字节对照。可通过 `--cases` 回放本地实际报文或 Go 生成报文，不将原始玩家报文入库。

```text
python scripts/client/test_start_map_extra_tail.py --exe <匹配累计EXE> --output <新回执.json> [--cases <本地用例.json>]
```
