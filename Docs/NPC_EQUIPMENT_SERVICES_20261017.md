# 90版装备跨界与封装

本分支接通NPC和道具的装备跨界、再封装，修正封装后仍为角色绑定、穿戴解封后又显示封装，以及跨界邮件领取时可能重置品级和当前耐久的问题。

## 四个入口

| 请求 | 入口 | 成功后的装备去向/状态 |
| --- | --- | --- |
| 557，模式2 | 歌兰蒂斯装备跨界 | 原装备实例寄给同账号所选角色，通过邮件领取 |
| 557，模式0 | 装备跨界石 | 消耗实际跨界石，原装备实例进入账号金库 |
| 81，模式1 | NPC灵魂封装 | 按PVF扣相应灵魂，原位再封装 |
| 81，模式0 | 普通/一次性蜜蜡 | 根据真实材料分流，保留原有品级调整箱处理 |

封装材料通过PVF路径、标志和当前版本已知一次性蜜蜡身份识别。标准黄金蜜蜡和已识别的封装材料不能落入品级调整owner，避免把封装操作误做成重新随机品级。

## 校验、材料和事务

- 服务端复核账号/角色归属、请求模式和物品编号、实际开放背包格、单件装备、原始行与物品ID、锁定/期限和真实PVF规则。NPC跨界不能寄给自己或其他账号，也不接受已删除角色。
- 普通NPC/蜜蜡封装检查剩余封装次数，次数用尽拒绝且不扣材；一次性蜜蜡沿用其不增加次数的规则。跨界不检查剩余封装次数，次数用尽仍可跨界。
- NPC跨界按真实PVF计算等级、品质、装备分类、灵魂、上级元素结晶和额外材料；异界品质使用独立`chronicle cost`，不乘配置中的负占位权重。结晶费用已声明却缺少对应行时拒绝，不能少扣材料。
- 65级以上史诗使用实际装备→碎片ID映射，从现有账号`epic_piece:<碎片ID>`账本扣除；65级及以下不误收碎片。角色材料与账号固定格材料各走原有资产归属，不拿角色历史灵魂副本抵扣。
- 角色装备、账号材料、碎片账本和接收邮件共用同一事务。材料不足、目标无效、保存失败或取消不提交整笔；重复请求不能重复扣材或再次发邮件。
- 费用表校验非数字、半行、重复定义、不合法ID及额外费用；封装价格拒绝非有限值和溢出。保留当前真实PVF合法零权重、异界占位和隐式分节形式。

## 装备实例与绑定周期

跨界保留完整119字节原始行及Extra，移动容器时只重写目的槽。封装保留品级、当前耐久、强化/增幅、锻造、附魔和装备徽章等原有实例数据，只变更封装位、必要的次数位和绑定周期标记。

封装后解除角色绑定，装备可走原有交易校验；再次穿戴清除封装位并恢复角色绑定。明确封装值（包括0）和首次穿戴解封证据优先，不能再由`Bind=true`把装备显示回封装状态。

跨界邮件的普通装备附件优先采用已有原始行中的品级种子、当前耐久和封装次数证据，再补PVF新建物品默认值。当前耐久0仍保留0；不因领取或打开邮箱重新随机品级、自动补满耐久。本分支不包含独立的装扮邮件空孔模板修复，也不批量修改玩家存量装备。

## 回包和刷新

- NPC跨界和NPC封装校验失败只拒绝并记录原因，不额外发错误弹窗；普通道具入口保留原生回执。蜜蜡不足返回`00 16`（当前90客户端文字“材料不足”），次数用尽`00 0d`，已封装`00 12`。
- 557成功按原生字段发送材料槽、目标槽、剩余数量、账号金库槽和模式，再刷新权威物品行。81封装先刷新权威行，再发送材料槽、剩余数量和封装结果类型；NPC灵魂模式使用`0xffff`材料槽，避免客户端误改普通物品。
- 史诗跨界提交后，从已提交账号账本发送一次图鉴全量快照，刷新扣除后的余额；最后一种碎片归零也发送空表清除旧显示。该刷新仅属于跨界，不改变邮件/拾取/礼包的全局碎片同步、默认推送档位或开盒事务；显式`off`、`vendor_empty`档保留。

## 验证与边界

回归覆盖四入口、真实PVF扣材、史诗碎片归零、保留其他碎片余额、完整装备行/附魔/徽章保留、跨界邮件落袋、封装后交易、两轮穿戴解封与再封装、次数用尽、NPC静默拒绝、蜜蜡原生错误、重复请求及事务回滚。完整检查结果在分支`changlog.md`记录；需要外部测试数据库的SQL用例按条件跳过，不计为已实跑。

真实PVF样本包括70级异界100080578、85级史诗100050203、90级史诗100050696，以及普通黄金蜜蜡14、一次性黄金蜜蜡2660238和粉装28309。费用取真实配置，样本数字不作为所有装备的固定费用。

R58同步主线后，普通黄金蜜蜡14由原有`itemgrade`事务优先处理，保留其回包顺序、费用和实例规则；其它一次性蜜蜡及NPC灵魂封装由本MR的`equipmentservice`处理。四入口及实例专项改用真实一次性蜜蜡覆盖后者，普通14继续由主线`TestRealPVFGoldenWaxResealsAncientWishWithNativeReply`及其单元回归独立验证。一次性蜜蜡不递增封装次数，普通NPC封装递增；两种路径不能共用同一个次数断言。

客户端需要能够接收557结果包；单独开放接收门禁不等于所有协议和UI已经验收。本分支不携带EXE、PVF、玩家数据、GM、Windows本机脚本或配置。自动回归和客户端只读契约核对不替代实际游戏UI与重登持久化验收。

已再封装次数大于0的装备显示“无法合成”符合当前客户端原生限制。服务端装备合成入口尚缺同样的次数复核，按本次范围保留待办，本分支没有修改装备合成规则。
