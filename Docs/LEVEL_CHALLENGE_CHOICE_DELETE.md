# Lv挑战角色选择与删除

普通创建请求已携带参与标记0时，自动参加配置不能覆盖玩家的明确选择。第8个创建选项为0的角色保持普通身份；为1时仍在原创建事务中登记活动、角色和初始资产。未携带该字段的旧请求仍沿用自动参加配置。无需修改PVF，旧角色及已发奖励不迁移、不补发。

客户端累计V206输入的删除处理器会在角色属于288名单时直接覆盖拒绝原因，阻止进入原有名字确认窗口。`scripts/client/patch_level_challenge_delete.py`只改`0x36C45CD`的一个条件跳转字节，使其继续检查既有删除资格。其它活动限制、角色状态、选择索引、忙碌与确认流程保持，服务端继续验证账号、索引、名字并软删除。

删除提交并成功应答后同步815中的剩余角色显示序号，避免删除中间角色后挑战标记指向其他人；不重发整个角色列表。历史报名数量和奖励回执保留，删除不退回已使用名额，也不触发补发奖励。界面删除恢复依赖配套客户端更新，仅服务端更新无法解除原生提示。
