# 公会仓库扩容购买

本阶段接通当前客户端 class1/op761 的仓库扩容内容。初始容量按批准策略为8格，目录和上限读取实际PVF：内容11增加16格、费用10000公会积分；内容12增加8格、费用5000公会积分；上限56格。

## 事务与请求

- 请求为u32内容ID及空DSTR，共8字节。购买使用职位权限bit8，与仓库读取bit15分别校验；有购买权的普通成员可以操作。
- 同一Guild UoW内重新校验角色账号、会员归属、权限、余额和容量，扣除`Guild.Mileage`、扩容及持久购买回执一并提交。保留已有物品和存取历史；失败不初始化仓库、不扣分、不留下成功回执。
- 会话在保存前后复验。未知提交结果不当作成功，也不自动重试；相同操作标识可以从持久回执恢复已提交结果。
- 原生upper包头具有连接内递增的u16序号。本阶段将所有upper及legacy包的序号扩展为u64，处理回卷及半序号空间内的迟到重发；每连接随机nonce与扩展序号生成购买标识。同连接同序号重发读取回执，不再扣分；新序号视为独立购买。相同正文不是去重键。
- 新连接具有新nonce。原生正文没有跨连接操作ID，不能把重新登录后重新点购买认定为旧请求重试；跨连接自动重试和超过半序号空间的迟到应用重放不在该保证内。TCP自身的重传由TCP处理。
- 现场761的13字节包头实际被拆为legacy，两个路径均传递原生序号并调用同一购买处理器。缺失原生序号的直接dispatch不执行付费操作。

## 回包与实际效果

成功发送class1/761 ACK，重新读取同会NOTI70刷新余额。有仓库权限、处于真实大厅仓库NPC场景的在线成员再收到261权威容量和物品快照，发送前重核会员/会话与目标公会。其他场景下次打开仓库读取新容量；购买后的广播只读，不初始化其他公会仓库。

权限不足返回36，公会积分不足22，超上限13，扩容失败14。目录币种0为公会积分，币种1为角色金币；本阶段仅接通币种0的type4，不将展示物品发入背包，不以金币替代公会积分。

属性与杀怪经验福利见 `GUILD_BENEFITS.md`。金币契约、改名道具和传送消费仍未接通；当前不扣费、不返回购买成功。扩容支出与持久购买回执同事务写入747近期积分流水，按目录内容ID显示支出。
