# 公会读取、排行与增量保存的延迟优化

本说明覆盖公会读取、排行采样与增量保存优化。源码验证、实际部署和游戏内验收分别记录。

## 读取范围与失效

原公会总状态同时包含成员、福利与历史收据。展示和经验加成重复读取、解析及验证整份状态，会放大数据库回传和对象分配。MySQL 现在提供固定长度 SHA256 内容指纹；只读消费者据此复用已完整验证的不可变快照。指纹取调用者当前数据库视图内的实际 `state`，能识别相同更新时间、GM 或旧写入方造成的内容变化。

未命中时读取权威状态，核对读取前指纹、实际正文摘要与读取后指纹，再解析并执行原校验。发生竞争有界重读；损坏或读取失败返回错误。只读事务中的成员资料和公会状态保持原 repeatable-read 视图。缓存按仓储命名空间隔离，最多八个来源、每来源三个版本；大于4MiB的正文不保留。并发未命中合并，等待可取消；命中不经过加载锁。

缓存只保留公会投影，不保留历史领取收据。经验权益只复制归属已核验的标记、名称和福利；每次消费仍按游戏时钟检查到期。名单返回独立对象，调用方修改成员或福利不能污染其他会话。写事务、发奖、领取及全局排行发布仍走原权威事务；没有修改持久化结构或增加数据库迁移。

与初始方案相比，本批选择“内容指纹与进程内投影”，避免先引入需要所有旧写入方配合的持久化版本表。数据库仍计算原文指纹；这一成本必须包含在真实数据库对照中。频繁改变总状态仍会失效；后续如需按会籍/福利拆分持久化版本，应独立验证迁移与所有写入口，不能仅使用时间戳或无限TTL缓存。

## 排行

MySQL 在一个只读一致性事务中，按分片和最多128个参数的批次读取账号角色基础事实、成员软删除证明和成员永久团本通关事实。原来逐角色读取的完整人物属性、位置与装备展示不再进入该路径。保留账号角色槽位上限、主列/兼容影子列语义、归属、删除状态、合法永久事件及原排行计分函数。

客户端排行查询读取有效的已提交快照。缺失、过期或跨月时只通知已有后台采样器，并沿用原失败应答；不会在玩家事件队列内重算全服或把旧分数当成新鲜结果。同周期刷新合并，采样许可等待支持取消，失败重试有冷却时间。后台原有五分钟周期、月界、源摘要比较发布和权威结算保持。

## 写入及观察

宠物事务包装器转发底层背包槽/装备条目的增量写，保留角色键与事务路由。底层不支持时继续可观测回退。穿戴按条目策略需要合批配置单独核对，代码合入不等于线上参数已切换。

角色扩展属性的替换写和差量写复用现有批量行数设置。只合并连续且冲突规则相同的键；普通属性、永久升级事件和永久领奖状态使用各自原合并规则，保留排序、参数/报文预算、失败回滚及报文过大后的原受限回退。

SQL观察增加固定表族的调用次数、耗时、读取行数及SQL模板字节数，覆盖普通和事务查询；行消费结束才记完成。另补连接池最大连接数。标签不含 SQL正文、参数、角色或其他动态身份；模板字节数不是实际网络字节。场景归因继续结合既有桥接分段指标，不能从表族计数直接推断某位玩家或某项玩法的全部成本。

已启用的批量写和背包按槽保存不重复列作新增能力。本批不预先扩大连接池、数据库缓存或修改刷盘语义；先比较读写缩减的结果，容量参数作为后续条件项。

## 验证与发布边界

验证覆盖内容相同复用、并发加载、同时间戳内容变化、错误归属、缓存对象隔离、损坏源拒绝、软删除与批次上限、排行查询不采样账号、后台等待取消、永久事件合并及增量接口透传。真实MariaDB专项使用显式开启的loopback一次性数据库，比较相同成员/账号输入的旧读取和候选读取，核对排行因子、直接写入失效、按槽/条目保存和故障回滚。

结果和命令绑定实际候选输入，另保留原实现负向对照。合成领域/SQL对照不代表多人客户端或公网效果；整服P95/P99目标须上线后继续读回。通过既有运行参数 DNFBRIDGE_EQUIPMENT_SAVE_SCOPE=entry 选择按装备条目保存时，应单独核对配置、容器及实际进程，再检验装备和宠物事务的一致性与回滚。资源发布的参数绑定增量见`resource-recipes/equipment-save-scope/`，采用精确输入补丁；完整旧发布器及生产配置不属于本公开增量。
