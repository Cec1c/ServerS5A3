# 剧情暂停通知接收门候选 v116

当前 v115 已向服务端发送剧情开始/结束的 COMMAND191，但接收门在分类分派之前拒绝编号170。服务端既有 `handleCurrentDungeonStoryPause` 在有效的当前角色、所属副本及两字节请求边界下发送 class0/NOTI170，四字节体为 u16来源键、u8状态、u8类型。此候选仅恢复已有回调的可达性，不改任务进度、玩家资产或服务端剧情规则。

## 当前客户端证据与边界

- class0入口`0x251e340`取得`0x25244a0`注册表；初始化`0x2524320`将`0x2001f60`等注册函数接入同一表。170注册点`0x20022d7`指向`0x1feb5e0`。不能仅凭注册点所在地址段判断class。
- 实际191序列化点`0x23fab98/0x23fbde8`写入(1,1)/(0,1)，`0x34a5529/0x34a5565/0x34c3620`写入状态与0/2类型。NOTI191的另一回调不属于该请求。历史v103已有相同写点取证，本轮在v115复核，不把它表述为新发现协议。
- 回调`0x1feb5e0`读取u16及两个u8；类型0/2按状态调用最终暂停函数，类型1先维护来源集合，仅集合为空时尝试恢复。来源键不能替换为PVF APC编号320。
- 实际启动链`0x2557880 -> 0x32d9890`建立管理器，`0x255788c -> 0x32d9900 -> 0x2245150 -> 0x2289330`构造子对象来源集合，子对象保存到管理器+0x4c；回调也从该位置获取对象。历史静态初始化取证仍有效，本轮补充执行实际集合构造、插入/重复插入、删除/不存在键/重复删除，共8步。仅标准C++分配与释放边界使用桩，未执行完整UI初始化或证明实际现场时序。
- 最终暂停函数`0x29120d0`进入保护VM；离线探针在受保护运行环境缺失时停止于未映射读取，未观察到状态写入。不能据此认定它在游戏内安全或已解除暂停，也不能把失败解释为游戏内崩溃。
- 当前PVF的“伦道夫的陈述”任务3917对应副本148及地图400222–400225，前置2984；原用户反馈仅有副本名称与时间，保留日志尚未绑定原现场任务/地图。因此该资源身份不证明已复现用户现场，伦道夫剧情卡死保持开放。

## 复现与构建

在另一个目录保存已经发布的v115 `DNF.exe`，运行Python3：

```text
python deploy/client/story_pause_gate.py <v115-DNF.exe> <new-DNF.exe> --receipt <new-receipt.json>
python deploy/client/verify_story_pause_gate.py <v115-DNF.exe> <new-DNF.exe> --receipt <new-native-receipt.json>
```

第二条需安装Unicorn，也可传`--emulator-deps <已有依赖目录>`。工具固定基底哈希、PE32、门指纹及位图地址，拒绝已有输出、原地覆盖和错误基底；逐一比较所有u16编号。验证器执行两版实际门指令131072次，检查返回值和栈平衡。EXE、PVF、运行配置和发布密钥均不提交到服务端仓库。Python工具是兼容工件生成工具，Windows部署入口继续使用既有BAT。
