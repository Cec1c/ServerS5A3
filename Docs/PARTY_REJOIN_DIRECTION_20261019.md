# 队员先退队重入与申请入队方向补修（2026-10-19）

## 现场证据

v140 + R86 实机反馈：回城双方模型可见；队员先退出、队长保留队伍后重新加入，血条位置和队长归属错乱，随后新队长视角看不到队员，队员视角正常。显式建立单人队伍再申请加入，也会转移队长及交换血条位置。

17:04:07 UTC 的实际 mode0 请求由 test78 发给已有单人队伍的 test99；17:04:08 的接受由 test99 发出。旧服务端无条件把接受者当入队者，销毁 test99 的单人队伍，建立 test78 为队长的新队伍。17:03:36 队员先退出后，旧发布器清空了仍留图队长的会话投影并回收小于两人的实例登记，17:03:39 又从中央管理器恢复单人队伍，造成两个状态来源不一致。

## 修改

- 仅 official-24.9 在线普通 mode0/12 请求登记时，在中央管理器锁内根据当时双方权威成员关系固定 JoinerID、AnchorID 和目标 PartyID。对已有队伍申请加入时，原队长为 anchor；普通邀请保持请求者为 anchor。显式强制邀请仍使用原 RecordInvite 方向，交易和快捷邀请保留原方向。
- 接受只消费同角色、同双方会话代际、同模式的待处理请求。目标队伍已退役或队长发生变化时不创建替代队伍。名单补发发给真正的入队者。
- 仅 official-24.9 的已确认队员放弃回城路径保留幸存队长的单人投影和正在运行的实例；清理离队接收者的全部旧副本记录，向仍留图成员发送当前副本上下文名册，不重放外观或 UDP 握手。
- 一般城镇离队、踢人、断线的既有单人发布规则保留；队长先退解散补修和 v140 保留。

## 验证与边界

旧代码回归红灯记录在本轮私有证据中：单人队伍申请和退队重入都换了队长；当前与漂移代际的队员退出都清空原队长投影。补修后对应回归通过，另测接受前本地 op12 单人队伍不改变邀请方向、退役提示不能重建队伍、已验收委任退队保护。完整组合、真实 PVF、BAT、部署分别留证，不能替代人测。

头像与资料窗时装另有原生证据：活动角色对象的显示时装数组在进图后被清空，而辅助对象仍完整。其写入原因尚未确定，本轮不提交未验证的 EXE 外观补丁，不宣称模型与头像全部修复。背包整理继续跳过。用户已验收单人申请与退出后重入队的组合流程。本MR仅包含相对于R85的组队净改动，累计运行源码保持私有。

完整检查初轮暴露旧测试以零值旧协议档假设邀请方向。最终将新入队识别限定 official-24.9，保留原旧档测试原样；另增实际 op12 + op10/op11 的官方档测试，校验双方线上 op9/op153 的队长槽位与血量，并保留接受前才生成本地单人队伍的邀请方向测试。
