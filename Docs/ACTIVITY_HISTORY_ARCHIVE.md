# 活动永久回执与冷热历史合同

活动流水参与拾取、通关、史诗来源与战令结算的永久防重。此实现提供可显式采用的永久回执和冷热历史布局；普通启动不创建归档表、不搬迁数据，也不安装触发器。未采用此布局的实例继续使用原表。

## 数据与事务

原 `activity_events` 完整物理表保留为 `activity_events_cold`，新热表使用原表名和原列、索引。新增 `activity_event_receipts` 保存 `(account_id,event_id)` 主键及 32 字节业务指纹，`activity_archive_state` 保存版本、阶段及合同摘要。表名前缀沿用仓储配置。

指纹包含账号、事件 ID、角色、指标、数量、副本、物品、稀有度及来源。各字段先按 UTF-8 字节长度编码四字节大端长度，再拼接内容并计算 SHA-256；整数使用十进制。显示名和发生时间不参与重复事件的业务相等性，与 `SameActivityEvent` 一致。不能用分隔字符串或不同的 JSON 序列化代替。

热表 AFTER INSERT 触发器在相同事务中插入永久回执。`Record` 仍执行原来的事件写入与计数写入；数据库内部增加回执写入。事件、回执、计数和关联资产须一起提交或回滚。重复主键或回执冲突后，归档模式从写分片锁定回执，指纹相同返回未新增，指纹不同返回 `ErrActivityConflict`；缺失或错误回执不会当作成功重放。

八个受管触发器禁止修改已记录的业务或展示历史、删除永久回执和删除冷历史。冷表新增行须同时具有正确永久回执及完整一致的热表前像；热表删除须先有完整一致的冷副本。移动中已提交的相同冷热重叠行在读取时只计算一次。永久回执与冷历史没有到期删除策略，本改动没有新增归档定时任务。

普通 `Summary` 继续读取计数表。史诗来源汇总和历史分页在同一个 SELECT 读视图中联合冷热历史；分页保留原时间/事件 ID 游标与排序，各分支及结果集有界。原历史和发生时间不会因分离而丢失。

## 启动资格与调用方式

`Component.Start` 在原有 schema 初始化之前执行只读资格校验，并在发布仓储组之前复核。所有写分片及读分片须具有一致模式。归档启用时检查四表的列、类型、排序规则、索引、热表标记、状态及全部触发器定义；半成布局、未知触发器、触发器不可见或分片混合均拒绝启动。资格校验有超时并接受上下文取消，不重算全库历史指纹。

直接装配 SQL 仓储的外部调用者应使用 `NewQualifiedMySQLGroupFromDB`，或先执行 `QualifyActivityArchive` 后把返回选项交给构造器。原 `NewMySQLGroup` / `NewMySQLGroupFromDB` 保持仅装配的低层接口，不隐式查询或采用归档模式。应用账户须能读取所需元数据；实际验证覆盖 schema 范围权限，不要求全局权限。安装触发器还需明确其 definer 的持久存在和权限。

`inactive` 仅用于已经统一回原表、全部受管触发器已撤除的回退布局。保留的回执是证据，不能继续当作当前完整回执使用；旧程序恢复后会产生未写入这些回执的新事件。再次采用须通过新的显式核对与迁移。

## 从候选程序导出规格

Linux 正式程序支持以下只输出规格的入口，在加载服务配置、连接数据库和启动组件之前返回：

```text
server --activity-archive-plan-v1 DATABASE TABLE_PREFIX
```

标准输出是单个 JSON 对象，含 `format`、数据库/前缀、四张限定表名、`hotDDL`、`receiptDDL`、`stateDDL`、`backfillSQL`、八条命名触发器 DDL 和 `contractSHA256`。该命令不执行 SQL；返回的全表 backfill 是规格，维护器必须在停止写者后按主键范围分批使用。无参数的普通服务启动入口保持原行为；维护参数残缺、非法标识符或未知维护版本返回非零，不能落入普通服务启动。

合同摘要是下列 UTF-8 字符串按换行连接后计算 SHA-256：format、hotDDL、receiptDDL、stateDDL、backfillSQL、按数组顺序列出的八条触发器 DDL。连接最后没有额外换行。维护工具须绑定候选程序摘要和精确源码，从该程序取得规格，不另外维护一份近似 SQL。

## 显式维护和旧版本回退要求

维护器必须具备完整恢复点、停止相关写者的证明、分片清单、写前记录及 DDL 未知结果对账。回填与切换前须证明原历史与永久回执完整对应；启动时的元数据检查不替代这一步。原表保留为冷表，避免复制全部旧历史；所有 DDL 自动提交和部分阶段须在维护器中处理。

旧程序不能完整服务已移入冷表的事件；触发器拒绝旧写者重复插入只能防止重复发放，不等于兼容完成。回退先停止候选写者，核对冷热重叠内容，把仅有的新热增量合入保留的原冷表，然后原子换回旧表名。撤除八个精确匹配的受管触发器并标记 inactive 后，才允许旧程序继续。保留退役热表和永久回执作为恢复证据，不恢复旧计数或重放奖励。

归档表布局会占用额外永久空间并增加数据库内部写入。受控测试只支持具体机制和所测工作集，不代表整服固定吞吐、尾延迟或维护秒数。显式生产安装器、备份和完整发布回退仍须单独验证，不能把本文或夹具安装过程直接当作生产执行流程。
