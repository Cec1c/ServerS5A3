# 德利拉分解费用

通关后的德利拉分解请求使用 class1/op26，NPC context 为1000。旧处理器只记录该上下文，资产事务删除装备并发放PVF产物，没有扣除金币。现在对该上下文按来源件数收取每件500金币。

## 数据与客户端依据

a56 PVF SHA256为 a56cacf96087ba34ca5299e04ab65f8268f694b214b97dec9879fdebf46f5290。npc/npc.lst将1000映射为Delilah.npc，其中文名为德利拉，角色为simple shop 1000、disjoint item 0，visible on dungeon clear为1。普通阿拉德修理机为NPC317。etc/disjoint.etc定义分解产物，未定义这笔服务费。

匹配客户端v141 SHA256为 26abf551753c2745c2e5b349fb24336422a189187ff847c995e0df9a68871079，image base为0x400000。NPC1000费用提示分支位于RVA 0x2f0e31e，比较1000后在RVA 0x2f0e34c选择DSTR72992，提示每次分解消耗500金币。RVA 0x2f1b42a读取窗口的NPC对象，0x2f1b434读取其ID，0x2f1b43e调用op26发送函数RVA 0x21f57c0；发送函数在RVA 0x21f5c02读取并写出context。

上述三个短窗口通过PE节表换算复核；这些节内文件偏移恰等于RVA，VA需加image base。stable v133 SHA256为 29a3f7f141841483f492e63834aac6c3f0eeb50baf373c0100ba6a3e33ec32b8，相同窗口逐字节一致。此服务端修复不依赖新客户端或PVF。

## 资产与发送顺序

- context1000要求当前选中角色所属账号的副本runtime已经完成且当前场景已清除；没有runtime、尚未通关、账号或角色失配均拒绝。
- 先校验单件或整批装备及PVF产物，再按件数扣费、删除来源并发放产物。角色金币、角色背包、账号产物在同一个领域账号/角色资产事务内保存；任何写入失败均回滚。分解领域Owner新增角色Stats的选择性保存，保留身份验证和集合写入边界。
- NPC费用使用Character.Stats中的gold，与普通NPC商店和修理相同；个人分解机的历史钱包回退配置不改变德利拉账户。NPC317、无NPC context、时装分解和个人分解机费用行为保持原规则。
- 事务成功后依次发送既有op26 ACK、既有批量槽位刷新和一次class0/op14钱包绝对余额。余额恰好500时仍发送零余额。事务拒绝不发钱包。
- 提交后ACK或钱包写失败直接返回连接错误，不补发业务失败，也不自动再次分解或再次扣费。

## 验证与范围

同一套正式入口测试对照原代码与候选，覆盖单件500、批量每件500、余额不足零消耗、晚保存失败回滚、普通机器免费、上下文与归属拒绝、独立于个人机器回退钱包、零余额即时刷新、提交后ACK/钱包写失败及非法批次。真实a56验证NPC身份和分解表；既有单件、批量及个人分解机事务回归一起运行。

完整领域、bridge、control、规定vet、Windows构建、BAT无数据库预检和服务边界需通过后才发布候选。固定资源专项不得把缺资源跳过计为通过。

当前协议没有独立的NPC对话票据，context缺失的历史路径仍按原行为处理，不能用本修复证明所有伪造请求都能被识别。源码与隔离回包验证不等于原生金币显示或德利拉实机验收。原始反汇编、环境与运行回执保存在本地诊断目录；本MR保持Draft，验收状态另行记录。
