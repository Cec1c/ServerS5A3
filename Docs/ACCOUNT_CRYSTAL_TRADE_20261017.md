# 账号晶块仓库交易

当玩家从账号晶块仓库把无色等小晶块放入交易窗口时，旧实现只检查角色背包并拒绝所有354..365共享格。这个范围的持久记录属于账号，不能通过移除拒绝条件把它当作角色物品交易。

当前候选只接通六种实际PVF自由交易小晶块：3033/3034/3035/3036/3037/3262，按已有映射使用354..359。在线挂单要求official-24.9、令牌确认的账号与角色归属一致，并读取实际账号仓库；挂单及取消只改变会话。灵魂、错槽、绑定、过期及缺少完整事务依赖的请求仍拒绝。

双方确认后，新事务边界覆盖两个账号仓库和两个角色钱包/背包。账号与角色按稳定键序读取并验证归属；MySQL在读取余额前先建立或锁定仓库父行，包含首次接收账号。仓库借出量全部扣除后再按接收账号合并，可混合普通道具和金币，不能通过同时挂单超额消费共享余额。同账号两个角色共用一个仓库记录，转移前后总量守恒。

事务内失败整批回滚。memory实现保留原始存在性与快照，并对已经写入后才报错的store作补偿；MySQL使用同一物理连接和sql.Tx跨写分片提交，仓储范围外的账号/角色在发SQL前拒绝。普通角色物品交易继续使用旧事务入口。

协议保持既有28字节op19请求、可见交易行3..11、op15物品投影及op18结果。入账的目标槽为账号固定格，随后发送既有容器刷新；不把客户端的目标槽或实例字段当作资产来源。交易开始时冻结双方账号，提交前重新检查在线令牌、账号与角色绑定；晚到确认不能重放已经清除的交易。

验证包括旧实现拒绝红用例、六种固定PVF物品经过桥接挂单及双方确认的隔离内存回放、混合金币/道具、同账号守恒、并发透支、失败补偿、越权仓储访问与MySQL事务/锁定SQL范围。数据库接口测试使用fake driver，未将其称为实际MySQL集成测试；玩家完整鼠标拖动、动画和重登仍需当前客户端实机验收。完成状态、源提交和部署另以回执为准。
