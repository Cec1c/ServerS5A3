# 个人统计游戏连接

配套客户端在小悦原生统计窗口内通过当前游戏连接查询，服务端按令牌确认的会话账号读取原有账本。今日、本周、累计、角色明细和四项史诗来源沿用已有汇总与 `PSA2` 格式。本机管理端及 HTTP 统计入口保持，但游戏内统计不再依赖 HTTP。

协议为 class1/opcode 32512（0x7F00），不占用新端口或公会编号。`PSQ1` 请求固定 12 字节：标识、uint32 请求号、uint32 客户端连接代次；不接受账号、角色、进程 ID 或 IP 身份参数。`PSR1` 回复为 20 字节头：标识、对应请求号、对应连接代次、uint16 状态、uint16 保留 0、uint32 数据长度，随后为 `PSA2`。服务端仍通过现有 fixed16 写锁/`DPROTO` 出口发送，不从查询协程直接写 socket。

身份必须具备令牌认证、非空账号、有效会话循环、当前角色绑定和角色代次；查询前后再次核对。禁止共享账号兜底。客户端关闭、换角、角色目录请求、重新登录和断线时废弃旧请求；回包收集与窗口操作分开，只有 UI 线程更新控件。客户端在原生解包后独立处理统计消息，原接收白名单和公会协议保持；其余消息重放被覆盖的原指令后回原分派。

每个会话最多一笔后台查询，服务端最多 4 笔并行查询，数据库上下文 3 秒超时。有效请求每秒最多接纳一次，重复请求不排队；成功结果在同一账号/角色/代次内缓存 5 秒，跨统计日失效。结果通过低优先级非阻塞队列投递，满队列仅舍弃该次统计。客户端 6 秒等待超时，之后可手动刷新，没有定时网络轮询。三个周期一次读取，切换页签和 7 行角色翻页只使用本地快照。

首版 `PSA2` 载荷上限 64 KiB；过大的历史明细返回状态 5 并提示使用管理页，不截断合计或虚报零值。后续大量删角历史应另做服务端分页。状态 2 表示繁忙，4 表示查询/编码失败。此限制不改变原账本或统计采集。

源侧隔离验证覆盖实际会话事件循环、阻塞仓储下继续处理事件、两账号与换角隔离、缓存及跨日、满队列舍弃、Go/C++ 共同夹具和机器码组包边界。原生 UI、socket、加密 CRC 表读取等叶子使用明确替身；这些结果不代替真实游戏往返、网络加密、安装或完整回归验收。
