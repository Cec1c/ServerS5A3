# 公会职位名称编辑

op749 修改职位名称，包含会长职位的显示名称；不会改角色名、成员职位、会长归属或权限掩码。

## 请求与保存

- class1请求为`u8 grade + DSTR`，DSTR使用既有GB18030编码和u32字节长度，必须完整消费，拒绝尾随字段。
- 仅当前会长可编辑，同时核对事务内账号归属、grade1和持久化会长角色ID。副会长和持全部权限位的普通成员不能编辑。
- 名称必须非空、非全空白、无控制字符，合法空格原样保留。同时满足最多20个UTF-16单位和23个GB18030字节，超长拒绝而非截断。
- 本地实现允许原生模型的成员职位槽1～5；当前已核实成员菜单只映射1～4，默认值6无效。没有为职位5新增界面入口。
- 在既有公会UoW内保存名称；同值请求不改时间戳，提交失败回滚。成功确认后重读并向同会当前成员刷新NOTI70，继续使用会话代次、角色预约及账号归属保护。
- 无有效公会身份/保存失败返回34，无权限36，非法名称或目标职位159；这三个错误都由匹配class1回调处理。

## 原生证据

输入作者v105 SHA256 `6fd3183de3cff52fa2feb5a5327ca43855cabbc6b0b63d920a87ab8ddf316da5`，ImageBase `0x00400000`。以下为该输入的RVA。

| 路径 | RVA | 已核实行为 |
| --- | --- | --- |
| 成员菜单事件 | `0x00dbf7e0` | 本人非grade1时禁用名称和权限按钮 |
| 名称窗口入口 | `0x00dbd330` | 菜单索引0～3映射grade1～4，其余为6；打开窗口488、模式1 |
| 名称窗口参数 | `0x03035fc0` | 模式1保存传入的grade；模式0是本人留言 |
| 输入验证 | `0x03035500` | 拒绝空白及超过20个UTF-16单位的文本 |
| 请求发送 | `0x03035670` | 模式1发送749、grade u8及DSTR |
| class1响应 | `0x01bbf7a0` | 成功只消费状态；失败识别34/36/159 |
| NOTI70管理状态 | `0x01c3e980` | 整块读取168字节，六行，每行权限u32和24字节名称 |
| 名称转换 | `0x033e0ae0` | 从窄字符串读取至NUL，因此可用名称上限为23字节 |

原生输入校验复用了留言界面，允许的UTF-16长度不能代替管理包的字节上限。NOTI70将名称转换到42字节宽字符缓冲区，再存入六个职位槽。本实现保留两项约束，避免持久化值与客户端显示不一致。

EXE-GUILD-010仅在009上开放749，完整SHA256 `513636c3af49f41a24ad1ac8df43c2d3fd6e97a20bc0ff71e6c54f04e616a952`。相对作者累计31位/13字节，保留65和1474门禁上限，351/746仍关闭。同号class0回调不用于名称确认。
