# 怪物死亡与冒险团完整资料的发送顺序

当前客户端的冒险团资料推送（class0/op1339）包含7424字节原生结构和账号角色等尾部字段。满级角色击杀后，经验提交会累计冒险团经验与成长胶囊；即使一组击杀已合并为一个经验事务，完整资料包仍可能排在下一组死亡通知、Boss强制清掉的剩余怪物通知之前。

TCP保持字节顺序。应用程序的Write迅速返回并不代表网卡已发完；当对端接收窗口较小时，先入队的完整冒险团资料会阻塞后续很短的死亡确认。只优化经验事务或增加发包批量，不能消除这段排队。

## 投影时机

- 沿用当前ordinary死亡批处理的版本和模式边界（official-24.9，排除锦标赛、团本入口、公会练习等原来不参与的模式）。账号与角色经验仍由原事务提交；提交成功后只在当前副本运行时记录一个待刷新标记。
- 未清房时不因每只怪或每批击杀推送完整冒险团。角色经验、熟练度、SP/TP及掉落、任务和死亡通知继续使用原路径。
- 清房后，等整条死亡命令或整段连续命令结束再读取账号最新状态并刷新。内部的升级、特殊对象及Boss经验提交点不会提前释放这个大包，Boss强制清掉其他怪物时也先发完视觉死亡通知。
- 独立Boss检查命令和队友清房/经验回调完成后同样处理待刷新。队友沿用自己的事件循环、角色代次校验和经验事务，不跨会话直接操作待刷新标记。
- 冒险团面板的主动查询（class1/op1401）仍直接读取账号最新持久状态；胶囊领取、商店操作、城镇和角色列表初始化保持原有刷新。中途回城或断线仅丢弃旧副本的投影标记，已提交账号经验不会丢失，重登由持久状态重建。

待刷新标记只属于当前副本运行时，不进入数据库。发送失败保留标记；旧运行时、切换角色或登录被替换后不能借此给新会话发送旧场景状态。不增加计时器、配置项或后台奖励任务，不改变经验公式、入账及回滚边界、爆率或物品归属。

## 验证

回归覆盖分批到达的普通怪死亡、战斗中主动查询、清房最后状态、Boss强制视觉死亡的单条/批量路径、重复报告、发送失败、账号事务失败、旧角色/运行时/替换登录隔离、组队双方死亡顺序与经验，以及其他版本/模式的原发送行为。真实PVF专项继续核对冒险团、胶囊领取与账号重载数据。

本修复只修改服务端源码，沿用既有op1339/op1401布局与玩家EXE/PVF。离线顺序检查证明不再在该战斗路径提前排入完整冒险团，不能替代部署后的画面和端到端延迟验收，也不承诺消除网络、客户端渲染或其他大包造成的全部停顿。
