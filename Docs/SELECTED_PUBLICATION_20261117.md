## 邮件消费者

游戏私有管理API新增 `notify_mailbox`。请求只对已提交邮件投影当前未读数；`online` 表示会话投递资格，不表示客户端已经显示图标。事务、永久回执和资产发放仍由原消费者负责。

PurpleMagic 的配套改动位于独立仓库的 `gateway/internal/modules/dnf/testbenefits` 和 `gateway/internal/services/gmtool`。单封、版本化任务、旧福利、自动扫描和补发在外层事务提交后调用游戏API。通知有整体超时，按回执实际角色去重；离线角色由登录或加载重读覆盖。没有新增持久通知队列或进程崩溃后的必达承诺。

## 客户端配对

帝国新1393正文需要新接收器，不能仅凭原普通双组Buff开关认定客户端支持。默认 `DNFBRIDGE_TAG_BUFF_GROUP_SYNC` 关闭，旧客户端继续接收两条旧格式。启用新接收器时同时要求原双组同步和精确客户端身份。

公开构建入口：

```text
python scripts/client/build_selected_feedback.py --base-zip <公开V215完整ZIP> --pvf <公开66482976的Script.pvf> --output <不存在的输出目录>
```

固定基底 `28e04d1d…`，帝国接收器中间结果 `40657c19…`，再叠加婚姻请求得到 `58e51fba…`。两件DLL及原生界面NPK逐件保持。输出包含独立EXE、固定gzip、完整ZIP和回执；该入口核对实际PVF摘要，只使用已公开的 `66482976…`，不包含本服后续礼盒政策PVF。

Docker实例在放入配套客户端后可显式配置：

```json
{
  "client_version": "official-24.9",
  "client_dir": "C:/DNF90/client",
  "buff_group_sync": "auto",
  "tag_buff_group_sync": "on",
  "wedding_gender_policy": "deny_male_male",
  "party_udp_relay_port_count": 512
}
```

`tag_buff_group_sync` 接受 `off/auto/on`，默认off；auto对旧客户端保持旧格式，显式on拒绝不具备接收器的EXE。婚姻默认 `opposite_only`，`deny_male_male` 要求配套婚姻请求EXE。通过原始进程环境启用时，部署者仍须保证整个频道内的客户端和资源已配对；配置开关不提供逐连接版本协商。

## UDP容量

`party_udp_relay_port_count` 为64–1024的严格整数，默认64，起点30000；512对应30000–30511。生成的环境数量、Compose映射及运行检查使用同一数量。外部防火墙、云规则与实际UDP往返由部署者另行核对。四人拓扑需要12条有方向的腿，共享池还保留探针及其他用途，不能把512当作512个队伍。
