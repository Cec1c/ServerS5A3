# V110 公会公告即时刷新

状态：用户确认公告重登后可见；客户端缓存更新缺陷已静态定位并通过局部回归，候选尚未安装或完成游戏内验收。

现有服务端的公告保存和同会 NOTI70 广播已实现。V110 的 NOTI70 回调 RVA `0x01c3e980` 将公告缓存赋值放在一次性聊天公告的条件内：全局“已显示”标志非零时跳到 RVA `0x01c3ed78`，跳过模型 `+24` 的公告更新。公会窗口从该缓存读取正文，因此首次登录能显示，随后编辑仍可能保留旧内容。

在成员菜单修复候选基础上，新增 `.gnotice` RX 段，仅重定向上述六字节公共续接点。每次完整读取公告后调用原生字符串赋值函数刷新缓存，再恢复寄存器、标志和被替换的原指令。一次性聊天提示条件保持；首次提示路径原有赋值仍保留，续接处再次赋同一内容。空公告也能清除缓存。

```text
python scripts/client/patch_guild_notice_v110.py <成员菜单修复候选> <新组合候选>
```

输入 SHA256：`413bbe6b900c419ec430ec10ba9acd3307d678351d423be6ae6007ce91078bd4`。
输出 SHA256：`d9533c44bf4147e9621ac47c45233b2985a95d3d4e808195a23a3e5e37755e52`。

四项自动化检查覆盖重复更新、清空、中文/换行/边界文本、缺失模型保护、原分支与提示标志、寄存器/栈、精确变更范围及拒绝覆盖。机器码仿真使用原分支和新续接代码，字符串分配函数使用明确的桩；未将其视为真实客户端 UI 验收。

测试环境需 Python、Unicorn 2.1.4；`DNF_GUILD_MENU_FIXED_EXE` 指向精确输入，执行 `python -m unittest discover -s scripts/client -p "test_patch_guild_notice_v110.py" -v`。
