# 转职书、技能栏转职与职业体验

转职处理由 `profession-change` 独立模块持有。领域事务共同保存职业、技能双页、技能点、任务及所需道具或金币；提交后的报文写失败允许补投，不再次扣费。

## 入口与资源

| 入口 | 上行 | 应答及通知 |
| --- | --- | --- |
| 转职书 | class1/502，`u16` 主背包槽位和 `u8` 目标分支 | 502 成功应答；通用拒绝使用本操作的错误码 1 |
| 技能栏转职 | class1/785，14 字节原生请求，末字节为目标分支 | 785 结果及次数；金币不足为 22，其他通用拒绝为 99 |
| 次数与等级同步 | 登录及成功转职后由服务端发送 | class0/1150 |
| 职业体验 | 规范 7142 单人直接入场 | 沿用副本入场、42/op24 返回确认及城镇资料重建 |

技能栏的可用等级、首免和后续价格读取配套 PVF，不在代码中舍入价格。配套资源的 15～49 级入口首次免费，之后依累计次数收费；价格为整数金币。

转职书读取真实 `[class change]` 定义及等级、职业、分支、觉醒、期限、锁定、冷却和使用地点限制。高级书按定义保留觉醒阶段；活动回归书要求匹配先前转换凭据。2683469、2683470 特别版成功使用后扣除一本，并按资源定义发放对应的 15 天转职书。

## 体验返回与物品来源

7142 的起点和首领坐标重合，地图解析只接受本副本明确归属的入口地图。规范直接入场使用 `RuntimeState=1`、`RuntimeToken=0xffff`；其他副本继续原有模式校验。

客户端结束体验后可能先收到 42/op24，再在 op15 前提交 502 或 785。处理器仅在当前账号、角色、原实例、单人体验及真实已发送的返回通知均匹配时完成已有回城确认。活动体验或其他副本不能直接修改正式职业。回城中途写失败保留坐标与发送游标，重试继续原事务投影。

该次已确认的体验返回代省略 op30，避免再次激活已退出体验的场景对象；角色重建、状态、技能及其他后续通知继续发送。普通城镇过场、普通副本和再次入图仍使用原流程。

原生转职窗口保留转职书对象，再按对象身份查找来源槽位。体验入图重复发送 op13/list0 会销毁这些对象，因此只有已成功建立当前角色主背包的规范 7142 入场保留主背包。其他容器继续初始化；冷入口、普通副本及返回选角后的新角色继续完整引导。正式提交始终校验原请求槽位，不猜测替换道具。

## 验证及适用边界

真实资源回归通过 `DNFBRIDGE_REAL_PVF_SMOKE` 与 `DNF_WORLDMAP_REAL_PVF_SMOKE` 指向部署方配套 PVF，覆盖转职书定义、觉醒保持、首免与收费、失败提示、完整体验返回、再次入场及写失败补投。来源回归从实际登录背包报文建立对象身份，再由保留对象产生提交槽位。

服务端源码不包含 EXE、PVF 或客户端接收位补丁。部署前须核对实际客户端能接收 class1/502、class1/785 和 class0/1150，并匹配其请求结构及资源；服务端自动回归不能代替公开客户端发布、玩家通道核验或全部职业的联机验收。

本实现不处理异次元气息装备技能随职业转换及转回恢复；道具说明中的该项功能不在本次范围。
