# 副本队友mode0状态保持

V195（EXE SHA256 `ab82e1d747c3018f97fac7c3f2c0f2f787f70a10db8a2be7904bf63199ac09ff`）的mode0不仅创建外观，还会更新已有actor状态。名字后第6个u8由 `22C531B` 读取到临时描述符，`22C592A → 2968720 → 12FB9F0` 最终在 `12FBAE4` 覆盖actor+0x4c。

原副本队友投影复用了城镇默认状态0。先到的USER_STATE=1会被晚到mode0重新改成0，重复外观投影也会再次覆盖。真实PVF的四人安徒恩回归执行开始攻坚、二队成员退出、加入一队、进入地图，再回城退队重组重进；旧生产代码的24个晚到队友mode0均触发状态断言失败。

修复只在 `sendDungeonPartyPeerActorState` 的严格mode0构建成功后，将该状态投影为1。校验单对象、对象key、名称和尾部边界，克隆包体且只改这一字节；原town/self构建器保持原状态。后续重复mode0沿用相同正文。没有额外发送会清理场景对象的USER_STATE，也未修改EXE。

原生隔离验证真实执行reader、wrapper与状态赋值，覆盖前态0/1；名称及受保护等级读写为适配边界，未执行完整actor分配、renderer或游戏画面。服务端请求链回归与原生局部结果用于确认这个状态覆盖缺陷；画面是否彻底恢复仍须记录实机验收。
