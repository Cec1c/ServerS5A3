## 礼袋服务端行为

- op515 动作号 **145** 使用真实背包槽位。当前完整摘要匹配的 EXE 将 `[add guildmileage]` 转为 token `0x2d66`，再映射到 145，并将该值保存、写入请求。早期候选沿用旧包动作 143，已由本次静态证据更正；`[use action packet] 1` 是开关。
- 校验当前会话、角色账号归属、城镇场景、会员关系、道具身份/有效期与等级。过图或切角色持有场景锁时返回失败，不等待对方形成锁循环。
- `GuildInventoryUnitOfWork` 按公会登记、角色、该角色背包的顺序取锁；扣除一个礼袋与增加公共积分在同一提交中完成。原公会创建事务不增加背包权限。
- 非会员、过期、积分溢出、非法请求、资产写入失败均不产生部分结算；未知 SQL 提交结果不自动重试。提交成功后依次投影 op515 ACK、op14 槽位和 op70 公会管理信息。
- 通用 op44/op251 路径不能只扣此类礼袋而漏记积分。缺少 PVF 时，已知礼袋也不能退回裸 `[waste]` 消耗。

op515 请求不含可用于持久去重的操作编号。每次有效使用消耗一个实物，不能将“重复请求仍有礼袋时再使用一次”说成同一操作的幂等回执。地下城结算等未来自动发分需要独立的持久事件去重。

成功回包为 `u8(1), u16(slot), u8(list), u32(145)`，共 8 字节。失败回包为 `u8(0), u8(error), u16(slot), u8(list), u8(145)`，共 6 字节；失败时原生回调仍读取源槽位和动作。旧候选复用的 10 字节剩余数量 ACK、2 字节通用失败体均不符合该回调，已替换。

ACK 不含剩余数量；客户端按动作消耗一个本地道具，随后的 op14 刷新权威数量。取消错误的 u16 数量限制，保留现有背包 i32 数量投影上限，拒绝超限库存以免截断。

## 积分记录

礼袋扣减、公共积分增长和记录追加共用上述事务。记录保存当时角色名称、内部角色标识、时间、类型和积分值；晚期 SQL 失败全部回滚，重新读取仍能查询已提交记录。每个公会保留最近 50 条作为近期展示策略，不将这份有限记录作为自动奖励的持久去重依据，也不由旧余额倒推历史。

op747 请求为空体，服务端从当前绑定的角色和账号查验会员归属，返回本会记录；不接受请求指定其他公会。跨频道同会成员可查同一份记录，其他公会及非会员不能读取。成功回包为 `u8(1), u32(count)`，随后每条 48 字节：

| 偏移 | 字段 |
| --- | --- |
| 0 | u32 Unix 秒；匹配原生有符号 32 位时间范围 |
| 4～33 | 30 字节名称区，GB18030、完整字符截断、末尾 NUL |
| 34 | u8 类型；礼袋为 8 |
| 35 | 零填充 |
| 36～39 | 内容参数；礼袋为 0 |
| 40～43 | u32 数额；格式化为有符号十进制，单条不超过 MaxInt32 |
| 44～47 | 礼袋为 0 |

失败仅返回通用失败体，匹配回调不读取后续记录。结果按最新在前输出。数量上限 50 是本服务端策略；原生界面每页可见 6 条，两者不同。

以上 EXE 的 class1 注册片段 RVA `0x1be8235` 指向回调入口 `0x1bc2340`，后者读取数量及 48 字节结构。格式化入口 RVA `0x11a4250` 按类型选择文案；配套 `dstr.dat` SHA256 `52948ff8267715c155c3867368adc12451a61e51801a6682e5357ea47ae4da7a` 的正常 FILE/102 资源中，`20992` 为“使用积分累计道具”，`40162` 为 `%s+%dGM`。类型 5/7 使用其他分支；不能将整个查询误解为仅消费记录，也不能据此宣称其他来源已接入。

回归覆盖礼袋后查询、同会跨频道/异会隔离、身份与畸形请求、旧余额空历史、名称边界、并发与事务回滚。完整 Go 检查、专项 race、真实 PVF 和一次性 MariaDB 通过。原生显示仍待配套客户端与服务端上线后的验收。
