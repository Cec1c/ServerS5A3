# 公会持久精确指纹

公会只读缓存仍使用完整源JSON的SHA256作为版本。持久指纹把散列计算移到写入时，读取只传输固定64字节，不使用TTL、更新时间或仅游戏进程维护的计数器。

数据库通过设置值表的三个AFTER触发器，维护独立InnoDB指纹表。旧游戏、GM及无列名的旧INSERT保持原列数；普通UPDATE、UPSERT、REPLACE、DELETE均在原事务内同步。空指纹事实会回退源SHA；原设置值被删除或TRUNCATE后，旧指纹不能投影成现存公会。

## 安装与验证

`GuildSnapshotFingerprintDDL`只生成可评审DDL；`EnsureGuildSnapshotFingerprint`是显式维护API，调用方必须启用`SchemaOptions.AutoCreate`。普通`EnsureMySQLSchema`和玩家请求不安装它。生产使用所在部署系统的统一维护入口、当前批准范围和唯一任务，不能照抄历史安装命令。

安装前验证源表为InnoDB，拒绝未知同名触发器和不符的指纹表。安装器以专用连接持有具名锁，先建立触发器，再以REPEATABLE READ锁住源键回填；源不存在时也保护对应键间隙。游戏写入和回填都按源→指纹顺序加锁。该过程不复制完整设置值表，也不改公会源、资产或永久回执。DDL仍会取元数据锁；API将本次安装限制在30秒内，调用方可以给出更短期限，应安排受控维护窗口及空间预算。

启动对全部读写分片核验InnoDB表、列和主键、三个完整触发器定义及当前源指纹；只在一致时使用持久指纹。安装缺失、不完整、权限不足或派生表排序规则不兼容时继续原源SHA读取；取消、连接和其他数据库错误仍正常报告。组件快照的`stored_guild_fingerprint`说明本进程实际选择，不将创建了表视为安装完成。

## 恢复与运行边界

源码读取保持旧模式兼容，指纹表是可重建派生数据。修复不完整安装须使用新维护任务，由安装器校验后补齐，不覆盖未知定义。历史版本仍可直接对源SHA校验。

回退时先停用所有持久指纹读者，再按批准维护流程移除触发器，最后才可移除派生表；不能在活跃触发器仍引用表时先删表。数据库恢复必须把源、触发器和派生表视为同一恢复合同，或停服后按原源重建并核验。运行期间不允许绕过维护流程删除/替换受信任触发器或直接改派生指纹；这样的DDL会破坏已经验证的写入合同。

本机制只解决重复散列。公会源的大JSON写锁、历史详情拆分及每种读取的字段投影仍需分别优化，不能据此声称所有公会负载已经消失。
