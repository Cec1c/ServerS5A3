# 公会红包页查询

当前客户端打开红包页会同时发出 1300、1301。此前服务端没有处理这两项，客户端接收位也未开放。本阶段接通同会红包集合及成员贡献查询，并补齐原生回调。

- 1300 成功体为 `u16 memberCount + u32 spending + u32 claimed + u32 rowCount`，随后每条 40 字节。当前服务端尚无红包发放和领取实现，返回真实公会人数及空红包集合，不凭公会资金生成红包或已消费记录。
- 1301 成功体为 `u32 count` 和每条 40 字节的成员记录：角色 ID 位于 +0、等级 +4、30 字节含 NUL 的名字 +5、独立成员贡献 +35、原生默认标志 +39。成员贡献与公会资金、成员 Mileage 分开。
- 两种失败均为 `u8 success=0 + u8 error + u32 error`；普通两字节失败体会缺少原生读取字段。固定原生缓冲区最多容纳 1000 条贡献记录，越界或不能完整编码的成员行拒绝，不截断名字或漏掉成员。
- 查询在现有公会事务锁内核实所属角色与会员身份，不保存、不生成奖励、不修改日额度。错误账号、旧归属、无公会和多余请求体返回完整失败体，其他公会不会收到查询结果。
