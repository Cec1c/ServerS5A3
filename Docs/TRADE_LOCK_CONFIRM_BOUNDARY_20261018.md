# 交易锁定、核对与最终确认边界

用户明确的流程：放入阶段隐藏对方物品；双方锁定后揭示供核对；随后双方最终确认成交。现服晶体资产交换已成功，但完整揭示与确认UI仍未通过验收。

## 已证缺口

旧服务端只在state3禁止改offer，state1（已锁定）仍允许物品新增/删除、金币增加/取回。客户端v125的本地操作入口在state1/5退出；服务端不能在此阶段接受绕过客户端的变更。重复state5在两侧state1后还会晋升state3，可能跳过明确最终同意；一方state3后另一方仍可解锁，从而使已经同意的内容失效。

修复：已锁定成员的四种变更全部拒绝；official-24.9重复state5只幂等确认，不进入state3，仍要求显式state3；任一方最终同意后拒绝解锁。其它客户端保留原state5兼容终确认路径。state5→op17/state1和state3的原发送策略保持，不猜控件编号、时间字段或改变物品隐藏时机。

## 取消投影

前轮4f03a436候选在add ACK写失败时把新行也放入op16。当前v125的NOTI16在0x20319ca注册0x200af50；该handler按u16数量和每行u16交易格/u8来源/u16目标解析。它取本地list0交易行；若目标背包格存在，则在0x200b1d9直接读取交易行虚表，没有先判空。

最小原生执行证实list0没有新行、目标格存在时到达source=0的读取；目标格不存在时则试图插入空item。ACK失败不能假定客户端已创建新交易行。因此只从该sender取消内容中排除新行，保留已成功ACK的旧行；金币ACK失败投影回操作前的已确认金币。remove ACK失败仍包含尚未确认取回的旧行/金币；ACK成功后peer通知失败不重复恢复。覆盖只用于取消内容，不把旧内容写回可成交map。
