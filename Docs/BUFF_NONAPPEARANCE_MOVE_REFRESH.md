# 非外观装备移动后的BUFF登记刷新

当前1426登记绑定物品实例。明确玩家op19把已登记装备从非外观穿戴槽移到背包后，资产owner和实例身份已正确提交，登记位置也可从仓储重新解析，但旧即时通知只随actor外观刷新发送。护甲等非外观槽经过外观闸门后不会触发该路径，当前登记界面缺少1368位置更新。

装备移动结果在Changed且没有外观刷新时标记登记刷新意图。bridge在ACK、物品刷新及已有后置动作完成后，复用现有sendBuffSwapReapply读取当前合法实例并发送1368。已有外观路径继续负责自己的登记重发；noop和失败事务不增加通知。

新增登记通知遵守既有后置投影暂缓边界。容器刷新遇到可暂缓的提交后错误时，本轮新增1368也暂缓；保留原返回结果及原循环后其他行为。直接ACK/物品写入失败沿原路径停止；1368自身写入失败不再次进入资产事务。

沿用DNFBRIDGE_BUFF_SWAP_REAPPLY=on开关和既有角色/会话校验，不修改运行配置、实例规则、1368编码或actor重建策略。登记持续绑定同一物理实例，重穿/同模板交换/普通背包移动和冷会话读条按当前owner重新定位；删除实例后投影失效但不清空持久登记。

累计部署保留R133登录复述owner修复。公开master232dc早于[MR180](https://gitgud.io/16ww/servers5a3/-/merge_requests/180)，连续无玩家标志复述仍有该既有缺口；公开独立回归和叠加MR180确切文件的兼容验证分别记录。部署本候选时须保留该owner修复。运行开关持久化另由[MR179](https://gitgud.io/16ww/servers5a3/-/merge_requests/179)负责。

实机验收先登记一件非外观槽装备，再明确卸下/重穿，并用同名不同实例交换作对照，观察登记位置随原实例移动；换角色、重登后核对。外观槽操作应只有原有一次actor及登记刷新。服务器请求/事务/报文回归与实际界面验收分别记录。
