# 原生 90 客户端协议兼容

本改动把玩法选择与线协议选择分开，适用于使用 90 原生客户端、但需要保留 `official-24.9` 玩法的服务端。当前取证客户端的 SHA256 为 `8a7af614769d0b47d0647b77c33bce725f2f20258651c01fc6c22ac1db44aa4d`。其他 EXE 应独立核对布局，不能仅凭版本名称套用。

## 配置

保留玩法版本，显式选择原生协议：

```text
DNFBRIDGE_CURRENT_CLIENT_VERSION=official-24.9
DNFBRIDGE_NATIVE_CLIENT_PROFILE=90cn
```

未指定原生配置时继续选择既有 `official-24.9` 分流；共享场景序列化辅助函数的变化仍需由 CI 和上游审查确认跨客户端影响。已有 `90cn` 玩法配置也会识别为原生客户端。原生频道通知使用实际匹配的命令/通知数量 `1519/1468`；602 字节登录形状保留令牌归属校验。

## 修改范围

- 角色列表、冒险团名称、好友与剧情通知：按客户端编号和字段宽度分流，避免界面状态被其他协议覆盖。
- 城镇、队伍与地下城：修正 op9、op24、房间槽表和怪物死亡格式，保留 actor 和会话归属检查。
- 安图恩：原生成员/元数据行、直接邀请检查、完整队员对象初始化、频道退出、断线保留与开团失败回滚。旧版 PVF 内嵌单人路线和普通团队阶段使用独立解析入口。
- 角色状态：原生键位完整保存及账户共享、任务手册完成路由、卸装回显窗口、光环装扮刷新、Buff 换装的 1428 登记和 1369 恢复。

旧格式安图恩资源缺少新版通关上限字段；兼容解析入口使用计数存储容量，不把 `WEEKLY ENTER COUNT` 的两个数擅自解释成角色/账号配额。本 PR 不包含本服额外七次入场事务策略、设备双开策略、私有卡片转换功能、部署配置或 PVF/EXE 文件。资源修改和发布仍需在部署环境独立执行。

## 与上游已有功能的关系

查重基线为公开主干 `335c850e264f974159ae1f13c997bbcd6f2d2ece`，同时核对当时 GitHub 已合并及未合并 PR。上游已经具有 Buff 登记/恢复、安图恩两阶段攻坚和奖励、完整对象重连恢复、键位存储、任务手册完成以及卸装回显保护。本贡献不重新实现这些领域 owner；修改的是原生 90 协议选择、编号/字段布局和进入已有 owner 的分流。

例如，现有 `raid_session_restore.go` 已在重连时发送完整对象，而申请/邀请获准仍只发 mode2 更新；本贡献将该完整对象机制补到原生队员入团入口。现有 Buff owner 已保存按角色绑定，本贡献避免原生 1428 被较新客户端的四字节记录解析器消费，并选择原生 1369 恢复通知。

游戏侧管理编辑围栏已在主干实现，相关本地扩展已从本贡献排除。私有扩展与服务器专属策略同样不纳入本 PR。
