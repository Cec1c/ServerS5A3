# 公会之契约购买与领取

761 支持匹配 PVF 中的金币契约（类型21，内容23—26）：按公会当前300/500/700/1000人容量档位，分别花费300万/500万/700万/1000万金币购买1天。购买权限为职位bit8；扣除购买角色金币，公会积分不变。有效契约从剩余期限续加，最多保留30天；过期后从当前时间起算。

金币、福利有效期和持久购买回执在同一事务中保存。NOTI70向同会成员刷新福利，金币刷新重新读取权威余额。重复请求不再扣费，回包丢失后可从持久回执恢复；余额不足返回10、人数档位不匹配38、超过30天19，失败不改变任何资产。

点击福利中的契约由1244领取当日礼盒。奖励从真实 `[guild contracts]` 读取，当前为490001385、数量1；商品展示道具不是奖励。必须是当前场景中的真实会员；普通成员也可领取。角色、背包、领取回执在同一事务内保存，背包满或保存失败均不记已领取。每角色每服务日一次，06:00重置；换会和重连不重置领取资格，同日时钟回拨不重复发放。礼盒沿用PVF每日06:00删除规则，重登不延长。请求回执永久防重，旧请求跨日重放不生成新礼盒。

## 精确客户端依据

V110完整输入SHA256 `fc4fa42ce9fd47307992fb6808840e68f84d89285570c383a100918aa641c3de` 的VA `0x1196560`发送17字节体，只有末尾u32=21初始化；前13字节是无业务含义的栈数据，不作为身份、道具或操作标识。VA `0x1196010`成功分支无附加字段，失败19显示今日已领取。成功后用NOTI14刷新权威背包；其他领取失败码没有原生提示分支，保留失败状态并记录诊断事件。

当前组合需额外开放1244接收位。生成工具 `scripts/client/patch_guild_contract_v110.py` 只接受上一版完整福利组合 `4f7cfec29d192505c9603fe024977566370e818e8da1e8ef56462114541c2e4b`，仅修改该位和PE校验和，保留全部既有修复及65/1474。

## 验证与上线

真实拆流验证金币扣款、福利列表、权威余额、领取及重试；领域测试覆盖档位、余额、30天、并发、保存回滚、未知提交、06:00、换会、过期、满包与普通成员领取。当前真实PVF和一次性MariaDB分别验证发奖定义、真实SQL扣款/发奖失败回滚、并发及重建后重放。

本功能的EXE必须先完成双端Release、实际玩家stable验签/完整下载以及EXE/PVF/dstr/NPK/profile一致性核验，再部署依赖服务端。原生购买和领取画面单独待验；不会用真实玩家资产制造测试条件。红包收发和其他未实现商品不在此单元内。
