# 进图前原生队伍连接检查

配方输入固定为累计 EXE `7861cd3c546e73651ddfd28047686a29e580f5bebd38b1a7fd681d3b36fc24e0`。
只使用 `.krtext` 剩余 RX 填充，接续原始接收白名单及已解码消息分派；保留其他自定义协议、队长完成应答和队长显示修复。不改 UDP 状态，不发送复活，不调用角色回血入口。

class1/opcode `0x7f13` 请求 PCQ1 固定 32 字节：magic4、nonce8、小端固定八槽角色 UID16、自身槽1、队长槽1、保留0两字节。响应 PCR1 固定40字节，回显除 magic 外的请求，并追加八槽状态。空槽和自身为0；其他槽必须存在原生连接表且连接状态为0。1/2/3及未知状态、缺失连接、名单或队长不一致都不能放行。

服务端逐次生成随机 nonce，绑定当前名单、成员会话代次、队长及原始选图请求。三秒内必须收到每人的有效回应；重复或旧回应、旧会话、伪造名单不能满足检查。读取报告发生在独立等待协程，客户端回应仍由各自事件循环处理。只有整队通过才重新进入原有完整选图校验，提交疲劳/门票前再次核对有效性。单人保持原流程。旧客户端没有此协议，会超时拒绝组队进图，必须与强制客户端资源更新配对部署。

`DNFBRIDGE_PARTY_NATIVE_ADMISSION=off` 是显式回退开关；official-24.9 默认开启。不能在正式部署中用此开关冒称已经修好超时准入。

范围为普通选图入口，包括安徒恩/卢克。超时空自动遭遇战会在同一次同步事务内创建临时战斗队伍并持有战区占用；本改动保留其已有专用准入，不把异步等待插入该事务。不能声称本次新增的原生连接检查覆盖了超时空自动遭遇战。

原生证据：`329ab90` UDP CONNECT FAIL 后 `32991e0(slot,3,1)` 设置3；UDP回连成功路径设置0。`3296c10` 对有效连接表读取 `manager+20a07c+slot*4`，空表项返回0，因此查询额外要求表项非空。`3296dd0` 接受0和3，是发送/过渡条件，不能作为连接成功凭据。本方案不赋予尚未证明的 CMD97 三字节报告任何成功语义。

`test_native.py` 执行实际候选 x86 查询及原生自身槽、角色记录 getter。内存可读性、组包和 socket 出口为显式隔离夹具；覆盖非零连接状态、空连接、名单/队长/自身槽错误、发送器占用及旧协议分派。它不等于玩家客户端渲染、网络畅通或用户验收。
