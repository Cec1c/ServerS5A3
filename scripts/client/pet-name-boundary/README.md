# 宠物名称接收边界

当前客户端的原生队友资料接收器在字段26使用13个WCHAR的目标缓冲区（包括结束NUL）。旧字符串读取器只检查25个编码字节；13个ASCII或中文字符可能通过字节检查，却在宽字符复制时进入无效参数处理并崩溃。

服务端统一将宠物显示名限制为12个UTF-16单元和25个GB18030字节，以完整字符为界。过长默认名先去除ASCII空格再截断，保留正常短名；自定义名直接取安全前缀。登录列表、op105和mode0均使用该边界，读取时不覆盖持久名称。改名仍遵守原有12编码字节及禁用字符规则，增加严格编码校验，拒绝发生在消耗更名卡之前。

客户端候选只替换一个经过指纹核对的宠物名读取调用点，保留其余历史代码、数据及来源通知。它先核对当前报文范围和后续6字节字段，再完整消费名称字段、调用原生编码转换、复制最多12个UTF-16单元；不会拆开代理对。损坏长度或超过255字节的名称沿原调用者失败分支退出。没有更改全局无效参数处理器。

输入固定为SHA256 `b965e2d1d04b4679eba1ba00de6bbceacdc1ccab8789ea22bef98a28f61283d5`，VA `0x0329E74E`，原指令 `8b168b52706a0d8d45d4508bceffd2`。原生分派类型10不能直接等同TCP命令10。工具拒绝不同输入；后续累计版本需重新核对适配。

在安装有x86 MSVC、Python和pefile的本机执行，输出目录必须不存在：

```text
python build_candidate.py --input <累计DNF.exe> --output <独立候选目录> --vcvars <vcvars32.bat>
python verify_candidate.py --baseline <累计DNF.exe> --candidate <独立候选目录>/DNF-pet-name-candidate.exe --output <离线回执.json>
```

离线验证另需Unicorn，执行精确调用点、原始读取/复制/错误处理代码、新辅助函数及原调用者的随后6字节读取；分配、转换、errno和指针解码使用明确的运行时桩。包含原版同址失败、ASCII/中文/增补字符、NUL、坏编码、截断/溢出长度、尾字段、重复接收端和寄存器/栈/缓冲区哨兵。重复接收端是隔离合成执行，不代表实际多人联机。

构建及验证均不启动游戏、不安装、不发布、不部署。EXE只是本地候选，客户端与服务端后续应配套验证；游戏内两人/四人进图、换房、回城及旧版混用仍需实机验收。PVF未改变，不需要为该代码修复生成新索引。
