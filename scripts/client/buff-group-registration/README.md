# Buff 两组登记配对候选

独立离线候选，默认关闭。构建器只写新目录，不安装或执行客户端；源码构造、正式发布和游戏内验收分别记录。

固定输入 EXE `9276348410bbf955f41a4d9e407f5288db883ff6edd68e66f30c83f56dfe3250`；输出 `0618b0db618224079a3d28fadff448b7c35cc463788554810861e6781be3264f`。保留原有累计客户端，只改四处已核对指令、现有 RX 节零填充区及对应虚拟长度与 PE 校验和；其他字节逐字节保持。入口、导入、TLS 和其他功能的指令地址不变。

## 已定位的行为

- 原生管理器每个角色有两组选择和两棵装备树，选择值位于记录 `+0/+4`；`+8/+C` 是等级差值，不能解释为额外两组技能。
- 原生 `0x998530` 在发请求前已更新目标组的选择，再次选同技能会取消。原 `0x994D20` 发出的六字节 1426 不包含组号，取消时的技能 0 尤其无法反推目标组。
- 完整快照 1368 会重置角色的两组记录并调用窗口重置路径。普通 1367 行通知保留选择，但原消费者将所有行固定写入组 0。单独换用未标记的 1367 不能完整修复问题。
- 服务端原状态仅有一份技能和装备槽；切换技能会将原装备沿用到新技能。

## 配对协议及持久状态

只在 `official-24.9` 且 `DNFBRIDGE_BUFF_GROUP_SYNC=on` 的配套环境启用；必须同步使用同一协议的客户端。旧客户端不能消费新增包头。

| 方向 | 消息 | 配对数据 |
| --- | --- | --- |
| 客户端到服务端 | 1426 | `B7, group:u8, skill:u16, slot:u8, list:u8, index:u16`，共 8 字节 |
| 服务端到客户端 | 1367 | `FE, group:u8, selectedSkill:u16, count:u8, rows[33]`，共 170 字节 |

组号仅允许 0/1。客户端使用每包栈局部变量路由，直接恢复指定组的选择，避免调用有切换语义的选择函数或清空管理器。普通六字节请求和未标记的 1367 保留旧路径。

装备按技能分别保存，另存两组当前选择；旧状态只迁入原技能和组 0。取消一组保留其他组及历史技能装备。沿用账号归属事务、物理实例绑定、宠物身份及真实穿戴位置解析；登记失败回传目标组的权威状态，发送失败可重试。登录和穿戴刷新分别投影两组，避免完整快照重置窗口。

本人 mode1 资料仍保留原有单技能载体，因此在选角资料、初始人物绑定、初始完整人物、穿戴人物重建和晚期登录重建成功发送后，配对模式立即恢复两组。称号、宠物或守护珠等后续刷新失败不再跳过这次恢复；普通关闭开关的顺序保持。选角恢复发送失败不标记完成，允许原边界重试。

当前候选处理本人的登记与恢复；其他玩家资料仍沿用既有单个活动技能的资料格式，尚未扩展为双组远端展示。战斗效果和实际窗口绘制仍须游戏验证，不能据离线结果宣称全链路多 Buff 已验收。

## 复建与验证

使用 Python 标准库复建，原生验证另需 `unicorn`：

```text
python scripts/client/buff-group-registration/build_candidate.py --input <BASE_927_EXE> --output-dir <OUTPUT_DIR>
python scripts/client/buff-group-registration/verify_native.py --base <BASE_927_EXE> --candidate-dir <OUTPUT_DIR> --output-dir <EVIDENCE_DIR>
python scripts/client/activeness-ui/Verify-ClientImage.py <OUTPUT_DIR>/DNF.exe
```

2026-11-09 实际结果：

- Linux 域套件 31 个主测试、55 个含子测试节点通过；新增双组协议用例通过。桥接扩大回归 86 个主测试、231 个通过节点，保留失败项及跳过项。
- 34 组固定 x86 指令执行验证通过，包含两组发送/恢复、相同选择重复恢复、原始行解析、绑定物品的组路由、旧 1367 兼容及管理器首次创建。STL、物品查找、网络和 UI 回调是明确模拟边界；未自动操作游戏。
- 复建摘要一致；Windows `SEC_IMAGE_NO_EXECUTE` 检查通过；相关 `go vet`、依赖校验及 Linux 服务端候选构建通过。
- 扩大套件并非全绿：D23 两个宠物重选主测试、D20 实际装备处理器主测试和 R139 关闭开关主测试均失败；用同一资源在原始基线逐项对比，失败节点及诊断一致。两项强化率对照测试缺少各自要求的成对实验 PVF，按原用例跳过。未修改断言来消除失败。
- 初次扩大回归使用未登记的当前 PVF 摘要而被旧校验助手拒绝；现只增加精确 `936cb6c0…` 摘要，未放宽为接受任意资源。中途源码变化的一次编译已作废，最终编译前后 Go 输入摘要一致。
- 后续人物重建专项 41 个主测试、113 个通过节点，包含新增两组恢复、后缀失败及重试用例。扩大登录世代的另 6 个旧主测试报“找不到公会角色”，已在同一资源的原始基线逐项执行，失败节点及诊断一致，保留两边失败。该专项也未声明整套全绿。

上述为离线证据，不代表正式发布或游戏内验收。配对运行仍须核对双组展示边界，并另行记录发布准备。
