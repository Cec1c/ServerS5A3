# 当前累计客户端的队友房间恢复候选

固定输入为112619520字节、SHA256 `250d78d27e115be21240959db1415f7eddabb0c26c255c9ad452a8841f8abc0c`。
构建输出SHA256 `7970c5ddb4253d79d99bcc958a51b2e3a7e0f3bdf9efdcc63f5322f646e52760`，长度保持。

复用已核对的原通知120槽位、UID、owner、对象代次及本地房间成员身份守卫，在原生mode1公共清理和本地角色成功登记后检查现有队友。公共清理执行不等于绑定成功；检查仍需实际对象和当前房间满足守卫。只插入角色类型0x111的现有对象，不创建怪物、不重播技能、不重放通知120或场景加载。

原累计镜像合并了旧代码节，且其虚拟尾部含未物理存储的空间。本配方按实际映射校验旧helper及原生锚点，使用现有`.gttext`的物理零填充和`.a4rw`的未用尾部，保持权限、入口、所有范围外字节和累计功能。旧69ea候选不能直接套用。

客户端不增加定时器，也不独立观察场景就绪。服务端在双方完成加载收尾后追加约750、2000、5000毫秒的有界队友快照，提供上下文后来就绪时的新mode1检查机会；三次之后不会无限补发。晚于该窗口仍未就绪、持续原生插入失败或渲染失败不在本候选的完成保证内。

```text
python build_candidate.py --input <current.exe> --output <candidate.exe> --receipt <build.json>
python verify_candidate.py --input <current.exe> --output <verify.json>
```
