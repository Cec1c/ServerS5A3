# 队友模型房间注册只读取证

用于区分模型指针缺失、模型存在但未在当前房间注册、已注册但显示仍异常。工具只读取操作者明确指定的 Windows 进程，使用 `OpenProcess(0x1010)`；不启动客户端、不挂钩、不写进程、不调用目标函数、不发游戏包。

只接受源码列出的四个 EXE 摘要，后三者是本批未发布候选；同时校验进程路径、固定映像基址和六处实际 getter/成员查询及邀请限制机器码。另比较网络保留/Buff/空技能保护的入口及RX辅助区，拒绝磁盘文件已替换但当前进程仍是另一受支持版本的情况。该范围比较不冒称完整运行映像哈希。持有同一进程句柄并记录创建时间，不按名称重新查找或跟踪重启后的进程。输出以独占新文件方式写入，不覆盖历史证据。

由测试者在故障现场选定进程后手动使用，例如：

```powershell
python collect.py --pid <客户端PID> --exe <该进程的DNF.exe完整路径> --output <新的本地JSON路径> --seconds 15
```

默认只采一帧，连续采样最多30秒、约每100毫秒一次。不要将这些本地取证 JSON 提交仓库。

## 静态依据与判读限制

- 当前735 EXE：`1fa2790 -> 251e810` 返回 `56a2250` 控制器；`32b4970` 读取控制器 `+C0` 当前模式。旧采样中的 `56a3758` 是另一个全局对象，不能代替本路径控制器。
- 初次落位 `1ff2ec0` 检查模式虚函数 `+104`，再由 `2046f30` 调模式 `+60` 取得房间，`370dc10` 读房间 `+C4` 注册表。
- `2879c90` 在注册表 `+C/+10` 指针区间中按 actor 指针查找成员；`288a260` 的普通插入分支在 `288a584` 将 actor 加入同一向量。工具最多读取1024项，越界或数量异常保留拒绝结果，不截断冒充完整集合。
- 模式方法只被动识别简单取字段/取地址以及常量布尔返回的机器码。复杂函数、跳板或未知代码保存地址和字节，标记 `known=false`，绝不执行或猜测结果。
- `activeManagerSlots` 来自现有活跃角色管理器；初次落位实际通过 `57b9080` 对象的虚函数 `+3C` 解析槽位。工具记录该函数地址和字节，但不执行，故两套槽位是否相同标记为未验证。
- `registrationObserved` 只表示该帧读取到的 actor 指针是否出现在该房间列表中。即便为真也不证明渲染可见、位置正确或初次120处理成功；注册也可能来自其他事件。
- 采样不暂停游戏。首尾指针/向量头检查只能发现部分并发切换，不能排除ABA、列表原地修改或采样间隙。变化时不输出确定的注册判断；未知函数、读取失败和文件变化不能当成“没有模型”。

## 等级职业错序修正的判读

`profileIdentity` 从wrapper内联profile读取职业、转职和觉醒值。`3C1BEA0` 返回wrapper+30，原生NOTI9新建资料将职业写到profile+4；`outsideNativeJobTable` 标识读到的职业超出原生0..15索引范围。首尾值或管理器槽位变化时该判断为null。等级字段经过编码，本工具不将其原始字节当作等级。职业90可支持旧错序路径的判断，正常职业仍不能单独证明模型可见；采样也无法证明最早写入者。

`invitationRestriction` 只读取NOTI7模式0的一个“不新建窗口”条件：`E91820`的既有全局指针565CEA8，成员+9非零且+5C为1时，`E90A50`返回真。该条件在20363CE被调用，跳过窗口后仍可到2036448播放提示音。初始化时+5C为0，2044D96的条件满足才经E92390写成1；其条件包含2961F70的本地角色+3C4标志和任务范围检查。此处不把它解释为攻坚队人数或用户拒绝邀请设置，不修改状态。

`wouldSkipNewMode0Window` 是当前采样值对应的谓词，不是故障时分支命中记录。已有169窗口会走另一条路径；此字段为false也不能排除窗口管理器拒绝创建等原因。所有样本的`notificationBranchObserved`固定为false。

本工具只完成源码与静态反汇编核对，未运行本工具或新增测试，未部署。独立客户端候选已生成，采样兼容摘要与代码范围已更新；已确认的协议字段错序有独立服务端修正。模型现场是否完全恢复仍未闭环，本工具本身不是修复。
