# 调用点 010164B1 的空来源保护

固定累计客户端的调用点 `010164AF` 通过虚方法 `+138` 查询来源对象，随即在 `010164B1` 将返回值传给 `02947D20`。来源为空且参数使用缺省等级时，原路径进入 `02930A20`，按 `NULL + 0xF94 + 1*8` 取得字段地址，在 `037DF6A3` 读取 `0xF9C` 时崩溃。

本机转储和另一台电脑提供的日志具有相同的这一条调用链。两份材料是不同机器的独立事件；另一台电脑明确未运行本次外部采样工具。两份记录不能合并为同一次事件，也不能据此认定本机采样完全无影响。原始转储、日志、角色资料和服务器信息不入库。

`patch_effect_source_null.py` 仅在这个调用点检查查询结果。非空分支保留原 thiscall、五个参数和调用；空分支不进入解引用空来源的函数，移除原调用应消费的20字节参数并保留零返回值，再进入原有公共收尾，写入该行的返回结果并恢复寄存器。不会跳过收尾而保留旧行指针，不修改通用数值解码器。原被调用函数本身在另一个缺失依赖分支也可以返回零；这不证明缺失来源时的完整效果与玩法已验收。

输入只接受 SHA256 `244b5c1e3126967d8a2b718658c586c1ac675a08b255d7377e95b93b4b815112`、112607232字节的累计正式客户端。构建器检查确切输入、调用点、参数准备、公共收尾和被调用函数签名，使用现有 RX `.gld127` 节 `06F88600` 的零填充区，仅修改入口、辅助代码、节虚拟大小和PE校验和。不新增节，不扩大权限，不覆盖原文件。

对象查询、行访问器、正常效果创建是明确夹具；非空缺失owner用例保留原被调用函数的空返回/退出指令，正常数值读取采用夹具。该回归没有启动游戏，没有执行GPU绘制，也未验证所有对象/技能效果。本保护处理这一条空来源调用链；首次队员模型登记由独立配方处理。目录中的命令只生成和检查离线候选，部署及实机验收另行记录；不要求重新启用已撤下的外部内存采样工具。
