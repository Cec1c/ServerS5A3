# 公会身份通知在切频道期间的空角色保护

匹配累计客户端输入的 NOTI127 回调 `VA 020384E0` 读取一个身份字节，更新现有角色后，通过 `0296DD80` 获取角色数据。后半段未经空值检查便取 `+30`、`+2DC` 的受保护字段。角色数据为空时，`ECX=0000030C`，在 `VA 037DF6A3 / RVA 033DF6A3` 的 `mov eax,[ecx]` 发生访问异常。注册点 `020463A3` 把该回调注册给 class0 消息127；这不是宠物名称接收路径。

工具只将 `02038539` 的7字节调用点改为局部保护。角色数据存在时恢复原指令及标志位；不存在时跳到此回调原有的栈帧退出点，保留已经消费的身份字节和前半段可用角色更新。没有修改通用受保护整数读取器、异常处理器、角色数据或公会权限。

输入必须是工具列出的完整摘要之一：累计V201或在其上加入宠物名称保护的候选。后续累计版本应先重新核验输入与挂接点，不能仅按地址套用。输出增加独立RX节 `.gld127`；除7字节挂接点及必要PE头外，所有原字节、来源通知、入口、导入、TLS和已有修复保持。

```text
python build_candidate.py --input <verified-client.exe> --output <new-empty-directory>
python verify_candidate.py --baseline <verified-client.exe> --candidate <output/DNF-guild127-candidate.exe> --output <receipt.json>
```

依赖 `pefile` 和 `unicorn`。验证运行真实NOTI127回调、角色缓存访问器、空对象失败指令及新保护；包读取、角色更新、有效整数读取、ID解析和公会接口使用显式桩。136个用例覆盖8种空对象组合及128种正常路径（16种对齐、角色显示对象有无、公会对象有无、缓存命中或解析）。原版空对象在相同地址失败，候选返回；正常路径的调用、返回值、标志位、栈、保留寄存器均与原版一致。工具不启动游戏，也不证明真实切频道已经验收。

配套服务端修复用同一个城镇锁串行化公会投影与EXIT应答。已有投影先完成，再发EXIT；成功应答后旧会话不再投影公会状态。写失败保留原有错误和交接撤销逻辑，新连接独立初始化。此时序窗口通过合成请求验证，但原始日志缺少寄存器和完整报文顺序，不能宣称已重放现场或证明它是唯一触发来源。

本轮仅修复和验证，不部署、不发布客户端、不更新玩家通道，不修改PVF或生成资源索引。
