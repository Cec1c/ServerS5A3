# 本人 Buff 快照保留队友登记

当前完整快照接收器 `0x998890` 在读技能号前调用全局清理 `0x997210`，删除所有 actor 的登记树，然后只重建本地角色。四端城镇登记一致，进入副本后两端丢失奶妈登记；失败端最后一次奶妈投影早于本人的 1368 快照，保留端在快照之后仍收到补发。

配方只将 `0x9988F5` 的一次调用改为 21 字节 helper。存在本地 actor 时调用已有 `0x997C30(manager, actor)`；该函数按键删除指定角色登记，并保留其原生 UI 刷新。没有本地 actor 时尾调用原始全局清理。其它全局清理调用、角色销毁、1367 行更新和队友 mode1 接收路径不变。

输入固定为累计网络保留候选，输出是独立 EXE，不访问进程或服务端。复用 `.gld127` 已验证空闲 RX 填充，允许改动只有调用点、helper、节虚拟尺寸及 PE checksum。发布时必须保留此前累计修复。

```text
python build_candidate.py --input <累计候选.exe> --output <独立候选.exe>
python verify_candidate.py --input <累计候选.exe> --report <新报告.json>
```

验证器需要 Unicorn。它执行完整快照接收器与原生按角色清理函数；STL 查找/删除、包读取、UI 查询及装备行消费是明确夹具。100 个用例含原始行为负对照，不能代替真实物品析构、实际施放和多人实机验证。

累计候选四客户端的一次隔离实测中，游戏界面组队、测试入口进入普通副本后，四端在进图前、进图后及稍后复采样均保留同一奶妈的七项登记及非空装备指针。旧候选在同一副本曾有两端丢失登记；队长和成员顺序不同，未覆盖全部加载顺序。此结果不证明实际施放等级、效果、战斗同步或通关再次挑战，也不表示正式部署或用户验收。
