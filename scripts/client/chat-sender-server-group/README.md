# 聊天发言者服务器组回归

当前客户端 SHA256 `9276348410bbf955f41a4d9e407f5288db883ff6edd68e66f30c83f56dfe3250` 的 NOTI12 (`2035370`) 和 NOTI370 (`2A042F0`) 在消息类型与发言者 UID 后读取一个字节，分别在 `20354AB` / `2A043F8` 写入聊天记录 `+1C`，含义为发言角色的服务器组。服务端原来错误写入收件连接的频道号；例如本服组0、频道42被写成组42，聊天姓名由此带上跨服务器身份。

`verify_native.py --exe <精确累计EXE> --packets <Go导出目录> --output <回执>` 在未修改的原生接收器上执行Go处理器导出的普通/物品链接消息，核对完整消费、UID、组0/7/249、消息文本与记录字段。每条消息另构造旧频道42投影作为反例，证明错误字段会原样进入记录。省略 `--packets` 只使用合成输入，不得将它写成Go处理器验证。

依赖现有 `scripts/client` 测试夹具与 pefile/unicorn。场景角色/姓名查询、DSTR转换、物品行存储及最终聊天布局是夹具；原生标量读取和记录构造实际执行。该回归不运行游戏，不修改EXE，不证明菜单已渲染或按钮已实机验收。频道、场景、实例投递及资料查询授权仍由既有服务端路径限制。
