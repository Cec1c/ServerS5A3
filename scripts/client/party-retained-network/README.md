# 副本保留队伍记录的连接维护候选

仅处理固定客户端 NOTI9 的别名记录更新。服务端在成员离队后更新多个记录；原生解析器将本地角色从一个记录绑定到同名单的另一个记录时，进入 join 分支并调用网络虚函数 +0xA8，导致剩余队员的连接被清空。保留模型的服务端修改本身不能解决这个问题。

候选只重定向 0x2017D97 六字节，在 .gld127 未使用 RX 填充写入 293 字节判定；保留全部寄存器、标志和原有后续名单差分。只有 route1、当前本地绑定、当前频道或 owner0、至少两个已有同槽同角色且模型存在的成员、恰好一个本地模型、至少一个仍存在的队友连接，才能跳过完整网络清理。缺席槽位仍交原生后续逻辑删除。新增、更换、换位成员以及缺少已有连接的情况继续执行原始清理。

输入 SHA256：735ed3e96f178bd2b546be18ff38ba4a578c951092b1d97a352ab73db7333d8b。
候选 SHA256：52223a060313b352fe43e718bc813ccb6824ea07913579f097d699dd21a91a1e。

`build_candidate.py --input <固定EXE> --output <新文件>` 离线构建，校验所有允许范围外字节不变。
`verify_candidate.py --input <固定EXE> --report <新JSON>` 以 Unicorn 执行实际机器码，69 个用例包含旧代码误清理对照、二至四人保留与离队、不同路由/频道、空管理器、新增、更换、换位、单人、缺少模型/连接和未绑定记录；检查寄存器、标志、栈及队伍内存未被改写。

与保留名单的服务端修复合用后，四个原生客户端在普通副本完成入场；普通成员退出、队长退出后，留队客户端的模型与连接在采样中持续保留。最后一人经游戏界面回城解散队伍后，成功重新组成四人队，并完成魔界裂缝（316，难度3）加载；四端均存在四个人物对象和三条队友连接。

上述入场通过既有受守卫的选择/进图测试入口发起，组队及退出使用原生界面。状态采样不能排除采样间隙的瞬态；魔界裂缝角色随后在无人操作时死亡，尚未验证战斗同步、通关再次挑战、勇气祝福等级或原闪退。该记录不代表正式部署或用户验收，发布前须完成本批剩余验证。
